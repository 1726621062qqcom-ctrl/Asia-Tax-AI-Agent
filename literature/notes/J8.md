# J8 Kuhn, Kacker & Lei, 2010. Practical Combinatorial Testing. NIST Special Publication 800-142（官方报告，按研究类结构记录）
版本：published（NIST SP，美国政府作品）；J8 文件为 82 页 PDF，下列页码为 PDF 页码（`=== [p.N] ===`，与印刷页码差 6）；阅读范围：第 8–28 页（第 1–4 章）、第 34–48 页（第 6、7 章，表 10–11 的数字表只读文字结论）、第 72–75 页（附录 B），第 22–23 页（约束，属第 3 章）；第 5、8、9、10 章（序列覆盖数组、模型检测、故障定位）、附录 A、C、D 略过

## 1. 问题与作者主张
- 作者主张组合测试（combinatorial testing）可降低软件测试成本并提高有效性；本报告是一份自足的教程 [p.8]。
- 作者指出"交互失败"（interaction failures）只有在两个或更多输入值交互时才暴露；关键洞见是并非每个参数都参与每个失败，多数失败由单个参数值或少数参数的交互触发 [p.10]。
- 作者提出由经验得到的 interaction rule：多数失败由单因素故障或两个因素的联合效应引起，三个及以上因素引起的失败逐渐减少 [p.11]。
- 作者指出组合测试的三个难点：高效生成覆盖所有 t-way 组合的测试集在数学上困难；多数参数是连续变量，必须离散化到少数取值；最突出的是确定被测系统对每组输入应输出什么（oracle problem）[p.12]。
- 作者强调覆盖数组只解决测试数据，oracle 问题仍需另行解决 [p.15]。

## 2. 方法
- 术语：error 是开发者的错误，fault 是错误程序与正确程序之间的差异，failure 是与规格不符的结果 [p.12]。
- 两种用法：对配置参数取值组合（用现有测试集在各配置上运行），或对输入参数取值组合（组合覆盖的输入成为完整用例）；两者可叠加 [p.12-13, p.15]。
- Covering array：每行一个测试、每列一个参数，任取 t 列均含这 t 个变量所有取值组合；所需测试数与 v^t log n 成正比（n 个参数，各 v 个取值）[p.14-15]。
- 输入空间划分：用 equivalence partitioning 与 boundary value analysis 把大值域降为少数代表值；理想是同一分区内任何值对被测程序的影响相同；分区最好依据规格确定，而不是在值域上均匀取点 [p.25]。Boundary value analysis 在每个边界及其两侧最小单位处各取一值，每个边界三个值；也要测试范围两端 [p.26]。
- Oracle 的四种做法：crash testing（等同于有纪律的 fuzz testing）；embedded assertions（代码内嵌前置、后置条件作为可执行规格）；model-based test generation（用模型与 simulator 或 model checker 生成期望结果，model checker 的反例即完整测试用例）[p.15-16]。
- 约束：不能简单删去不可测组合的测试，否则会丢失本该覆盖的其他组合；应在覆盖数组工具（ACTS）中声明约束，让工具生成不含非法组合但仍覆盖其余组合的数组 [p.22]。
- 组合覆盖度量：variable-value configuration（t 个变量各取一个有效值的组合）；simple t-way combination coverage（所有取值配置都被覆盖的 t 变量组合所占比例）；(t+k)-way 覆盖；configuration coverage；(p, t)-completeness（配置覆盖至少为 p 的 t 变量组合所占比例）[p.35-37]。
- 不依赖源码的度量：代码覆盖（statement、branch、condition、MCDC）依赖源码，组合覆盖是黑盒度量 [p.35]。

## 3. 数据与设置
- 经验失败数据（附录 B）：医疗设备、浏览器、服务器、NASA 分布式科学数据库、网络安全五类系统为自然发生的缺陷，TCAS 研究使用植入缺陷；六个研究的最大交互数为 4 到 6 [p.72]。

## 4. 结果
- 经验数据：NASA 应用中 67% 失败由单个参数值触发，93% 由 2-way 组合、98% 由 3-way 组合；其他应用的检出曲线类似，在 4 到 6-way 达到 100% [p.11]。医疗设备 66% 由单变量触发，97% 由一或两个变量触发 [p.72]。
- NVD 的 DoS 漏洞累计比例：1 变量 93%，2 变量 99%，3 变量 100% [p.73]。
- 航电代码中分支表达式含 1 个变量的占 74.1%，含 2 个累计 93.7%，3 个累计 98.2%；作者称多数失败由比分支表达式更复杂的变量交互触发，只有 NASA 开发阶段数据库的分布与分支分布相似；作者推测测试与使用会使曲线向下并右移 [p.74]。
- 10 个二值变量穷举为 2^10 = 1,024 种组合，3-way 覆盖数组只需 13 个测试 [p.14]。
- 34 个开关共 2^34 = 1.7 x 10^10 种设置，3-way 覆盖只需 33 个测试，4-way 只需 85 个；每个 34 参数的测试含 5,984 个 3-way 与 46,376 个 4-way 组合 [p.27]。
- 访问控制例：time 取值 0000、0539、0540、0541、1019、1020、1021、1440，总组合 2·8·7·2·2 = 448，覆盖数组 t = 2、3、4 分别需 56、112、224 个测试；作者称在参数少时相对穷举的优势不大 [p.26]。
- 4 个以上参数且每参数 v 个取值时测试数按 v^t 增长；作者建议每个参数取值不超过 8 到 10 个，并建议从 t = 2 起逐步提高 t，直到 t-way 测试不再发现错误，再（可选地）试 t+1 [p.27-28]。测试数随参数个数仅对数增长；20 个参数产生数百个测试时，40 到 50 个参数可能只多几十个 [p.28]。
- 嵌入断言作 oracle 用于智能卡测试：用 JML 断言可找到 80% 到 90% 的错误 [p.16]。
- 随机对覆盖数组：10 个参数、每个 4 个取值的所有 3-way 组合，覆盖数组 151 个测试，纯随机需要超过 900 个 [p.15-16]。达到 100% 组合覆盖所需随机测试数与覆盖数组之比在多数情形超过 3，t = 2、3、4 的平均比分别为 3.9、3.8、3.2 [p.40]。
- 若随机测试集覆盖 99% 的 4-way 组合，SUT 含 m 个独立失败时同时覆盖全部失败的概率为 .99^m；作者据此称有多个失败时随机测试可能明显更差 [p.44]。参数多于约 20 个时，随机生成可覆盖 99% 以上的 4-way 组合；覆盖数组生成器在参数很多时可能耗时数小时到数天甚至无法处理，而随机生成很快，可先随机再测量覆盖并补齐 [p.47]。
- 作者称覆盖数组生成是 NP-hard 问题 [p.47]；不同算法产生的数组大小可相差 50%，最紧凑的 t-way 数组可能含较少的 (t+1)-way 组合，较大的次优数组反而可能检出更多 [p.43-44]。
- 度量例（4 个二值变量的测试集）：simple 2-way 覆盖为 1/3 = 33.3%，3-way 为 0%；configuration 覆盖 19/24 = 79%；(.50, 2)-completeness 为 100% [p.36-37]。

## 5. 作者陈述的局限
- 经验数据"虽非定论"（not conclusive），仅表明失败涉及的交互数相对较低 [p.11, p.72]。TCAS 一项使用植入缺陷 [p.72]。
- 离散化、期望输出的确定都不是组合测试独有的问题，需要工程判断 [p.12, p.28]。
- 分区的理想（同分区内行为一致）在实践中不一定成立 [p.25]。
- 覆盖度量工具需把测试映射为离散数值（如星期映射到 0–6 或 1–7）[p.39]。
- 对随机与组合测试比较，已有研究结论相互冲突；分析并不表明组合测试一律优于随机，只表明成本相同时更倾向组合方法 [p.40, p.47]。
- 何时停止测试需在成本与漏检风险间权衡，选择 t 取决于资源、时间与成本收益 [p.27]。

## 6. 原文摘录
- "Most failures are induced by single factor faults or by the joint combinatorial effect (interaction) of two factors, with progressively fewer failures induced by interactions between three or more factors." [p.11]
- "Generating 1,000 test data inputs is of little help if we cannot determine what the system under test (SUT) should produce as output for each of the 1,000 tests." [p.12]
- "partitions are usually best determined from the specification" [p.25]
- "errors are more likely at boundary conditions because errors in programming may be made at these points" [p.26]
- "we cannot simply delete tests with these untestable combinations, because that would result in losing other combinations that are essential to test but are not covered by other tests" [p.22]
- "statement coverage is a relatively weak criterion. At best, statement coverage represents a sanity check: unless statement coverage is close to 100%, the test set is probably inadequate." [p.34]

## 7. 对本库的可用点（笔记者推断）
- 阈值邻域（电池层）：报告的边界值分析（每个边界取边界处及两侧最小单位三个值，例如 539/540/541）[p.26] 可直接对应本库的 183 天、持股比例、750m EUR 等阈值。事实包应由"规则中引用的阈值参数"自动派生邻域取值（阈值 -1 单位、阈值、阈值 +1 单位），而非人工固定；阈值可取自库里 ~300 个带 verbatim quote 的参数，因此事实包与库同源（层：battery 生成器、parameters）。报告用 ATM 的 `<` 与 `<=` 为例说明边界错误，本库的"含/不含阈值本身"（`>=` 对 `>`）同样需要由引文确定，而不凭记忆。
- 组合覆盖代替全网格：事实包 x 模板 x 辖区 x 时点的全网格会爆炸；覆盖数组按 v^t log n 增长，可对"辖区安排、收入类型、持股档、居住天数档、时点档"做 2-way 到 4-way 覆盖，并用 ACTS 类工具的约束声明排除不可能组合（如某辖区无某税种）[p.22]。注意报告的约束机制要求不能事后删测试（会丢组合），应在生成时声明约束（层：battery）。
- 把"coverage"换成可量化的输入空间覆盖：报告的 simple t-way coverage 与 (p, t)-completeness [p.36-37] 可作为电池的新度量，与"规则至少触发一次"并列；它不依赖源码，是黑盒度量（层：评测度量）。报告同时说明 statement coverage 只是 sanity check [p.34]，可用来支持"规则 fired 至少一次"只是下限，而不是充分性证据。
- Interaction rule 对 t 的选取：经验数据中 2-way 到 4-way 已覆盖绝大多数失败 [p.11, p.72-73]，但数据来自嵌入式、浏览器、服务器与漏洞，不是税务规则。对本库应先用 t = 2 或 3，并把"每提高 t 是否发现新缺陷"作为停止规则记录下来 [p.27]。税务规则往往涉及多条件联立（辖区 x 持股 x 时点 x 收入类型），是否符合该规则需在本库自测数据中验证，不能直接套用。
- 取值数控制：报告建议每个参数不超过 8 到 10 个取值 [p.28]，并按规格而非均匀取点划分 [p.25]；本库的分区应来自库里条款的阈值与分档，不是任意档位。
- Oracle 问题：报告指出覆盖数组解决不了期望输出 [p.12, p.15]，且 crash testing 只能发现崩溃 [p.15]。本库现有不变量（floor ≤ ceiling、非负、每个税项有引文等）正相当于"弱 oracle / 嵌入断言"；报告称断言型 oracle 在智能卡例中找到 80% 到 90% 的错误 [p.16]，但那里的断言是完整规格的可执行形式，本库的不变量远不是完整规格。因此可用的做法是增加 metamorphic 关系和对照用例（来自官方样例或条款算例），而不是依赖这几条不变量。
- 指标作弊：报告对覆盖度量的结论是"工具要能量化剩余风险"，并给出带分母的度量（全部 t-way 组合数）。本库可把"未覆盖的 t-way 组合"列表作为必须解释的输出，使放宽容差或宣告规则为 silent 都得显式记入，而非让指标变好（层：评测治理）。报告本身没有讨论度量被操纵的情形。
- 随机补足：报告说明随机测试在参数多时对 4-way 覆盖率已很高，但对多个独立失败的联合发现率按 c^m 下降 [p.44, p.47]；可先随机生成大量用例，再用覆盖度量找缺口并补测 [p.47]。
- 不适用：数据来自软件缺陷而非税法规则；报告把参数当成独立可选的输入，而本库的规则存在强依赖（辖区决定税种），需要大量约束；报告的离散化假设值域内行为一致，对分段累进税率或封顶规则只在分段内成立；序列覆盖数组、模型检测与故障定位章节（第 5、8–10 章）本次未读，不作结论。
