# M5 Koreeda & Manning, 2021. ContractNLI: A Dataset for Document-level Natural Language Inference for Contracts. Findings of EMNLP 2021, pp. 1907–1919
版本：published；M5_Koreeda2021_ContractNLI.pdf；第 1–9 页全读（任务定义、数据、Span NLI BERT、实验、讨论），第 11–13 页附录读（采集细节、17 条假设、超参），参考文献略过

## 1. 问题与作者主张
- 作者提出合同的文档级自然语言推理：给定一份合同和一组假设句，判断每条假设被合同蕴含、与合同矛盾、还是合同未提及，并以合同中的若干片段作为判断的证据 [p.1]。
- 作者称这是首个用 NLI 做合同的数据集，也是最大的标注合同语料（607 份）[p.2]。
- 作者称已有模型在该任务上表现很差；提出的 Span NLI BERT 把证据识别建模为对预定义片段的多标签分类而不是预测起止 token，并用动态切分处理长文档 [p.1-2]。
- 作者称合同的语言特征，尤其是"以例外作否定"，是任务困难的来源 [p.1]。

## 2. 方法
- 任务：三类 NLI（ENTAILMENT / CONTRADICTION / NOTMENTIONED）加证据识别；证据片段是句子或句内列表项，只在前两类时定义 [p.2]。作者主张整句作证据，因为律师要在可理解的上下文里核对证据，这与事实型问答的 token 级片段不同 [p.2]。
- 假设集固定为 17 条，适用于所有合同（含测试集）；因此可用面向例子的标注指南提高一致性 [p.2-3]。
- Span NLI BERT：在每个片段前插入 [SPAN] 标记，在其上接 MLP 做二分类；[CLS] 上接 MLP 做三类 NLI；动态步长切分保证每个片段至少在一个窗口里完整且有足够上下文（算法 1）；多窗口结果按片段概率平均，NLI 概率按窗口内片段概率之和加权 [p.4-5]。
- 基线：多数类、文档级 TF-IDF+SVM、片段级 TF-IDF 余弦、片段级 TF-IDF+SVM、SQuAD 式 BERT [p.5]。

## 3. 数据与设置
- 607 份保密协议（NDA），来自 EDGAR 与搜索引擎；训练 / 开发 / 测试 423 / 61 / 123 [p.3]。
- 训练集每份文档平均 77.8 个片段、2,254.3 个 token；86% 的文档超过 BERT 的 512 token 上限 [p.3]。
- 标签分布：ENTAILMENT 与 NOTMENTIONED 占大头，约半数假设同时有蕴含与矛盾两种情形；多数蕴含 / 矛盾的假设有 1–2 个证据片段，最多 9 个 [p.3]。
- 指标：证据识别用 mAP 与 P@R80；NLI 用 accuracy、矛盾类 F1 (C)、蕴含类 F1 (E)，先按文档微平均再按标签宏平均 [p.5]。

## 4. 结果
- 表 4：Span NLI BERT（BERTlarge）mAP .922、P@R80 .793、Acc .875、F1(C) .357、F1(E) .834；片段级 TF-IDF+SVM mAP .836、P@R80 .322；SQuAD BERTlarge mAP .869、P@R80 .661；SQuAD BERT 的 mAP 不比 TF-IDF+SVM 好 [p.6]。
- 矛盾类 F1 远低于蕴含类，作者归因于标签不平衡 [p.6]。
- 表 3：更大的骨干（DeBERTa v2 xlarge）同时改善证据识别与 NLI（mAP .933、Acc .885）；在判例语料上预训练无益；在 CUAD 上微调过的 DeBERTa 略有提升，是最好结果（Acc .892、F1(C) .405）[p.6]。
- 表 5：把假设句换成随机初始化的符号，证据识别与 NLI 一致下降，说明假设的表面词有用但差距不大 [p.6]。
- 表 6：给模型 oracle 证据片段做二分类，NLI 明显提高，F1(C) 从 .490 升到 .657（BERTbase）[p.7]。
- 以例外作否定：局部情形占 12% 的文档—假设对（59% 的文档），非局部占 7%（44% 的文档）；少数类准确率从 .77 降到 .40（局部）、从 .72 降到 .00（非局部）[p.7]。
- 不连续证据片段占 28% 的文档—假设对（81% 的文档），对整体 mAP 无负面影响，但"读到全部片段前要读的片段数"受影响，片段间距越大越明显（Spearman ρ=0.205，p=0.015）[p.7-8]。
- 引用定义的情形并不比无引用更难（表 9）[p.8]。

## 5. 作者陈述的局限
- Span NLI BERT 对稀有标签表现差，易受以例外作否定的影响 [p.9]。
- 只覆盖一种合同类型；换到其他类型要再标注类似数据 [p.2]。
- 数据从机器学习角度规模有限，标签不平衡且多任务 [p.7]。

## 6. 原文摘录
- "We argue that extracting whole sentences is more appropriate for ContractNLI because a lawyer can then check the evidence with comprehensible context around it" [p.2]
- "Span NLI BERT performed significantly better than the baselines, both in terms of evidence identification and NLI. Nevertheless, the performance for contradiction labels is much worse than that of entailment labels, due to the imbalanced label distribution." [p.6]
- "We can observe in Table 6 that giving models oracle spans substantially improves NLI performance, notably the F1 score of CONTRADICTION." [p.7]
- "This phenomenon can occur both locally (i.e., within a single span) or non-locally, sometimes pages away from each other." [p.7]
- "Contrary to our expectation, discontinuous setting did not have a negative effect on overall evidence identification mAP score (Table 8)." [p.7]

## 7. 对本库的可用点（笔记者推断）
- 本库把每个布尔字段读成"是 / 否 / 缺失"，与本文的 ENTAILMENT / CONTRADICTION / NOTMENTIONED 同构：把字段释义写成假设句（如"受让方在转让后 12 个月内持续持有该股权"），对候选段落做 NLI，就得到值和"未提及"。这一步可用 MNLI 微调的 DeBERTa 在程序侧做，不用语言模型；本文的 TF-IDF 片段检索 mAP 已达 .836，说明候选段落用检索取是可行的。
- "以例外作否定、非局部、相隔数页"是本库"值错引文真"的一种来源：一段说了一般规定，几页后的例外把它翻转。单段落读值拦不住；需要（a）把同一字段的所有候选段落一起给读取器，（b）各段单独读得出不同值时报冲突。本文表 6 还说明证据找对了判断就大幅变好，所以定位的召回比读取的精巧更值钱。
- 本文证据以整句、可独立理解为准，与本库"引文须逐字在原文、交给人复核"的做法一致；可把本库的引文粒度明确为句或列表项，便于与案例校验和人工复核对齐。
