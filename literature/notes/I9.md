# I9 Su et al., 2024. STARD: A Chinese Statute Retrieval Dataset Derived from Real-life Queries by Non-professionals. Findings of EMNLP 2024
版本：published；I9_Su2024_STARD.pdf；全文读至第 10 页（正文与局限），参考文献与附录略过（附录 B–I 的实现细节未读）

## 1. 问题与作者主张
- 作者认为现有 statute retrieval 基准多来自律师资格考试和判决书等正式专业查询，忽略了缺少精确法律术语的普通公众查询 [p.1]。
- 作者发布 STARD：1,543 个来自真实法律咨询的查询，55,348 个候选法条；称其为据其所知首个查询来自普通公众的 statute retrieval 数据集 [p.1-2]。
- 作者称法律检索的相关性标准与开放域不同：涉及对不同法律领域及其关系的理解，而不只是文本相似 [p.1]。
- 作者主张现有检索方法对这类真实查询都不够好，最佳方法 Recall@100 仅 0.907 [p.1]。
- 作者提出三步标注框架（recall、query decomposition、filter），并称其可能适用于其他大陆法系国家 [p.3-4]。

## 2. 方法
- 标注三步，模拟法律三段论 [p.3]：
  - Recall：自顶向下，先确定部门法（民法、刑法、行政法），再逐级细化（如合同法/侵权法及具体类型），把范围缩小到相关部门法的特定章节 [p.3]。
  - Query decomposition：把口语事实（如"被宠物咬"）解释为法律事实（如"造成他人损害""家养动物"），并对应到民法典侵权责任编第 9 章的规定 [p.3-4]。
  - Filter：用 subsumption 方法，每个法律事实 F_i 对应一组法条 S_Fi，取各子集之并与第一步召回集 S 的交集，得到 S_Golden = (S_F1 ∪ S_F2 ∪ S_F3) ∩ S；例中 S_Golden = {S1, S3} [p.4]。
- 语料：法律团队整理"现行有效"的中国成文法规清单，从政府官方网站手动下载最新版本，再用脚本按条切成"最小可检索单元" [p.4]。
- 查询来源：12348 中国法律服务网上的真实咨询，人工匿名化 [p.4]。
- 基线：词法（QL、BM25）、通用预训练（Chinese-RoBERTa-WWM、SEED、coCondenser）、法律预训练（SAILER、Lawformer）、微调稠密检索（Dense-CAIL、Dense-STARD 五折交叉验证、Dense-GPT4）、分类器 LSI-STARD（每条法条一个标签）[p.6]。
- Dense-GPT4：让 GPT-4 针对语料中的法条生成法律问题，得 (q, 法条) 对，再用对比学习训练稠密检索器 [p.7]。

## 3. 数据与设置
- 标注者：16 名法学院学生，每问题两人，仅当两人认定同一法条时才形成金标；意见不一致的问题不进入最终数据集 [p.4-5]。作者要求标注者不使用生成式模型 [p.5]。
- 一致性：Cohen's Kappa K = 0.5312，作者称为 moderate agreement [p.5]。
- Table 2：1,543 查询；55,348 候选法条；1,445 条至少与一个查询相关；相关条文出现 2,717 次；每查询平均相关法条 1.76；平均查询长度 27.30 词；平均法条长度 119.93 词 [p.6]。
- 843/1,543 查询只对应 1 条相关法条；45% 查询需要多条 [p.5]。
- 指标：Recall@k（k 取 5 至 200）与 MRR@3/5/10 [p.7]。
- RAG 实验：JecQA（KD/CA 题，准确率）与 CAIL 2018 charge prediction；检索 top 10 法条放入 prompt [p.7-8]。

## 4. 结果
- Table 3（R@5 / R@10 / R@100 / R@200 / M@10）[p.7]：
  - QL：0.3363 / 0.4020 / 0.6515 / 0.7224 / 0.3304。
  - BM25：0.3349 / 0.3943 / 0.6493 / 0.7035 / 0.3369。
  - Roberta（zero-shot）：0.3216 / 0.3908 / 0.6633 / 0.7351 / 0.3010。
  - SEED：0.2897 / 0.3555 / 0.5626 / 0.6260 / 0.2816；coCondenser：0.1120 / 0.1598 / 0.4292 / 0.5246 / 0.1004。
  - SAILER：0.2330 / 0.3050 / 0.5674 / 0.6463 / 0.2234；Lawformer：0.2411 / 0.2989 / 0.5478 / 0.6309 / 0.2412。
  - Dense-STARD：0.5206 / 0.6061 / 0.9065 / 0.9531 / 0.4724。
  - Dense-GPT4：0.4382 / 0.5174 / 0.7984 / 0.8521 / 0.4106。
  - Dense-CAIL：0.0887 / 0.1272 / 0.3281 / 0.3819 / 0.0842。
  - LSI-STARD：0.1861 / 0.2069 / 0.3410 / 0.3956 / 0.2156。
- 作者的解读 [p.7]：zero-shot 下词法方法超过通用与法律领域 PLM；无人工标注的方法里 Dense-GPT4 最好；SAILER 为长文档案例检索设计，对短查询与中等长度法条表现不佳；在 CAIL2018 上微调的模型表现次优，说明非专业查询与正式法律查询差异大；LSI 分类在 5 万以上标签时表现不佳；词法与非微调模型不如 Dense-STARD，因其缺乏把生活问题解释为法律事实的能力，而 Dense-STARD 训练集仅一千多个查询-法条对，Recall@100 仍只有 90.65%。
- RAG（Table 4，准确率）[p.8]：Baichuan 在 JQA-CA 上 w/o RAG 0.231、BM25 0.233、Dense-STARD 0.238；ChatGPT 在 JQA-KD 上 w/o RAG 0.206、BM25 0.293、Dense-STARD 0.252；CAIL 上 Baichuan w/o RAG 0.850、BM25 0.766、Dense-STARD 0.816；ChatGPT CAIL 0.496 / 0.528 / 0.503。作者称对 Baichuan 与 ChatGLM，微调稠密检索优于 BM25，对 ChatGPT 则 BM25 更好；并推测 Baichuan 在 CAIL 上的 w/o RAG 高分源于预训练中用过该数据集 [p.8]。

## 5. 作者陈述的局限
- 数据集围绕中国法律体系设计，直接适用范围受限；直接翻译不能保证适用于外国法律体系，扩展到其他大陆法系国家需要新建并标注数据 [p.4, p.9]。
- 作者承诺定期更新数据集以反映法律变动 [p.5]。
- 其余局限文中未专门讨论。

## 7. 对本库的可用点（笔记者推断）
- 标签构建：三步法（recall 缩小范围→query decomposition→filter 取交集）与本库现有 (scope, income, topic) 单元格检索天然对应：scope 即部门法/法域，income/topic 即法律事实；可把"事实→条款集合"的映射显式存为表，S_Golden = ∪ S_F ∩ S 的交集运算是确定性集合运算，可直接实现（层：retrieval & ranking、evaluation）。
- 标签构建：双人标注，仅在两人一致时保留，一致性 Kappa 0.5312；本库没有人类专家（见"无专家，自行核验"），可改为"规则作者提出 + 脚本按 quote 校验 + 与第二套独立构造的标签比对"，并记录分歧项而不是丢弃（层：evaluation、provenance & verification）。
- 评测：每查询平均相关法条 1.76，R@5 至 R@200 的设定；本库相关条款也很少，可用 R@1/3/5/10 与 MRR，并按 BM25 与 Dense 同表对比（层：evaluation）。
- 基线数字：BM25 R@100 = 0.6493，M@10 = 0.3369，法律领域预训练 SAILER 在 R@100 为 0.5674；说明"法律预训练"不保证优于词法，应在本库语料上自测，勿默认 dense 更好（层：retrieval & ranking）。Dense-STARD 经微调 R@100 达 0.9065，说明标注的 in-domain 对是关键，而本库可由现有 cite_id 引用对自然产生。
- 分类式做法（每条款一个标签）在 5 万标签下表现 R@100 = 0.3410，不适合本库规模增长后的检索（层：scale & maintenance）。
- 版本与更新：作者只取"现行有效"版本并承诺定期更新，与本库"废止即删除"一致；但文中没有给出版本 id 或条文变更追踪机制，本库需要自己设计 slice 的稳定 id 与更新日志（层：identifiers & versioning，论文未覆盖）。
- 条文粒度：作者以"条"为最小可检索单元，平均 119.93 词；对应本库中以条为单位的法条，但对按页切分的指引文档不适用（层：clause granularity）。
- LLM 边界：Dense-GPT4 用 GPT-4 生成合成训练问题，不进入计算，仅作离线检索训练；合成问题不是官方文本，需标注为非权威。RAG 结果显示不同 LLM 偏好不同检索器、且 w/o RAG 有时更好（Baichuan CAIL 0.850 对 0.766），提示 LLM 辅助起草时检索增强效果不稳定，仍需核验（层：LLM boundary）。
- 不适用：论文无关系图与交叉引用使用，只引 SAILER（利用文档内部分间逻辑关系）和 LeSICiN（引用网络）作为相关工作 [p.6, p.9]；单一语言与法域。
