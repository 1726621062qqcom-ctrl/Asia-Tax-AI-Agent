# L19 Tizpaz-Niari, Darian & Trivedi, 2024. Metamorphic Debugging for Accountable Software. ProLaLa 2024 extended abstract, arXiv 2409.16140v2
版本：preprint；L19_TizpazNiari2024_MetamorphicDebugging_preprint.pdf；第 1–10 页全读（第 11–12 页为参考文献，略过）。这是综述性扩展摘要，结果部分转引作者自己与合作者的两项先前工作（TenForty [47]、Escher 与 Banovic [23]）

## 1. 问题与作者主张
- 作者指出税务申报软件等社会法律关键软件难以发现和解释“问责缺陷”，原因有三：从自然语言的法律要求中提取形式规约困难；缺少能给出标准答案的预言（oracle problem）；因隐私和法律原因难以获得可信数据集 [p.2]。
- 作者主张用关系型规约：不知道某输入的确切输出时，两个相关输入的输出之间的关系也许更容易表达；这类似判例法中“相似案件须相似判决”的原则和软件工程中的蜕变关系（MR）[p.1, p.5]。
- 作者主张以蜕变调试（metamorphic debugging）作为检测、解释和修复这类软件的基础，并称问责软件可以充当法律与社会规范的替身，使决策者能像软件工程师做测试一样查询法律 [p.2]。
- 作者称美国个人所得税的若干 IRS 出版物与宾夕法尼亚州福利资格手册中的要求都可表达为蜕变关系 [p.2]。

## 2. 方法
- 两类蜕变关系：输入扰动类，要求两个相似输入在两个（功能等价的）软件变体上输出相同；输入输出扰动类，要求一个输入与其扰动之间的输出满足特定关系 [p.3]。
- 形式化：x ≡_L y 表示除标签集 L 外 x、y 各标签相等；蜕变关系是含 ≡_L、数值比较、布尔连接词、量词的一阶逻辑公式，F 为联邦税额函数 [p.5]。
- 例：Property 1，已婚联合申报且配偶为盲人者的税收利益不得低于其他条件相同、配偶非盲者；Property 2，已婚分别申报者不得享受 EITC；Property 3，已婚联合申报且 AGI 超过 56,844 者不得享受 EITC [p.6]。Property 5 是涉及四个相似个体的“4-property”，要求 AGI 低于 160k 的个体获得不低于 AGI 在 160k 至 180k 之间个体的税收利益差 [p.6]。
- 跨税年：法律变动后关系须更新，如 EITC 的 AGI 门槛在 2018、2019、2021 年分别写成 54884、55952、57414 [p.6]。
- 验证（TenForty）：寻找满足蜕变关系前置条件、违反后置条件的输入；每步选取并扰动有希望的输入以最大化与期望结果的偏离，超过阈值标为失败；用 Jeffreys 检验（Bayes 因子的一种）给出无失败的统计置信，所需连续样本数 K ≥ ⌈(−log2 B)/(log2 θ)⌉，B 可取 100 表示很强证据 [p.7]。
- 解释：对失败与通过的测试用 CART 决策树推断失败情形，可在输入变量空间与软件内部变量（循环次数、条件）空间中解释 [p.4, p.8]。
- 另一条线（Escher 与 Banovic）：作者自己依据手册写一个“真值”程序，用人口普查数据生成测试家庭，与线上筛查工具比较，差异即缺陷；这是比较两个语义等价输入的差分性质 [p.4, p.6]。

## 3. 数据与设置
- TenForty：被测对象是开源报税软件 OpenTaxSolver 的 2018–2021 四个税年版本；由作者与法律、税务专家合作整理出 16 条蜕变关系，涉及五个领域：老年或残疾人抵免、EITC、儿童税收抵免、教育抵免、分项扣除 [p.4-6]。
- 运行 15 分钟每版本，平均生成超过 36,000 个测试用例 [p.7]。
- Escher 与 Banovic：来自宾夕法尼亚州美国社区调查 PUMS 数据的测试家庭，用 Selenium 填入“Do I Qualify?”筛查网站，用 Python 实现的“真值”程序对照，涉及 SNAP 手册的三十二章 [p.8]。
- 评测指标：失败数与通过数，首个失败所用时间 T_F [p.7]。

## 4. 结果
- 表 2（OpenTaxSolver 2020 / 2021 的用例数、失败、通过、T_F）：P.1 为 35,790 / 0 / 35,790 与 32,355 / 0 / 32,355；P.2 为 19,936 / 16,381 / 3,555 / 0.05 s 与 32,343 / 0 / 32,343；P.3 为 18,258 / 18,258 / 0 / 0.04 s 与 16,556 / 16,556 / 0 / 0.05 s；P.4 为 36,450 / 0 / 36,450 与 32,883 / 0 / 32,883；P.5 为 18,015 / 0 / 18,015 与 16,346 / 0 / 16,346 [p.7]。
- 作者称 2018 与 2019 年版本在初步蜕变关系下没有失败证据，2020 与 2021 版本有；其中一项失败与更新后的 EITC 收入门槛政策有关 [p.7]。
- P.2 在 2020 版失败、在 2021 版通过；作者进一步调查后称，由于 IRS 公布的税法更新，2021 版在没有代码更新的情况下是正确的 [p.7]。
- TenForty 在 OpenTaxSolver 中发现三类失败：缺少某些资格条件（如已婚分别申报不能享受 EITC）；税额非常接近零（小的非零值）时不满足要求；2021 版允许用户显式选择在边角情形下不满足某些要求的选项 [p.4]。
- 决策树解释示例：软件对所有情形失败，除非 AGI 低于 167k 且联邦税额低于 79 美元 [p.8]。
- Escher 与 Banovic：对子女托育补贴，“Do I Qualify”将每个测试家庭都预测为不合格，而至少 4.6% 的测试家庭可能合格 [p.5, p.7]。
- 作者还称 Merigoux 等为法国税法写了编译器，并以动态随机搜索而非形式验证做核验 [p.8]。

## 5. 作者陈述的局限
- 动态测试中没有发现失败不意味着正确，因此用假设检验给出无失败的统计置信 [p.7]。
- 对依赖关系复杂的条件（如医疗费用超过 AGI 的 7.5% 才可分项扣除），带方框约束的标准决策树会产生庞大难解释的模型，作者提出用多面体等更丰富的域 [p.10]。
- 提取蜕变关系仍依赖与法律税务专家合作；作者把用大模型生成蜕变关系、更完整的蜕变要求集、因果图、灰盒模糊测试列为未来工作 [p.9-10]。
- 现有灰盒模糊测试主要找通用漏洞，功能正确性需要超出其范围的技术 [p.10]。
- 全文是扩展摘要，细节依赖所引的先前工作；文中未专门讨论本方法对“蜕变关系本身写错”的防范。

## 6. 原文摘录
- "While the exact output for a given input may be unknown, the relationship between the outputs of two related inputs may be easier to express." [p.1]
- "the correctness of tax preparation software must also be viewed in comparison with similar cases." [p.5]
- "Since the absence of evidence for failures in the dynamic testing approach does not imply correctness, TenForty used hypothesis testing to provide statistical confidence on the absence of failures" [p.7]
- "Upon further investigation, we found that due to an update in the tax law (as published by the IRS), version 2021 turns out to be correct without any code update." [p.7]
- "As the tax law has evolved over different years, the metamorphic relations need to be updated to reflect those changes." [p.6]

## 7. 对本库的可用点（笔记者推断）
- §3.2 MR 的法律依据：论文把“相似案件相似结果”的蜕变关系与判例原则对应 [p.1, p.5]，并给出税务蜕变关系的一阶逻辑写法 [p.5]。本库 MR6（事实改为对纳税人更有利，下限不升）与论文 Property 1、4 的“单调性”同类；可借其 ≡_L（除集合 L 外全部相等）的写法，为 MR 逐条写出前置条件，做成可机读的规约。
- 论文的 MR 带门槛：Property 3、4 含 AGI > 56,844 这类常量，并随税年改写 [p.6]。本库的 MR5（不跨门槛时拆分）、MR7（有效期内平移日期）同样要把门槛取自参数表而不是写死，否则法律更新后 MR 自己成为过期的“期望值”；对应 §3.2 与口径库的版本管理。
- 论文的失败案例提示：2020 版 P.2 失败而 2021 版“没有代码更新”即正确 [p.7]，说明蜕变关系的失败可能来自规约与年度参数不同步，而非软件缺陷。归因时先查 MR 引用的参数年度（C 层变化归因）。
- 论文用决策树（CART）把失败与通过的用例区分成输入区域 [p.8]，可作为 C 层归因之外的补充：MR 在电池上批量失败时，自动给出“哪些输入字段范围内失败”，比逐例读更省人力；论文也指出带方框约束的树不适合 AGI×7.5% 这类比率条件 [p.10]，本库有大量比率与门槛，需考虑用比值特征。不适用之处是论文的特征是报税表字段，本库是多法域的结构化事实与方案动作。
- 论文用 Jeffreys 检验给出“无失败”的统计置信 [p.7]。本库电池案例是穷举的有限集，此统计手段只适用于随机生成扩展部分；该公式的 θ、B 取值需要自己设定，论文没有给出对应本库的取值依据。
- 差分性质 G(x)=F(x′)：Escher 与 Banovic 自写“真值”程序再对照 [p.4, p.8]，与 §3.3 独立核验器同构；论文承认那份“真值”是作者读手册后自写的，并未独立验证，所以只能当作第二实现而不是标准（§0 原则：官方文本才是标准）。
- 论文也未讨论本库的区间输出（下限与上限）；MR 在区间上如何表述（如 MR1、MR6）需自行定义，论文不提供。论文的 MR 针对单点税额 F(x)。
- 论文设想用大模型生成蜕变关系 [p.9]：与本库“不用大模型判对错”不冲突，只要生成的 MR 仍由人对照条文确认、且 MR 不由大模型来判定通过与否；论文未报告其质量。
