# I12 Gutiérrez et al., 2024. HippoRAG: Neurobiologically Inspired Long-Term Memory for Large Language Models. NeurIPS 2024（arXiv:2405.14831v3）
版本：author（arXiv v3，2025-01）；I12 文件见 literature/ 下 I12_* 前缀；第 1–10 页全读，附录 F（错误分析）、G（成本）、H 略读，其余附录与参考文献略过

## 1. 问题与作者主张
- 作者指出现有 RAG 对每个新段落单独编码，难以跨段落边界整合知识；多跳问答需要多轮检索与生成迭代拼接段落 [p.1-2]。
- 作者提出 HippoRAG：受海马体记忆索引理论启发，协同使用 LLM、知识图谱与 Personalized PageRank (PPR) [p.1]。
- 作者主张在多跳问答上比现有方法最多高 20%；单步检索与 IRCoT 这类迭代检索相当或更好，同时便宜 10–20 倍（摘要）或 10–30 倍（正文）、快 6–13 倍；与 IRCoT 结合带来进一步提升 [p.1-2]。
- 作者提出"path-finding"多跳问题（多条路径可探索，需找出连接一组实体的那条）并称现有检索器和迭代检索对此失败 [p.9]。

## 2. 方法
- 离线索引：用指令微调 LLM 做 OpenIE，得到无模式 (schemaless) KG 的名词短语节点和关系边；先抽取命名实体，再把实体加入 OpenIE prompt 抽取三元组，均为 1-shot prompting [p.3-4]。
- 同义边：用检索编码器，当两个实体表示的余弦相似度高于阈值 τ 时添加 synonymy 边 E′；索引同时得到 |N|×|P| 矩阵 P，记录每个名词短语在每个段落中出现的次数 [p.4]。
- 在线检索：LLM 从查询中抽取命名实体 Cq，经同一编码器链接到 KG 中余弦相似度最高的节点，得到 query nodes Rq [p.4]。
- PPR：在含 |E| + |E′| 条边的图上运行，个性化分布中每个 query node 概率相等、其余节点为零；得到节点概率 n′ 后乘以矩阵 P 得到段落分数 p 用于排序 [p.5]。
- Node specificity：si = |Pi|^−1，Pi 为抽取出节点 i 的段落集合；在 PPR 之前乘到各 query node 的概率上，作为仅需局部信息的 IDF 替代 [p.5]。
- 增量更新：作者称 RAPTOR、MemWalker、GraphRAG 通过摘要整合信息，新数据加入时必须重复摘要过程，而 HippoRAG 仅需向 KG 添加边 [p.9]。

## 3. 数据与设置
- 数据集：MuSiQue（answerable）、2WikiMultiHopQA、HotpotQA；各取验证集 1,000 题，候选段落（含支持与干扰段落）汇成检索语料 [p.5]。
- 语料规模（Table 1）：段落数 MuSiQue 11,656、2Wiki 6,119、HotpotQA 9,221；唯一节点 91,729 / 42,694 / 82,157；唯一边 21,714 / 7,867 / 17,523；唯一三元组 107,448 / 50,671 / 98,709；Contriever 同义边 145,990 / 146,020 / 159,112 [p.5]。
- 基线：BM25、Contriever、GTR、ColBERTv2、Propositionizer、RAPTOR，以及多步检索 IRCoT [p.5]。
- 指标：检索用 recall@2 与 recall@5，QA 用 EM 与 F1 [p.5]。
- 实现：LLM 默认 GPT-3.5-turbo-1106，temperature 为 0；检索器 Contriever 或 ColBERTv2；用 MuSiQue 训练集 100 个例子调两个超参数：同义阈值 τ = 0.8，PPR damping factor = 0.5（决定 PPR 从 query nodes 重启随机游走的概率）；作者称性能对超参数相当稳健 [p.6]。PPR 使用 python-igraph 实现 [p.29]。

## 4. 结果
- 单步检索（Table 2，R@2 / R@5 平均）：HippoRAG (ColBERTv2) 57.4 / 72.9，ColBERTv2 53.9 / 65.6，BM25 46.5 / 58.4；2Wiki 上 HippoRAG (ColBERTv2) 70.7 / 89.1，ColBERTv2 59.2 / 68.2；MuSiQue 上 40.9 / 51.9 对 37.9 / 49.2；HotpotQA 上 60.5 / 77.7 对 64.7 / 79.3，即 HippoRAG 在该集上低于 ColBERTv2 [p.6]。
- 作者称 2Wiki 上 R@2、R@5 分别提升 11 和 20 个点、MuSiQue 约 3 个点；2Wiki 的收益部分源于其以实体为中心的设计 [p.6]。HotpotQA 较低的原因，作者归于其知识整合要求较低和 concept-context 权衡 [p.6]。
- 多步检索（Table 3）：IRCoT + HippoRAG (ColBERTv2) 平均 R@2 / R@5 为 62.7 / 78.2，IRCoT + ColBERTv2 为 57.9 / 70.0 [p.6]。
- QA（Table 4，平均 EM / F1）：无检索 24.6 / 35.5；ColBERTv2 30.8 / 42.5；HippoRAG 35.9 / 48.1；IRCoT 33.3 / 44.7；IRCoT + HippoRAG 38.4 / 51.7；HotpotQA 上 HippoRAG F1 55.0 低于 ColBERTv2 的 57.7 [p.7]。
- 全召回 (Table 6，AR@5)：2Wiki 上 HippoRAG 75.7 对 ColBERTv2 37.1，MuSiQue 上 22.4 对 16.1；HotpotQA 上 57.9 对 59.0 [p.8]。
- OpenIE 替换（Table 5，平均 R@2 / R@5）：REBEL 46.2 / 58.4（作者称 GPT-3.5 产生的三元组数量是 REBEL 的两倍）；Llama-3.1-8B 54.4 / 67.8；Llama-3.1-70B 57.1 / 72.5；GPT-3.5 为 57.4 / 72.9 [p.7]。
- PPR 替代（Table 5）：仅用 Rq 节点 50.7 / 56.2；Rq 节点加邻居 42.2 / 59.2，作者称不用 PPR 而加邻居比只用 query 节点更差，PPR 在三个数据集上都明显更有效 [p.7-8]。
- 消融：去掉 node specificity 平均 54.7 / 70.9，作者称在 MuSiQue 与 HotpotQA 上改善明显，在 2Wiki 几乎无变化；去掉同义边平均 56.2 / 70.5，对 2Wiki 影响最大 [p.7-8]。
- 成本（Table 17，1,000 个查询，GPT-3.5）：ColBERTv2 API 费用 0 美元、1 分钟；IRCoT 1–3 美元、20–40 分钟；HippoRAG 0.1 美元、3 分钟 [p.28]。
- 离线索引：作者称 HippoRAG 比 IRCoT 慢约 10 倍，每 1 万段落贵约 15 美元；Llama-3.1-70B 用 vLLM 与 4 块 H100 索引 1 万文档约需 4 小时 [p.28]。
- 错误分析（MuSiQue，100 个错误）：NER 局限 48%，OpenIE 错误或缺失 28%，PPR 24% [p.26]。

## 5. 作者陈述的局限
- 所有组件均为现成使用、未经微调；大多数错误来自 NER 与 OpenIE，其余为图搜索错误，可改进的方向包括让关系直接引导图遍历 [p.10]。
- OpenIE 在较长文档上的一致性比在较短文档上更差，需要更多工作 [p.10]。
- 可扩展性仍需验证：作者尚未实证当索引规模远超当前基准时的效率与效果 [p.10]。
- PPR 无法直接利用查询上下文；当语料中存在多个主题相近的段落时，PPR 难以找出正确子图（混淆信号）[p.25]。
- 实体中心设计偏重概念，丢弃了大量上下文线索，作者称忽略上下文约占 48% 的错误 [p.26]。

## 6. 原文摘录
- "an LLM to transform a corpus into a schemaless knowledge graph (KG) as our artificial hippocampal index" [p.2]
- "a version of PageRank that distributes probability across a graph only through a set of user-defined source nodes" [p.3]
- "each query node has equal probability and all other nodes have a probability of zero" [p.5]
- "the synonymy threshold τ at 0.8 and the PPR damping factor at 0.5" [p.6]
- "adding the neighborhood of Rq nodes without PPR leads to worse performance than only using the query nodes themselves" [p.8]
- "HippoRAG’s scalability still calls for further validation." [p.10]

## 7. 对本库的可用点（笔记者推断）
- 关系图（建图方式）：论文的图由 LLM 做 OpenIE 抽取并用嵌入相似度加同义边，边无法逐条验证，且同义边带阈值噪声（作者自己称其为 noisy entity standardization [p.8]）。这违反本库"库内不得有 LLM 抽取边"。本库应保留正则与结构建出的显式边（层级、交叉引用、zh↔en 同条款、定义词、立法事件），HippoRAG 的 LLM OpenIE 与同义边不能入库（层：relation graph、LLM boundary）。
- 检索与排序（PPR 的贡献）：论文的消融显示，PPR 本身是收益来源：不用 PPR 只扩展邻居反而比只用 query 节点更差 [p.8]。本库的 PPR 已经作用于确定性边，这一点是论文对其做法的旁证，但论文的图是实体图，本库是条款图，不能直接外推数值收益。参数：damping 0.5 在 MuSiQue 的 100 个样本上调得 [p.6]，本库应在自己的 gold 集上调，并显式记录；注意论文中该值定义为"重启概率"，对应到具体库（igraph、networkx）的 damping 参数时要核对约定，避免取反（层：retrieval & ranking）。
- 检索与排序（种子与节点特异性）：论文以等概率种子起步，再乘 1/|Pi| 的 node specificity；本库可用确定性的等价物：种子由精确命中（cite_id、条款号）与 BM25 给出，权重用定义词或术语在库中出现的条款数的倒数，这是纯统计、无 LLM（层：retrieval & ranking）。论文的 query NER 与节点链接用 LLM 加稠密相似度，本库中前者必须换成规则或精确匹配，不然违反 LLM 边界。
- 失败模式：论文列出的三类错误中，NER 局限 48%、OpenIE 28%、PPR 24% [p.26]；其中前两类在本库不存在（无 LLM 抽取），但"PPR 在主题相近的段落间被混淆信号干扰" [p.25] 在本库会出现：税法中大量条款文字高度相似（不同税种、不同地区的同类条文）。因此 PPR 后需保留 scope（地区、税种、现行有效）的硬过滤，而不是依靠图分数区分（层：evaluation、retrieval）。
- 评测：论文用 R@2、R@5 与"全召回" AR@k 衡量多跳；AR@k（所有支持段落都取回）适合本库需要同时取到规则、例外和定义条款的场景，可作为确定性指标，用 cite_id 的 gold 集合计算。论文 HotpotQA 上 HippoRAG 低于 ColBERTv2 [p.6, p.8]，提示图扩展不应无条件开启，应在评测中分单跳与多跳（层：evaluation）。
- 溯源：HippoRAG 返回的是原始段落，排名由图分数加总得到，这一点与本库"返回逐字单元"一致；与之对照，I11 的社区摘要为二次生成文本。因此 HippoRAG 的输出形态比 GraphRAG 更适合本库（层：provenance & verification）。
- 规模与维护：作者称增加新数据只需添加边，不必重做摘要 [p.9]；本库新增或修订条款时，确定性边同样可增量重算，且无 LLM 成本。论文的索引成本（每 1 万段落约 15 美元或 70B 模型约 4 小时 [p.28]）说明若用 LLM 建图，310 份官方文件及每次修订的重跑成本不小，且不可复现。论文规模最多约 1 万段落，作者承认超出后未验证 [p.10]；本库约 2.95 万单元、约 8,500 条引用边规模与之同量级，PPR 本身（igraph）算力需求不大，但需自测延迟。
- 不适用：论文无法律文本，无版本、生效期与"缺失即待定"概念；其同义边会把不同法域的相似表述合并，与本库的"zh↔en 同条款链接必须逐条核对"冲突。
