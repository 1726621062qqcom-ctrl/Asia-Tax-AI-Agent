# I16 Green, Karvounarakis & Tannen, 2007. Provenance Semirings. PODS 2007
版本：author；I16_Green2007_ProvenanceSemirings_author.pdf；全文读至第 10 页（第 1–10 页；第 7–8 页的算法细节与证明仅略读，参考文献略过）

## 1. 问题与作者主张
- 作者观察到：不完整数据库（c-tables）、概率数据库（event tables）、bag 语义和 why-provenance 四类带注解关系，其查询时对注解的计算"惊人地相似" [p.1]。
- 作者提出用交换半环（commutative semiring）作为注解的代数结构统一这四类，并称关系代数中的若干期望恒等式"迫使"注解结构成为交换半环 [p.1, p.3]。
- 作者主张用整系数多项式半环 N[X] 记录 provenance，并称对任何交换半环 K 的 RA+ 语义都可经由 provenance 语义因式分解得到（Theorem 4.3）[p.1, p.4]。
- 作者把结果推广到 datalog（含递归、可能无限多的推导），用形式幂级数半环表示 provenance，并给出判断有限性与计算的算法 [p.1]。

## 2. 方法
- K-relation：把关系看作从元组到 K 的函数，K 中含 0 与 1 两个不同元素，且支撑集（support）有限（Definition 3.1）[p.3]。
- 正向关系代数 RA+ 的运算（Definition 3.2）[p.3]：union 与 projection 把注解相加（+）；natural join 把注解相乘（·）；selection 用 0/1 谓词乘注解；renaming 不改注解。
- Proposition 3.4：RA+ 的一组恒等式成立当且仅当 (K, +, ·, 0, 1) 是交换半环 [p.3]。Proposition 3.5：K 到 K′ 的变换与任意 RA+ 查询可交换，当且仅当它是半环同态 [p.4]。
- Why-provenance 对应半环 (P(X), ∪, ∪, ∅, ∅)，记录哪些输入元组"贡献"了输出；作者给出其局限的例子，并提出记录"如何贡献"的 how-provenance [p.4]。
- Provenance 多项式（Definition 4.1）：以输入元组 id 为变量、自然数为系数，半环 (N[X], +, ·, 0, 1)；Proposition 4.2：任一赋值 v: X → K 唯一决定一个半环同态 Eval_v: N[X] → K [p.4]。
- 传播规则：先给每个输入元组一个自己的 id 作为注解，再按 +（并/投影）与 ·（连接）逐运算计算，得到输出元组的多项式 [p.4]。
- Datalog：输出元组的注解 = 对其所有推导树（derivation tree）求和，每棵树的值 = 叶子注解之积（Definition 5.1）；推导树可能无限多，故要求 ω-continuous 半环以定义可数和 [p.5]。
- 等价的不动点定义：为每个 idb 元组引入变量，得到一组多项式方程（algebraic system），其最小不动点即答案（Theorem 5.6）[p.6]。
- Provenance 取形式幂级数半环 N∞[[X]]；算法 All-Trees 判断每个元组是否有无限多推导并在有限时计算幂级数，Monomial-Coefficient 计算指定单项式的系数 [p.7-8]。
- 对有限分配格 K（含 PosBool(B)、P(Ω)）修改 All-Trees，使其总返回多项式，再在 K 中求值，得到 datalog 在 boolean c-tables 与事件表上的语义 [p.8-9]。

- 本文是理论论文，无真实数据集与实验；用小型例子说明：maybe-table 与 c-table（Figure 1–2）、multiset（Figure 3）、事件表及概率 0.6 / 0.5 / 0.1（Figure 4）、why-provenance 与多项式（Figure 5）、datalog 在 bag 语义下的两个小例（Figure 6–7）[p.2-6]。
- 例中的查询 q 对元组 p, r, s 做 π_ac(π_ab R ⋈ π_bc R ∪ π_ac R ⋈ π_bc R) [p.2]。
- 半环例子：(B, ∨, ∧, false, true)、(N, +, ·, 0, 1)、(PosBool(B), ∨, ∧, false, true)、(P(Ω), ∪, ∩, ∅, Ω)、tropical (N∞, min, +, ∞, 0)、fuzzy ([0,1], max, min, 0, 1) [p.3, p.5]。
- 评价方式：定理与命题的形式证明（多数仅给证明概要）。

## 4. 结果
- 作者称 (B, ∨, ∧, false, true) 给出集合语义的 RA+，(N, +, ·, 0, 1) 给出 bag 语义，PosBool(B) 恰好给出 Imielinski–Lipski 的 c-table 代数，P(Ω) 给出事件表代数 [p.3]。
- 例（Figure 5）：(f, e) 与 (d, e) 的 why-provenance 相同，都是输入 r 和 s；作者指出查询也可单由 s 算出 (f, e)、单由 r 算出 (d, e)，why-provenance 无法区分 [p.4]。
- 同一例的 provenance 多项式为：(d, e) 为 2r² + rs，(f, e) 为 2s² + rs；作者解读为 (f, e) 有三种算出方式，其中两种两次使用输入 s，一种用 r 和 s [p.4-5]。
- 作者验证：把 2r² + rs 在 N 中取 p = 2, r = 5, s = 1 求值得 55，等于 Figure 3 中 (d, e) 的 multiplicity [p.4]。
- Datalog 例（Figure 7）：在 N∞ 上，经两轮不动点迭代得 x = 8, y = 3, z = 2, u = 2, v = 2, w = 2，之后 u, v, w 无界增长，作者称可用算法检测无界增长，答案中 b-d、d-d、a-d 的值为 ∞ [p.6]。
- Theorem 9.2：当 K 是分配格时，对合取查询的并，K-relation 语义下的包含关系 q1 ⊑_K q2 当且仅当集合语义下 q1 ⊑_B q2；作者称此时判定过程与标准集合语义相同，PosBool(B)、P(Ω) 与 fuzzy 半环都是分配格 [p.9]。
- Proposition 5.7：ω-continuous 半环同态与任意 datalog 查询可交换 [p.6]。

## 5. 作者陈述的局限
- 仅考虑 boolean c-tables，结果可推广到一般 c-tables [p.10]。
- 希望把 Definition 3.2 扩展到含否定（negation），作者称这似乎需要公理化一个类似 N 中 proper subtraction 的额外运算 [p.10]。
- All-Trees 算法不能直接给出 tropical 半环上 datalog 的有效求值方法，作者推测存在这种过程 [p.10]。
- 关于 bag 语义下合取查询（并）的包含蕴含 N[X] 语义下包含，作者仅作猜想；若成立可把某个不可判定性结果迁移到 N[X] [p.10]。
- 作者希望将来在非关系数据模型上寻找 provenance 结构，并研究需要细粒度 provenance 的应用（如在受逻辑约束关联的数据库间双向传播信息）[p.9-10]。

## 6. 原文摘录

## 7. 对本库的可用点（笔记者推断）
- 溯源与核验（provenance & verification）：本库的每个派生结果（如某场景的税额）可记为"由哪些 cite_id/参数 id 以何种组合得到"的多项式：+ 表示可替代的多条推导路径，· 表示必须同时用到的多项输入。相比只存"用到了哪些 cite_id"的集合（why-provenance），多项式能区分同一组输入的不同用法（论文 Figure 5 的 (d, e) 与 (f, e)），便于审计与"这条参数改了会影响什么"。该解读为推断；论文只在关系代数和 datalog 上给出。
- 规模与维护（scale & maintenance）：Proposition 4.2 说明先算出多项式、再对不同赋值求值即可得到不同解释。可对应本库：同一份 provenance 多项式，令某 clause 取 0（被 superseded 或 removed）即可重算受影响的输出，无需重跑全部推导；这给"法条被删后哪些结果失效"提供了形式化办法。注意：这要求被删 clause 的 id 仍可在已存的 provenance 里引用，与"废止文本删除、仅在 removed.csv 留一行"之间有张力——removed.csv 至少要保留 id 与废止日期，使旧 provenance 不悬空（层：identifiers & versioning）。
- 关系图（relation graph）：约 45% 条款含显式交叉引用，引用可能成环（A 引 B、B 引 A）。论文的 datalog 部分正面处理递归与循环：推导可能无限，需检测并给出有限表示；对本库，可用同类思路对引用传递闭包做环检测，而不是限深遍历。
- 检索与排序、评测：论文不涉及文本检索、排序与评测指标，这些层无直接可用点。
- LLM 边界：provenance 的传播是纯确定性代数运算，不含 LLM，符合"计算中无 LLM"的约束；它可作为核验层，检查 LLM 提出的候选结论能否由库内 cite_id 推出。
- 不适用/冲突：(1) 论文仅覆盖正向代数（无否定、无差集），而税法规则普遍含"除……外""不超过"之类的例外与条件；这类规则的 provenance 论文未给出模型（作者自己也把 negation 列为待做）。(2) 论文的注解运算是 + 与 ·，不涉及税率相乘、阈值比较、取整等数值计算，数值计算的可追溯性需另行设计。(3) 论文未讨论时间（有效期）注解，把 effective_from/to 放入注解是笔记者的延伸，论文没有此内容。
