# I1 Thakur, Reimers, Rücklé, Srivastava & Gurevych, 2021. BEIR: A Heterogeneous Benchmark for Zero-shot Evaluation of Information Retrieval Models. NeurIPS 2021 Datasets & Benchmarks
版本：published；I1_Thakur2021_BEIR.pdf；正文读至第 10 页（摘要、引言、方法、结果、局限），参考文献（第 11–16 页）略过；文本文件不含附录（Table 9 等附录内容未读）

## 1. 问题与作者主张
- 作者称现有神经检索模型多在同质、窄域设置下研究，限制了对 out-of-distribution（OOD）泛化能力的认识 [p.1]。
- 作者提出 BEIR：18 个公开数据集、9 类检索任务，评测 10 个系统，涵盖 lexical、sparse、dense、late-interaction、re-ranking 五类架构 [p.1-2]。
- 作者的结论：BM25 是稳健基线；re-ranking 与 late-interaction 平均 zero-shot 表现最好，但计算代价高；dense 与 sparse 更高效但常不及其他方法 [p.1]。
- 作者称数据集中存在较强的 lexical bias（标注时多用 lexical 系统取候选），对非 lexical 方法不公平；需要更无偏的数据集 [p.2]。
- 作者称模型的 in-domain 表现与其泛化能力相关性不好 [p.2]。

## 2. 方法
- 数据集选择依据：任务多样、领域多样、任务难度足够、标注方式多样（众包、专家、社区反馈）[p.3]。
- 统一数据格式 corpus / queries / qrels，并提供 Python 框架（pip install beir），封装 Anserini、Elasticsearch、Sentence-Transformers、DPR、ColBERT 等 [p.4-5]。
- 领域差异度量：数据集两两之间在 unigram 词重叠上的 weighted Jaccard 相似度；作者观察到跨领域重叠较低 [p.4]。
- 模型与设置 [p.5-6]：所有神经模型文档只用前 512 个 word piece。
  - Lexical：BM25（Anserini，Lucene 默认 k=0.9、b=0.4；title 与 passage 作为独立字段索引）；作者也试过 Elasticsearch BM25 与 Anserini + RM3，称 Anserini BM25 最好。
  - Sparse：DeepCT、SPARTA（作者自行重实现，稀疏向量 2,000 个非零项）、docT5query（每文档生成 40 个 query）。
  - Dense：DPR（Multi 模型）、ANCE、TAS-B、GenQ（用 T5 为每个文档生成 5 个 query，微调 TAS-B；每个数据集文档数上限 100K）。
  - Late-interaction：ColBERT（faiss 取 top-100 候选后重排）。
  - Re-ranking：BM25 + CE（对 BM25 top-100 用 6 层 384 维 MiniLM cross-encoder 重排）。
- 评测指标：作者认为 Precision/Recall 不排序敏感，MRR 与 MAP 是二元排序指标无法处理分级相关；选用 nDCG@10，经 pytrec_eval 计算 [p.5]。
- 效率测量：从 DBPedia 随机抽 100 万文档，dense 用精确搜索，ColBERT 用 ANN；CPU 为 8 核 Intel Xeon Platinum 8168 @ 2.70GHz，GPU 为单块 Tesla V100 [p.8]。

## 3. 数据与设置
- 18 个英文 zero-shot 数据集（另加 MS MARCO 仅报告、不计入 zero-shot 比较），语料规模 3.6k 至 15M 文档，query 平均长度 3 至 192 词，文档平均长度 11 至 635 词 [p.2-3]。
- Table 1 [p.4]：TREC-COVID 50 个 test query、171,332 文档、平均每 query 493.5 个相关文档；NFCorpus 3,633 文档；BioASQ 14,914,602 文档；SciFact 5,183 文档；FiQA-2018 57,638 文档（语料规模取自表）。
- 19 个数据集（含 MS MARCO）中仅 8 个有训练数据；除 ArguAna 外 query 都较短 [p.4]。
- 相关性标注：多数为二元，部分为 3 级或 5 级 [p.4]。
- 未微调模型使用公开 checkpoint（Table 6）；训练数据与 hard negative 来源各异，作者注明这可能使比较不公平 [p.5-6]。

## 4. 结果
- Table 2（nDCG@10，部分数据集，顺序 BM25 / docT5query / DPR / ANCE / TAS-B / GenQ / ColBERT / BM25+CE）[p.7]：
  - TREC-COVID：0.656 / 0.713 / 0.332 / 0.654 / 0.481 / 0.619 / 0.677 / 0.757。
  - BioASQ：0.465 / 0.431 / 0.127 / 0.306 / 0.383 / 0.398 / 0.474 / 0.523。
  - NFCorpus：0.325 / 0.328 / 0.189 / 0.237 / 0.319 / 0.319 / 0.305 / 0.350。
  - FiQA-2018：0.236 / 0.291 / 0.112 / 0.295 / 0.300 / 0.308 / 0.317 / 0.347。
  - Touché-2020：0.367 / 0.347 / 0.131 / 0.240 / 0.162 / 0.182 / 0.202 / 0.271。
  - ArguAna：0.315 / 0.349 / 0.175 / 0.415 / 0.429 / 0.493 / 0.233 / 0.311。
  - SciFact：0.665 / 0.675 / 0.318 / 0.507 / 0.643 / 0.644 / 0.671 / 0.688。
  - MS MARCO（in-domain）：BM25 0.228，ColBERT 0.425，BM25+CE 0.413。
- 表末 “Avg. Performance vs. BM25” 一行：DeepCT -27.9%，SPARTA -20.3%，docT5query +1.6%，DPR -47.7%，ANCE -7.4%，TAS-B -2.8%，GenQ -3.6%，ColBERT +2.5%，BM25+CE +11%（该行依表中顺序读出）[p.7]。
- 作者归纳 [p.7-8]：
  - BM25 在 in-domain MS MARCO 上比神经方法低 7-18 点，但在 BEIR 上是强基线。
  - DeepCT 与 SPARTA 在几乎所有数据集上不及 BM25；docT5query 在 11/18 个数据集上超过 BM25。
  - Dense 模型在领域漂移（如 BioASQ）或任务漂移（如 Touché-2020）时明显差于 BM25；DPR 泛化最差。
  - BM25+CE 在 16/18 个数据集上超过 BM25（输在 ArguAna 与 Touché-2020）；ColBERT 在 9/18 个数据集上超过 BM25。
  - TAS-B 在 14/18 个数据集上优于 ANCE、17/18 上优于 DPR；TAS-B 偏好短文档：TREC-COVID 上检索结果文档长度中位数 10 词（ANCE 160 词），Touché-2020 上 14 词（ANCE 89 词）。
  - GenQ 在科学文献、金融、StackExchange 等专门领域优于 TAS-B，在 Wikipedia 等通用领域弱于 TAS-B。
- 效率，Table 3（DBPedia 100 万文档）[p.8]：
  - 延迟（GPU / CPU）：BM25+CE 450ms / 6100ms；ColBERT 350ms / –；docT5query – / 30ms；BM25 – / 20ms；TAS-B 与 GenQ 14ms / 125ms；ANCE 20ms / 275ms；DPR 19ms / 230ms；SPARTA – / 20ms；DeepCT – / 25ms。
  - 索引大小：BM25、docT5query、DeepCT、BM25+CE 0.4GB；TAS-B、GenQ、ANCE、DPR 3GB；SPARTA 12GB；ColBERT 20GB。
  - 作者称 re-ranking 与 late-interaction 延迟 > 350 ms；dense 比 re-ranking 快 20-30x（< 20ms）；CPU 上 sparse 最快（20-25ms）。
  - 大语料下：ColBERT 存 BioASQ（约 15M 文档）索引需约 900GB，BM25 仅 18GB。
- 标注偏差，Table 4（TREC-COVID）[p.9]：
  - Hole@10：BM25 6.4%，docT5query 2.8%，DeepCT 19.4%，SPARTA 12.4%，DPR 30.6%，ANCE 14.4%，TAS-B 31.8%，ColBERT 12.4%，BM25+CE 1.6%。
  - 作者手工补标 980 个 query-document 对后，nDCG@10 变化：docT5query 0.713 → 0.714；ANCE 0.654 → 0.735；ColBERT 0.677 → 0.735；DPR 0.332 → 0.445；TAS-B 0.481 → 0.555；BM25 0.656 → 0.668；BM25+CE 0.757 → 0.760。
  - 作者称补标后 ANCE 比 BM25 高 6.7 点，ColBERT 高 5.8 点；即使有多个系统参与 pooling，标注池仍偏向 lexical 方法。

## 5. 作者陈述的局限
- 所有数据集均为英文；多语言与跨语言任务留待未来 [p.10]。
- 文档平均长度至多数百词；长文档检索需要不同的设置（transformer 常有 512 word piece 限制）[p.10]。
- 只考虑纯文本检索，未纳入 PageRank、recency、authority、点击等多因素信号 [p.10]。
- 多字段检索（标题、摘要、正文、作者等）：已纳入数据集只有一两个字段 [p.10]。
- 任务专用模型可能在单一任务上胜过通用模型，本基准不评测这点 [p.10]。
- 数据集标注受 annotation guideline、setup、annotator 三方面偏差影响，不可能对所有 (query, document) 对人工标注；未被标注的文档默认为不相关 [p.9]。

## 6. 原文摘录
- "Overall, BM25 remains a strong baseline for zero-shot text retrieval." [p.2]
- "In-domain performance is not a good indicator for out-of-domain generalization." [p.7]
- "Many BEIR datasets are found to be subject to a lexical bias" [p.9]
- "ColBERT requires ~900GB to store the BioASQ (~15M documents) index, whereas BM25 only requires 18GB." [p.8]
- "Better datasets that use diverse pooling strategies are needed for a fair evaluation of retrieval approaches." [p.10]
- "all datasets covered in the BEIR benchmark are currently English" [p.10]

## 7. 对本库的可用点（笔记者推断）
- 检索与排序：BM25 在 18 个 zero-shot 数据集上是强基线，dense 单独使用常不及 BM25（DPR 平均比 BM25 低 47.7%）。对本库，exact + BM25 应作为主干，dense 只作为可选的第三路，并经 RRF 融合后用本库自己的金标集验证后才启用（层：retrieval & ranking）。
- 检索：BM25 实现细节可借鉴——title 与正文作为独立字段索引。对应本库把条文标题/heading_path 与 clause 正文分字段建 FTS，而不是拼成一个字符串（层：clause granularity、retrieval）。
- 评测：nDCG@10 与 Recall@100 的组合可用，但本库金标是“来自已溯源引用的少量相关 cite_id”，多为二元相关，可直接报 Recall@k 与 MRR；nDCG 的分级价值有限。BEIR 用 pytrec_eval 的 corpus/queries/qrels 三件套格式，可原样作为本库金标文件格式，便于以后换引擎重算（层：evaluation）。
- 评测偏差：Hole@10 方法可直接迁移——金标由本库已有检索（exact/substring）产生的引用构成，天然偏向 lexical；评测 dense 前应统计其 top-10 中“未被标注”的比例，并对这些空洞做人工核对后再比较，否则会低估 dense（层：evaluation）。
- 规模与成本：索引大小（BM25 0.4GB 对 ColBERT 20GB/100 万文档）与延迟（BM25 CPU 20ms）说明 late-interaction 在大库上代价高；本库约 7,900 条 slice，规模远小于 BEIR 数据集，成本不是约束，但“库扩到多法域多语言”时 BM25 仍可维持低成本（层：scale & maintenance）。
- LLM 边界：cross-encoder 重排表现最好但属学习型模型，只能作为候选排序的可选离线环节，最终输出须回到 cite_id 并核验；不进入计算层（层：LLM boundary、provenance）。
- 不适用：BEIR 全为英文、短文档、通用/学术领域，未涉及法条、多语言对齐、交叉引用或版本；其“BM25 稳健”的结论不能直接外推到中英双语的法条检索，须在本库金标上重测（层：identifiers & versioning、relation graph、multilingual 均未覆盖）。512 word piece 截断也与本库长条款切片的粒度选择相关，但论文未讨论切片。
