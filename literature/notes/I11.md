# I11 Edge et al., 2025. From Local to Global: A Graph RAG Approach to Query-Focused Summarization. arXiv:2404.16130v2（预印本）
版本：preprint；I11 文件见 literature/ 下 I11_* 前缀；第 1–12 页（摘要、引言、方法、实验、讨论）全读，附录 A、C 略读，其余附录与参考文献略过

## 1. 问题与作者主张
- 作者指出 vector RAG 适合答案集中在少量记录内的问题，但不支持需要对整个语料做全局理解的 sensemaking 查询（如"主要主题是什么"），这在本质上是 query-focused summarization (QFS) 任务而非检索任务 [p.1-2]。
- 作者提出 GraphRAG：用 LLM 构建两阶段图索引（先从源文档导出实体知识图，再为所有紧密相关的实体组预生成 community summaries），查询时对各摘要做 map-reduce 生成全局答案 [p.1-2]。
- 作者主张在 100 万 token 量级的数据集上，GraphRAG 在答案的 comprehensiveness 与 diversity 上显著优于 vector RAG 基线 [p.1]。
- 作者称其评测是针对"无标准答案的全局问题"的 LLM-as-a-judge 新用法 [p.2]。

## 2. 方法
- 流程：Source Documents → Text Chunks → Entities & Relationships → Knowledge Graph → Graph Communities → Community Summaries → Community Answers → Global Answer [p.4]。
- 实体与关系由 LLM 按 prompt 从每个文本块中抽取，并生成实体与关系的简短描述；也可抽取 claims；作者说明抽取属于 abstractive summarization，关系与 claims 可能并未在文中明说 [p.4-5]。
- 建图：重复抽取的实例合并为节点和边，重复次数成为边权重；本文分析使用 exact string matching 做实体匹配 [p.5]。
- 社区划分：分层使用 Leiden 算法，递归检测子社区直到叶子社区；每一层对节点形成互斥且完全覆盖的划分 [p.5-6]。
- 社区摘要：叶子层按边两端节点度数之和降序，把节点、边与 claims 的描述加入 LLM 上下文直至 token 上限；高层不能装下时用子社区摘要替代元素摘要 [p.6]。
- 查询：社区摘要随机打乱并切块 → map 阶段并行生成中间答案并让 LLM 打 0–100 的有用性分，0 分剔除 → reduce 阶段按分数降序装入上下文生成最终答案 [p.6]。
- 抽取块大小：块越长，LLM 调用越少，但块内靠前信息的召回下降；作者用 self-reflection（"glean"）多轮补抽实体以便使用更大块 [p.4, p.18]。

## 3. 数据与设置
- 数据集：Podcast 转写（1669 个 600-token 块，100 token 重叠，约 100 万 token）；News 文章（3197 个 600-token 块，约 170 万 token，来自 MultiHop-RAG 基准）[p.8]。
- 六个条件：C0–C3（四个社区层级）、TS（对源文本直接做 map-reduce 摘要）、SS（vector RAG 语义检索）；上下文窗口与答题 prompt 保持一致 [p.8]。
- 问题生成：LLM 生成 K 个用户画像、每人 N 个任务、每组 M 个问题，K = M = N = 5，每数据集共 125 题 [p.7]。
- 评测准则：Comprehensiveness、Diversity、Empowerment，外加对照准则 Directness；LLM 评判两个答案，每次比较重复多次后平均 [p.7-8]。
- 配置：生成社区摘要、社区答案和全局答案的上下文窗口固定为 8k token；Podcast 图索引耗时 281 分钟（gpt-4-turbo）；Leiden 用 graspologic 实现 [p.9]。
- Experiment 2：用 Claimify 抽取事实性 claims，Comprehensiveness 为平均 claims 数，Diversity 为 claims 聚类数（1 − ROUGE-L 距离，complete linkage）[p.9]。

## 4. 结果
- 图规模：Podcast 为 8,564 个节点、20,691 条边；News 为 15,754 个节点、19,520 条边 [p.9]。
- 全局方法对 vector RAG：Podcast 上 comprehensiveness 胜率 72–83%（p<.001），diversity 胜率 75–82%（p<.001）；News 上分别为 72–80%（p<.001）与 62–71%（p<.01）[p.9]。
- Directness 作为有效性检验：vector RAG 在所有比较中给出最直接的答案 [p.9]。
- Empowerment：对 vector RAG 以及对 TS 的比较结果混合；作者称能否提供具体例子、引文与出处是帮助用户获得有依据理解的关键，调优元素抽取 prompt 可能保留更多此类细节 [p.9-10]。
- 社区摘要对源文本（TS）：除根层外有小而一致的提升，如 Podcast 中间层 comprehensiveness 胜率 57%（p<.001），News 低层 64%（p<.001）[p.10]。
- Token 成本（Table 2）：Podcast 的 C0 为 34 个单元、26657 token（占 TS 的 2.6%），TS 为 1669 单元、1014611 token；News 的 C0 为 55 单元、39770 token（2.3%），TS 为 3197 单元、1707694 token [p.10]。作者称 C3 比 TS 少 26–33% 上下文 token，C0 少 97% 以上；C0 相对 vector RAG 仍有 72% 的 comprehensiveness 胜率与 62% 的 diversity 胜率 [p.10]。
- Experiment 2：全部全局条件与 TS 的平均 claims 数高于 SS（如 News：C0 34.18，SS 25.23；Podcast：C0 32.21，SS 26.50），差异均显著（p<.05）；各全局条件之间、全局与 TS 之间无显著差异 [p.11]。
- Diversity 的 claims 聚类：Podcast 上全局条件在所有阈值显著优于 SS；News 上只有 C0 在所有阈值显著，C1–C3 仅在部分阈值显著 [p.11]。
- LLM 判断与 claims 指标的一致性：非平局情形下，comprehensiveness 一致率 78%，diversity 为 69–70% [p.11]。
- 上下文窗口选择：在 8k、16k、32k、64k 中，8k 对 comprehensiveness 一致更好（平均胜率 58.1%）[p.19]。
- 自反思：GPT-4 在 600 token 块上抽取的实体引用数约为 2400 token 块的近两倍；多轮 self-reflection 使大块不降质量 [p.18]。

## 5. 作者陈述的局限
- 评测仅覆盖两个约 100 万 token 的语料上的 sensemaking 问题，向不同领域与用途的泛化需进一步研究；虚构率比较（如 SelfCheckGPT）可加强分析 [p.11]。
- 实体匹配只用了 exact string matching；作者称更软的匹配只需小幅调整，且 GraphRAG 对重复实体总体有韧性 [p.5]。
- 作者指出，若生成答案不能准确反映源数据，下游决策有风险，使用时应披露 AI 参与及可能错误 [p.12]。
- 图抽取的质量受 prompt 工程方法影响很大（引 Zhu et al.）[p.18]。

## 7. 对本库的可用点（笔记者推断）
- 关系图（建图方式）：论文的图完全由 LLM 抽取（实体、关系、claims，且作者承认关系可能是原文未明说的抽象概括），边权是重复抽取次数 [p.5]。这与本库"边必须可验证、库内不得有 LLM 抽取边"冲突；本库的层级、交叉引用、zh↔en、定义词、立法事件边由正则和结构确定，应保持。论文的 LLM 图只能当不入库的浏览辅助（层：relation graph、LLM boundary）。
- 关系图（可借用的纯算法部分）：Leiden 社区划分和按节点度数排序是确定性图算法，可在本库显式边上直接运行（需固定随机种子并验证可复现），得到"税种 / 主题簇"用于导航；但社区摘要由 LLM 生成，不适用，本库只能展示簇内原文条款列表而非生成摘要（层：relation graph、provenance）。
- 检索与排序：论文解决的是全局摘要类问题；本库的查询多为点查（某税率、某条件的 cite_id），论文自己承认 vector RAG 在该类问题上最直接 [p.9]，因此其 map-reduce 全局路径对本库主要用例无增益。map 阶段的 0–100 有用性打分由 LLM 给出，不能进入计算（层：retrieval & ranking）。
- 评测：论文评测依赖 LLM 判官和 LLM 生成问题且没有标准答案；本库应使用 cite_id 级别 gold 集合与确定性指标。Experiment 2 的"可数的 claims"思路只可借其精神，即用可计数的事实单元替代整体印象，但 Claimify 本身是 LLM 方法，不适用（层：evaluation）。
- 溯源与验证：社区摘要是二次生成文本，会丢失逐字性与页码；论文把 Empowerment 与出处引文联系在一起 [p.9-10]，说明出处对用户有价值，本库的逐字单元和 cite_id 已满足这一点，不需要摘要层（层：provenance & verification）。
- 规模与维护：建图靠 LLM，Podcast 约 100 万 token 就耗时 281 分钟 [p.9]；本库约 310 份文件若全做 LLM 抽取，每次法条修订都需重跑，也引入不可复现性。确定性正则抽取成本低且可增量更新（层：scale & maintenance）。
- 可借用的小点：块大小与抽取召回的取舍 [p.4, p.18] 提示本库的检索单元不宜过长，但本库单元按条款结构切分，不按固定 token 切。论文数据集是播客与新闻，无版本、生效期、现行有效的约束，结论不能直接外推到法条。
