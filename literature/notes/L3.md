# L3 Cheung, Gleixner, Steffy, 2017. Verifying Integer Programming Results. IPCO 2017, LNCS 10328, 148–160
版本：preprint（arXiv 1611.08832v2 = ZIB Report 16-58，修订于 2017 年 3 月）；L3_Cheung2017_VerifyingIPResults_preprint.pdf；全文（第 1–13 页，参考文献略读）

## 1. 问题与作者主张
- 作者指出混合整数线性规划（MIP）求解器偶尔会返回不正确或可疑的结果，原因之一是浮点运算；即使用精确算术的求解器，也可能有编程或算法错误 [p.3]。
- 作者主张：与其对数十万行的求解器做形式化代码验证，不如让求解器输出额外信息（证书），由独立程序检查；证书应让检查比从头求解花费更少的资源，并尽量简单 [p.3-4]。
- 主要贡献：一种 MIP 证书格式，由一系列可用少量推理规则逐条验证的陈述组成，类似自然演绎，也类似 SAT 不可满足性证明的验证；作者称它比 Applegate 等（旅行商）与 Carr 等（未发表）的格式结构简单得多 [p.4]。
- 作者说明 MIP 与 LP 不同：LP 有对偶与 Farkas 证书，MIP 的小（多项式规模）证书甚至可能不存在，可选的证书形式很多（分支定界树、割平面列表等）[p.4]。

## 2. 方法
- 全文假设问题以精确有理算术给出和求解 [p.5]。
- LP 证书：线性不等式推断。对系统 Ax ≥ b、A′x ≤ b′、A″x = b″，取乘子 d ≥ 0、d′ ≤ 0 的线性组合得到 cᵀx ≥ v；LP 最优性由对偶性保证可由此推出 [p.5]。例 1 中 min 2x+y 的证书为 1×C1 + (−1)×C2，推出下界 1 [p.5-6]。
- 整数规划：加入"向上取整"的舍入操作得到 Chvátal-Gomory 割；证书是原约束后接依次导出的约束列表（例 2）[p.6]。
- 分支切割证书：把分支定界树"压平"成可顺序检查的陈述列表；分支用分裂析取 aᵀx ≤ δ ∨ aᵀx ≥ δ+1；通过引入"假设"约束与"解除分裂（unsplitting）"操作，自底向上逐步撤销假设，最终导出 0 ≥ 1（不可行）或所要的界 [p.6-8]。
- 假设列表不必在证书中写明，检查器可在读取时推出；任何线性不等式都可作为假设引入，因此可对一般析取分支 [p.7]。
- 工具：参考检查器 viprchk（C++，GMP 精确有理算术）、证书压缩程序 viprttn（建依赖图，对包含最终约束的分量做深度优先拓扑排序，删去不必要的导出约束）、转 HTML 的 vipr2html；另扩展了基于 SCIP 的精确有理 MIP 求解器以输出证书 [p.8-9]。

## 3. 数据与设置
- 实验用 Cook 等人（文献 [13]）的 107 个实例：easy 集 57 个、hard（数值困难）集 50 个，来自 MIPLIB 等已知库 [p.9-10]。
- 硬件为 Intel Xeon E5-2660 v3 2.60 GHz 的集群，独占运行；时限 1 小时，证书文件上限 10 GB；平均值为移位几何平均（时间移位 10 秒，内存 1 MB）[p.9]。
- 对比三列：SCIP（精确版默认对偶界策略）、SCIP+C（同时输出证书，只用支持证书输出的两种对偶界方法）、VIPR（检查证书的时间和内存）[p.9]。
- 四个类别：all、solved（SCIP 与 SCIP+C 均在限制内解出）、memout（SCIP+C 因证书文件超限而停止）、timeout（其余有求解器超时）[p.9]。

## 4. 结果
- Table 1（部分）：easy-solved 39 个实例，SCIP 的 tMIP 为 23.2 秒，SCIP+C 为 48.0 秒，tchk 为 11.5 秒；hard-solved 13 个实例，对应为 22.9、40.7、5.3 秒 [p.10]。
- easy 集 57 个实例中，SCIP 解出 54 个，SCIP+C 解出 39 个；hard 集 50 个实例中，SCIP 解出 23 个，SCIP+C 解出 14 个 [p.10]。
- 证书大小（MB）：easy-solved 原始 77、紧缩后 34、gzip 后 10；easy-memout 原始 10286、紧缩后 513；hard-memout 原始 10266、紧缩后 235 [p.10]。
- 作者观察：生成证书的成本"显著但不至于过高"；SCIP 与 SCIP+C 的时间差来自对偶界策略不同和写文件开销，作者估计文件 I/O 约占 easy-solved 求解时间的 7%；检查证书所需时间明显少于求解时间 [p.10]。
- 紧缩程序使证书大幅缩小，memout 类最明显；最极端的实例 markshare1_1 从 10 GB 缩到 8 kB，作者解释为根节点对偶界已为零、树搜索只为找最优解 [p.10]。
- 作者在其他类别看到的缩减"严格高于 50%"，说明紧缩不止去掉内部节点 [p.10]。
- 作者称软件已成功用于电路设计验证与 Frankl 猜想相关的两类 MIP 模型的证书生成与检查 [p.4]；并称这是首个对一般 MIP 证书做验证并向优化界公开的软件 [p.4-5]。

## 5. 作者陈述的局限
- 引言说明 MIP 小证书可能不存在 [p.4]；证书格式只在概念层次描述，完整规范在随附文件中 [p.5]。
- 证书输出目前与求解过程同时进行，产生可压缩的冗余，且 memout 实例是因证书超过 10 GB 而停止；作者指出可改进的两处：缓冲以避免打印内部节点的对偶界推导，以及不为未改进父节点界的节点生成推导 [p.9-10]。
- 修改后的精确求解器是开发版，仅向作者索取 [p.9]；证书输出目前只支持 Project-and-shift 与 Exact LP 两种对偶界方法 [p.9]。
- 作者称这只是验证整数规划求解器结果的"第一步" [p.10]；未来方向包括用浮点加方向舍入/区间算术生成证书，以及转成可由证明助手（如 HOL Light）形式化验证的形式 [p.10-11]。

## 6. 原文摘录
- "Naturally, certiﬁcates should be as simple to verify as possible if they are to be convincing." [p.4]
- "small (i.e. polynomial size) certiﬁcates for infeasibility or optimality may not even exist" [p.4]
- "Throughout this paper, we assume that problems are speciﬁed and solved with exact rational arithmetic." [p.5]
- "Therefore, linear inequality inference is suﬃcient to certify optimality for linear programming." [p.5]
- "Perhaps most importantly, we observe that the time to check the certiﬁcates is signiﬁcantly less than the time to solve the instances." [p.10]
- "a certain risk of an implementation error remains" [p.3]

## 7. 对本库的可用点（笔记者推断）
- §3.4"下界与差距"：论文的证书结构（给定约束、逐步导出、每步写明理由、最后得到界）可作为"下界证书"的格式参照：下界 = 一条由若干条款参数按固定规则推出的陈述，每步附条款编号和算术。如"支柱二范围内每个法域超额利润至少按 15% 计"可写成一步步导出的记录，供核验器顺序检查。
- 与论文的区别（必须说明）：论文的界由线性不等式推断加取整、分裂规则推出，检查器只需有理算术；本库的"下界"是法律事实推理（例如某法域在范围内），其推理规则不是线性推断，核验器只能核对每一步所引参数和算术，不能核对"该法条适用"。因此 §3.4 里"参照整数规划结果的核验证书"只适用于数值部分；适用性判断仍在 A 层和专家包。
- 精确算术（p.5）：论文全文基于精确有理数；本库的税额计算若用浮点或有舍入口径（D37 ETR rounding），核验器应用定点小数或分数独立复算，并在轨迹里写明每步舍入规则；这是 §3.3 现有写法未明说的。
- D 层结构搜索与证书的分工：论文对"不可行/最优"的证书要穷尽所有分支（叶子合起来覆盖所有情形）[p.6-7]。本库的结构搜索是随机抽样，不构成"候选找得全"的证书，只能作警示；若要对某一模板空间声称穷尽，可借用"分支覆盖全部情形再逐一被推翻"的结构，但需要把结构空间形式化为有限分裂，目前没有。
- 紧缩与规模（p.8-10）：证书紧缩把无用步骤删掉，对本库对应"轨迹只保留对最终税额起作用的项"，可减小专家包和界面里点开推导时的负担。论文的规模数据（GB 级）来自 MIP 分支树，本库轨迹规模小得多，不能类推。
- 不适用：论文没有讨论证书生成方的缺陷如何被发现（只说检查器拒绝）；结果中无负面的"检查器误判"数据；107 个实例是数学规划库，与税务案例无关。
