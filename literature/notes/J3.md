# J3 Darwiche & Marquis, 2002. A Knowledge Compilation Map. JAIR 17: 229–264（arXiv 版）
版本：preprint（arXiv 版本，JAIR 2002 正文）；J3_Darwiche2002_KnowledgeCompilationMap_preprint.pdf；第 1–15 页全读（正文、Table 1–7），第 16–18 页附录引理略读，其余证明与参考文献略过

## 1. 问题与作者主张
- 作者主张从两个维度分析编译目标语言：语言的 succinctness，以及它在多项式时间内支持的 queries 与 transformations [p.1]。
- 知识编译的动机是把计算开销推到离线阶段，由之后的所有在线查询摊销；作者称生成尽可能小的编译表示是主要计算瓶颈 [p.1]。
- 作者把十余种语言统一为 NNF（带 ∧/∨ 内部节点的有根 DAG）的子集，并给出按 succinctness 与多项式时间操作的交叉排序（map）[p.2]。
- 作者建议的用法：先确定应用需要的 queries 与 transformations，再选在这些操作上多项式时间可行的最 succinct 的语言 [p.2]。
- 作者要求目标编译语言至少支持多项式时间的 clausal entailment；单一的一致性检验不足以证明编译值得 [p.2]。

## 2. 方法
- NNF：叶为 true、false、X、¬X，内部节点为 ∧ 或 ∨；大小为边数 [p.2]。性质：decomposability（∧ 的子节点不共享变量）、determinism（∨ 的子节点两两互斥）、smoothness（∨ 的子节点涉及同一变量集）、decision、ordering、flatness [p.3-4]。
- 语言：DNNF（decomposability）；d-DNNF（再加 determinism）；sd-DNNF（再加 smoothness）；BDD（根为 decision 节点）；FBDD（= DNNF ∩ BDD，read-once）；OBDD<（FBDD 加变量序）；OBDD（所有序的并）；MODS（DNF 且满足 determinism 与 smoothness）；另有 DNF、CNF、PI、IP [p.4-5]。
- Succinctness：L1 ≤ L2 当且仅当存在多项式 p，使 L2 中每个句子在 L1 中有大小不超过 p 的等价句子；不要求可在多项式时间内算出 [p.8]。
- Queries：CO（一致性）、VA（有效性）、CE（clausal entailment）、IM（implicant）、EQ、SE、CT（model counting）、ME（model enumeration）[p.10]。作者说明只研究多项式时间算法是否存在，不给出算法本身 [p.10]。
- Transformations：CD（conditioning，即将变量代入 true/false）、FO 与 SFO（forgetting）、∧C、∧BC、∨C、∨BC、¬C [p.12-13]。
- 引理：满足 CO 与 CD 的语言满足 ME 与 CE（通过检验 Σ | ¬α 是否不一致）；满足 VA 与 CD 的语言满足 IM；满足 CO 且对 ¬ 与 ∧ 封闭的语言满足 SE [p.12-13, p.16-17]。

## 3. 数据与设置
- 本文为理论分析，无数据集与实验。证明在附录 A；需要的复杂度假设为 P≠NP，以及部分 succinctness 结论依赖多项式层次不塌缩 [p.8-9, p.11]。
- 作者在讨论概率时说明：假设所有变量互相独立时，命题句子的概率在其所考虑的子集里，凡能多项式时间 model counting 者均能多项式时间算出 [p.10]。

## 4. 结果
- Succinctness 链（Table 3，Figure 5）：DNNF < d-DNNF < FBDD < OBDD < OBDD< < MODS；每加一个性质语言的 succinctness 降低（在多项式层次不塌缩时）[p.8]。除 PI 外 DNNF 是目标编译语言里最 succinct 的；是否比 PI 更 succinct 未知 [p.8]。
- 加入 smoothness 不改变 d-DNNF 的 succinctness（sd-DNNF 与 d-DNNF 同样 succinct）；任一 d-DNNF 可在多项式时间转成 sd-DNNF [p.8, p.16]。
- Table 5（queries）：DNNF 支持 CO、CE、ME；d-DNNF、sd-DNNF、FBDD 支持 CO、VA、CE、IM、CT、ME，EQ 标为未知；OBDD 另支持 EQ；OBDD< 支持全部八项（含 SE）；MODS 支持全部八项；DNF 支持 CO、CE、ME；CNF 只支持 VA、IM；NNF、d-NNF、s-NNF、f-NNF、BDD 在 P≠NP 下一项也不支持 [p.11]。
- 作者称只有 deterministic 语言（d-DNNF、sd-DNNF、FBDD、OBDD、OBDD<、MODS）支持多项式时间 counting；counting 蕴含 VA，反之不然 [p.12]。
- 单独加 smoothness、determinism、flatness 或 decision 都不带来多项式时间查询；decomposability 是例外，直接带来 CO、CE 和 ME [p.11]。
- Table 7（transformations）：所有考虑的语言都满足 CD [p.14]。多变量 forgetting（FO）只有 DNNF、DNF、PI、MODS 满足；FBDD、OBDD、OBDD< 不满足多变量 FO，OBDD 与 OBDD< 满足单变量 SFO，FBDD 连 SFO 都不满足；d-DNNF 两者均不满足 [p.14-15]。
- 没有任何目标编译语言对 ∧ 封闭；对 ∨ 封闭的目标编译语言只有 DNNF 与 DNF；对 ¬ 封闭的只有 FBDD、OBDD、OBDD<；OBDD< 是唯一同时对 ¬、有界合取、有界析取封闭的目标编译语言，作者称这是主流 OBDD 编译器的基础 [p.15]。
- 作者称 d-DNNF 与 FBDD 支持相同的多项式时间查询，区别在于 FBDD 对 ¬ 封闭，但 d-DNNF 更 succinct [p.15]。
- 作者称 OBDD< 的 EQ 与 SE 需要固定的变量序 [p.12]。
- 文中未讨论 weighted 或最小代价的优化查询（如求使某代价最小的模型）。文内仅提到概率（独立变量下由 counting 得到）[p.10]。

## 5. 作者陈述的局限
- 作者只研究多项式时间算法是否存在，不给出算法，也不涉及实际编译时间或实际大小 [p.10]。
- 作者只考虑 complete 的语言（每个命题句子都有等价元素），因此未包含 Horn 等子集 [p.4]。
- 部分关系未知（Table 3、Table 5 中的 "?"），例如 d-DNNF、FBDD 的 EQ，d-DNNF 与 sd-DNNF 对 ¬ 的封闭性，DNNF 与 PI 的 succinctness 关系 [p.8-9, p.11, p.14]。
- 作者说明 d-DNNF、FBDD 的 EQ 在 coNP 内，但既无 coNP-hard 证明也无确定性多项式算法；可用概率算法在多项式时间判定 [p.12]。
- 作者指出最 succinct 的目标语言不适合人手工编写或解读 [p.2]。

## 6. 原文摘录
- "the succinctness of the target compilation language, and the class of queries and transformations that the language supports in polytime" [p.1]
- "we propose that one starts by identifying the set of queries and transformations needed for their given application, and then choosing the most succinct language that supports these operations in polytime." [p.2]
- "Adding each of these properties reduces language succinctness (assuming that the polynomial hierarchy does not collapse)." [p.8]
- "polytime counting implies a polytime test of validity, but the opposite is not true." [p.12]
- "Conditioning also plays a key role in building compilers that enforce decomposability." [p.13]
- "It is important to stress here that none of FBDD, OBDD and OBDD< permits polytime forgetting of multiple variables." [p.14]

## 7. 对本库的可用点（笔记者推断）
- 选型问题（层：分析低效、局部最优）：本库对"每个候选结构的 pending 条件"需要的是：对全部 pending 赋值取 min/max 税额、固定若干 pending 后重算（conditioning）、判断某 pending 是否相关。映射到本文：CD 是所有语言都满足的 [p.14]，故"强制某 pending 取另一值"在编译表示上是多项式时间的局部操作，不必整图重算；这支持把每条 flow 的条件树编译为 OBDD< 或 d-DNNF 并缓存。
- 相关性判定：当前做法对其余 pending 的 2^7 组合各跑两遍。若每个条件树编译为 OBDD<，则变量是否相关可由该变量是否在规范图中出现判定（OBDD< 对固定序规范）；论文给出 OBDD< 的 EQ 与 SE 为多项式时间 [p.11]，可用于等价性检查。这是推断；论文只给出可行性，未给出具体算法或规模。
- 不适用（关键）：本文所有 query 都是布尔性质（consistency、counting、entailment）。论文没有 min/max 代价优化查询，也没有数值加权；本库要求"最小/最大税额"是对带数值的函数求优，需要的是 ADD/AADD 一类带数值终端的结构（见 J4）或 weighted model counting 的扩展，不能直接引用本文表格推出多项式时间。本文只能用于布尔层：哪些 pending 组合使某条款条件为真，条件树的 SAT/validity/counting 的可行性。
- 模型计数的用途：CT 在 d-DNNF、OBDD 上多项式时间 [p.11]；可用于统计"使 floor 与 ceiling 不同的 pending 组合数"，但本库目前并不需要计数，不要为此引入编译。
- 联合效应：Forgetting（FO）可对 d-DNNF/OBDD 不成立 [p.14]；若要把若干 pending 变量整体消去（取 exists/forall 以得到 floor 或 ceiling），OBDD 只能逐个 SFO，多变量会不满足 FO 的多项式保证——这对"精确 min/max over all pending decisions"的布尔层实现是一个冲突点，需通过实测大小决定，论文无规模数据。
- 规模：本库 pending 项上限约 7 个、条件树小，编译带来的收益可能不如直接穷举 2^7；论文的收益针对"一次编译、大量在线查询"[p.1]，只有当同一条件树被不同候选结构重复查询时（本库的跨候选重复 flow）才合算。论文未给出盈亏平衡点。
- 记忆化：论文是离线编译后在线查询的摊销模型，不涉及输入变化后的增量更新，对"数据库变更后的增量重算"没有直接帮助（该问题见 J1、J2）。
