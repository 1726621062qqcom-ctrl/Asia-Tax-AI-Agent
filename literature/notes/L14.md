# L14 McMinn, 2004. Search-Based Software Test Data Generation: A Survey. Software Testing, Verification and Reliability 14(2), 105–156
版本：author（作者主页的网络档案副本，文件自注为发表文章的 preprint）；L14_McMinn2004_SBSTSurvey_author.pdf；阅读范围：第 1–8 页（引言与三种搜索方法）、第 25–26 与 29–37 页（进化测试分类、目标函数、分支距离问题）、第 46–48 页（功能测试展望、灰盒测试）、第 51–52 页（结论）；逐个结构覆盖技术的细节（第 9–24、27–28、38–45、49–50 页）未读，参考文献略过

## 1. 问题与作者主张
- 作者指出工业界测试数据的选取通常靠人工，成本高、费力；穷举输入对稍大的程序不可行，随机方法不可靠，难以触及"更深"的功能 [p.1-2]。
- 作者指出以往自动化尝试受软件规模与复杂度限制，且一般情形下测试数据生成是不可判定问题 [p.2]。
- 作者主张元启发式搜索可以在合理计算代价下处理这类问题：把测试准则转换成目标函数，用目标函数在候选解之间比较，把搜索导向有希望的区域 [p.2]。
- 作者归纳元启发式搜索已用于四类目标：覆盖特定程序结构；执行规约描述的某个特定功能；设法证伪灰盒性质（诱发错误条件、证伪与安全性有关的断言）；验证非功能性质（如最坏执行时间）[p.2]。

## 2. 方法
- 综述性质。第 2 节介绍三种搜索技术：爬山、模拟退火、进化算法（遗传算法为代表）[p.3-8]。
- 爬山：从随机初始解出发，检查邻域，找到更好的就替换，直到邻域无改进；有最陡上升与随机（首次）上升两种策略 [p.3]。作者指出它简单、结果快，但会陷入局部最优，也会停在"高原"（所有邻居目标值相同，没有改进信号）；结果依赖起点，常用扩展是多次重启 [p.3]。
- 模拟退火：与爬山相似，但以一定概率接受较差解，概率由"温度"控制，温度按降温方案下降 [p.4-5]。
- 遗传算法：维护一个种群，用重组（交叉）与变异迭代产生后代，选择压力由选择方式（适应度比例、锦标赛等）决定 [p.5-7]。
- 目标函数是关键：好的解应得到更好的目标值，差的解得到更差的值；最小化的目标函数在此语境下常称代价函数 [p.3]。
- 结构测试的目标函数：分支距离（把分支谓词的"离满足有多远"数值化）与接近层（approach level，到目标结构还有几个控制依赖节点未按所需方向执行）；Wegener 等的形式为 (dependent − executed − 1) + m branch dist，其中分支距离用对数映射到 [0,1] [p.29]。作者把进化方法分为覆盖导向、分支距离导向、控制导向与二者结合 [p.25-26]。
- 灰盒：Korel 与 Al-Yami 把"找测试数据证伪断言"化为"执行某条特定语句"——把断言取反，转成析取范式，生成嵌套 if，目标是执行 report_violation() [p.47]。

## 3. 数据与设置
- 综述，没有自己的实验。引用的实验规模：Watkins 的两个无循环的实验程序且输入域被人为限制 [p.25-26]；Korel 与 Al-Yami 的 9 个 Pascal 程序、25 个有缺陷版本；Tracey 等的 7 个不超过 200 行的简单程序及一个发动机控制器的工业实验 [p.47-48]；Distronic 巡航控制系统的功能测试 [p.46]。

## 4. 结果
- 作者对进化结构测试的比较结论：覆盖导向的目标函数对只在输入域一小部分取值下才执行的结构缺乏引导，对非平凡程序难以期望全覆盖；结构导向方法为每个未覆盖结构单独搜索并用量身定制的目标函数，作者称这是更成功的策略 [p.26, p.52]。
- Watkins 的路径覆盖实验：与随机测试相比，遗传算法达到路径覆盖所需的测试少一个数量级，但两个程序都很简单、没有循环、输入域被人为限制 [p.25-26]。
- 目标函数的地形问题：局部最优与高原；全局搜索比局部搜索更稳健，但在有大高原或多个局部最优的恶劣地形里仍会吃力 [p.31]。
- 标志变量（flag）问题：谓词里出现布尔标志时，目标函数地形成为真、假两个高原；这时进化搜索不比随机搜索好 [p.33]。已有处理：用给标志赋值的谓词替代（Bottaci）；程序变换去掉标志（Harman 等，尚不能处理循环里的标志）；数据流分析确定要先执行的节点序列（Baresel 等，有循环体内多余赋值问题）[p.33-35]。
- 欺骗性目标函数：例（r = 1/d 后判断 r == 0），目标函数引导搜索离开 d == 0，使搜索以为越来越接近 [p.35-36]。
- 嵌套谓词或短路求值的条件要一个接一个满足，满足后一个而不破坏前一个的概率下降，搜索表现差；作者称理想做法是同时评估所有条件，可借助数据依赖分析 [p.35-37]。
- 变量依赖分析可排除不影响某分支结果的输入变量，缩小搜索空间 [p.37]。
- 灰盒：断言违反在 92% 的情形下找到了输入（9 个程序、25 个故障版本）[p.47]。异常条件测试：元启发式方法几乎能为所有异常条件产生测试数据，并在存在异常处理器时达到完全分支覆盖；但在发动机控制器的工业实验中，生成的输入情形在系统实际运行中不可能出现，这些异常实际上无法触发 [p.48]。
- 对断言方法的展望：作者称能嵌入任意断言并搜索其违反是很强大的概念；可用于组件复用测试（搜索违反使用假设的调用）和用黑盒断言充当结构测试输出的预言 [p.48]。

## 5. 作者陈述的局限
- 爬山易陷局部最优与高原，结果依赖起点 [p.3]。
- 测试数据生成一般是不可判定问题 [p.2]。
- 标志问题的程序变换方法尚不能处理循环中的标志 [p.34]；接近层在非结构化控制流下有乐观/悲观两种分配，实验未能断定哪种总体更好，作者称该问题仍开放 [p.31]。
- 功能测试自动化的障碍：需要提供从规约抽象模型到实现的映射；系统测试的搜索空间可能很大；内部状态需要测试序列 [p.46]。
- 作者在每节末列出未来方向；结论称各领域仍有许多问题待解 [p.52]。

## 7. 对本库的可用点（笔记者推断）
- §3.4 结构搜索：论文的"搜索"是针对一个目标（覆盖某分支、证伪某断言）的有导向搜索，用爬山、退火、遗传算法加目标函数。§3.4 现写的是"随机变换结构后用同一引擎计算"，等于随机测试。可改为：目标 = "找一个保证税额低于现方案上限的结构"，目标函数 = 候选的保证税额（或与方案上限之差），变换（加减一层控股、移角色、拆流、调债股比例、调时点）充当邻域算子，用爬山加多次重启，必要时用退火。论文称随机方法难以触及深处，这点支持改用有导向搜索 [p.1-2]。
- 灰盒"证伪断言"对应 §3.4 的整体设计：把"方案最优"当作断言，搜索反例；找到的低税结构就是违反。论文把断言违反化为"执行一条特定语句"[p.47]，对应这里的"找出一个满足可落实前提且税额低于方案的结构"。
- 景观问题直接适用于税务引擎：门槛类规则（183 天、持股比例、15% 最低税）使税额成为阶梯函数，邻域内大片取值相同，相当于高原 [p.3, p.31]。标志变量问题对应：中间量被离散化成布尔（"是否居民""是否适用豁免"）之后，税额不再给出"离翻转还有多远"的信号 [p.33]。可行办法：沿用论文的思路，给每个布尔门槛定义"距离"（离门槛的天数、百分点），在目标函数中加入该距离项（分支距离）；这与 §3.4 的"稳定余量"共用同一数据。这是笔记者的类推，论文未涉及税务。
- 结构搜索的结论是单向的：搜索找到更低结构可作反例，搜索没找到不能证明模板空间完全；论文也没有给出搜索何时可以停的保证，只有经验结果。所以 §3.4 与 §6 中应写成"在 N 次搜索、种子 S 下未找到"，不能写成"已证最优"；"可证下界"仍须用单独的证明路线。
- 论文的工业实验提示：搜索产生的输入可能是实际中不可能的 [p.48]。对应 §4 专家包"结构搜索找到的更优结构能否落实"：搜索必须带可行性约束（法域允许、角色可行），否则会产出不可落实的结构，把专家时间花在无效候选上。
- 重现性：搜索依赖随机种子与起点 [p.3]，应记录种子，并纳入 C 层"换种子重跑"的不稳定检查；同一目标多次重启的结果分布可作为"搜索是否充分"的粗略证据。
- 不适用：论文的对象是程序的控制流与输入向量，目标函数依赖程序插桩得到分支距离；本库的"程序"是规则图加参数表，没有现成的分支谓词，距离函数要自行从规则的阈值条件中构造。综述也没有讨论多目标（税额区间的上下限）的搜索。
