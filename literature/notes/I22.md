# I22 Joren et al., 2025. Sufficient Context: A New Lens on Retrieval Augmented Generation Systems. ICLR 2025（预印本 arXiv:2411.06037v3）
版本：preprint；I22_Joren2025_SufficientContext_preprint.pdf；第 1–10 页全读，附录与参考文献略读

## 1. 问题与作者主张
- 作者提出一个开放问题：RAG 的错误是因为 LLM 没有利用好检索到的上下文，还是上下文本身不足以回答问题 [p.1]。
- 作者定义 sufficient context，并给出分类方法；该分类只依赖（问题，上下文）对，不需要标准答案 [p.1-2]。
- 作者称理想行为是：上下文加上模型参数知识足以回答时输出正确答案，否则应拒答（abstain）或要求更多信息 [p.1]。
- 作者称更大的模型（Gemini 1.5 Pro、GPT 4o、Claude 3.5）在上下文充分时回答好，但上下文不足时常输出错误答案而不是拒答；较小的模型（Mistral 3、Gemma 2）即使上下文充分也常幻觉或拒答 [p.1]。
- 作者提出结合 sufficient context 信号与模型自评置信度的 selective generation，称可把回答中的正确比例提高 2–10%（Gemini、GPT、Gemma）[p.1]。

## 2. 方法
- 定义：实例 (Q, C) 有 sufficient context，当且仅当存在一个答案 A'，使 A' 是给定 C 时对 Q 的一个合理（plausible）答案；与 AIS 蕴含不同之处是不预设答案 A'，因此允许上下文含错误答案 [p.4]。
- 作者对多跳、歧义查询和歧义上下文给出三条说明：不得推出上下文中没有的联系；歧义查询须由上下文消歧并给出答案；上下文含多个合理答案时须能区分 [p.4]。
- Autorater：在 115 条人工标注实例（来自 PopQA、FreshQA、Natural Questions、EntityQuestions，含高度相关但不充分的上下文）上比较 Gemini 1.5 Pro（0-shot / 1-shot）、FLAMe（PaLM 24B 微调，上下文切成 1600 token 块，任一块充分即判充分）、TRUE-NLI（需标准答案）、Contains GT（需标准答案）[p.4-5]。
- Selective generation：用 FLAMe 给出的二值 sufficient context 标签与自评置信度（P(True) 或 P(Correct)）训练简单逻辑回归来预测幻觉，低于阈值则拒答；阈值控制 coverage–accuracy 权衡 [p.8-9]。
- 微调：把部分训练样本的答案改为 "I don't know"，包括仅在上下文不足的样本上改写 [p.9-10]。

## 3. 数据与设置
- 数据集：FreshQA（True Premise，452 例，上下文取自支持答案的 URL）、Musique-Ans（20 个支持片段作上下文，随机抽 500 例）、HotPotQA（top-5 检索，随机抽 500 例）；上下文截断到 6000 token [p.6]。
- 模型：Gemini 1.5 Pro、GPT 4o、Claude 3.5 Sonnet、Gemma 27B，另有 Mistral 3（微调实验）[p.1, p.7]。
- 回答标注为 correct / abstain / hallucinate；先做与标准答案的匹配，无法确定时用零样本 LLMEval（基于 Krishna et al., 2024 的提示）[p.6]。

## 4. 结果
- Autorater（Table 1，115 例）：Gemini 1.5 Pro 1-shot F1 0.935、Accuracy 0.930；0-shot 0.878 / 0.870；FLAMe 0.892 / 0.878；TRUE-NLI 0.818 / 0.826（precision 0.938，recall 0.726）；Contains GT 0.810 / 0.809 [p.5]。
- 数据集中充分上下文比例（Figure 2，6000 token）：FreshQA 77.4%，HotPotQA 46.2%，Musique 44.6%（按图中顺序与图注；2000 token 下三者更低，对应 63.7 / 45.4 / 33.4）；图 1 称 Musique 中不充分的实例占 55.4% [p.3, p.6]。
- 作者称上下文充分时模型仍然产生错误答案；上下文不足时，模型更常幻觉而不是拒答，多跳问题尤甚 [p.2]。
- 加入 RAG 后拒答减少：Claude 3.5 Sonnet 的拒答率由 84.1% 降至 52%，GPT 4o 由 34.4% 降至 31.2%，Gemini 1.5 Pro 由 100% 降至 18.6% [p.7]。
- 作者称 SOTA LLM 在上下文不足时仍有 35–62% 的时间输出正确答案；HotpotQA 上三个模型在不充分上下文下都能答对 35% 以上 [p.2, p.7]。
- 对不充分上下文下仍正确的实例，作者归为：Yes/No 题、选项有限、多跳片段/部分（用参数知识补全）、跳数过多、歧义查询（猜对解释）、rater 错误、闭卷即答对等类型（Table 2）[p.8]。
- 反向情形（充分上下文却答错）：标准答案与来源冲突；模型未能正确组合信息（多跳或算术）；不少情形难以判断原因 [p.8]。
- Selective generation：与仅用自评置信度相比，结合 sufficient context 一般更好，例如 Gemma 27B 在 HotpotQA 高准确率区间提高超过 10%，Gemini 1.5 Pro 在约 70% coverage 处提高超过 5%；Gemma 27B 在 Musique 上总体准确率 18.4%，sufficient context 系数为 0，两种方法相同 [p.9-10]。
- 微调：微调后正确率在不少情形提高，但仍常幻觉，且幻觉多于拒答；Mistral 3 微调可导致更高拒答率、更少正确答案（引言）[p.2, p.10]。

## 5. 作者陈述的局限
- 分析仅限 QA 数据集，摘要等任务同样使用上下文，其充分性未研究 [p.10]。
- 未探讨不同检索方法产生充分上下文的频率；若用 autorater 迭代判断是继续检索还是作答，可能表现更好 [p.10]。
- 作者提出未来方向：输出分数而非二值标签的细粒度 autorater（可用于检索后排序）、多模态扩展 [p.10]。
- 作者也说明直接对不充分上下文一律拒答是"heavy-handed"，会降低整体表现，因为模型在不充分上下文下仍答对一部分 [p.8]。

## 6. 原文摘录
- "Otherwise, the model should abstain from answering and/or ask for more information." [p.1]
- "Crucially, it does not require a ground truth answer." [p.2]
- "models tend to hallucinate more than they abstain, especially for multi-hop questions" [p.2]
- "The context is sufficient to answer the query if it contains all the necessary information to provide a definitive answer." [p.3]
- "Without RAG, Claude 3.5 Sonnet abstains on 84.1% questions, while with RAG, the fraction of abstentions drops to 52%." [p.7]
- "this heavy-handed approach can lower overall performance, since all models answer some questions correctly even with insufficient context" [p.8]

## 7. 对本库的可用点（笔记者推断）
- 评测：论文把查询按"上下文是否充分"分层再看结果，而不是只看总体准确率。本库可对每个（问题，检索结果）先判定"所需 cite_id 是否都在结果中"（有 gold 时为确定性判断），分层报告：检索充分时是否被正确使用、不充分时是否正确报缺（层：evaluation of retrieval）。
- 缺失信息处理：论文称理想行为是不足就拒答；本库硬约束同样要求"缺失信息是显式 pending，绝不猜测"。可把"拒答"落成库的一等输出：检索接口返回（命中 cite_id 列表 + 缺口清单），缺口写入 gap 表而非让下游补全。论文发现大模型在不足时仍猜（Claude 拒答率 52%、Gemini 18.6%），说明不能靠模型自觉拒答，须由程序规则决定（层：provenance & verification、LLM boundary）。
- 充分性判定的程序化：本库的规则有固定结构（税种 × 收入类型 × 主体 × 参数），所需字段是已知清单，可用确定性的"必需字段是否都能追到 cite_id + quote"代替 LLM autorater；多跳时只有显式交叉引用边可跳，不得推出上下文中没有的联系（对应论文 Remark 1）。论文 autorater（Gemini 93%）及 FLAMe 方案不能进入计算路径（层：relation graph、LLM boundary）。
- 版本/歧义：论文的 Remark 3（上下文有多个合理答案时须能区分）对应本库的跨版本、跨辖区同名条款（如 section 编号相同、不同年度）；检索结果需带版本与辖区元数据，缺则判为不充分（层：identifiers & versioning）。
- 检索与排序：作者建议细粒度的充分性分数可用于检索后排序；本库可用"覆盖了多少个必需字段"作为排序/截断依据，而非语义相似度（层：retrieval & ranking）。
- 不适用：论文结果来自开放域 QA 与商业/大模型（Gemini、GPT、Claude），自评置信度 P(True)/P(Correct) 与逻辑回归阈值均依赖模型内部信号，本库计算层不可使用；"不充分时仍有 35–62% 答对"来自模型参数知识，在本库的"每个数字须逐字可追溯"约束下不能被接受为正确。
