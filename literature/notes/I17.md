# I17 OASIS LegalDocML TC (Palmirani, Sperberg, Vergottini & Vitali eds.), 2018. Akoma Ntoso Version 1.0. Part 1: XML Vocabulary. OASIS Standard
版本：published（OASIS Standard，2018-08-29，标准文本，非论文）；I17_OASIS2018_AkomaNtoso.pdf；阅读范围：第 1–16、19、32–57、85–87 页（目录、概览、范围、设计、FRBR 四层、命名与 URI/IRI、修改与版本、引用、元数据、分析元数据与修改记录、temporalData、合规等级与一致性）；其余页（第 17–18、20–31、58–84 页：文档类型、表格、列表、各类结构的元素说明）与致谢略读或未读

## 1. 问题与作者主张
- 本文件是 OASIS LegalDocumentML（Akoma Ntoso）技术委员会的标准文本，第 1.4 节称其为非规范性（non-normative）材料，面向需决定如何以数字方式管理法律来源的各方，阐述动机、设计原则与好处 [p.7]。
- 目标（标准自述）：为议会、立法与司法文件建立可在各机构间交换的通用格式；提供兼具长期存储与检索的格式；建立通用数据与元数据模型；建立命名与链接资源的通用机制（URI）以便相互引用；自解释；可扩展 [p.8]。
- 标准自述其主张："point-in-time consolidation of legislation" 这类高级服务可经机器可读标记实现 [p.8]。
- 标准称其覆盖议会记录、委员会简报、公报、立法与条例（覆盖立法生命周期）、判决等文件类型 [p.11]。
- 规范性内容（含一致性条款）在 Part 2 与 XML schema 中，本文第 8 章只引用 Part 2 第 3 节 [p.2, p.87]。

## 2. 方法（标准的结构与机制）
- 三个特性：descriptiveness（每个有意义的部分都有名字，约 310 个元素名）、ontologies（用本体把文档内容关联到外部概念、人物、组织）、数据与元数据分离（作者与编辑的区分）[p.8-9]。
- XML 语言的四部分：namespace、vocabulary（310 个元素名、69 个属性名，lowerCamelCase）、grammar、semantics（偏好声明式语义）[p.14]。
- 6 类内容模型：markers、inlines、blocks、subFlow、containers、hierarchy；元数据元素都是 marker，元数据值作为属性值而非文本内容 [p.15-16]。
- URI/IRI：每个文档、本体概念甚至标记语言本身都有系统化的 URI/IRI，命名规则见另一份 Naming Convention 文件 [p.14]。
- FRBR 四层（Work / Expression / Manifestation / Item），分别是抽象的法律资源、含具体内容的版本（语言、修订等）、电子或物理格式、一份具体文件 [p.14-15, p.40-41]。
- 文档按组成部分（component）切分：WorkComponent、ExpressionComponent、ManifestationComponent、ItemComponent [p.39]。
- 元数据 `<meta>` 的区块：identification、publication、classification、lifecycle、workflow、analysis、temporalData、references、notes、proprietary、presentation [p.38-39]。
- 版本管理：lifecycle 元素列出事件；文档按 `@contains` 分为 originalVersion、singleVersion、multipleVersions；multipleVersions 中的片段用 `@start`、`@end`（有效）与 `@startEfficacy`、`@endEfficacy`（效力）以及 `@status` 标注，start/end 引用事件的 id [p.33]。
- 引用：引用元素带 href、eId、showAs、shortForm；`ref`/`mref`/`rref` 指向其他文档（单个/一组/一个范围），`mod`/`mmod`/`rmod` 表示对其他文档的修改 [p.35-36]。
- 分析元数据：activeModifications（本文档对他文档的修改）、passiveModifications（他文档对本文档的修改）、restrictions、judicial、parliamentary、mappings、otherReferences、otherAnalysis [p.46]。
- 合规等级：Level 1 使用标准文档结构（并可逐级加基本元数据、规范性引用、高级元数据、语义元素）；Level 2 另要求使用 AKN 命名规范（FRBR 元数据与 id）[p.85]。

## 3. 数据与设置
- 本文件不含实验、数据集或评测；以 XML 片段为例，示例涉及英国、美国、乌拉圭、智利、南非、肯尼亚等国的文件 [p.34-37, p.43, p.47-50, p.55]。
- 命名示例：Work `/akn/un/act/2011-11-22/10/!main`；Expression `/akn/un/act/2011-11-22/10/eng@2013-12-19/!main`；Manifestation `/akn/un/act/2011-11-22/10/eng@2013-12-19/!main.xml` [p.42-43]。
- 标准列出 URI/IRI 应包含：国家、文档类型、文档日期及适用时的版本、主语言、各部分（附件等）[p.41]。

## 4. 主要条款（标准无实验结果）
- 命名原则（Naming convention）：MEANINGFULNESS（名字是对资源的有意义、合乎逻辑的描述，而非物理路径）、PERMANENCE（名字必须长期稳定）、INVARIANCE（名字来自资源的不变属性，使不同流程、工具、人员得到同一名字）[p.39]。
- 引用应指向哪一层：立法引用多指向 Work（法律引用其他法律时与具体版本无关）；附件与附表列表属于特定 Expression；XML 内部用 Manifestation 的 URI 指向各组成部分；非文档概念通过两步引用（先在 references 区建条目，再用 URI 指向概念）[p.40]。
- Expression 的 URI 以 `语言@日期` 标识版本；无日期时可用 `FRBRversionNumber`（示例 `eng@v_3`）；翻译用 `FRBRtranslation`（含 fromLanguage、by、pivot）建立 Expression 间的关系 [p.42-43]。
- 别名：同一来源可有多种引用方案并存，`FRBRalias` 与 `alternativeReference`（如 ELI）记录功能等价的其他 URI [p.37-38]。
- 事件模型的两个假设：事件发生于可客观确定的具体时间并归属某一日期；事件由一份可用 IRI 追溯的具体文件的颁布引起；两份文件同日修改同一法律须记为两个独立事件 [p.33]。
- lifecycle 对 singleVersion 与 multipleVersions 文档为必需，且须完整列到所引用的最新修改文件的颁布日期 [p.33]。
- `lifecycle/eventRef` 带 date、source、type（如 generation、amendment）；`workflow` 的步骤不一定改变 Expression，但出现新 Expression 时要记录相关步骤 [p.45-46]。
- `textualMod` 的类型：repeal、substitution、insertion、split、join、renumbering；子元素 source、destination（`@pos` 取 after、before、end、start、inside、unspecified）、old、new、previous；`@incomplete` 表示信息不足以自动执行修改，`@exclusion` 表示存在阻止自动合并（consolidation）的例外 [p.47-48]。
- passiveModifications 使用 `@period` 指向时间区间，并可存放被修改的旧文本（示例用专有元素）[p.49]。
- mappings 记录 renumbering 或非主 Expression 造成的 id 变化：`@original` 保存最初的 wId、`@current` 保存当时的 eId，`@start`/`@end` 连到时间数据 [p.53]。
- temporalData：以 `temporalGroup` 与 `timeInterval` 记录 in force 与 efficacy 两种区间，`@refersTo` 连到 references 区中的概念 [p.54]。
- judicial 区块可对判决引用作定性：supports、isAnalogTo、applies、extends、restricts、derogates、contrasts、overrules、dissentsFrom、putsInQuestion、distinguishes；restrictions 目前只定义了 jurisdiction 一种 [p.50-52]。
- references 区：original、activeRef、passiveRef、attachmentOf、hasAttachment、jurisprudence、TLC 系列引用 [p.55]。
- 元数据按定义属于编辑性添加，不是原文内容；元数据区带 `@source` 标明提供者，且日期与作者与正文分开 [p.38-39, p.56]。
- 一致性：Level 1 要求 XML 源通过 schema 校验；Level 2 另要求 eId、wId、FRBRuri、FRBRthis、href、src 的取值遵循命名规范或其功能等价规范 [p.87]。

## 5. 作者陈述的局限
- 文中未设专门的局限章节。
- 标准声明：Item（物理文件）按定义不在本标准范围内，仅简述 [p.39]。
- 标准称 `<lifecycle>` 须列全至所引最新修改的日期，但"可能存在未包含的后续修订" [p.33]。
- 标准称 omissis 状态仅供非权威发布使用；修改信息可能"不完整"（`@incomplete`）而无法自动执行 [p.33, p.47]。
- 本文为非规范性概述，约束性定义在 Part 2、schema 与 Naming Convention 文件中 [p.7, p.87]。

## 6. 原文摘录
- "EXPRESSION: any version of the WORK whose content is specified and different from others for any reason: language, versions, etc." [p.15]
- "PERMANENCE: the name must be permanent and stable over time" [p.39]
- "If two different documents affect the same act on the same date, then these must be counted as two different and separate events on the amended act." [p.33]
- "Legislative references will most probably refer to WORKs: acts referring to other acts do so regardless of the actual version" [p.40]
- "multipleVersions: this value reflects the fact that the content of the document is the juxtaposition of fragments belonging to two or more different versions of the same document" [p.33]
- "By definition, all metadata is editorial in nature, it is not content, but statements about the content" [p.38]

## 7. 对本库的可用点（笔记者推断）
- 标识与版本（identifiers & versioning）：本库现有 doc id（如 `treaty.cn-sg.2007.zh`）把作品与语言混在一个 id 里。可参照 FRBR 拆成三个分量：work id（如条约本身，语言与版本无关）、expression（语言 + 生效版本日期，仿 `zho@2020-01-01`）、manifestation/item（实际文件，对应 official/ 里的文件与哈希）。cite_id 里的 `#10.2` 属于 Work 内部的部分路径。引用默认指向 Work 层，由检索时再解析到 Expression，这与标准"法律引用其他法律与具体版本无关"一致 [p.40]。
- 标识稳定性：标准的 meaningfulness、permanence、invariance 三原则可作为 cite_id 与 doc id 的设计检查表——id 不应编码文件路径或语言，且同一资源在不同构建、不同人手里得到同一 id。
- 条款粒度（clause granularity）：标准以 eId（文档内唯一、如 `sec_2__list_1__point_2`）与 wId（跨 Expression 保持）区分"当前位置"和"最初位置"，并有 mappings 记录重编号 [p.53]。本库的 cite_id 在修订导致条款重编号时目前无法保持跨版本等同；可借鉴"稳定 wId + 版本内 eId + 映射表"。
- 关系图（relation graph）：`textualMod`（repeal/substitution/insertion/split/join/renumbering，含 source、destination、old、new）是现成的"修订事件"词表，可映射到 superseded.csv 的记录：一行记录应对应一个事件，写明来源文件（引发修改的文件）、目标条款与动作类型，并区分 `@incomplete`（无法自动应用）。两文件同日修改同一法的"记为两个事件"规则也适用于 superseded.csv。判决引用的定性词（overrules、derogates 等）可作为条约/公告之间关系边的类型参考。
- 溯源与核验（provenance & verification）：区分 in force（`@start`/`@end`）与 efficacy（`@startEfficacy`/`@endEfficacy`）两种时间，对应税法中"生效日"与"适用于哪些纳税期间"的差别；本库参数的 effective_from/effective_to 目前只有一对，可能需要拆成两对。元数据按定义是编辑性添加并标注 `@source`，对应本库应区分"官方原文"与"建库者补充的元数据"。
- 规模与维护（scale & maintenance）：Level 1/Level 2 合规分级和由网络服务按需生成定制 sub-schema 的做法 [p.85]提示本库可分阶段达标（先结构与基本元数据，再规范引用，再高级元数据），而不要求一次到位。
- 与"只保留现行法"规则的张力：标准的 multipleVersions 与 passiveModifications 就是为了在同一文档内保留过往版本及旧文本；本库用户规则是废止文本删除，仅在 removed.csv 留一行。可兼容的最小做法是保留事件元数据（id、废止日期、由谁废止、替代者），不保留正文；是否也保留旧参数值须由用户决定，标准本身不替本库作此决定。
- 检索与排序、评测、LLM 边界：标准不涉及这三层，无直接可用点。
- 不适用：标准面向议会、立法全生命周期及 XML 标记（约 310 个元素），本库是 SQLite 加切片的轻量结构，没有必要采用 XML 或整套本体；标准的 URI 方案是 `/akn/国家/类型/日期/编号`，对中文公告、条约、税务机关指引页的适配需自行定义。
