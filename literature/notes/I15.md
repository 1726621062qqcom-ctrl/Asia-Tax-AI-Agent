# I15 Sannier, Adedjouma, Sabetzadeh & Briand, 2017. An Automated Framework for Detection and Resolution of Cross References in Legal Texts. Requirements Engineering
版本：author；I15_Sannier2017_CrossReferences_author.pdf；全文读至第 21 页（第 22 页起为参考文献，略过）

## 1. 问题与作者主张
- 作者称分析合规需求时，分析人员需要沿交叉引用（cross reference）查阅被引条文；这要求自动检测引用表达式、在上下文中解释它、并链接到目标条文 [p.1]。
- 作者称现有门户（LegiLux、LegiFrance 等）的链接只到 article 或整部法律层级，到 paragraph、clause 的细粒度链接少见，人工建链代价高 [p.2]。
- 作者称已有工作的不足：最佳实践手册（Bluebook、ALWD）对旧文本的检测不够；多数工作未区分 detection 与更复杂的 resolution；歧义情形未充分处理 [p.2]。
- 作者主张：用文本结构 schema + 一组自然语言引用模式，可同时做检测与解析；schema 按法域定制 [p.1, p.21]。

## 2. 方法
- 四步流程：Step 1 人工定义 schema；Step 2 由 schema 自动生成正则把非标记文本转为结构化标记文本；Step 3 检测并解析引用；Step 4 用于可视化与分析 [p.6]。
- Schema：UML 类图，类为结构单元（Act、Chapter、Part、Section、Subsection、Clause、Paragraph 等），聚合关联表示包含，带多重性约束；每个单元有 Header（起始/前置/后置/结束分隔符、概念标记、标题、编号格式）[p.6-7]。
- 结构标记（Algorithm 1）：schema 视为 DAG，取拓扑序；为每个类生成 HeadRegEx 与 SegmentRegEx；一个段落止于同级或更高级的下一个标题或文档结束 [p.7-8]。
- 检测：用 GATE 的 Tokenizer、Sentence Splitter、Named Entity Recognizer 加 gazetteer（法律名称、implicit 词等），JAPE 规则匹配；采用 appelt 控制（只触发最长匹配）[p.5-6]。
- 解析：先预处理（序数、罗马数字、文字数字转阿拉伯数字；缩写如 art. 展开为 article）[p.10]。
- 工具：LeCA，约 114 个 JAPE 脚本、约 13K 行 JAPE，另约 5K 行 Java [p.16]。

## 3. 数据与设置
- 模式来源：Luxembourg Income Tax Law（约 2013，法语）1223 个 CRE 的 Grounded Theory 研究；之后研究 PHIPA（Ontario）英文版 1197 个、法文版 1192 个 CRE，未产生新模式；共 3612 个表达式 [p.2, p.8]。
- RQ1（检测）：卢森堡 13 部法律共 1640 页，每部随机抽 10% 页，共 164 页；手工标出 1852 个 CRE [p.16]。
- RQ2（解析）：7 个文本（T1–T5 卢森堡法律，T6 PHIPA 英文，T7 PHIPA 法文），共 4474 个 CRE，其中 internal 2595 个，含 71 个 unspecific；评测 2524 个 [p.17-18]。T5、T6、T7 曾用于推导模式 [p.17]。
- RQ3（可扩展性）：笔记本 2.3 GHz Intel CPU、8GB 内存 [p.18]。
- 金标：前两位作者独立人工标注后交叉核对 [p.19]。

## 4. 结果
- 引用分类 [p.4-5]：
  - internal（引用同一法律内）与 external（引用其他法律）；
  - explicit（用文本的字母数字标签）、implicit（形容词、副词、指代词，如 “this section”、“the following paragraphs”）、delegating（仅限 external，不点名文本，如 “Grand-Ducal regulation”）；
  - unspecific：implicit 中使用 “provision” 之类模糊词，无法对应到具体结构单元；作者称 delegating 与 unspecific 之外的引用原则上可自动解析。
- 模式语法（Fig. 10，BNF）[p.8-9]：
  - simple：explicit（internal / external）与 implicit。internal = marker-term + num-expr，或 ordinal + marker-term，或 generic-term（如 “sub”、“under”）+ num-expr；num-expr 可为数字、字母、字母数字（如 “2bis”）。
  - external = name-term，或 category-term + link-term + DATE，或 adj-term + category-term + link-term + DATE，或 internal-expr + auxiliary-term + external-expr，或 delegating-expr。
  - implicit 词表含 “above”、“below”、“preceding”、“following”、“next”、“previous”、“this”、“same” 等。
  - complex：multivalued（枚举、范围、两者组合，如 “articles 119 to 121 and 124”）与 multilayered（沿层级导航，可自上而下、自下而上或混合，如 “article 3, paragraph 2 of the Law of 8 June 1999”）。
  - 以 “Term” 结尾的非终结符（marker-term、name-term 等）为 gazetteer 词表，随法域与语言而异，须针对具体情境提供 [p.9]。
- 解析规则 [p.10-12]：
  - 单一 implicit：current → 含该 CRE 的同类段；previous/next → 之前/之后的同类段；same/that → 之前最近的同类 CRE（作者称这是 best-guess 启发式）。
  - generic term（如 sub）按法域惯例：卢森堡法中后接字母则为 Letter，否则为 Number。
  - multivalued：每个枚举项补上结构标记；范围区分全文唯一编号的单元（如 Article）与随上级重置编号的单元（如 Paragraph），后者先在最内层段内解析，失败则逐级上溯到父级、祖父级；范围元素不能只靠整数枚举，因字母数字编号（如 99ter）。
  - multilayered：先统一成严格自上而下的形式；只给最深层标记的（如 “subclause 21 (1) (e) (iii)”）补全中间层标记；含范围/枚举的歧义片段，先在最深已用上下文中尝试，失败则上升一层。
  - 例外 CRE（如 “with the exception of”）在被例外的主 CRE 的上下文而非所在条文中解释；修订 CRE（“is added”、“is modified”、“a new”、“is repealed”）总是 external，须在被修订文本的上下文中解析。
  - external 仅点名的引用通过“名称、日期 → 资源定位符”的映射解析；external 引用内部条文需要被引文本也已有标记 [p.10]。
  - 链接：目标为 XML 用 xlink，HTML 用 href [p.12]。
- 无法解析的原因分三类：解释出错（如修订 CRE 被误当 internal）、措辞不规范（如 “Number 3e” 把两级编号合并）、目标不存在（如首个 alinea 中的 “previous alinea”；跳过层级；被引条文已废止并删除）[p.12-13]。
- 应用 [p.13-15]：HTML 超链接视图与树视图；高级检索（“Article 24” 在法中被四处范围引用，如 “Articles 4 to 155bis”，字符串查找为空）；用 RML/CrocoPat 在带类型图（节点为结构单元，边为 Containment 与 Citation）上做 trace link 分析与 transitive closure；循环引用分析（PHIPA 中长度为 2 的循环，作者称均属“来源条文说明细节见被引条文，被引条文回引以提示上下文”的模式）。
- RQ1 检测，Table 1（1852 个 CRE）[p.16-17]：
  - Internal 857：正确 848、部分 8、漏 1；External 995：正确 965、部分 30、漏 0；Explicit 1389：1350 / 38 / 1；Implicit 463：463 / 0 / 0；Simple 1031：1029 / 1 / 1；Complex 821：784 / 37 / 0（Multivalued 373：372 / 1 / 0；Multilayered 448：412 / 36 / 0）。
  - 漏掉 1 个：“au (1)”（法语介词 + 数字）；作者未加该模式，因法语中该写法常非引用。部分识别 38 个（约 2%），主要为 external 或 multilayered internal，原因是法律名称/auxiliary 词表不全、结构标记词表不全（出现了最佳实践未列的标记）。另有 5 个误报。
  - 不补全词表：precision 99.7%、recall 97.9%、F-measure 98.8%；补全词表后：99.7%、100%、99.8%。未出现新模式。
- RQ2 解析，Table 3 [p.18]（precision / recall / F）：
  - T1 100% / 100% / 100%；T2 100% / 100% / 100%；T3 100% / 100% / 100%；T4 98.98% / 100% / 99.49%；T5 99.94% / 100% / 99.97%；T6（PHIPA 英）99.87% / 98.95% / 99.41%；T7（PHIPA 法）99.87% / 98.94% / 99.40%。
  - 误解释（misinterpreted）每文本最多 3 个；T4、T5 的误解释为 external 被当成 internal（只影响 precision），T5 的例子是 “paragraph 11bis”；T6/T7 共有的一个：标题 “Conflict between persons in same paragraph” 中的 “same paragraph” 应解析为 26.(1) 的 8 个 paragraph，算法失败，计为 8 个 false negative。
  - 作者将 anomalous（措辞不规范、目标不存在）计为 true positive。作者称生成的链接与警告完整覆盖了尝试解析的 internal CRE；未遇到链到错误条文的情形，但承认可能发生。
  - unspecific CRE 占比平均 3.4%，最高 T3 12.5%、T5 5.1%；评测排除它们，也不评 external CRE 的解析（需要被引文本的 schema）。
- RQ3 [p.18]：检测约 34 秒（164 页，1852 个 CRE）；T5（1223 个 CRE）检测约 15 秒、解释约 151 秒、生成链接约 139 秒；Table 4 总时间 T1 25 秒、T2 25 秒、T3 3 秒、T4 79 秒、T5 305 秒、T6 90 秒、T7 90 秒；生成链接数与时间近似线性。
- 与相关工作比较：Tran 等以机器学习处理日文法律，报告检测 F 约 80%、检测加解析 67% [p.20]。

## 5. 作者陈述的局限
- 规则方法无法保证规则完备，总有例外；文本可能偏离预定 schema，使指向不一致部分的引用无法解析 [p.18]。
- 修订 CRE 指向尚未并入被修订文本的条文，在修订生效前无法解析 [p.18-19]。
- 未做用户研究（分析人员是否更容易、质量是否更好）；未评成本效益，包括为每个法域定制 schema 的投入 [p.19]。
- 外部效度：模式完备性需更广研究；解析准确率能否迁移到其他法域取决于新 schema 的开发，作者认为分析少量有代表性的文本后会趋于饱和 [p.19]。
- 评测中 external CRE 的解析和 unspecific CRE 都未覆盖 [p.17]；delegating 与 unspecific 类引用不能自动解析 [p.5]。

## 7. 对本库的可用点（笔记者推断）
- 关系图（引用解析）：论文的“检测”（模式）与“解析”（结合结构）两阶段分离，可直接作为本库 `ref` 抽取的流水线：先用中英文模式表抽出 CRE，再按 (当前条文、所属法律、层级) 解析为 cite_id 集合；解析失败进入显式 pending 清单，而非猜测（层：relation graph、provenance）。
- 引用模式：论文的 internal/external、explicit/implicit/delegating、simple/multivalued/multilayered 分类与本库观察到的写法（“第X条”“本法第X条”“《条例名》第X条”，英文 “section 15(1)(a)”“paragraph 3 of Article 12”）基本对应。范围与枚举展开（“第三条至第五条”“sections 11, 12 and 15”）、“前款”“本条”“the same section” 这类相对引用需要专门规则；范围展开必须依据 schema 的实际编号（如 99ter），不能只数整数（层：relation graph）。
- 标识符与粒度：论文强调法律文本在条文细分层缺少唯一标识，要从结构派生（如 Section 43(1)(a)）。这支持本库 cite_id 的“层级路径”设计，并为每种法域/语言建独立的结构 schema（层级名、编号格式、是否随上级重置）。论文指出同名层级在不同法域不对应（French paragraphe 对 English subsection），意味着中英文 zh↔en 对齐应按结构位置而非术语直译（层：identifiers、clause granularity、zh↔en alignment）。
- 解析上下文：解析需要“所在位置 + 父级回退”。可映射到 cite_id 前缀：先在同条款内、再上溯到条、章。对“修订类”条文（“增加”“修改”“废止”），其引用指向被修订文本，不属于本库“只保留现行有效法”范围内的 internal 引用，应单独标记（层：relation graph、versioning）。
- 评测：论文的做法可直接复制——人工（本库为已溯源引用）建金标，分别报 detection 与 resolution 的 precision / recall，按 internal/external、simple/complex 分组，并单独列出“无法解析”的原因。本库还可把解析器对已核验参数引用的复现率作为验收（层：evaluation）。
- 检索：论文 8.3 的例子（“Article 24” 被 “Articles 14 to 108bis” 范围引用，字符串检索找不到）说明纯 substring 不够；范围展开后的 `cited_by` 反向边可让“谁引用了本条”查询完整，这是对 exact/BM25 的补充而非替代（层：retrieval & ranking）。
- LLM 边界：论文的检测与解析全是确定性规则（GATE/JAPE），无学习组件，符合本库“计算层无 LLM”约束；论文报告的 Tran 等机器学习方法数字更低，但这只是单一对比，不能据此推断一般性（层：LLM boundary）。
- 规模与维护：词表（法律名称、标记词、auxiliary 词）按法域/语言维护，RQ1 的错误主要来自词表不全，所以每新增法域/语言需要做词表审计，并把“无法解析”清单作为回归测试（层：scale & maintenance）。论文的循环引用分析和 transitive closure（trace link）可用于检查本库引用图完整性与影响分析（层：relation graph）。
- 不适用或冲突：论文只评测 internal 引用，external 解析未评测；而本库税务法规大量引用“条例”“税务总局公告”“协定第X条”，因此 external 解析（法律名称 → 文档 id 映射）才是本库的难点，论文只给出方案描述（名称/日期映射）而无数据。论文语言为法语与英语，无中文、无 HK/SG 英文条文的结果；中文“第X条之一”“第X款第（一）项”等编号体系须自行建 schema 并自行评测。论文文本为单版本，没有版本问题（层：versioning 未覆盖）。
