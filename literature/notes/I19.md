# I19 de Martim, 2025. An Ontology-Driven Graph RAG for Legal Norms: A Structural, Temporal, and Deterministic Approach (SAT-Graph RAG). FAIA (IOS Press) 2025 / arXiv 2505.00039
版本：preprint（arXiv v5，2025-09-11，文件为预印本）；I19_deMartim2025_SATGraphRAG_preprint.pdf；全文读至第 21 页（第 1–21 页，参考文献略过）

## 1. 问题与作者主张
- 作者称标准的平铺文本检索对法律的层级、历时与因果结构"视而不见"，会导致不合时宜（anachronistic）且不可靠的回答 [p.1]。
- 作者称"时间天真"（temporally-naïve）的系统无法确定性地检索某一历史日期有效的法律版本 [p.1]。
- 作者提出 SAT-Graph RAG：以 LRMoo 启发的本体建图，区分抽象的 Work 与带版本的 Expression，把时间状态建为对未变组件版本的聚合（aggregation），把立法事件建为一等 Action 节点 [p.1]。
- 作者主张该骨架支持三类确定性查询：时点检索、层级影响分析、可审计的溯源重建，并用巴西宪法案例展示 [p.1]。
- 作者指出现有工作的三处缺口：多数法律 RAG 把文档当平铺文本块；时序知识图谱（TKG）工作很少把规范演化与 RAG 及溯源结合；缺少兼具时间与层级要求的基准 [p.3]。

## 2. 方法
- 四类节点（基于 IFLA LRMoo）：Norm（Work）、Component（Component Work，如编、章、条）、Temporal Version（TV/CTV，语言无关的时点快照，对应 F2 Expression）、Language Version（LV/CLV，某语言的具体文本）[p.4-5]。
- 作者说明选 LRMoo 而非 Akoma Ntoso 的理由：后者把 Work/Expression/Manifestation 主要表示为文档 `<meta>` 块内的标识符，本文把它们提升为本体中的一等实体，使版本链可在图中显式遍历 [p.4]。
- 构建：先做结构感知的语义分割（解析器或微调 LLM，最好再人工复核），建 Norm 与 Component 节点形成层级骨架；文本块（Text Unit）只挂在 Language Version 上 [p.5-6]。
- 多语言：加入英文译本只需新建 LV/CLV 节点并挂到已有 CTV，Work 与 TV 节点不变 [p.6-7]。
- 聚合而非组合：某组件被修订时为其新建 CTV，并为各级祖先建新 CTV，新父 CTV 聚合各子组件"最新可用"的 CTV——被修订的子取新 CTV，未变的子复用旧 CTV；作者称这避免冗余且能明确哪些组件真被改动 [p.7-8]。
- Action 节点：每个细粒度变更一个 Action，连接 1) 下达变更的来源条文、2) 被终止的 CTV、3) 新建的 CTV；原始颁布（enactment）没有可终止的前一版本 [p.9]。每个 Action 还生成一个自然语言描述的 Text Unit 以便检索 [p.9]。
- 元数据文本化：Norm、Component、TV 的结构化属性与"信息性关系"（如两部法律的继承关系）都转为 Metadata Text Unit，各有向量，形成 multi-aspect embeddings [p.10]。
- 受控社区：用文档内部层级（编、章）与外部主题分类（Theme 节点）限定检索范围，在子图内做向量检索 [p.10-11]。
- 统一执行策略（planner 引导）：规范化结构/时间/文本约束 → 按声明的归属策略解析范围 → 选策略（structure-first / span-first / time-first）→ 按声明的时间策略确定性选 CTV → 范围内检索 Text Unit → 必要时聚合 Action → 组装 Action 的 DAG → 事实扎根生成并披露策略与 JSON 溯源附件 [p.18]。
- 时点选择条件：tv.valid_start ≤ t < coalesce(tv.valid_end, +∞)；区间内有多个 CTV 时用时间解析策略（默认 SnapshotLast），策略随答案披露 [p.15]。
- 层级影响分析的范围归属策略：默认 snapshot-anchored（时间窗口开始时属于该章的组件），可选 action-time、lifetime [p.16]。

## 3. 数据与设置
- 案例研究数据：巴西联邦宪法（1988）及截至 2024 年初的全部宪法修正案；作者称宪法自颁布以来有一百多项修正 [p.11-12]。
- 概念性实现（用"could"表述，并非已完成的系统）：关系型向量数据库（如 Oracle Database 23ai），实体存为表，Text Unit 表带向量列；嵌入模型举例 Qwen3 Embedding；生成模块举例 Gemini 1.5 Flash；作者称框架与工具无关 [p.12]。
- 基线：把"标准 RAG"定义为在宪法现行版本的平铺文本块索引上做检索、没有任何历时结构的系统 [p.14]。
- 评测：定性对比，选三个查询模式（时点检索、层级影响分析、溯源重建）；无定量实验 [p.11, p.14-17]。
- 作者建议的运行默认值：Qwen-3 256 维、余弦相似度、k = 8、默认时间策略 SnapshotLast [p.18]。

## 4. 结果（定性）
- 模式 1（"1999 年第 6 条列出的社会权利"）：作者称基线 RAG 会检索现行文本，产生含后来才加入的"住房（a moradia）""食物（a alimentação）"的不合时宜答案；SAT-Graph RAG 经 LLM 规划器解析出组件 id 与时间区间后，沿图遍历选出有效 CTV，答案不含这些词 [p.14-15]。
- 作者称规划器若查询无明确时间约束则默认当前系统日期 t = now() [p.14]。
- 模式 2（"2010 年之后第二章的文本修改汇总"）：作者称平铺 RAG 因没有层级表示而"根本无法"可靠回答，SAT-Graph RAG 可经范围识别、后代组件检索、Action 聚合、层级摘要完成；给出的输出为示意（illustrative），如 Art. 6 caput 的 CA 64/2010 加入 "food"、CA 90/2015 加入 "transportation"，以及章级影响日期 {2010-02-04, 2013-04-02, 2015-09-15} [p.15-16]。
- 模式 3（"追溯第 6 条中 'food' 一词的立法谱系"）：作者称平铺 RAG "不适合"；SAT-Graph RAG 先按结构定位，再在范围内的版本历史中找文本片段、找到创建该 CTV 的 Action、反向装配 Action 链，输出溯源报告（含 Pre-State、Causal Event、Post-State、Audit Trail）[p.16-17]。
- 示例 Action（CA 26，2000-02-14）：终止第 6 条 caput 1988-10-05 的 CTV，并生成 2000-02-14 的新 CTV [p.9, p.13]。
- 本文无定量结果；作者建议未来用的指标（Temporal Precision、Temporal Recall、Action-Attribution Accuracy（F1）、Summary Completeness、Causal-Chain Completeness）尚未实施 [p.19-20]。

## 5. 作者陈述的局限
- 全国规模应用需要大量工程与治理；策略是自动化入库加人工复核、预计算索引、物化常用时点快照、增量处理新立法 [p.19]。
- 对上游数据质量依赖：错误的有效期区间或错误的 Action 元数据会导致系统性错误检索；缓解办法包括多来源互证、为输出附置信度、校验与回滚流程 [p.19]。
- 本体最适合层级与修正动作明确的成文法；判例法需转向引文图与先例演变，合同和法规的结构异质性可能需要定制分割规则 [p.19]。
- 要严格验证确定性与准确性的主张，需要专门基准，这是当前的明显缺口；用户研究亦必要 [p.19-20]。
- 系统被设计为产生可核验的辅助输出，而非确定性的法律意见；需保持策略透明，并保留不可变的审计日志 [p.20]。

## 6. 原文摘录
- "A system that is 'temporally-naïve' cannot deterministically retrieve the version of a law that was valid on a specific historical date" [p.1]
- "A new parent CTV on date Dn is formed by aggregating the most recent available CTVs of each of its children." [p.8]
- "we introduce an Action node for each granular change" [p.9]
- "Fundamentally, all answers generated by the system should explicitly state the temporal and membership policies used for that specific query" [p.18]
- "Erroneous validity intervals or incorrect Action metadata will lead to systematically flawed retrievals." [p.19]
- "A rigorous quantitative validation of our framework's claims of determinism and accuracy requires a dedicated benchmark, which is currently a notable gap in the legal AI community." [p.19]

## 7. 对本库的可用点（笔记者推断）
- 标识与版本（identifiers & versioning）：Work / Temporal Version / Language Version 三分与本库的问题直接对应——现有 doc id 把"作品 + 语言"混在一起，且 superseded/removed 机制没有"同一条款的多个时点版本"的位置。可仿此拆为：作品 id（语言与时间无关）、版本 id（含 valid_start/valid_end）、语言版本（文本）。加入新语言只增语言节点、不动作品与版本节点，可解决"多语言扩展导致 id 与切片重复"的问题（论文 p.6-7 的论证）。
- 条款粒度（clause granularity）：聚合模型（未变的子条款复用旧版本，只给被改动者新建版本）可避免每次修订复制整个文档的所有切片；对 ~7,900 个切片的库，当单部法律多次修订时，这比整文档快照省空间，且能直接回答"哪些条款在这次修订中真被改动"。但引用块仍属于"新建版本"的范围，需明确定义"未变"的判定（逐字相同）。
- 关系图（relation graph）：Action 节点（来源条文 → 被终止版本 → 新版本）与 superseded.csv 的结构接近：superseded.csv 只列"哪些条款被取代"，可补上"由哪条下达""何时生效""产生了哪个新版本"三个字段，使关系成为可遍历的边而不是并列的文字说明。论文把"继承（succession）"这种终止整部作品的关系与"修订"区分开，本库的 removed.csv（整文档废止）与 superseded.csv（部分废止）已有同样的区分，可将其显式类型化。
- 检索与排序（retrieval & ranking）：先按结构范围与有效期做确定性过滤，再在剩余子集上做向量或词面排序（论文的 structure-first / span-first 选择）。本库已有"(scope, income, topic) 格 + 子串查找"，可把有效期过滤放在最前，而不是事后检查。
- 评测（evaluation of retrieval）：论文提出的 Temporal Precision / Temporal Recall（返回的版本是否在目标日期有效）是可以直接机械计算的指标；但论文自身没有做实验，数字只是设想，不能引为证据。
- 溯源与核验（provenance & verification）：论文要求每个答案披露所用的时间策略与归属策略，并附机器可读的 JSON 溯源附件；对本库可对应为：每次检索或计算结果附 `as_of` 日期、所用版本 id 与策略名。
- LLM 边界（LLM boundary）：论文让 LLM 做查询规划（把自然语言转为结构化约束）和最后的生成，版本选择则是图遍历。这与本库"计算中无 LLM"的约束可兼容的前提是：规划器的输出（组件 id、日期）要经确定性校验（id 是否存在、日期是否合法）后才使用。
- 与硬约束的冲突：(1) 论文的 Action 与 metadata 的 Text Unit 是对事件的"自然语言摘要"，这类生成文本不是官方原文，若进入检索索引必须标成非权威、不得作为引用依据，否则违反"每条规则可溯源到逐字官方文本"。(2) 规划器在查询缺少时间约束时默认 t = now()；本库要求缺失信息为显式 pending，不应静默补当前日期。(3) 论文保留全部历史版本以支持任意历史时点查询，而本库的用户规则是废止文本删除、只留 removed.csv 一行——两者直接冲突，需要明确本库是否需要回答"过去某日的规则"（如往年申报）；若需要，则与该规则存在张力，应上报用户而非自行取舍。
- 规模与维护（scale & maintenance）：物化常用时点快照、增量处理新立法、人工复核与回滚流程、不可变审计日志，都是论文列出的维护措施；其中"上游有效期区间错误会被确定性检索放大"一点对本库的 effective_from/to 校验有提醒意义。
- 不适用：论文是单一法域（巴西宪法）的概念性设计，无定量评测，也无对中文、条约、行政公告、数值参数的处理；Oracle 23ai、Qwen3、Gemini 等组件只是举例。
