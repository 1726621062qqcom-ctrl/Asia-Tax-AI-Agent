# J5 Bjørner, Phan, Fleckenstein, 2015. νZ – An Optimizing SMT Solver. TACAS 2015（LNCS 9035, pp. 194–199）
版本：published；J5_Bjorner2015_nuZ.pdf；全文 p.1–6 全读（工具论文，共 6 页，p.6 含参考文献）

## 1. 问题与作者主张
- νZ 是 SMT 求解器 Z3 的一部分，让用户提出并求解 modulo theories 的优化问题；用户不必自己在求解器外写循环去找最优值 [p.1]。
- 作者称 νZ 提供一组方法（portfolio）来解线性优化、MaxSMT 及其组合；多个目标可按 Pareto front、lexicographic 或各自独立优化来组合 [p.1]。
- 作者称其集成了最优化的前沿算法并加了自己的改进：直接支持 difference logic 求解器，用非标准数上的 Simplex 发现无界约束，对 MaxSAT 采用 MaxRes 的增量版本 [p.1]。
- 作者称在 Microsoft Dynamics AX 的仓库管理场景中，约束可写成 0-1 变量上线性约束的布尔组合，目标可写成几个代价函数的 lexicographic 组合；此类代价函数预期会随用户经验演变，模型的抽象层提供这种灵活性 [p.5]。

## 2. 方法
- 目标命令：SMT-LIB 中加入 maximize t、minimize t（t 的类型为 Integer、Real 或 Bit-vector）和 assert-soft F，可带整数权重 :weight n 或小数权重 :dweight d，默认权重 1，可加 :id 名以区分多个软目标 [p.2]。
- 多目标组合 [p.2]：
  - Lexicographic（默认）：找模型 M 使 ⟨M(t1), M(t2)⟩ 在字典序上最大，即不存在 M′ 使 M′(t1) > M(t1) 或 M′(t1) = M(t1) 且 M′(t2) > M(t2)。
  - Pareto：给出一组互不被支配的模型，用 Guided Improvement Algorithm 产生。
  - Box：各目标独立求最优，最多需要两个模型 M1、M2，分别取得 t1、t2 的最大值（Symba 工具使用）。
- 编程接口：Z3 的 C、C++、Java、.NET、Python API，另有接入 Microsoft Solver Foundation（MSF）的库 [p.3]。Python 例子用 opt.set(priority='pareto')，在 x+y==10、x>=0、y>=0 下对 x、y 各 maximize，产生全部 11 个 Pareto front [p.3]。
- 架构 [p.4]：输入公式与目标先经自定义策略改写，检测 0-1 整数变量并改写为 Pseudo-Boolean Optimization（PBO）约束；0-1 变量上的目标改写为 MaxSAT。多目标时 νZ 调度 SMT 或 SAT 内核；实数上的 box 约束把所有线性算术目标合并，调用一个 OptSMT 引擎实例；soft constraints 的 lexicographic 组合则多次调用 MaxSAT 引擎。
- OptSMT [p.4]：在 Z3 的 dual Simplex 内核上增加 primal 阶段，求实数的最大赋值，并在改进为整数时改进整数变量的界；通过检查 t ≥ ∞ 在扩域 R∪{ϵ, ∞:=1/ϵ} 上是否可行来发现无界目标，与 [9] 中沿超平面搜索的做法不同。另有 Pseudo-Boolean 理论求解器，可用 dual simplex 剪枝。
- MaxSMT [p.4–5]：实现多个 MaxSAT 引擎：WMax、MaxRes、BCD2、MaxHS。WMax 用代价理论求解器，在 SAT 求解器赋值下累计被跟踪变量为 false 的罚分，代价超过当前最优值时产生冲突子句，可在任意时刻中断并给出当前上界。MaxRes 在软约束出现 unsatisfiable core 时抬高下界，并把 core F1…Fk 替换为 k−1 个新软约束；作者称其实现通常明显优于 WMax。
- SAT 层 [p.5]：Pseudo-Boolean 公式经 sorting circuit、简单 PB 不等式的 Shannon 分解（BDD）以及位向量约束转为命题 SAT。

- Table 1 [p.5]：MaxSAT 2014 wpms industrial 解出 361/410，时间 0.5–1800s；pms industrial 解出 406/568，0.5–1800s；Longest Paths bb 8/8，<0.05s；chat 34/34，1–36s；DAL Allocation challenge（PBO）SampleA&B 96/96，0.02–6s；Symba（LRA）2435/2435，0.2s–36s；OptiMathSAT（LRA）9 个非随机例，0.5–20s。
- 作者称 Vampire 的策略调度问题（MaxSAT）在新 MaxSAT 引擎下容易，而 Vampire 原先用的二分搜索较难；Kaliszyk 调优 portfolio 求解器的线性算术约束系统明显更难（运行数天），WMax 在搜索中提供部分解 [p.6]。
- Longest Paths 的 p2p 类（约 30K clauses）超时 [p.6]。

## 5. 作者陈述的局限
- 文中未设局限专节。作者提到 p2p 类基准超时 [p.6]，并说期望新应用能推动非线性算术、混合符号/数值算法、与 Horn clauses 结合方面的进展，即这些方向当前未覆盖 [p.3]。
- 作者说明 MSF 使用的 OML 模型中，灵活的布尔组合是"事后补充"，这是推动 νZ 的缺口 [p.3]。
- 最优性如何证明、各引擎的完备性条件，文中未专门讨论（细节指向伴随论文 [3]，未在本文中展开）[p.3]。

## 6. 原文摘录
- "νZ provides a portfolio of approaches for solving linear optimization problems over SMT formulas, MaxSMT, and their combinations." [p.1]
- "Objective functions are combined as either Pareto fronts, lexicographically, or each objective is optimized independently." [p.1]
- "By default, νZ maximizes objectives t1, t2 subject to the constraint F using a lexicographic combination." [p.2]

## 7. 对本库的可用点（笔记者推断）
- 目标形式（层：objective / ranking）：本库的区间 [floor, ceiling] 与 lexicographic 排序 (floor, ceiling, 判断项数, …) 可对应 νZ 的 lexicographic 组合；若要保留"floor 与 ceiling 都不被劣于"的支配关系，对应的是 Pareto 组合，而非 box。box 只给各目标独立最优，不能回答"某一结构同时在两端都好"，因此不适合直接做支配标记。
- (a) 模板之外的结构：νZ 的输入是约束加目标，结构选择可写成布尔/整数决策变量（角色放哪、股/债、时点、退出路径），搜索空间不再被模板限定，只受规则约束限定。但这要求把条款规则编码成 SMT 公式，与现有"编译后的三值规则"之间需要一个翻译层；论文没有讨论税务类规则的编码，也没有评估规模，代价未知。
- (b)(d) 按流决策与联合效应：assert-soft 加权的 MaxSMT 把"每个待定项取哪端"变为对总目标的联合优化，天然不是逐项翻转；税额若为线性或分段线性可用 maximize/minimize 直接对总税额。但抵免、CFC 计入、Pillar Two 补税的非线性/条件结构需先线性化；论文只涵盖线性算术（及 Bit-vector 等）目标，非线性算术被作者列为待发展 [p.3]，此处不适用或需自行分段。
- (c) 固定求值顺序：论文不涉及不动点语义；SMT 把规则作为同时成立的约束，隐含了联立求解，但循环依赖的规则编码是否合法，论文未讨论。
- (e) floor 排序：区间的 floor 与 ceiling 可作为两个 minimize 目标；对 pending 项取有利端与不利端分别对应对待定变量的 minimize 与 maximize，可在同一公式下各求一次（box 的做法，最多两个模型 [p.2]）。这样 floor 与 ceiling 来自可检验的模型，而不是逐项翻转。
- 最优性保证：论文说明 WMax 可给当前上界、MaxRes 通过 unsatisfiable core 抬高下界 [p.5]，即上下界同时收敛；对本库的含义是可得到"已证明的最小税额"或带界的近似值，但论文未给出形式化的正确性证明，只引用伴随论文。
- 性能：Table 1 的数据来自 MaxSAT 竞赛类基准与线性算术基准，规模与本库无可比性；p2p 类超时说明大规模不保证可解。对本库的 pending 项通常个位数到十几项的规模，这类求解器的实际耗时需自测，论文无法作为依据。
- 不适用：νZ 是外部求解器，引入它与"程序确定性、可逐条追溯"的约束需兼容——模型输出可复核，但求解过程（启发式、portfolio）不是人工可读的推理链；且论文不提供"自检最优"的方法。
