# M13 Stanisławek, Graliński, Wróblewska, Lipiński, Kaliska, Rosalska, Topolski, Biecek, 2021. Kleister: Key Information Extraction Datasets Involving Long Documents with Complex Layouts. ICDAR 2021（arXiv:2105.05796v1）
版本：preprint；M13_Stanislawek2021_Kleister_preprint.pdf；第 1–14 页全读（数据集构建、统计、流水线、实验、结论），参考文献略过

## 1. 问题与作者主张
- 关键信息抽取（KIE）面向真实业务文档：长、多页、版面复杂、扫描件 OCR、需归一化；公开数据集与业务需求之间差距很大 [p.1-2]。
- 作者发布两个数据集：Kleister NDA（540 份保密协议，3,229 页，2,160 个实体）与 Kleister Charity（2,788 份慈善机构年度财务报告，61,643 页，21,612 个实体）[p.1]。
- 作者称 KIE 与 NER 不同：不要求取出片段，而是取出具体可用的数据点；文档级标注，输出须归一化 [p.4, p.9]。
- 最好的基线（LAMBERT）F1 为 81.77（NDA）与 83.57（Charity），远低于 SROIE 等相近任务（98.17），显示现有模型的弱点 [p.1, p.14]。

## 2. 方法
- 流水线：自动标注（用正则加文档级标准值把片段标出来，只用于训练）→ NER（Flair、BERT、RoBERTa、LayoutLM、LAMBERT）→ 归一化（日期统一为 ISO 8601）→ 聚合（候选按归一化后的形式分组，组内分数求和，取最大者）[p.10]。
- 文档按 300 词或 510 个 BPE token 重叠切块，重叠部分分数平均 [p.10-11]。
- 比较四种 PDF 文本提取工具：Azure CV、pdf2djvu（仅原生 PDF）、Tesseract、Textract [p.11]。

## 3. 数据与设置
- NDA 实体：party、jurisdiction、effective_date、term；Charity 实体：post_town、postcode、street_line、charity_name、charity_number、report_date、income、spending [p.7]。
- NDA 标注 κ=0.971；Charity 开发 / 测试集双人标注，κ=0.9 [p.5, p.7]。
- Charity 的标准值直接取自慈善委员会网站，只抽网站上也有的实体；抽检 100 份：机构名 5% 错误、13% 轻微差异，地址 9% 错误、63% 轻微差异 [p.6-7]。
- term 实体只在 36% 的文档出现；party 一份文档最多 7 个标准值 [p.8]。

## 4. 结果
- 表 3（NDA，pdf2djvu）：LAMBERT 总 F1 81.77；effective_date 85.27、party 78.70、jurisdiction 96.50、term 55.03（Flair 60.33）；自动标注器 60.09；人工 97.86% [p.12]。
- 表 3（Charity，Azure CV）：LAMBERT 83.57；income 74.70、spending 74.20、charity_number 95.80、report_date 96.80；人工 97.45% [p.12]。
- LAMBERT 对表格类实体（income +4.03、spending +5.60）提升最大 [p.11]。
- 归一化问题：income、spending 约 5% 的例子需要按文档语境推断数量级（千、百万）[p.12]。
- 文档越长所有模型越差（图 6）[p.12]。
- OCR：扫描件上商业引擎明显优于 Tesseract；原生 PDF 用专用工具（pdf2djvu）优于 OCR [p.13]。
- 作者指出 term 一般在文档中部的 Term 章，有时文末又出现一次，任务是判断哪个值对 [p.9]。

## 5. 作者陈述的局限
- 基线远低于相近域数据集，显示现有 SoTA 的弱点 [p.14]。
- 自动标注基于正则，对机构名缩写、简称无能为力（party 自动标注 33.15）[p.12]。
- 其余未专门讨论。

## 6. 原文摘录
- "Some entities such as, say, a list of trustees might not be in the reports. Thus, we decided to extract only those entities which also appear in the form of a brief description on the website." [p.6]
- "Since entities could appear in documents multiple times in different contexts, we must be able to understand long documents as a whole." [p.9]
- "However, sometimes we could also find a term entity at the end of the document, the task is to find out which of the values is correct." [p.9]
- "We take a simple approach: all candidates are grouped by the extracted entities' normalized forms and for each group we sum up the scores and finally we return the values with the largest sums." [p.10]
- "For example, for the entities income and spending in the Kleister Charity dataset, we manually checked that in about 5 % of examples we need to also infer the right scale (thousand, million, etc.) for each monetary value based on the document context (see Figure 5)." [p.12]
- "It turns out that, for all models, worse results are observed for longer documents, see Figure 6." [p.12]

## 7. 对本库的可用点（笔记者推断）
- 本文的流水线形状（找出全部出现 → 归一化 → 聚合）正是本库定位改造该有的形状，差别只在最后一步：本文按分数求和取最大（多数票），本库按原则不能默选，改为"归一化后一致则落值，不一致则报冲突"。
- 慈善委员会登记数据与报告文本之间 5%–9% 的错误、13%–63% 的轻微差异，是"登记簿与文档不一致"真实发生率的一个量级参照；本库 B 渠道上线后要预期这个比例的冲突，并把"轻微差异"（Limited 与 LTD）交给归一化而不是报冲突。
- 金额的数量级（RMB'000）约 5% 需要靠语境推断，且金额在 2021 年的 SoTA 上也只有 74 F1：本库把表格金额归为 C 渠道（结构化来源优先）有依据；留给模型读的金额必须带单位守则，并由程序从引文里解析数字与单位。
- 文档越长越差，与 M3 一致，支持按字段取候选段落而不是整篇。
