# L6 Papadakis, Kintis, Zhang, Jia, Le Traon & Harman, 2019. Mutation Testing Advances: An Analysis and Survey. Advances in Computers 112, 275–378
版本：author（ORBilu 接受稿，文件 L6_Papadakis2019_MutationTestingAdvances_author.pdf，页眉标"Preprint submitted … December 14, 2017"，PDF 共 153 页，正文约 82 页）；阅读范围：第 1–3 页（引言）、第 6–9 页（背景、变异算子、变异分数）、第 13–17 页（变异体与真实缺陷的关系）、第 24–25 页（变异体选择）、第 28–31 页（等价与冗余变异体）、第 65–82 页（测试评估中的使用与威胁、检查清单、结论与开放问题）；未读工具表、模型与安全等应用章节、参考文献

## 1. 问题与作者主张
- 作者称变异测试通过检查测试发现人工缺陷的能力来衡量测试集的可信度，主要用来评估测试集充分性、引导测试生成并支持实验 [p.1-2]。
- 本章综述 2009 年以来（Jia 与 Harman 综述覆盖至 2009 年）的进展，分析 400 余篇论文，并给出把变异测试用作实验方法的最佳实践 [p.1, p.3]。
- 作者主张：以变异分数作充分性度量时，隐含假设所有变异体价值相同，这一假设不成立；存在等价变异体与冗余变异体（重复的、被包含的），冗余变异体使分数膨胀、难以解读 [p.9]。
- 作者认为变异体与真实缺陷的联系有三条依据：变异体是测试者要针对的潜在缺陷、简单缺陷的测试能暴露复杂缺陷（耦合效应）、杀变异体要求测试把被破坏的状态传播到可观察输出 [p.14]。
- 作者认为用变异体评估测试技术有若干威胁：算子与语言的选择、被包含变异体、测试集强度与规模、工具差异、干净程序假设；并给出七点检查清单 [p.65-79]。
- 作者结论：等价与冗余变异体问题基本未解；变异体与真实缺陷何时相关尚缺清晰认识与实证 [p.80-81]。

## 2. 方法
- 综述方法：按变异测试流程的各步骤归类进展：选变异体、生成、静态剔除等价与冗余、生成测试、执行、杀死判定、测试选择与排序等 [p.17]。
- 基本概念：变异算子是语法变换规则，Offutt 等的五算子集（ROR、LCR、AOR、ABS、UOI）常被当作最低标准；变异分数是被杀死变异体的比例，可作充分性指标 [p.7-8]。无法编译的变异体称"死产"（stillborn），需要剔除 [p.6]。
- 杀死条件分弱、稳固、强三种：弱杀死比较变异之后紧接着的程序状态，强杀死要求输出可观察地不同；由于错误传播可能被后续计算掩盖，三者之间没有形式上的包含关系 [p.7]。
- RIPR 模型：要暴露缺陷，测试须到达缺陷位置（Reachability）、造成状态被破坏（Infection）、把破坏传播到输出（Propagation）、使之可被观察/断言（Revealability）[p.16]。
- 冗余变异体的"不相交变异体集"：用测试矩阵近似，先去掉存活与重复的变异体，再反复选出"与最多存活变异体联合被杀"的变异体并放入集合，直至原集合为空 [p.71, p.73]。
- 变异体选择：算子子集（选择性变异）、随机抽样、高阶变异、按位置选等 [p.24-25]。

## 3. 数据与设置
- 综述，无自己的实验。作者另收集了用变异测试做测试评估的实证研究，共 190 篇（用于描述使用趋势）[p.66]。引文献中的数字（如 5% 变异体、60% 偏倚）均转述自被引研究 [p.72, p.80]。

## 4. 结果
- 变异体与真实缺陷：Chekam 等的研究称强变异中变异体传播要求对 36% 的缺陷的暴露负责 [p.16]；作者引用称"如果软件含有缺陷，通常存在一组只能被同时发现该缺陷的测试杀死的变异体"这一前提得到该研究的实证支持 [p.16]。Chekam 等称在考虑干净程序假设的稳健方法下，变异测试在真实缺陷暴露上优于语句与分支覆盖 [p.76]。
- 耦合效应：Gopinath 等发现许多高阶变异体与其所含一阶变异体语义不同；Langdon 等与 Papadakis 与 Malevris 发现测试杀死高阶变异体的比例明显高于一阶 [p.15-16]。
- 胜任程序员假设：Gopinath 等发现仓库中挖出的缺陷平均需要三到四个词法单元的改动即可修复，作者称这在一定程度上印证了该假设 [p.15]。
- 变异体选择：随机抽样 5% 的（选择性）变异体就足以高精度预测选择性变异的分数 [p.24]；随机选择与选择性变异无显著差异，最大可能改进为 13% [p.24]。但对"包含变异体"为标准评估时，选择性变异与随机抽样表现很差 [p.25]。二阶策略可减少 80% 到 90% 的等价变异体，代价约 10% 或更少的测试有效性 [p.25]。
- 等价变异体：检测等价变异体是不可判定问题，只能用启发式 [p.29]；"平凡编译器优化"（目标代码相同即判等价）至少能识别 30% 的等价变异体 [p.29]；用于重复变异体时平均识别 C 的 21%、Java 的 5.4% [p.31]。
- 冗余变异体：基于谓词的静态分析可把运行时间减少约 20%，并避免最多约 10% 的变异分数高估；Fernandes 等的 37 条规则平均减少 13% 的变异体 [p.30-31]。这些局部分析对强变异可能不成立，精度损失最多约 8% [p.31]。
- 被包含变异体威胁：不相交变异体约占全部的 9%，最小变异体占 1.2% 与 4%（两项研究）[p.72]；Papadakis 等估计在任意实验中有超过 60% 的机会因此影响科学结论 [p.70, p.72]。
- 测试集强度：Chekam 等称低强度测试集下各准则无实际差异，强度高时差异才显现；低于阈值的覆盖会带来噪声 [p.72]。
- 工具差异：Java 变异测试工具的判断之间存在大量分歧 [p.75]。
- 干净程序假设：对原程序做测量即假定其代表对变异体的测量，Chekam 等证明该假设不成立，且可能改变实证研究的结论 [p.76]。
- 开放问题：作者称目前约 5% 的变异体在实践中有用，其余是噪声 [p.80]；自动生成能杀大量变异体的测试与预言仍未解决 [p.81]。

## 5. 作者陈述的局限
- 作者称在变异体与真实缺陷何时相关、哪些缺陷不被简单或复杂变异体捕获、可捕获多少未来回归错误、何时停止测试等问题上缺乏理解与实证 [p.81]。
- 作者称缺乏关于哪些变异体有价值的清晰理论，多数工具只支持少数算子，这在一定程度上是任意的 [p.80]。
- 作者称局部（谓词级）冗余分析不一定适用于强变异 [p.31]。
- 综述本身的覆盖范围与偏倚：本文未专门讨论文献选取偏倚。

## 6. 原文摘录
- "In practice using mutation score as adequacy measure, implicitly assumes that all mutants are of equal value." [p.9]
- "if the software contains a fault, there will usually be a set of mutants that can only be killed by a test case that also detects that fault" [p.16]
- "Detecting equivalent mutants is a well-known undecidable problem" [p.29]
- "In case the mutants we are using are trivial, then we only measure the ability of test suites to cover some parts of the code, instead of their ability to uncover faults at these parts." [p.70]
- "only few of the mutants produced (approximately 5%) is practically useful." [p.80]
- "there is neither clear understanding nor much empirical evidence concerning whether and when mutants are correlated with real faults" [p.81]

## 7. 对本库的可用点（笔记者推断）
- §3.5 变异分数的解读：论文称分数会被冗余（被包含）变异体抬高、被等价变异体压低 [p.9]。本库 `mutation.py` 的 NEG/DROP/PRED/SHIFT 在同一规则上会产生互相包含的变异体（例如对同一阈值，PRED 的 ">=" 改 ">" 与 SHIFT 移一个单位，往往被同一批边界用例杀死）。应在报告里同时给出"原始分数"与"不相交变异体上的分数"（论文算法 [p.73] 以完整的 mutant×case 杀死矩阵为输入；而 `mutation.py` 每个变异体遇到首个差异即停，不产生完整矩阵，需另跑一遍补全，成本待估），并用后者作为门禁指标，防止"分数高"只是因为大量冗余变异体被同一用例杀死。
- 与现行写法的冲突：`mutation.py` 文件头把"编译器拒绝变异后的规格"算作杀死。论文把无法编译的变异体称"死产"，要剔除出分母 [p.6]。若本库把"规格被拒"计为杀死，会抬高分数而不说明测试的力度；建议单列"被拒"计数，不进分数。
- 等价变异体的处理：论文称自动判定不可判定，启发式（编译器优化式的"规格化后相同"）能识别一部分 [p.29]。本库对应物：把变异后的规则集规范化（排序、删死规则、合并同类项）后与原规则集比较，相同即判等价，且不会误报（类似"平凡编译器优化"，其特点是只声明有把握的等价 [p.31]）。其余存活者须人工据官方条文逐个判，不得整体归入等价（见 J9 的同类提醒）。
- 变异体选样：论文称随机 5% 即可预测选择性变异分数 [p.24]，但对包含变异体为标准时表现很差 [p.25]。本库若为提速做抽样，应以不相交变异体上的分数衡量抽样是否失真，而不是以原始分数；结论来自程序变异，本库需自测。
- 与真实缺陷的联系：论文承认变异体与真实缺陷何时相关尚不清楚 [p.81]，并指出传播要求（RIPR）是变异体强于覆盖的原因 [p.16]。对应本库：变异体被"杀死"必须是税额或结论可观察地变，而不是中间量变；`mutation.py` 的杀死判据（候选上下限、待决组、税项、期限）是否等同"可观察"，应在 §3.5 写明。另外本库的真实缺陷样本（2026-10-09 缓存-顺序缺陷、已修复的规则缺陷历史）可作小规模"变异体是否对应真实缺陷类型"的核对，论文也建议把结论放到有控制的小样本上对照 [p.78]。
- 七点检查清单 [p.77-79]：算子选择理由、工具与版本、冗余控制、测试集与规模、等。可作为 `out/mutation_report.md` 的固定栏目（算子集、冗余控制方式、用例数）。其中"测试集强度与规模"一点提醒：电池用例数变化会改变分数，比较版本间的分数须固定用例集 [p.72]。
- 不适用：论文面向代码级变异与大量开源程序，其比例类数字（5%、60%、13%）不能直接搬到规则库；"胜任程序员假设"需改写为"录入者出错是局部的"，对整段口径错（D 系列决定）不成立，需要另设语义级算子（换引用条款、换基数）。
