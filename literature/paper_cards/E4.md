# Constraint Answer Set Programming without Grounding

## 1. 研究问题与作者主张

- 问题：作者指出，在 ASP 中加入约束（CASP）并不直接，因为多数 ASP 系统的 grounding 阶段会消去变量及变量间的联系，并使程序规模出现组合爆炸 [p.1]。作者称已有做法需要限制约束域（如离散而非稠密）、约束可出现的位置，或可返回的模型的类型或数量 [p.1]。作者举例：X #> 0（X ∈ N 或 Q）的域无界，X #> 0 ∧ X #< 1（在 Q 或 R 中）的域有界但含无穷多个元素 [p.2]；并称 translation-based 方法可能 (may) 得到很大的命题表示或较弱的传播强度，constraint propagator 扩展限于 finite domain solver 并增量生成 ground 模型 [p.2]。
- 提议：把约束并入 s(ASP)（目标导向、自顶向下、不做 grounding 的执行模型），得到 s(CASP)；变量在执行期间和答案集中都保留，如同 CLP [p.1]。
- 作者主张：s(CASP) 继承并推广 s(ASP) 的执行模型，并对约束求解器保持参数化 (parametric) [p.1]。
- 作者称：通过若干示例，s(CASP) 相对 ASP、CLP 和其他 CASP 系统的 expressiveness 有所增强 (enhanced) [p.1] [p.12]；它已用于解决在其他自顶向下系统中会无限递归、在 s(CASP) 中有限结束的一系列问题，以及需要稠密或无界域约束的问题 [p.3]。
- 作者报告相对 s(ASP) 与 clingo 5.2.0 的运行时间（数字见第 4 节）[p.7] [p.16]；摘要称在某些基准上相对其他成熟、高度优化的 ASP 系统有 improved performance [p.1]；结论称相对原始 s(ASP) 实现有 very substantial performance increase，并称在某些程序上可以胜过 (beat) 最先进的 ASP 系统 [p.16]。

## 2. 方法

背景（第 2 节）：

- ASP 程序是规则的有限集合，规则形如 a ← b1 ∧…∧ bm ∧ not bm+1 ∧…∧ not bn；answer set 是 Gelfond-Lifschitz reduct 的极小模型；求解器先对规则做 grounding（代入 C_Π 中的常量），要求规则 safe [p.3]。
- s(ASP)：自顶向下、目标导向的 ASP 解释器，以 Prolog 写成；每个答案由成功推导的 mgu、其 justification 与一个 (partial) stable model 组成；unsafe 变量取值于扩展的 Herbrand Universe [pp.3–4]。not p(X) 由对偶规则 (dual rules) 求解，而非 negation as failure [p.4]。
- 对偶程序：先取 Clark's completion，再用 De Morgan 律；体中的全称量化由 forall 实现；为避免冗余答案，¬l_i 的各子句带上对 l_j (j < i) 的正文字调用 [pp.4–5]。
- Constructive disequality `\=`：X \= a 表示 X 可为任何与 a 不可合一的项 [p.5]。
- forall(V,Goal)（Algorithm 1）：令 V 未绑定地执行 Goal；成功后若 V 仍未绑定则 forall 成功；若 V 被绑定则回溯；若 V 被约束为不同于一系列值，则对每个值重新执行 Goal；Goal 对某值不为真则失败；Goal 本身不成功时亦失败 [p.6]。
- NMR check：对每条一致性规则生成 chk_i，并在 query 之后调用 nmr_check ← chk1 ∧…∧ chkk [p.6]；循环处理（odd/even loops over negation、positive loops）只在补充材料 Appendix B 概述 [p.7]。

s(CASP)（第 3 节）：

- 规则形如 a ← ca ∧ b1 ∧…∧ bm ∧ not bm+1 ∧…∧ not bn，ca 为约束或约束的合取；query 形如 ← cq ∧ l1 ∧…∧ ln；语义依 Jaffar and Maher 1994 扩展 s(ASP) 的语义 [p.8]。
- 解释器用 Ciao Prolog 重写，原则是 Prolog 能原生处理的操作（绑定、回溯、约束操作等）交给 Prolog；Figure 1 为极简代码（solve/3、solve_goal/3、pr_rule/2）[pp.7–8]。
- 新增 disequality 约束求解器 CLP(≠)（用 attributed variables 实现）和接入约束求解器的通用接口；当前接入 CLP(≠) 与 Holzbaur 的 CLP(Q)；编译器扩展到 {<,>,=,≥,≤,≠}，`\=` 在运行时决定调用 CLP(Q) 还是 disequality 求解器 [pp.7–9]。
- 调用路径检查：positive loop 仅当循环目标与其祖先相同才失败；当前调用与已证明的祖先相同时成功 [p.9]。
- C-forall（Algorithm 2）：在约束存储 C_i 下执行 Goal，检查答案对 V 的域是否细化；无细化则成功；有细化则从 V 中去掉 Goal 已对其成功的元素，在 C_{i+1} 下重新执行；存在 Goal 不为真的非空域则失败 [p.9]。Figure 4 为 Prolog/CLP 实现 eval_forall/3；合取的否定产生析取，作者称多数约束求解器不能原生处理析取，故 dual/2 返回各分量，add/3 只保留一致的分量 [p.11] [p.12]。

## 4. 结果

### 实证结果

- Table 1（单位 ms，依次为 s(CASP)、s(ASP)）：hanoi(8,T) 为 1,528 与 13,297；queens(4,Q) 为 1,930 与 20,141；One hamicycle 为 493 与 3,499；Two hamicycle 为 3,605 与 18,026 [p.7]。
- Table 2（Towers of Hanoi，单位 ms，依次为 s(CASP)、clingo 5.2.0 standard、clingo 5.2.0 incremental）：n = 7 为 479、3,651、9,885；n = 8 为 1,499、54,104、174,224；n = 9 为 5,178、191,267、> 5 min。incremental 在 n = 9 一格原文为 > 5 min，未说明是否为超时上限；列与表头的对应见第 8 节 [p.16]。
- Stream reasoner：query ?- valid_stream(Pr,Data) 返回三个答案：{Pr=1, Data=p(A),A\=a, A \= b}；{Pr=2, Data=q(b)}；{Pr=3, Data=p(a)} [p.13]。
- Yale shooting：作者引用的 clingo[DL/LP] 程序在 n = 3 时返回两个计划 {do(wait,1),do(load,2),do(shoot,3)} 与 {do(load,1),do(load,2),do(shoot,3)}；s(CASP) 对 ?- T#<100,holds(T,st(dead,_,_),Actions) 返回六个答案（Actions 按时间倒序）：T=55 [shoot,load,load]；T=66 [shoot,load,wait]；T=80 [shoot,load,load,load]；T=91 [shoot,load,load,wait]；T=91 [shoot,load,wait,load]；T=96 [shoot,load,shoot,wait,load] [p.14]。
- TSP 变体：?- D#<10,travel_path(b,D,Cycle) 返回 {D=61/10, Cycle=[b,[31/10], c, [1], a, [1], d, [1], b]} [p.15]。

### 作者的解释或推论

- 作者将 Table 1 的差异与重写方式联系起来：让 Prolog 原生处理它能处理的操作，带来较大的性能提升 (a large performance improvement)；同时称在优化解释器上投入的工作很少 [p.7] [p.8]。
- 作者称在 Table 2 中 s(CASP) 比两个 clingo 变体快若干个数量级 (orders of magnitude)，原因是它不必生成并测试所有可能的计划，而是直接计算最小解；standard 变体不返回最小移动数，只检查在给定移动数内是否可解；incremental 变体用递增的移动数反复检查，因而最慢 [p.16]。
- 作者称 Yale shooting 的 s(CASP) 程序不需要步数计数器；clingo[DL/LP] 程序每次迭代增大 n 并重新 grounding [p.14]。
- 作者称 TSP 的 ASP 与 CLP(FD) 解法性能相当 (comparable performance)，ASP 编码更紧凑 (more compact)；ASP 中限制路径长度需要 ad-hoc builtin；s(CASP) 把 ASP 式的 Hamiltonian cycle 建模与 CLP 式的路径长度构造结合，距离可写成有理数区间（Figure 7 第 35 行）；作者认为若只有 CLP(FD)，这将不那么直接（甚至不可行）：CLP(FD) 虽可编码 CLP(Q)，所得程序会难以维护且比 CLP(Q) 版本慢得多，因为要以枚举取代 Gaussian elimination，这实际上会损及完备性（极限情形下还有终止性）[pp.14–15]。
- 作者称约束与目标导向策略使 stream reasoner 无需评估整个 stream 数据库；若以时间戳作可信度，?- T#>10,valid_stream(T,p(A)) 将验证 T=10 之后的 stream（原文为条件句，未给运行结果）[p.13]。
- 作者在第 4 节开头列出表达能力的三个来源：执行与答案中保留未绑定变量；可直接使用结构或函子；约束与目标导向策略允许直接算法并缩小搜索空间（如给路径长度设界）[p.12]。
- 作者用 Figure 2、3 示意 C-forall：答案 A1–A4 覆盖整个域时成功，A3 ≡ C3 时结束，无需生成 A4 [p.10]；答案未覆盖整个域时，在 C4 = C3 ∧ ¬A′3 下 A4 与 C4 无公共元素，C-forall 失败 [pp.10–11]；Example 7 对 {X < 0 ∨ X > 5} 的两个分支分别求值并成功 [p.12]。
- 作者称：只要 Goal 的无穷多个答案集中有一个有限子集覆盖 V 的域且可被程序有限枚举，C-forall 就会结束；这一条件对 constraint-compact 域（如有限常量集上的 disequality、gap-order 约束）总是成立 (always true) [p.10]。
- 作者在结论称，单个程序可同时使用 ASP 式的非单调表达与类似传统逻辑编程的控制 [p.16]。

## 5. 作者陈述的局限与前提

- disequality（Marple et al. 2017b 的实现）：变量只能对 ground 项做 disequality 约束，作者称这缩小了合法程序的范围，但在实践中似乎不成问题；两个复合项的不等可能要回溯以检查所有情形，作者称这影响性能，可用携带项析取的更复杂实现缓解 [p.5]。当前的 CLP(≠) 未处理这些限制，作者称其改进与解释器核心正交 [pp.8–9]。
- 实现状态：作者称在优化解释器上投入的工作很少，仍有较大的改进空间 [p.8]；结论列出后续工作：用分析优化 NMR check 规则的编译；使其执行与自顶向下策略交错以尽早丢弃不一致的模型；改进 disequality 求解器以处理未决情形；用依赖分析改进对偶程序的生成；用 partial evaluation 和更好的编译技术去除解释执行带来的（部分）开销 [pp.16–17]。
- 语义前提：unsafe 变量取值于扩展的 Herbrand Universe（常量集加无穷多个新元素）[p.4]；对偶程序所用的 Clark's completion 假设规则完整刻画原子为真的所有方式 [p.4]；析取程序可借 default negation 转成非析取程序 [p.3]。
- 终止：若 Goal 有无穷多个答案集，C-forall 的终止需要有限子集覆盖 V 的域且可被有限枚举 [p.10]；作者称若以带 variant calls 或 entailment 的 tabling 系统为实现目标，终止性会增强，使有限 grounding 或具 constraint-compact 性质的程序都终止 [p.9]。
- 求解器：CLP(Q) 是有理数上的线性求解器，作者注明 CLP(R) 也可使用 [p.3]；forall 的实现以新的、无约束的 V 被调用为前提，因为代码由编译器生成 [p.11]。
- 文中未专门讨论实验设计方面的局限。

## 6. 关键术语

- **CASP、grounding、safe**：CASP 指带约束的 ASP [p.1]；grounding 指对每条规则代入 C_Π 中常量的所有可能代换 [p.3]；规则 safe 指其变量都出现在体内某个正文字中，否则 unsafe [p.3]。
- **s(ASP)**：自顶向下、目标导向、类 SLD resolution 的过程，按 ASP 语义求值，执行之前和执行期间都不做 grounding，并保留逻辑变量 [p.2]；其 partial stable model 只含支持 query 及其输出绑定所需的文字 [p.4]。
- **s(CASP)**：在 s(ASP) 上加入约束的执行模型与系统，规则体可带约束 ca [p.2] [p.8]。
- **dual**：作者定义为 'The dual of a predicate p/1 is another predicate that returns the X such that p(X) is not true' [p.4]；程序的对偶程序含每个谓词的对偶 [p.4]。
- **constructive disequality**：`\=` 表示合一的 constructive negation，用于从否定文字构造答案 [p.5]；CLP(≠) 是处理它的约束求解器 [p.8]。
- **forall、C-forall**：forall(V,Goal) 检查 Goal 对 V 的所有可能值是否为真 [p.6]；C-forall 是其对约束的推广，通过收窄 Goal 执行时的约束存储来判定 [p.7] [p.10]。
- **NMR check**：non-monotonic checking rules，用于保证 partial stable model 与程序的全局约束一致 [p.6]。
- **constraint-compact**：原文仅以例子说明（有限常量集上的 disequality、gap-order 约束），未给形式定义 [p.10]。

## 7. 原文摘录

- "This extension is not straightforward as the grounding phase, present in most ASP systems, removes variables and the links among them, and also causes a combinatorial explosion in the size of the program." [p.1]
- "In this paper we propose to incorporate constraints into s(ASP), a goal-directed, top-down execution model which implements ASP while retaining logical variables both during execution and in the answer sets." [p.1]
- "s(ASP) is a goal-directed, top-down, SLD resolution-like procedure which evaluates programs under the ASP semantics without a grounding phase either before or during execution." [p.2]
- "The former restriction reduces the range of valid programs, but this does not seem to be a problem in practice: since positive literals are called before negative literals in the dual program, the number of cases where this situation may occur is further reduced." [p.5]
- "While the s(CASP) interpreter performs better than s(ASP), little effort has been invested in optimizing it (see Section 5), and there is ample room for improvement." [p.8]
- "even if there were an inﬁnite number of answer sets to Goal, as long as a ﬁnite subset of them covers the domain of V and this subset can be ﬁnitely enumerated by the program, the algorithm will ﬁnish." [p.10]
- "while CLP(FD) can encode CLP(Q), the resulting program would be cumbersome to maintain and much slower than the CLP(Q) version, since Gaussian elimination has to be replaced by enumeration, which actually compromises completeness (and, in the limit, termination)." [p.15]
- "s(CASP) is orders of magnitude faster than both clingo variants because it does not have to generate and test all the possible plans; instead, as mentioned before, it computes directly the smallest solution to the problem." [p.16]
