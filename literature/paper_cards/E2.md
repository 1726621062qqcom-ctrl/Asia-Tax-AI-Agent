# Incomplete data: what went wrong, and how to fix it

## 1. 研究问题与作者主张

- 问题：作者问能否建立一种理论，既为理论研究者和实践者所接受，又能解释 incompleteness，同时可实现、可用于应用；文中先批评实践与理论两方面对 incomplete data 的处理，再勾勒一条可能的出路 [p.1]。
- 对现状的判断：作者称许多本科课程中可得满分的查询在存在 incomplete data 时不能正确工作，其求值方式固定在 SQL 标准中 [p.1]；作者概括为实践以正确性换效率、理论以效率换正确性，并称这幅图景 quite bleak [p.2]。
- 对理论的质疑：作者称许多理论研究把 representation systems 与 certain answers 当作不可触碰的前提（sacrosanct），并主张重新审视这一地位 [p.5]，并列出若干尚无充分答案的基本问题 [p.6]。
- 方案：把三条各自使用过的路线结合起来：certain answers 与 representation systems；把 incomplete databases 视为 logical theories；用 orderings 表达信息的相对价值 [p.1][p.6]。
- 主张：答案的语义不必与输入数据库相同，应使信息更多的输入给出信息更多的输出；intersection 不是定义 certain answers 的唯一方式，作者称有时是错误方式（plain wrong way）；作者结合 (9) 与既有 preservation 结果得出：输入与答案同用 owa 语义时 naive evaluation 对 UCQ 有效，同用 cwa 语义时对 Pos∀G / RAcwa 有效 [pp.10–11]。作者说明本文不声称回答所有这些问题 [p.6]。

## 2. 方法

作者说明的结构：Section 2 回顾既有关系型理论，Section 3 批评，Section 4 讲对偶（duality），Section 5 给出通用模型与 certainty 的两种定义，Section 6 用于查询答案，Section 7 讲方向 [p.3]。作者注明 Section 5 的通用模型沿用 [51, 52] [p.7]，certainty 的定义及其后的结果来自 [52] [p.9]。

- 既有框架：certain(Q, D) 为 [[D]] 中各 D′ 上 Q(D′) 的交 (1) [p.2][p.5]；strong representation system 要求答案表 A 满足 [[A]] = Q([[D]]) (2)，weak 要求 [[A]] ∼ Q([[D]]) (3)；naive evaluation 有效时 Q(D)cmpl = certain(Q, D) (4) [p.4]。
- 对偶（Section 4）：incomplete relation 可看作 Boolean conjunctive query 的 tableau，如 R = {(1, ⊥), (⊥, 2)} 对应 QR = ∃x R(1, x) ∧ R(x, 2)，ModC(QR) = [[R]]owa (5)；cwa 对应带全称量词的公式；把数据库视为 logical theory Φ，Boolean Q 在 certain 意义下为真当且仅当 Φ ⊨ Q，求 certain answers 因此是 logical implication 或 query containment 的特例 [pp.6–7]。
- 通用模型（Section 5）：⟨D, C, [[ ]]⟩ 加公式集 F；要求 c ∈ [[c]] 与 c ∈ [[x]] ⇒ x ⪯ c，每个 x 有 δx 使 ModC(δx) = [[x]]，F 对合取封闭，并有等价关系族 Iso，得 domain 与 representation system RS = ⟨D, F⟩ [pp.7–8]。owa 取 F = UCQ，cwa 取 Pos∀G；⪯owa 对应 homomorphism，⪯cwa 对应 strong onto homomorphism [p.8]。
- certainty：certainK X 满足 Mod(ϕ) = Mod(Th(X)) (6)，Th(X) 含 X 中所有对象都满足的公式；certainO X 为 X 的 greatest lower bound (7)；certainK X 也可写作 Th(X) 的 greatest lower bound (8) [p.9]。
- 查询（Section 6）：Q 是两个 domain 间的映射，输入输出语义可不同；monotone 即 x ⪯ y ⇒ Q(x) ⪯′ Q(y)；Q monotone 且 generic 时，certainO(Q, x) = Q(x) (9)，certainK(Q, x) = δQ(x) (10) [p.10]。对 Boolean 关系查询，monotone 化为 homomorphism（owa）或 strong onto homomorphism（cwa）下的 preservation，并用 [63]、[32] 的 preservation 结果 [pp.10–11]。

## 3. 数据与范围

- 文中没有数据集、样本量、时期、法域、基准或被评测的系统，也未报告实验、实现或对具体 DBMS 的测试（原文未说明此类内容）。
- 示例为手工构造的小实例：Order(o_id, product) 与 Pay(p_id, order, amount)，Order = {(oid1, pr1), (oid2, pr2)}，Pay = {(pid1, ⊥, 100)}，100 未标单位 [p.1]；schema mapping Order(i, p) → Cust(x), Pref(x, p) [p.2]；naive table R 与 Codd table S [p.3]。
- 范围：以关系数据库中的 naive nulls 为主要示例（SQL nulls 为特例），查询语言为 relational algebra、first-order logic (FO)、UCQ [p.3]；语义为 owa 与 cwa，另提及一种 cwa 的弱化版本 [p.8]。作者称方法不假设特定数据模型 [p.3]；XML 与 graph 数据只在 Section 7 作为方向 [p.12]。

## 4. 结果

文中没有实验结果。第一组为示例的输出与形式化陈述（不少陈述作者引自他处，已注明），第二组为作者的解释与推论。

### 示例输出与形式化陈述

- 在 Order = {(oid1, pr1), (oid2, pr2)}、Pay = {(pid1, ⊥, 100)} 上，作者报告 SELECT o_id FROM Order WHERE o_id NOT IN (SELECT order FROM Pay) 返回空集，而已知至少有一个订单未付款 [p.1]。
- 作者报告：单属性关系上写成 NOT IN 的 R − S，S 只含一个 null 时返回空集，与 R 的内容无关，而 |R| > |S| 时 R − S 不可能为空 [p.1]。
- 作者报告：同一数据库上 SELECT p_id FROM Pay WHERE order = 'oid1' OR order <> 'oid1' 产生空表，而作者称无论 null 换成哪个非 null 值，答案都是 pid1 [p.2]。
- 复杂度（作者引 [3, 33]）：full relational algebra（FO）的 data complexity，certain answers 在 owa 下 undecidable，在 cwa 下 coNP-complete；positive relational algebra 查询由 (4) 得 AC0 ⊊ DLogSpace [p.5]。作者另述：owa 下对关系演算求 certain answers 恰为 validity 问题，只考虑有限结构并不使之更容易；应用中常见 coNP、Πp2、Pspace、coNEXP 等复杂度类，甚至对 data complexity [p.2]。
- 作者称离开 positive queries 后 tractability 会丧失，是普遍现象；Boolean combinations of conjunctive queries 等类可多项式时间求解 [33]，但作者称其算法过于复杂，难以在现有 DBMS 上高效实现 [p.5]。
- representation systems：conditional tables 对 full relational algebra（cwa）是 strong representation system 最广为人知的例子（best known example）；R = {1, 2}、S = {⊥} 时 R − S 的 Q([[D]]cwa) = {{1, 2}, {1}, {2}}，作者称表示它的 conditional table hardly meaningful to humans [p.4]。weak representation system 的例子（owa、cwa 均可）：Codd tables 对 selection/projection 查询，naive tables 对 UCQ [p.4]。
- naive evaluation：作者引 [40]，对 UCQ 在 owa 与 cwa 下都有效；引 [51]，owa 下对 Boolean FO 查询，有效则等价于 UCQ；反例 πA(R − S)，R = {(1, ⊥)}，S = {(1, ⊥′)}，naive evaluation 得 {1}，certain answer 为 ∅ [p.4]。有效时，直接求值后去掉含 null 的元组（或加 IS NOT NULL 条件）即得 certain answers，作者称无需发明新的求值技术 [p.5]。
- 对偶：对 Boolean conjunctive query Q，owa 下 certain(Q, D) 为真当且仅当 D ⊨ Q [pp.6–7]；cwa 下 naive evaluation 能否用于更大的查询类，作者称后文答案为肯定 [p.7]。
- intersection：R = {(1, 2), (2, ⊥)}，Q 返回 R，certain(Q, R) = {(1, 2)}（owa 与 cwa 相同）[p.9]；owa 下 {(1, 2)} ⪯owa R′ 对每个 R′ ∈ [[R]]owa 成立，cwa 下 {(1, 2)} ⪯cwa R′ 对每个 R′ ∈ [[R]]cwa 不成立 [pp.9–10]。作者称 intersection 一般与 ordering 和答案语义不对应，可能对应但仅限很有限的条件 [52] [p.10]。
- certainK X 与 certainO X 一般不一定存在；存在时可能不唯一但彼此等价；certainO [[x]] ⊨ certainK [[x]]，一般的 certainO X ⊨ certainK X 不一定成立 [p.9]。
- 作者引 [52]：Q monotone 且 generic 时 (9)(10) 成立；无 representation system 时 (9) 不一定成立，需先证 (10) 再推出 (9) [p.10]。preservation：FO 句子在 homomorphisms 下保持当且仅当等价于 UCQ [63]；onto homomorphisms 的 preservation 结果在有限结构上已知不成立 [6, 65]；Pos∀G 在 strong onto homomorphisms 下保持 [32] [p.10]。
- 输入与答案同一语义时：owa-naive evaluation 对 UCQ 有效，cwa-naive evaluation 对 Pos∀G 有效；RAcwa = Pos∀G，故对 RAcwa 有效 [p.11]。作者称 Pos∀G 可粗略理解为 positive relational algebra 加对基关系的 division，实际略更有表达力 [p.11]。

### 作者的解释或推论

- 作者概括：实践以正确性换效率，且完整与不完整数据共用同一求值引擎；理论以效率换正确性，并引入新的查询回答语义 [p.2]。
- 作者对理论的质疑：(i) (2) 要求输入与答案同一语义，作者认为先验上没有理由如此；(ii) ∼L 看上去 quite ad hoc，作者说明它是为保证 compositionality 而如此定义；(iii) intersection 去掉的是数据而非信息，这一过程可能增加信息（如 cwa 下去掉一个元组即得知它不在答案中），故 (1) 的 certain answers 并非在所有场景下都能称为 certain；(iv) 基于 ordering 的研究未与 representation systems、certain answers 结合；(v) 作者问表、XML 文档、图等对象能否表示可能无限的 Q([[D]])；(vi) 作者问高复杂度结果有多少源于不愿调整的刚性设定，并指出高复杂度常在输入与答案同一语义的设定下得到 [pp.5–6]。作者在 p.6 称仍有基本问题缺少充分答案，所列问题包括何时可依赖现有求值算法给出有意义的答案 [p.6]。
- 作者提出的原则：对查询输入知道得更多，对输出也应知道得更多（文中形式化为 monotonicity）；作者认为大多数方法忽略它，包括 strong 与 weak representation systems 的定义 [p.10]。
- 作者在 Section 7 的小结：并非所有结果都可疑；前提之一是 naive（marked）nulls，作者称这可行并已在现有 DBMS 中实现 [38]；此时可完全信任 positive relational algebra 查询的答案，在 cwa 下较宽松地加入 division 亦然；答案语义恰当时，标准查询求值的答案可信 [p.11]。
- 作者列出的后续方向：更富表达力的查询，作者称 (9)(10) 表明只要语义选择正确就没有限制 [p.11]；求值技术，含能否总保证没有 false positives [pp.11–12]；constraints；XML 与 graphs；data integration、data exchange、consistent query answering 等应用，作者称其中使用基于 intersection 的标准定义，除少数例外以 owa 为主，且常在已知 naive evaluation 不适用的情形下使用它；作者称把本文的 certainty 概念用于这些应用似乎（seems）是自然的下一步，这有可能（may well）涉及重新思考过去的若干语义假设 [p.12]。

## 5. 作者陈述的局限与前提

- 本文不声称回答所列的全部问题，只尝试勾勒一种做法 [p.6]。
- 数据模型：文中只处理关系数据库。作者称 XML 中结构也可能缺失，已有结果显示结构性不完整很快导致 intractability；推广到 XML 需找到满足 homomorphism preservation 条件的查询类，这对树状结构 not a trivial task at all，带数据时更难；对 graph 数据所知更少 [p.12]。
- 通用模型的前提：c ∈ [[c]] 与 c ∈ [[x]] ⇒ x ⪯ c，作者称它们对 owa、cwa 及许多其他语义成立 [p.7]；公式须能定义语义并尊重信息性，对象集须有足够多的 valuation [pp.7–8]；结果的成立只需要不完整数据库语义的定义，与 null 的含义无关 [p.3]。
- naive evaluation 结果的前提：查询须 monotone 且 generic，并需要答案语义的 representation system [p.10]；onto homomorphisms 的 preservation 结果在有限情形下失败，作者改用充分条件 [p.10]；certainK X 与 certainO X 一般不一定存在 [p.9]。
- 可信性结论的前提：使用 naive（marked）nulls，且答案的语义恰当 [p.11]。
- 实践方面：作者假设数据库厂商不会采纳激进方案，称或许（perhaps）可建议小而易实现的改动，并肯定（definitely）可为专门产品提出新算法 [p.2]。
- 未解决：能否总保证没有 false positives（作者指出引言示例中的查询没有 false positives）；对高效求值技术与恰当 certainty 概念的相互作用，作者称尚未充分理解 [p.12]；constraints 方面少有关于语义作用的研究 [p.12]。

## 6. 关键术语

- certain answers：certain(Q, D) 为各 D′ ∈ [[D]] 上答案的交，即无论缺失信息如何解释都属于答案的元组 [p.2][p.5]。
- naive（marked）nulls 与 Codd nulls：naive database 中同一 null 可出现多次；Codd database 中每个 null 至多出现一次，对应 SQL nulls [p.3]。
- owa 与 cwa：[[D]]cwa = {D′ | D′ = v(D)}，只把 null 换成值；[[D]]owa = {D′ | D′ ⊇ v(D)}，换值后可再添加新元组 [p.3]。
- strong / weak representation system：strong 要求存在 A 使 [[A]] = Q([[D]]) (2)；weak 把等号换成等价关系 ∼L，即 [[A]] ∼ Q([[D]]) (3) [p.4]。
- naive evaluation works：(3) 中的 A 就是 Q(D)，即把 null 当作普通值直接求值，此时 Q(D)cmpl = certain(Q, D) [p.4]；文中另定义 ∗-naive evaluation works 为 certainO(Q, D) = Q(D)，∗ 为 owa 或 cwa [pp.10–11]。
- information ordering：x ⪯ y 当且仅当 [[y]] ⊆ [[x]]；作者称一个不完整对象能表示的对象越多，所含信息越少 [p.7]。
- certainK X 与 certainO X：前者为满足 Mod(ϕ) = Mod(Th(X)) 的公式 ϕ，后者为 X 在 ⪯ 下的 greatest lower bound [p.9]。
- Pos∀G 与 RAcwa：Pos∀G 是在 positive FO 公式（由原子公式经 ∧、∨、∃、∀ 构成）上再对规则 ∀x̄ (R(x̄) → ϕ(x̄, ȳ)) 封闭的公式类 [p.8]；RAcwa 含关系名，对 σ、π、×、∪ 封闭，并允许 Q ÷ Q′（Q′ 属于 RA(Δ, π, ×, ∪)）[p.11]。

## 7. 原文摘录

- "The key idea is to combine three hitherto used approaches to incompleteness: one based on certain answers and representation systems, one based on viewing incomplete databases as logical theories, and one based on orderings expressing relative value of information." [p.1]
- "Is there a way out of this predicament? Can we have a theory of incompleteness that will appeal to theoreticians and practitioners alike, by explaining incompleteness and being at the same time implementable and useful for applications?" [p.1]
- "The picture looks quite bleak: it is almost 40 years since nulls were introduced, and yet the practice has taught generations to live with incorrect answers, while the theory is not really addressing the right problems." [p.2]
- "removing tuples amounts to removing data, not information. In fact, the process can actually add information: for instance, under cwa, by removing a tuple we gain information that it is not in the answer." [p.5]
- "This paper does not claim to provide all such answers, far from it." [p.6]
- "if we know more about the input of a query, then we should know more about its output." [p.10]
- "Thus, we have two large classes of queries for which simply evaluating queries using existing technology does produce correct answers." [p.11]
- "Not all results become suspect. You can sometimes trust the result you get from a database with nulls." [p.11]
