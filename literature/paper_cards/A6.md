# Coding the Code: Catala and Computationally Accessible Tax Law

## 1. 研究问题与作者主张

- 要回答的问题：作者写道，问题不在于是否把税法形式化（formalize），而在于如何形式化 [p.3]。她把「如何形式化」分成两部分：形式化如何完成，以及形式化本身的最佳版本 [p.3]。文章把第一部分作为给定前提（至少目前由人对 Internal Revenue Code 做形式化，而不是由计算机分析大量文本得出自动形式化），集中讨论第二部分 [pp.3–4]。
- 标准与对象：作者称，在最抽象的层面上，税法应以使 transparency、government accountability 和 accuracy 最大化的方式形式化 [p.4]。文章介绍编程语言 Catala，创建者为计算机科学家 Denis Merigoux、Jonathan Protzenko 与律师 Liane Huttner、Sarah Lawsky（Sarah Lawsky 即本文作者）[p.2] [p.4]；脚注 8 称实现由 Merigoux 主导 [p.4]。
- 对现状的主张：作者称，Part II 所述的现有形式化（税表、worksheets、报税程序等）'do not track the structure of the underlying law and are not transparent; sometimes, they are even inaccurate' [p.5]。
- 对 Catala 的主张：作者称 Catala 提供一种 'tractable and functional' 的美国税法编码方式，给出更透明的形式化，并 'could potentially' 比现有的税表、worksheets 和 'secret programs' 更能使政府负责 [p.4]。三个要素（domain-specific programming language、pair programming、literate programming）使它 'particularly well-suited' 于形式化税法 [p.4] [p.7]，这些特征 'could generalize' 到其他形式化法律的编程语言 [p.4]。作者同时写明：形式化不会消除歧义，不预测案件结果，Catala 也不是 machine learning 或 artificial intelligence [pp.4–5]。
- 对前景的主张：作者讨论形式化的潜在好处（更易于管理、对中低收入纳税人有利、政府自办在线报税）[p.19] 与风险（可能使某些类型的 tax shelter 更易制造）[p.20]，并在结论中称政府应尽快建立 computationally accessible 的税法版本 [p.24]。

## 2. 方法

本文是法学评论文章，写法是描述与论证，不含实验、统计估计或定理证明。结构：Part II 描述美国税法自动化应用的现状 [pp.5–7]；Part III 说明 Catala 的三个要素并配一个编码示例 [pp.7–18]；Part IV 讨论形式化的好处与风险，文中的支撑材料是作者的推理、对 Summa Holdings 案事实的复述和脚注文献（脚注 123、147），未报告作者自己的搜索实验或模拟 [pp.18–24]；Part V 为结论 [p.24]。

- domain-specific programming language [pp.8–9]：作者称 Catala 的领域特定性体现在：程序先列出相关主体、结构与变量，'Items are named before they are used' [p.8]；程序员可为被编码的规则定义 scope，对应 Code 中规则与定义只适用于特定部分的结构 [p.8]；以 default logic 为结构，因为美国税法（作者称还包括法国税法等）大量以 general rules followed by exceptions 的方式写成 [p.9]。
- default logic [pp.9–10]：规则带优先级，高优先级规则覆盖低优先级规则，已得出的结论可在获得更多信息后撤回（nonmonotonic）；standard logic 则是 monotonic，已证明的集合只会增长 [pp.9–10]。
- 示例的形式化 [pp.10–11]：作者以 §61(a)(11)（债务免除所得计入 gross income 的一般规则）、§108(a)(1)(B)（纳税人 insolvent 时不计入的例外）和 §108(a)(3)（该例外只在 insolvent 的范围内适用的限制）为例，公式见本节末 [p.10]。
- pair programming [pp.12–16]：作者提到让同一个人兼具法律与编程专长的做法，并给出顾虑：熟练编程需要大量时间与经验，阅读税法本身就有难度，形式化法条的任务 'should not be left to a single person' [pp.12–13]。她称 pair programming 'is the better approach'，此前美国法学文献未讨论（脚注 80：截至写作时仅一篇文章顺带提及）[p.13]。本文的做法是一名律师加一名程序员；作者称为使其最有效，律师应略懂编码、程序员应略懂税法 [p.13]；示例是作者（律师）与 Jonathan Protzenko（程序员）对 §61(a)(11) 与 §108(a)(1)(B) 的编码 [pp.13–16]，过程见第 4 节。
- literate programming [pp.16–18]：Catala 代码含面向读者的大量注释；定稿代码把相关法条原文作为计算机忽略的 comment 纳入，并可标明每段代码所编码的 subsection、paragraph 或 subparagraph [p.16]。作者称注释还可以（'can—and should'）包含两类信息：编码团队决定的说明（含 extra-statutory legal support），以及团队察觉到的歧义及其处理方式与理由 [p.17]。

示例公式 [pp.10–11]，按页面图像转录（文本层把 σ 写作 s）：

```text
σ3: $X Income from Discharge of Indebtedness → Include $X
σ2: ($X Income from Discharge of Indebtedness and Insolvent) → Include $X
σ1: ($X Income from Discharge of Indebtedness and Insolvent) → Include ($X - Lesser($X, (Liabilities - Assets)))
```

作者写道，依 'the specific controls over the general'，最具体的 σ1 优先于 σ2，σ2 又优先于 σ3；这只是表示这些规则的众多方式之一 [p.10]。同一组规则的 standard logic 语句如下（作者注明这同样只是一种可能的表示）[pp.10–11]：

```text
($X Income from Discharge of Indebtedness) → Include ($X - Lesser($X, Maximum(0, (Liabilities - Assets))))
```

## 3. 数据与范围

- 数据与时期：文中没有数据集、样本量、统计检验、基准、评测的模型或研究期间 [pp.2–24]。
- 法域与条文：美国税法（Internal Revenue Code 与 regulations）[p.3] [p.17]。编码示例用到 §61(a)(11)、§108(a)(1)(B)、§108(a)(3)、§108(d)(3) [p.10] [p.14]；一般规则与例外的说明用到 §61(a) 与 §121 [p.9]。作者称美国与其他国家的税法都适合译成公式与算法 [p.3]，称法国税法同样以一般规则加例外的方式写成 [p.9]；脚注 10 称 Catala 适用于以 general rules and exceptions 方式起草的任何 statute [p.4]。
- 材料：法条与规章；判例 Summa Holdings, Inc. v. Commissioner, 848 F.3d 779 (6th Cir. 2017) [p.2] [pp.20–22]；IRS 的税表、ITA 的页面说明，以及 Blank 与 Osofsky 对自动化指引的研究 [pp.5–7]。
- 编码示例的规模：一次 pair programming 会话，对象为 §61(a)(11) 与 §108(a)(1)(B) [pp.13–16]；参与者为作者（律师）与 Jonathan Protzenko（程序员）[p.13]。

## 4. 结果

本文是论述性文章，文中没有数据集上的统计结果、基准分数或对照实验 [pp.2–24]。「实证结果」指作者报告的示例推演、编码过程与事实陈述，「作者的解释或推论」指作者据此作出的论述。

### 实证结果

- 示例推演（default logic 与 standard logic）：作者写道，就 outputs given inputs 而言，两种表示相同 [p.11]。对 standard logic 语句她演算三种情形：not insolvent 时计入 $X - 0 = $X [p.11]；insolvent 且债务减免小于 insolvency 的程度时，计入 $X - $X = 0，即全部债务减免被排除 [pp.11–12]；insolvent 且债务减免大于 insolvency 的程度时，计入额减少 Liabilities - Assets，即仅在负债超过资产的范围内排除 [p.12]。
- 编码会话（流程与修改）：会前律师提供书面说明与上述形式化，会上律师讲解并举带数字的例子；作者写道这一步约十分钟，因为 §61(a)(11) 与 §108 的 insolvency 例外 'fairly straightforward'，更复杂的条文仅这一步就可能 'well over an hour' [pp.13–14]。程序员起初把变量命名为 `DEBT_REPAYMENT`（没有理解纳税人是被免除债务的一方），讲解后改为 `DISCHARGE_OF_INDEBTEDNESS_INCOME`；起初写成该变量增加 `INCOME`，律师指出应增加 `GROSS_INCOME`；scope 起初写成 108a1b，律师指出应写 108a1B；第一条规则被标为 delta_3，以便之后把 delta_2 编为它的例外 [p.14]。
- 编码会话（对 insolvent 的处理）：§108(d)(3) 把 insolvent 定义为 'the excess of liabilities over the fair market value of assets'，而 §108(a)(1)(B) 写的是 'the discharge occurs when the taxpayer is insolvent' [pp.14–15]。作者写道，按字面判断 taxpayer = insolvent 是否为真会不连贯，二人因此偏离法条语言，代码改为检查 insolvency > 0 是否成立；她称这一偏离 'was necessary and reflects how this section is always implemented'，同时称 'it is indeed a departure' [p.15]。二人选择让纳税人输入资产的公允市场价值与负债额，而不是 insolvent 的程度；律师建议新建 excess_of 运算符（'excess of' 一语在 Code 中反复出现），insolvency 的程度被定义为 excess_of(assets, liabilities)（按原文印刷）[p.15]。
- 编码会话（结果）：delta_1 被编为 delta_2 的例外，对应 §108(a)(3) [p.16]。作者写道整个过程约一小时，产出仍需修改语法以符合 Catala 要求的初步版本；此后程序员独自定稿，并以各种资产、负债和 gross income 的输入运行代码，检查其是否准确反映法定规则 [p.16]。输入的数量、具体取值与检验结果：原文未说明。
- literate programming 的例子：§121 有时要求按相关期间与两年之比按比例计算排除额，规章允许按月（分母 24）或按日（分母 730）计算，注释可说明规章支持这一做法 [p.17]。'income' 一词在 Code 中未被直接定义，代码可让纳税人输入属于 income 的金额而不必定义它，即保留这一歧义 [pp.17–18]；计算顺序等歧义则必须解决才能编码，作者称 IRS 有时在表格中解决这类歧义，因而没有向纳税人显示歧义的存在 [p.18]。
- 文中陈述的现状事实：作者引述 Blank 与 Osofsky：ITA 是 simplexity 的例子，其答案常常不正确或掩盖了导致答案的有争议的政府决定 [pp.6–7]。脚注 114 称 2020 财年超过 94% 的个人所得税申报表以电子方式提交 [p.19]；作者称 IRS 目前不提供在线报税界面，依赖营利公司（如 Intuit、H&R Block）提供在线申报选项，直到最近合同还禁止 IRS 自建；记者揭露营利公司的不道德行为后，免费申报计划中的两家最大公司退出，Taxpayer Advocate Service 将该计划的状况列为 IRS 面临的最严重问题之一 [p.19]。
- Summa Holdings 案事实：DISC（domestic international sales corporation）由国会设计以激励出口 [p.20]。Benenson 家族拥有制造业公司集团的母公司 Summa Holdings；两个孩子 'each established a Roth IRA and put in $3,500'；每个 Roth IRA 以 $1,500 购买新设 DISC JC Export 的股份，随后把这些股份卖给公司 JC Holding，此后每个 Roth IRA 持有 JC Holding 的 50%，JC Holding 持有 JC Export 的 100% [p.21]。Summa 六年间向 JC Export 支付超过 $5 million，JC Export 分配给 JC Holding，后者就股息缴纳规定的 33% 所得税并把余额分配给 Roth IRA；Tax Court 把这些支付重新定性为 Summa 向股东分配的股息，之后是（过量的）对 Roth IRA 的缴款，Sixth Circuit 推翻并维持原来的定性；作者写道该家族用这一结构绕过了 Roth IRA 的缴款上限 [p.21]。
- 他人研究（仅见脚注）：脚注 123 称 Hemberg 等（2015）用计算机程序模拟 tax evasion 与 auditing 的 co-evolution，'to demonstrate how tax shelters could be developed' [p.20]；脚注 147 引用 Rosen 的 MIT 硕士论文（2015）与 Hemberg 等的同一篇文章，支持正文 'Generating tax shelters from computationally accessible tax law has been proven possible' [p.22]；本文未报告这些研究的方法或结果。

### 作者的解释或推论

- 现有形式化：作者写道，税法已被形式化多年，没有这种形式化，管理现代税法 'would be essentially impossible' [p.3]。她引述 Davis 与 Reddy 所称 TurboTax 以 'faithfully represents the logic and meaning' 的方式为美国税法建模，并称 'This is almost certainly not correct'；她称报税程序编码的是政府制作的税表与 worksheets，而不是法律的底层逻辑 [p.5]。她称表格与 worksheets 'accurate, for the most part'，但 'far abstracted from the tax law'；写出步骤最少、对纳税人最高效的表格，与写出准确反映法律语言结构的表格之间存在 tension；一些表格把对结构性歧义的解决隐藏在起草之中 [p.6]。作者推论 ITA 的简化形式化既误导纳税人（所给指引常常不正确），又掩盖实际法律，从而降低政府问责 [p.7]。
- default logic 与 standard logic：作者称选择哪种逻辑是 'a pragmatic choice'，两者 'can be used to represent the exact same law, both equally and accurately' [p.10]；同时列出 default logic 的四点优势 [pp.11–12]：(1) 示例中的 standard logic 语句 'incomplete and therefore wrong'，因为只体现 §108 众多例外中的一个（其余如 Title 11 case 等），而 default logic 形式化 'incomplete but not wrong'，可继续增加例外，不需免责说明 [p.11]；(2) standard logic 表示 'hides the law even as it implements the law'，验证它最简便的办法是核对 outputs given inputs；作者称法条传达的内容超出输出，包括基线规则、关注的特征（insolvency 不是开关，而是与资产和负债的关系）与对该特征改变一般规则程度的限制 [pp.11–12]；(3) 译成 default logic 更容易，因为底层逻辑跟随法条 [p.12]；(4) 法条变化时 default logic 形式化更易修改，各条文可保持分离，起草更模块化 [p.12]。
- pair programming 与 literate programming：作者称 pair programming 可使法律在不要求一人兼具税法与编程专长的情况下被编码，并称 'evidence shows that pair programming can lead to fewer bugs and better designs' [p.13]。她称 literate programming 有助于代码传达输出之外的含义 [p.12]，使编码者能记录对法条语言的偏离与对歧义的处理，从而 'increasing transparency' [p.17]；对必须解决的歧义，代码可在注释中说明、提供备选代码，或把选择权交给用户 [p.18]。
- 好处（Part IV.A）：作者称，以忠实于法律底层结构、并公开剩余歧义的方式用 Catala 形式化税法，'will obviate the need for other formalizations'，包括税表与 'simplexified' 的自动化指引；IRS 可依托法律本身的形式化，向负担不起专业人士的纳税人提供更准确的指引，并大体免于制作表格 [p.19]。她称形式化 'will make it easier' 让政府自行提供在线报税服务，若形式化公开，其他非营利机构利用它创建或改进在线申报程序将 'fairly straightforward' [p.19]。
- 风险（Part IV.B）：作者称给税法编码也可能为避税提供路径，使某些类型的 tax shelter 更易创建 [p.20]。她称有的 tax shelter 靠赋予词语立法者未预期的含义，有的靠虚假陈述（如夸大慈善捐赠金额），有的靠 'chaining' 互不相关的规则 [p.20]。她称计算机在考察大量复杂规则与事实模式的排列、找出使应纳税额最小的组合方面 'far better than humans' [p.20]；称 Summa Holdings 的结构不是利用词义歧义或虚报估值而成，而是 'chaining' 看似无关的条款 [pp.21–22]。作者推论：若税法语料可供计算，'neither time, patience, nor money may be necessary' 来找出复杂条款如何降低税负；计算机 'might be able to' 找出类似的 chaining 机会，'could check' regulatory arbitrage 的机会 [p.22]；'If such a program is developed'，tax shelter 的边际成本 'will drop to zero'，而 'even if, in theory, anyone could generate a tax shelter, tax shelters benefit only the wealthy' [p.22]。她称 Catala 本身不创造这种可能性，但因紧跟 Code 的结构而使税法更易被计算访问，一旦税法可被计算访问，tax shelter 'will be easier to generate' [p.22]。
- 对政府的应对：作者称 IRS 目前事后依据已遇到的 shelter 列出相关交易；IRS 若拥有自己的 computationally accessible tax law，这 'could permit' 其事前列出有问题的交易，并可 'essentially brute force' 该问题、给出禁止交易清单 [p.23]。作者写道，若私人个体或行业建立 computationally accessible tax laws 而政府没有同样的语料，这 'could be disastrous'，因为富有的纳税人可能以很低或零边际成本识别并实施 tax shelter [p.23]。她称理想情况下税法代码与相关程序应开源并向所有人开放，以增加透明度与问责，并使个人与非营利组织能向政府举报 tax shelter；援引 Schizer，私人税务律师在许多方面于人员、资源与知识上 'outmatch' 政府，开源代码 'could help' 其他有意发现并关闭 shelter 的人平衡这一不对等 [pp.23–24]。结论中称私人个体与企业有 'a significant incentive' 编码税法以谋取自身利益 [p.24]。

## 5. 作者陈述的局限与前提

- 前提：形式化至少目前由人完成，而非由计算机分析大量文本得出 [p.3]；作者称 natural language processing 等自动化形式化 'have yet to succeed' 把税法译成计算机代码或其他形式化 [p.3]。脚注 6 称这并不令人意外，因为 Code 与 regulations 的篇幅 'relatively small'（作者以英法机器翻译所需的文本量对照其 'four million words'）；并称二者 'highly stylized'，但风格在 Code 与 regulations 之间、甚至 Code 内部并不一致 [pp.3–4]。
- Catala 的作用边界：形式化 'won’t eliminate' 歧义 [p.4]；不预测案件结果，不是 machine learning 或 artificial intelligence [pp.4–5]；Catala 不创造文中讨论的各种可能性，无论是好处还是风险 [p.18] [p.22]。
- 对示例与方法的限定：三条 default logic 规则只是 'one of many ways' 的表示，standard logic 语句同样只是 'one possible representation' [p.10]；default logic 形式化 'incomplete but not wrong' [p.11]；pair programming 'isn’t necessarily right for every project'，最有效的条件是律师略懂编码、程序员略懂税法 [p.13]。
- Code 与 regulations：作者称 Code 不是美国税法的完整陈述，'coding the Code' 更应理解为 'coding the Code and regulations'；规章常提供解释 Code 的细节，编码时需要它们 [p.17]。
- 可行性：手工翻译整个 Code 与 regulations 'unlikely, at least in the near future'，翻译其中部分 'could be manageable'，并称 Code 中相当大且相关的部分 'may soon be encoded' [p.18]。
- 对 tax shelter 清单的限定：脚注 149 称 IRS 可能无法生成所有可能的 shelter，因为法条与规章构成的链条长度 'may be no limit'；是否能证明不再有 shelter 可被生成，作者称 'totally outside the scope of this Article' [p.23]。脚注 148 称 reportable transactions 制度 'has its own problems'（目标活动常被定义得过宽或过窄，'similarity' 概念难以把握）[p.23]。
- 范围外的问题：自然语言之间能否做到完全准确的互译，作者称 'truly outside the scope of this paper' [p.8]。

## 6. 关键术语

- formalization / computationally accessible formalization：脚注 2 称，to 'formalize' 某物是用符号和逻辑连接词等把它表示出来；computer code 是一种计算机可访问的形式化 [p.3]。
- domain-specific programming language：为特定目的或应用而设计的编程语言，与适用范围普遍、不为特定领域设计的 general-purpose programming language 相对；Catala 是针对编码税法这一领域的 DSL [p.8]。
- default logic：基本想法是规则带优先级、高优先级规则覆盖低优先级规则的非标准逻辑；它是 nonmonotonic 的，已得出的结论可因更多信息而撤回，与 monotonic 的 standard logic 相对；作者称它有时被称为 'the logic of everyday reasoning' [pp.9–10]。
- pair programming：通常指两名程序员并肩在同一台计算机上写代码；本文中指一名律师与一名程序员合作编码 [p.13]。
- literate programming：Donald Knuth 提出的想法：程序不仅向计算机传达做什么，也向阅读程序的人传达程序要计算机做什么；在 Catala 中表现为代码内含大量注释，并把相关法条原文作为 comment 纳入 [p.16]。
- simplexity：文中引用 Blank 与 Osofsky：把税法描述为清晰且无争议、加上行政性修饰、且未能充分解释税法（如省略例外或特定要求）的指引 [pp.6–7]。
- chaining：作者用以指把互不相关的 Code 条款连起来、产生未预期的节税机会的 tax shelter 做法 [pp.20–22]。

## 7. 原文摘录

- "The question is not whether to formalize tax law but rather how to formalize it." [p.3]
- "Catala provides a tractable and functional approach to coding U.S. tax law that offers a more transparent formalization and could potentially hold the government more accountable than the current patchwork of forms, worksheets, and secret programs." [p.4]
- "Formalizing tax law in this way won’t eliminate its ambiguities." [p.4]
- "Most critically, Catala is structured using default logic, a nonstandard logic that represents the underlying structure of the U.S. tax code more accurately than does standard logic." [p.9]
- "Deciding which logic to use is a pragmatic choice. Default logic and standard logic can be used to represent the exact same law, both equally and accurately." [p.10]
- "Formalizing the tax law has the potential to make tax law more easily administrable in ways that will redound to the benefit of middle- and low-income taxpayers." [p.19]
- "If such a program is developed, the marginal cost of developing a tax shelter will drop to zero." [p.22]
- "To affirmatively help taxpayers and tax administration, and to guard against increased tax avoidance, the government should act as soon as possible to create a computationally accessible version of tax law." [p.24]
