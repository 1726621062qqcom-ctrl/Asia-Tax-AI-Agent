# From Text to Structure: Using Large Language Models to Support the Development of Legal Expert Systems

## 1. 研究问题与作者主张

- 研究问题：作者考察 LLM（如 GPT-4）能在多大程度上从立法文本中自动提取结构化表示：按 JusticeBot 方法用 LLM 从立法生成 pathways，评估这些 pathways，并与人工创建的 pathways 比较 [p.1]。两个研究问题：RQ1，LLM 能在多大程度上从真实立法中提取可用于 decision support system 的 pathways；RQ2，LLM 生成的 pathways 与人工创建的 pathways 相比如何 [p.2]。
- 背景与设想：作者写道 "Encoding legislative text in a formal representation is an important prerequisite to different tasks in the field of AI & Law." [p.1]。作者称，分析立法等来源并将其编码为所需形式表示的过程可能耗时，并构成此类系统开发中的 bottleneck [p.1]；作者设想由 LLM 生成 draft pathway，再由 legal expert 核对和补全，并称这可能使 JusticeBot 这类 legal decision support tools 的创建更高效，对 access to justice 产生更大影响 [p.2]。
- 方法主张：作者提出一个框架，输入单条立法（a single article or paragraph），用 LLM 提取其中规则的 pathway，pathway 可导入 JusticeCreator 由 legal experts 编辑；作者为此构建了 JusticeCreator Automatic Pathway Generator（JCAPG）[p.3]。作者要了解该方法能否生成可作为 legal decision support tool 基础的 plausible drafts [p.3]。
- 结果主张：作者报告，在 Civil Code of Quebec 的 40 条法条上，评审者把 40% 的自动生成 pathways 评为可直接使用（correct），另有 50% 评为只需 slight adjustment；盲测中 60% 的生成 pathways 被评为与人工 pathways equivalent 或 better [p.9]。作者称结果是 promising，并称该方法 suggests 'a promising path'，即利用 LLM 减轻基于符号方法的系统（作者称其 transparent and explainable）的开发成本 [p.1]。
- 定位：作者写道 "To our knowledge, this is the first attempt that uses LLMs to directly convert a text to a structured legal representation." [p.3]。Related Work 提到的既有工作包括 rule-based 表示（如 PROLEG）以及从立法文本自动抽取结构的尝试（如转为 UML/OCL、基于 morphology 的逻辑形式）[p.2]。作者称该研究意在对该方法做 initial validation [p.9]。

## 2. 方法

- 框架与 Figure 1（据 PDF 图像）[p.3]：输入为一条立法；用 LLM 提取其中规则的 pathway；pathway 可导入 JusticeCreator（作者引文献 27），用于创建 JusticeBot 工具，并由 legal experts 核对、改进和补充。作者构建 JCAPG 来提供这一功能。Figure 1 的步骤：System prompt 与 Legislation Text 输入 GPT-4，经 Intermediary Structure JSON 转为 JusticeBot JSON，再进入 JusticeCreator（adjustment，Legal Expert 参与），最终得到 JusticeBot。
- 提示与输出（§3.1）[p.4]：立法文本作为 user message；system message 要求提取 requirements 和 legal conclusions 并建立它们之间的 links；二者合并作为 prompt 提交。GPT-4 返回 logic blocks 及其连接的 JSON，随后转换为与 JusticeCreator 兼容的 JSON，导入后由 legal experts 核对并调整，例如纠正 logical errors。system message 全文未在论文中给出；footnote 3 给出含 prompt 与代码的 GitHub 地址 [p.5]。
- pathway 的构造（§4.2）[pp.4–5]：方法与文献 27 大体相似，把 legal criteria 编码为 'questions' blocks，并把其成立或不成立链接到更多 legal criteria 或 legal outcomes；作者不创建面向外行的简化语言 interviews，而使用 legal criteria 的第三人称表述 [p.5]。示例（Figure 2）：条文 Art 547 P1 CCQ 对应的 pathway 含 2 个 question blocks 和 2 个 conclusion blocks [p.5]。
- 人工 pathways [p.5]：四位 annotators（均为论文共同作者）创建人工 pathways，均有一定法律教育背景，其中 3 人此前使用过 JusticeCreator；他们在创建后给出法条的 'complexity' 评级（作者说明其涵盖结构复杂度与歧义），并记录创建所用时间（见 Table 1）。
- 自动 pathways [p.5]：通过 openai Python library 调用 GPT-4，默认模型参数，仅将 temperature 设为 0，作者给出的理由是降低模型 hallucinating 的风险并使输出更可复现。prompt 用 4 条不属于测试数据的法条迭代优化：例如模型偶尔生成会使 JSON parser module 崩溃的 recursive pathways，于是加入避免指令；作者还指示模型避免 'denying the antecedent'，效果为 'partial success'。最后在 40 条选定法条上运行 JCAPG。
- E1（§4.3）[p.5]：每位 annotator 对自动生成的 pathways 评分，并对照立法与自己的人工 pathway 比较，问题例如涉及 textual 与 structural accuracy 及作为初稿的 usefulness（Table 2）；作者说明 E1 不是盲测 [p.9]。E2（盲测）[p.5]：每位 annotator 拿到同一法条的两个 pathways，一个自动生成、一个人工创建，不知道哪个是哪个，就不同方面指出更偏好哪一个（Table 4）。
- 评价项 [pp.6–7]：Table 2 有五项：Textual Accuracy（pathway 的文本内容是否与法条一致）；Completeness（法条的所有 logical elements 是否都在 pathway 中）；No Hallucination（模型没有发明 criteria 或 conclusions）；Matching（pathway 的逻辑是否与人工 pathway 完全一致）；Overall Rating（作为 JusticeBot 工具基础的适合程度，等级 Correct / Slight Adjustment Necessary / Starting Point / Useless）[p.6]。Table 4 有三个盲测问题（整体、内容、逻辑结构），见 §4.1 [p.7]。
- 原文未说明的细节：每位 annotator 负责或评分的法条数量（Table 2 与 Table 4 中各问题的计数之和均为 40）；E2 中展示的人工 pathway 是否为评分者本人所作；Overall Rating 各等级的判定标准（除上述问题文字外）；GPT-4 的具体版本与调用日期；是否重复运行及运行次数；统计检验、置信区间和 annotator 之间的一致性指标 [pp.4–7]。

## 3. 数据与范围

- 来源：Civil Code of Quebec（CCQ）的条文；作者筛选出 40 条符合标准的法条：独立的条文或段落，含 criteria 和 conclusions 的描述，不依赖也不引用其他条文 [p.4]。正文没有列出这 40 条的清单；CCQ 条文所用语言原文未说明，Figure 2 的示例条文为英文 [p.5]。
- 复杂度范围：从很简单（一个 requirement 对应一个 outcome）到中等复杂（涉及多个相连的 criteria 与 legal conclusions）；这次初步实验排除了 'overly complicated articles that would pose considerable challenge even to domain experts' [p.4]；实验中还排除了 intermediary conclusions [p.7]。
- 难度分组：annotators 指定 Easy 18 条、Normal 14 条、Hard 8 条；各组平均统计见 Table 1（列于 §4.1）[p.4]。
- 评测的模型与对照：GPT-4（经 openai Python library 调用），论文未报告其他模型或 prompt 变体 [pp.4–5]；对照为 annotators 人工创建的 pathways；prompt 调优另用 4 条不在测试数据中的法条 [p.5]。
- 可得性：prompt 与运行分析的代码在 GitHub（https://github.com/samyarj/JCAPG-JURIX2023）[p.5]。

## 4. 结果

### 4.1 实证结果（作者报告的数字）

**E1：Table 2，40 个自动生成的 pathways，由 annotators 评价 [p.6]；作者说明 E1 不是盲测 [p.9]**

- Textual Accuracy：Yes 37（92.5%），No 3（7.5%）[p.6]。
- Completeness：Yes 29（72.5%），No 11（27.5%）[p.6]。
- No Hallucination：Yes 35（87.5%），No 5（12.5%）[p.6]。
- Matching：Yes 8（20.0%），No 32（80.0%）[p.6]。
- Overall Rating：Correct 16（40.0%），Slight Adjustment Necessary 20（50.0%），Starting Point 4（10.0%），Useless 0（0.0%）[p.6]。
- 按难度分组的 Overall Rating（Table 3 左）[p.6]：
  - Easy：Starting point 1（5.6%），Adjustment Necessary 6（33.3%），Correct 11（61.1%）[p.6]。
  - Normal：Starting point 1（7.1%），Adjustment Necessary 10（71.4%），Correct 3（21.4%）[p.6]。
  - Hard：Starting point 2（25.0%），Adjustment Necessary 4（50.0%），Correct 2（25.0%）[p.6]。
- 正文中的汇总数字：作者写道 Matching 为 Yes 的占 20%，同时 67.5% 的生成 pathways 被评为与人工 pathways 'equal logical quality' [p.6]；该 67.5% 在 Table 2 至 Table 4 中没有对应的行，原文未说明其计算方式 [pp.6–7]。作者在 §6.3 汇总：90% 的生成 pathways 为 correct 或只需 small adjustment，无 useless；Hard 法条中 75% 为 correct 或经调整后 useful [p.8]。
- 标签对应：§5.1 写 'Logical accuracy and lack of hallucination were slightly weaker, with 72.5% and 87.5% respectively'；72.5% 在 Table 2 与 §6.1 中对应 Completeness [pp.6–7]。

**E2：盲测，Table 4（各问题三栏计数之和为 40）[p.7]**

- Which Pathway is better overall?：Automatic Pathway 15（37.5%），Equivalent 9（22.5%），Manual Pathway 16（40.0%）[p.7]。
- Which Pathway Better Reflects the Content of the Law?：Automatic 14（35.0%），Equivalent 16（40.0%），Manual 10（25.0%）[p.7]。
- Which Pathway Better Reflects the Logical Structure of the Law?：Automatic 14（35.0%），Equivalent 10（25.0%），Manual 16（40.0%）[p.7]。
- 按难度分组的盲测整体比较（Table 3 右）[p.6]：Easy：Automatic 9（50.0%），Equivalent 5（27.8%），Human 4（22.2%）；Normal：Automatic 3（21.4%），Equivalent 4（28.6%），Human 7（50.0%）；Hard：Automatic 3（37.5%），Equivalent 0（% 栏印为 0），Human 5（62.5%）[p.6]。
- 作者在正文汇总：Easy 法条中 automatic pathway 被评为 better 或 equivalent 的比例为 77.8%，Hard 法条中降至 37.5% [p.7]。

**法条与耗时统计：Table 1（各难度组的平均值）[p.4]**

- Easy（N = 18）：Character Count 202.17；Token Count 40.83；Manual Time 3.19 min.；Automatic Time 19.18 sec.；Manual Nodes 4.06；Automatic Nodes 4.61 [p.4]。
- Normal（N = 14）：Character Count 256.50；Token Count 52.00；Manual Time 5.66 min.；Automatic Time 22.84 sec.；Manual Nodes 5.29；Automatic Nodes 5.43 [p.4]。
- Hard（N = 8）：Character Count 371.38；Token Count 74.38；Manual Time 7.32 min.；Automatic Time 27.54 sec.；Manual Nodes 6.13；Automatic Nodes 6.00 [p.4]。
- §6 的讨论中没有对这些时间和 nodes 数据作专门讨论 [pp.7–9]；Nodes 的计数口径、Automatic Time 的计时范围和 Token Count 的分词方式原文未说明 [p.4]。

### 4.2 作者记录的观察与评论（正文描述）

- 难度与评分：作者称，被 annotators 评为较难的法条，其生成 pathways 的评分整体上也较低（Easy 法条 61.1% 为 correct，Normal 与 Hard 分别为 21.4% 与 25%，即 Table 3 左）[p.7]。
- 歧义：作者称 annotators 的评论 frequently 提到法条的 ambiguity；法条有歧义时，模型 'would occasionally rely on (reasonable) assumptions not contained in the article' [p.7]。
- 拆分方式不唯一：作者称，即使法条清晰，也常常没有唯一 'right' 的方式把 criteria 和 conclusions 拆分成不同元素；模型有时把一个 criterion 放入最终 conclusion block，而不是作为 question；法条含多个 conclusions 时，由于实验排除了 intermediary conclusions，也不存在唯一 'correct' 的建法 [p.7]。
- 错误类型：作者称模型偶尔犯 'denying the antecedent' 的错误；也有较简单的错误，如误解法条结构，或生成带多个起点或不相连 blocks 的 pathway，作者称这些 'were rare' [p.8]。对更难的法条，作者称模型 sometimes 产出错误输出，例如 'missing important elements' 或基于文本之外的假设 [p.8]。
- 自我纠错：作者称 annotators 的评论中，有 5 处是 human annotators 在阅读自动生成的 pathway 后发现自己推理中的 logical errors [p.8]。

### 4.3 作者的解释或推论

- 作者认为 Textual Accuracy 的 92.5% 表明，在 prompt 中提供立法文本并要求模型贴合该文本 'seems like a viable method to constrain the textual output to the targeted legislative text' [p.7]。对 Completeness 的 72.5%，作者写 'somewhat lower'；对 40% correct 与 50% slight adjustment，作者称 'a promising result' [p.7]。
- 作者认为拆分方式的不唯一 'explains the low structural correspondence between manually and automatically created pathways, but does not necessarily impact the usefulness of the generated pathway' [pp.7–8]。关于歧义，作者称这 'mirrors prior discussion in the field'，并写道 doctrine, court cases and domain expertise 'may be needed' [p.7]。
- 盲测：作者称整体偏好 'evenly split between the generated and the manual pathways' [p.7]；作者称模型在 law 的 textual content 上 'shows strong performance'（'only 25%' 偏好人工 pathway）；在 logic 与 overall 上结果 'slightly weaker'（40% 偏好人工 pathway）；并称 60% 偏好 automatic 或认为 equivalent 'is a positive result' [p.8]。
- 难度的影响：作者写道 it seems like 模型创建 pathway 的能力 'compares favourably to human annotators, especially for the case of easy articles'；对更难的法条，'the model sometimes produces an incorrect output' [p.8]。
- augmented intelligence：作者称 E1 的最后一个问题给出 'A first indication'，并称多数生成的 pathways 因此被视为有用，'which is promising' [p.8]。作者称 JCAPG 的 pathways 在 37.5% 的情况下被评为优于人工 pathways，并写 'It seems like in some instances, the model can capture nuances or logical particularities that the humans missed'，同时提到 5 处自我纠错的评论 [p.8]。
- 作者写道，这些结果 'seem to indicate' JCAPG 与 human expert 配合使用 'has the potential to support the annotator with a strong draft, resulting in more efficient annotation, and even leading to more logically correct pathways' [p.8]。作者把对 'the quality and efficiency of using the generated pathways as drafts for annotators' 的研究列为 future work [p.9]。

## 5. 作者陈述的局限与前提

- 作者称该研究意在对该方法做 initial validation [p.9]。
- 法域：实验只基于 CCQ 的一组条文；作者指出该法典属于 civil code tradition，该传统 'focuses on drafting articles that are easy to understand for laypeople'（引文献 3），并写道 "It is possible that the results would not translate to jurisdictions that do not have this aim." [p.9]
- 法条选择：作者有意选择独立且相对简单的条文，其中一些为中等复杂度；作者写道 "The results may not replicate to very complex articles, or articles that can only be read in conjunction with other articles (see future work)." [p.9]
- 评估设计：第一个实验（E1）不是盲测，annotators 数量相对较少；作者称这意味着 biases may have entered into the analysis [p.9]。
- 范围：pathway 的结构化只是创建 JusticeBot legal decision support tool 的一部分；还需要简化内容、为各个 criteria 撰写面向外行的解释，以及给各个 question blocks 添加判例摘要 [p.9]。
- 文中明确的范围设定：只处理单条立法 [p.3]；排除过于复杂的条文 [p.4] 与 intermediary conclusions [p.7]；设想由 legal expert 核对并补全生成的 draft [p.2]。
- 作者列出的 future work [p.9]：增加 annotators 并纳入更复杂的法条；处理多条相连的法条；可能整合 case law 和/或 doctrine 以消解歧义；研究把生成的 pathways 作为初稿时的质量与效率；以其他方式整合 LLMs，例如把案件事实映射到生成的 pathways。

## 6. 关键术语

- pathway：作者采用文献 27（参考文献列表中的 JusticeBot 一文 [p.10]）的表示，写道 "which comprises legal criteria and legal conclusion that are linked together in a pathway that shows the criteria that need to be met to arrive at given conclusions" [p.2]。
- 'questions' blocks：作者把 legal criteria 编码为 questions blocks，并把其成立或不成立链接到更多 legal criteria 或 legal outcomes [pp.4–5]；Figure 2 中的 question block 带有 Yes / No 选项 [p.5]。
- JusticeBot 与 JusticeCreator：作者称 JusticeBot 方法用于 legal decision support systems [p.1]；JusticeCreator 用于创建 JusticeBot 工具，pathway 可导入其中由 legal experts 编辑 [p.3]。
- JCAPG（JusticeCreator Automatic Pathway Generator）：作者构建的工具，目的是 "to make this functionality accessible to the legal experts" [p.3]。
- denying the antecedent：作者写道 "Another error the model made occasionally was 'denying the antecedent', i.e., incorrectly inferring conclusions not in the article." [p.8]
- augmented intelligence（或 hybrid intelligence）：作者以此称呼工具的用法，即 "that suggests a pathway to the expert annotator, who can then evaluate it and adjust it if necessary" [p.8]。

## 7. 原文摘录

- "The results are promising, with 60% of generated pathways being rated as equivalent or better than manually created ones in a blind comparison." [p.1]
- "RQ1 - To what degree can the LLM extract pathways from real-world legislation to be utilized in a decision support system? ... RQ2 - How do the pathways generated by an LLM compare to manually created pathways?" [p.2]
- "we specifically selected stand-alone articles or paragraphs containing descriptions of criteria and conclusions, which did not depend on nor reference other articles." [p.4]
- "We used default model parameters, except the temperature value, which we set to 0 to decrease the risk of the model hallucinating and making the output more reproducible." [p.5]
- "Even though only 20% of the generated articles matched the manually created pathways, 67.5% of generated pathways were rated to be of equal logical quality as the manually created pathways." [p.6]
- "Overall, the preference was evenly split between the generated and the manual pathways. ... While for the easy articles the automatic pathway was rated as better or equivalent in 77.8% of cases, for the hard articles this percentage dropped to 37.5%." [p.7]
- "Thus, it seems like the ability of the model to create a pathway from legislation compares favourably to human annotators, especially for the case of easy articles. For the more difficult articles, the model sometimes produces an incorrect output, e.g., missing important elements ..." [p.8]
- "Third, our first experiment is not conducted in a blind fashion, with relatively few annotators, which means that biases may have entered into the analysis." [p.9]
