# SQL’s Three-Valued Logic and Certain Answers

## 1. 研究问题与作者主张

- 问题：作者要弥合含 null 数据库上查询求值的理论做法与实践做法之间的差距。理论界以 certain answers（不论缺失信息如何解释都为真的答案）为正确性标准，作者称其计算复杂度很高；SQL 为了效率用 three-valued logic 求值。作者问：SQL 是否总给出可以确定的答案 [p.1]。
- 作者报告：SQL 的语义与 certain answers 语义可以毫无关系 [p.1]；SQL 的求值规则可同时产生 false negatives（漏掉 certain answers）与 false positives（返回并非 certain 的答案）[p.3]。作者依据复杂度差异（certain answers 对完整关系演算在多数 reasonable semantics 下为 CONP-hard，SQL 求值在 DLOGSPACE，甚至 AC0）认为 SQL 求值必产生 false negatives 或 false positives [p.2]。
- 作者主张：对 SQL 所用 three-valued 语义（针对 relational calculus 查询）做小的改动，即可使返回的元组都是 certain answers，即 certainty guarantees [p.1][p.3]。做法是充分利用三值，把候选答案分为 certainly true、certainly false、unknown，而非只分 certain 与否 [p.1]；在 relational calculus 与 relational algebra 两层给出求值程序 [p.1]；并用 certain answers with nulls，使答案可含 null 元组 [p.4]。
- 取舍：作者把 false negatives 比作隐去部分真相，把 false positives 比作公然的谎言 [p.2]，并采取后者更糟的立场；目标是消除 false positives，同时求值快、不大幅改动现有求值技术 [p.3]。

## 2. 方法

- 数据模型：数据库由 constants（Const）与 nulls（Null，记 ⊥）构成；作者采用 marked（naive）nulls，同一 null 可在表中重复出现，SQL 的 nulls 相当于禁止重复的特例 [p.4]。valuation 是把 null 映成常量的 homomorphism；closed-world assumption (CWA) 下 [[D]] = {h(D) | h 为 valuation}，open-world assumption (OWA) 下还可加入有限多个完整元组 [p.5][p.14]。
- 正确性标准：cert(Q, D) 是 [[D]] 中所有 Q(D′) 之交 [p.2]。cert⊥(Q, D) 是使每个 valuation h 都有 h(ū) ∈ Q(h(D)) 的 ū ∈ adom(D)^k 的集合；去掉含 null 的元组即得 cert [pp.9–10]。
- 求值程序 Eval(ϕ, D, ν)：取值于 {0, 1} 或 {0, 1/2, 1}（1/2 表示 unknown）；∨、∧、¬、∃、∀ 依次按 max、min、1 − x、max、min 计算（规则 (5)），各程序只在原子公式的规则上不同；Eval(ϕ, D) 取 Eval = 1 的元组 [pp.5–6]。EvalFO 是朴素求值；EvalSQL 对 R(x̄) 同 EvalFO，对 x = y：两常量相等得 1、不等得 0、任一为 null 得 1/2 [p.6]。
- Eval3v（作者提出）：R(x̄) 在 ν(x̄) ∈ R^D 时得 1，在 R^D 中无元组与 ν(x̄) unify 时得 0，否则得 1/2；x = y 在 ν(x) = ν(y) 时得 1，在两者为不同常量时得 0，否则得 1/2 [p.8]。作者的理由：EvalFO 与 EvalSQL 对关系原子过于轻易地取 0，否定会把 0 变 1 而产生 false positive；不同 nulls 的等式应得 1/2，ν(x) = ν(y) 应得 1，否则漏掉 certain answers [p.8]。
- 变体：UCQ≠（带不等式的 UCQ）用两值的 EvalUCQ≠，只对 x ≠ y 加规则：两者为常量且不等得 1，否则得 0 [p.13]。OWA 下的 Eval3v^OWA 有三处不同：R(x̄) 不属于 R^D 时得 1/2；∃ 的值至少为 1/2；∀ 的值至多为 1/2 [p.15]。
- 关系代数：RA 含 σ、π、×、∪、∩、−（unnamed perspective）；RAnull 的选择条件另含 const(♯n)、null(♯n) [pp.16–17]。作者给出翻译 Q → (Q+, Q−)，要求 Q+(D) ⊆ cert⊥(Q, D)、Q−(D) ⊆ cert⊥(Q̄, D)（Q̄ 为补查询）[p.17]。条件翻译 θ*：等式不变，(♯n ≠ ♯m)* = (♯n ≠ ♯m) ∧ const(♯n) ∧ const(♯m)，(♯n ≠ c)* = (♯n ≠ c) ∧ const(♯n) [p.17]；relative complement R⊖ = {ū ∈ adom(D)^k | 不存在 t̄ ∈ R 使 ū ⇑ t̄} [p.17]。各规则（Figure 1，取自 Theorem 6.1 的证明）：R+ = R，R− = R⊖；(σθ(Q))+ = σθ*(Q+)，(σθ(Q))− = Q− ∪ σ(¬θ)*(adom^k)；(πα(Q))+ = πα(Q+)，(πα(Q))− = πα(Q−) − πα(adom^ar(Q) − Q−)；∪ 的 + 取并、− 取交；∩ 的 + 取交、− 取并；(Q1 − Q2)+ = Q1+ ∩ Q2−，(Q1 − Q2)− = Q1− ∪ Q2+；(Q1 × Q2)+ = Q1+ × Q2+，(Q1 × Q2)− = Q1− × adom^ar(Q2) ∪ adom^ar(Q1) × Q2− [pp.18–20]。
- 其他：作者把翻译看作一族（每个运算 ω 对应一对查询 F+ω、F−ω）[pp.21–22]；semijoin 与 antijoin 的规则为 (11) [p.25]。作者不走 RA→FO→RA 的路径，理由是可能产生不必要地复杂的表达式，且结果取决于所选的 RA–FO 翻译 [p.16]。证明用对公式或查询结构的归纳 [p.11][p.18]。

## 3. 数据与范围

- 无数据集、样本量、时期或被评测的系统，不涉及法域；全文为形式化论证，所用数据库是作者构造的小例子（如 R^D = {1}、S^D = {⊥}）[p.3][p.7][pp.14–16][pp.23–24]。
- 查询范围：FO（relational calculus）与 relational algebra，采用 set semantics；对应 SQL 的 select-from-where（含子查询），不含 grouping 与 aggregation；作者处理的是 SQL 翻译后的查询，而非 SQL 本身 [pp.3–4]。语义以 CWA 为主，OWA 见第 5.2 节 [pp.14–16]。
- DBMS：脚注 1 称 query (9) 的行为对多数有 except（Oracle 为 minus）运算符的 DBMS 成立；没有该运算符的（如 MySQL）可用一个 left outer join 查询得到同样结果；具体系统、版本与检验方式原文未说明 [p.23]。

## 4. 结果

- 【实证结果】原文未报告实验或实现；作者在结论中写明还需要实验研究 [p.26]。以下为形式结果与作者构造的示例。
- 【示例】select S.A from S where S.A = 0 or S.A <> 0 在仅含一行 null 的 S 上不返回元组 [pp.1–2]；R.A not in (select S.A from S) 在 S 含单个 null 时不返回任何元组，与 R 无关 [p.2]；T(A, B) 仅含 (1, null) 时 select T.A from T where T.B=T.B 返回空结果 [p.4]。作者称例 (1) 漏掉了 certain answer（false negatives 的例子），例 (2) 实际给出了 certain answer，但可轻易改成产生 false negatives [p.2]。
- 【示例】query (4)（表达 R −(R −S)）与 (select * from R) except (select * from S) 在 R = {1}、S = {null} 上都输出 {1}，certain answer 为空 [p.3]。T = {(1, ⊥)}、ψ(x) = ∃y (T(x, y) ∧ (x = 1 ∨ ¬(x = 1)))：certain answer 为 {1}，EvalSQL 得空集 [p.7]。
- 【命题】cert(ϕ, D) ⊆ EvalFO(ϕ, D)；EvalFO 对 UCQ 有 certainty guarantees（作者引 Imielinski and Lipski 1984），对类 Q^cert_FO 也有（引 Gheerbrant et al. 2014）；Proposition 3.2：EvalSQL 对 UCQ 有 certainty guarantees；对一般 FO 查询，作者写 EvalSQL 与 cert 之间没有任何联系 [p.7]。
- 【定理】Theorem 4.1：Eval3v 对所有 FO 查询有 certainty guarantees [p.9]。Theorem 5.3：Eval3v(ϕ, D) ⊆ cert⊥(ϕ, D)；若 Eval3v(ϕ, D, ā) = 0，则 ā ∈ cert⊥(¬ϕ, D) [p.10]。
- 【示例】ϕ(x) = R(x) ∧ ¬(R(x) ∧ ¬S(x))、R^D = {1}、S^D = {⊥}：EvalSQL(ϕ, D) = {1}，Eval3v(ϕ, D) = ∅。R^D = {(⊥, ⊥)}、ψ = ∃x, y R(x, y) ∧ x = y：Eval3v(ψ, D, ν) = 1，EvalSQL(ψ, D, ν) = 1/2；作者据此说 Eval3v 的结果不必含于 EvalSQL 的结果 [p.9]。
- 【命题】Proposition 5.2：cert = cert⊥ ∩ Const^|x̄|；cert⊥ ⊆ EvalFO；ϕ ∈ Q^cert_FO 时 cert⊥ = EvalFO；存在 FO 查询使 cert⊥ ≠ EvalFO [p.10]。Corollary 5.4：cert⊥(ϕ, D) ⊆ adom(D)^|x̄| − Eval3v(¬ϕ, D) [p.12]。Proposition 5.5：D 完整时 Eval3v 只取 0、1，且等于 EvalFO [p.12]。
- 【命题】Proposition 5.6：对每个 FO 查询 ϕ 与 α ∈ {0, 1/2, 1}，有 FO 查询 ϕα（词汇表加一元谓词 const）使 {ā | Eval3v(ϕ, D, ā) = α} = EvalFO(ϕα, D)，故 Eval3v 的 data complexity 在 AC0 [p.12]；作者称由此复杂度论证可知，存在 Eval3v 得不到全部 certain answers 的情形 [p.13]。
- 【定理与反例】Theorem 5.7：对 UCQ≠，EvalUCQ≠(ϕ, D) = Eval3v(ϕ, D) ⊆ cert⊥(ϕ, D) [p.13]。ψ = ∃x∃y R(x, y) ∧ x ≠ y、R^D = {(⊥, 1), (⊥, 2)} 时，cert⊥(ψ, D) = cert(ψ, D) = true 而 EvalUCQ≠(ψ, D) = 0，作者称 Eval3v 同样未捕获 cert⊥；经 3-colorability 的归约，UCQ≠ 的 certain answers 有 CONP-complete data complexity，即使无自由变量 [p.14]。
- 【OWA】Eval3v 在 OWA 下无 certainty guarantees：R^D = {(1, 2)}、S^D = {(⊥1, 1), (2, ⊥2)}、ϕ = R(x, y) ∧ ¬S(x, y) 时 (1, 2) ∈ Eval3v(ϕ, D)，但 S^D′ = {(1, 1), (2, 2), (1, 2)} 的 D′ ∈ [[D]]OWA 上 EvalFO(ϕ, D′) 为空 [p.15]。Proposition 5.8：Eval3v^OWA 在 OWA 下有 correctness guarantees；该例中 (1, 2) ∉ Eval3v^OWA(ϕ, D) [pp.15–16]。
- 【定理】Theorem 6.1：Figure 1 的翻译有 correctness guarantees [p.18]。Proposition 6.2：D 完整时 Q+(D) = Q(D)，Q−(D) = Q̄(D) [p.20]。Proposition 6.3：包含于该翻译的翻译都有 correctness guarantees；作者举 (Q1 × Q2)− 用 Q1− × Q2−、(σθ(Q))− 用 Q− 为例，并称代价是结果中的答案可能更少 [pp.21–22]。Corollary 6.4：PosRA≠ 查询的每个条件 θ 换成 θ* 得 Q*，则 Q*(D) ⊆ cert⊥(Q, D) [p.22]。
- 【示例】两值语义下等价的 ϕ(x) = ∃y (R(x, y) ∧ (y = 1 ∨ y ≠ 1)) 与 ϕ′(x) = ∃y R(x, y)：R^D = {(1, ⊥)}、ν: x → 1 时 Eval3v(ϕ, D, ν) = 1/2，Eval3v(ϕ′, D, ν) = 1 [p.16]。
- 【示例】R = {1, 2}、S = {⊥}：query (2) 返回空集，query (9) 返回 {1, 2} [p.23]。表（R^D = {1}、S^D = {⊥}；ϕ = R(x) ∧ ¬S(x)，ψ = R(x) ∧ ¬∃y (S(y) ∧ ȳ = x)）在输入 1 上：EvalFO 为 1、1，EvalSQL 为 1、1/2，Eval3v 为 1/2、1/2；输入 ⊥ 时各程序均为 0 [p.23]。
- 【命题】Proposition 7.1：存在 D、ν、ν′，使 EvalSQL(S(x)) 在 ν 下小于、在 ν′ 下大于 EvalSQL(S_D(x))（证明中为 0 对 1/2、1 对 1/2）[p.24]。Proposition 7.2：Eval3v(S(x̄), D, ν) ≤ Eval3v(S_D(x̄), D, ν)，S^D 中 nulls 不重复时取等；作者称取等需要此条件，并给出 S^D = {(1, 2)}、adom(D) 含 ⊥、ν: (x, y) → (⊥, ⊥) 时 0 对 1/2 的例子 [p.24]。
- 【定理与推论】Theorem 7.3：在 Theorem 6.1 的翻译上加 semijoin、antijoin 的规则 (11) 后仍保持 correctness guarantees [pp.25–26]。Corollary 7.4：(Q1 antijoin Q2)+ = (Q1 − Q2)+ [p.26]。
- 【作者的解释或推论】SQL 出现 false positives 的原因：条件用 three-valued logic 求值，但结果只保留取值 true 的元组，unknown 与 false 被合并；否定把 true 翻成 false，而把 unknown 与 false 都翻成 true [p.3]。
- 【作者的解释或推论】作者认为，把 Q+ 当作含 null 数据库上 Q 的实现时，antijoin 与集合差相同，query (2) 与 (9) 不再有差别，方案在声明式（Eval3v）与过程式（Q+）两层处理了 SQL 的这一不一致 [p.26]；作者称 Propositions 5.5 与 6.2 表明其近似没有无谓地漏掉答案 [p.27]。

## 5. 作者陈述的局限与前提

- 集合语义：全文用教科书版 relational algebra/calculus 的 set semantics，而 SQL 用 multiset semantics；作者称目前没有 multisets 上 certain answers 的恰当对应概念与不完备性的关系理论，需先建立才能扩展结果 [p.4][p.27]。
- 范围与前提：不含 grouping 与 aggregation；处理的是 SQL 翻译后的查询 [pp.3–4]。null 理解为缺失值 [p.2]，采用 marked nulls [p.4]。作者假设所有属性共用单一域（称其为标准的理论简化），实际各列有类型，作者称这点容易处理 [p.26]。
- 保证的方向与上限：方案保证无 false positives（underapproximation）[p.12]；因 cert⊥ 的 data complexity 为 CONP，作者认为不能期望相等，称此保证是能指望的最好结果 [p.17]；Eval3v 在某些情形得不到全部 certain answers [pp.13–14]。
- OWA：Eval3v 在 OWA 下失去保证 [p.15]；作者称 OWA 下复杂度更高，因而更难得到 good approximations，且 OWA 下求 certain answers 不可判定（引 Abiteboul et al. 1991、Gheerbrant et al. 2012）[pp.14–15]；Eval3v^OWA 对关系原子不返回 0，对 ∃ 的最低值与对 ∀ 的最高值都是 1/2 [pp.15–16]。
- 效率：作者称所提程序的理论复杂度与关系演算、代数本身的 data complexity 一样低；翻译产生的大笛卡儿积会增加实际复杂度，需要实现并作调整 [pp.26–27]；取更小的包含翻译可提高效率，但答案可能更少，需权衡 [p.22]。
- 作者所列待做：实验研究 false positives 在实际中多常见（与真实 certain answers 比较的代价很高）[p.26]；近似质量的实验与理论分析 [p.27]；查询优化规则在新求值下是否仍成立 [p.27]。

## 6. 关键术语

- certain answers，cert(Q, D)：Q 在 [[D]] 中所有完整数据库上的答案之交，即不论缺失信息如何解释都在答案中的元组；只含常量元组 [p.2][p.6]。
- certain answers with nulls，cert⊥(Q, D)（Definition 5.1）：使每个 valuation h 都有 h(ū) ∈ Q(h(D)) 的 ū ∈ adom(D)^k；作者称这是对 Lipski [1984] 的扩展，该概念曾有其他名称 [p.9]。
- false negatives / false positives：求值程序未产生某些 certain answers / 产生了并非 certain 的答案 [p.2]。
- certainty guarantees（Definition 3.1）：对类 Q 中每个查询 ϕ、每个数据库 D、每个常量元组 ā，ā ∈ Eval(ϕ, D) 蕴含 ā ∈ cert(ϕ, D) [p.6]。对翻译 Q → (Q+, Q−)，作者称满足 Q+(D) ⊆ cert⊥(Q, D) 与 Q−(D) ⊆ cert⊥(Q̄, D) 时 provides correctness guarantees [p.17]。
- marked (naive) nulls：可在表中多次出现的 nulls [p.4]；EvalFO 在不完备数据库上通常称 naive evaluation [p.6]。
- unify（t̄ ⇑ s̄）：同长元组若存在 homomorphism h 使 h(t̄) = h(s̄) 则称 unify；作者称可在线性时间检验（引 Paterson and Wegman 1978）[p.8]。
- Q+ 与 Q−：Q 的两个翻译查询，作者称可看作找出 Eval3v 取 0 或取 1 的元组的类似物；Q+(D) ∩ Q−(D) = ∅，不属于二者的元组本质上是 unknown [p.17]。

## 7. 原文摘录

- "This is not so: SQL’s and certain answers semantics could be totally unrelated. We show, however, that a slight modiﬁcation of the three-valued semantics for relational calculus queries can provide the required certainty guarantees." [p.1]
- "SQL query evaluation must produce either false negatives or false positives." [p.2]
- "Three-valued logic is used to evaluate conditions, but then query results return only those tuples for which conditions evaluate to true, effectively collapsing unknown and false." [p.3]
- "We take the view here that the outright lie (false positives) is worse than hiding some of the truth (false negatives)." [p.3]
- "Understanding how to extend results to the multiset semantics is a project for future work. We do not, at this time, have a proper analog of certain answers and relational theory of incompleteness for databases with multisets, ..." [p.4]
- "The evaluation procedure Eval3v no longer has certainty guarantees under OWA." [p.15]
- "As noticed already, due to CONP-data complexity of cert⊥(Q, D), we cannot hope for equality, so this correctness guarantee is the best we can count on." [p.17]
- "We need an experimental study showing how common the problem actually is. A starting point could be a set of benchmark queries on randomly generated data; the main challenge is comparing with real certain answers that are computationally very costly." [p.26]
