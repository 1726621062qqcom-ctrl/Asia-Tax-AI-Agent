# Metamorphic Testing: A Review of Challenges and Opportunities

## 1. 研究问题与作者主张

- 目标：作者综述 metamorphic testing（MT）的现有研究，讨论尚待解决的 challenges，提出改进 MT 的 visions，并指出新研究的 opportunities [p.1]。作者称本文不求穷尽已有研究，而聚焦其所称 “most important and influential” [p.3] 的 MT 研究、这些研究之间的关系及其影响。
- 作者主张 MT 同时用于 test case generation 与 test result verification，因而同时应对 oracle problem 与 reliable test set problem [p.2]；称 MT 是缓解（alleviate）oracle problem 的 effective approach [p.2]，但写明该问题无法被完全解决 [p.8]。
- 作者称有三项贡献（均限定为 to the best of our knowledge）：概括并澄清 MT 的核心概念（Sections 2–3）；讨论传统测试、测试之外的扩展、与其他软件工程方法的集成三类情境中的 MT 研究及 challenges（Sections 4–6）；列出 opportunities（Section 7）；三项均用 by far the most 的比较表述 [p.3]。
- 概念澄清与优势：作者澄清四个常被误解的概念——并非所有 necessary properties 都是 MR（如 −1 ≤ sin(x) ≤ 1 只涉及单个输入）；并非所有 MR 都可拆成仅涉及输入与仅涉及输出的子关系；并非所有 MR 都是等式；MT 在有或没有 usable oracle 时都可应用 [pp.6–8]。作者列举四项优势：概念简单、实现直接、有 MR 时易于自动化、成本低，称这些优势并非 MT 独有，但 MT 是同时具备它们的 few techniques 之一 [pp.5–6]。
- MR 含义与结论建议：作者称 MR 已由目标算法的 necessary properties 扩展为也含用户期望的属性，并预期这一演变继续 [p.14][p.22]；建议开发假定或需要 test oracle 的新软件工程方法时可考虑 MT，称这 may 降低对 oracle 的要求并扩展方法的适用范围 [p.22]。

## 2. 方法

本文是综述加讨论，已读正文中未描述作者自行开展的实验或系统实现。Sections 4–6 各先概述 state of the art，再提出 critical challenges，Section 7 列 opportunities [p.3]。作者所述的重点研究取舍标准：研究开辟了 MT 的新方向，或其结果有 significant impact [p.3]；文献检索来源与筛选程序原文未说明。

- 形式化 [pp.4–5]：Example 1（最短路径）的 MR 为交换起点 a 与终点 b 后路径长度不变，|f(G,b,a)| = |f(G,a,b)|。Definition 1：MR 是 f 在由 n ≥ 2 个输入组成的序列及其输出上的 necessary property，记作 R ⊆ X^n × Y^n；脚注称 necessary property 指可由算法逻辑推出的条件 [p.4]。Definition 2–3：已指定的输入为 source inputs，据其（必要时含其输出）按 R 构造的为 follow-up inputs，合称 metamorphic group (MG)。
- Definition 4（MT 的步骤）[p.5]：(1) 在 R 中以 P 代 f 得 R′；(2) 执行 source test cases，按 R′ 构造并执行 follow-up test cases；(3) 对照 R′ 检查结果，R′ 不成立即表明 P 有 fault。作者称由此无需核对任一 test case 的 P(xi) = f(xi)，即无需 test oracle [p.5]。
- 已有评估的常见设计（作者概括）[p.8]：以 random testing (RT) 为基准；向 base program 植入 faults 得 mutants，base program 作 oracle；有 oracle 的 RT 为上界，无 oracle 的 RT 为下界（只能检出与崩溃相关的 faults）。
- Proving MRs [pp.12–13]：semi-proving 用 symbolic analysis 证明 MR，MR 不成立时给出使其被违反的输入约束；Gotlieb 与 Botella 用 constraint logic programming，约束系统矛盾即表示 MR 被满足。
- 集成框架 [pp.14–15]：单个 test case 对应一个 MG；pass/fail 对应 MR 的 satisfaction/violation。作者以此改写 debugging with slicing 与 Spectrum-Based Fault Localization，称改写后可用于没有 test oracle 的应用领域 [p.15]。

## 3. 数据与范围

- 本文为综述，已读正文未描述作者自己的数据集、样本或基准；文中数字转述自所引研究（如 [50]、[55]、[81]），这些研究的样本与统计细节除第 4 节所列外原文未说明 [pp.2–11]。
- 文献范围：MT 自 1998 年首次发表以来的研究 [p.2]；作者提及 Segura 等 [81] 的综述分析了 1998 至 2015 年发表的 119 篇论文 [p.2]；本文涉及的文献总数、检索数据库与纳入/排除标准原文未说明 [p.3]。
- 作者列出的应用领域：bioinformatics、web services、embedded systems、components、compilers、databases、machine-learning classifiers、search engines、software product lines、security [p.8]；被引研究的对象与样本见第 4 节各条。

## 4. 结果

**实证结果（作者转述所引研究的结果；已读正文未报告新实验）**

- Siemens suite：作者报告 MT 在其七个程序中的三个里检出 three real-life faults [77, 93]；这些程序规模较小，此前约二十年反复用于研究 [p.2][p.10]。
- 编译器：Le 等 [50] 用一个 MR（源程序 SP 与 SP′ 在输入 I 上等价，则其 object programs 也在 I 上等价；SP′ 由 SP 删去 I 下未执行的语句得到）在 GCC 与 LLVM 中检出 over 100 faults，同一技术在 OpenCL compilers 中检出 over 50 new bugs [51] [p.11]；Tao 等 [86] 此前用 MT 在 GCC 与 UCC 中各只找到 one fault [p.11]。
- Segura 等 [81] 报告 MT 已检出 about 295 real-life faults [p.10]；其观察到的以往研究中，57% 的 source test cases 随机生成，34% 来自已有 test suites [p.11]。
- Liu 等 [55]：六个 subject programs 中，MT 平均只需 three to six diverse MRs 即可揭示 oracle 能检出的 faults 的 at least 90% [p.8]；作者概括，MRs 用得越多，MT 检出的 faults 越接近有 oracle 的 RT，MRs 足够 diverse 时其检错效果被发现趋近 oracle [p.8]。
- 比较：作者称通常的报告是 MT always 比无 oracle 的 RT 检出更多 faults；与 assertion checking 相比，MT 的计算成本 slightly higher，被观察到检出更多 faults；MT 与 error trapping 检出不同类型的 faults，故有人建议测试 spreadsheets 时二者并用 [pp.8–9]。
- 以往实验：作者指出部分 MT 实验的结果 contradictory，MRs 的效果（如 [17, 62]）has not been conclusively determined [p.9]。
- Validation：kNN 与 Naive Bayes 的实现违反部分 MRs [91]；进一步调查发现其中一些被违反的 MRs 并非目标算法的 necessary properties，而是用户期望的属性，如用户期望类别标签顺序不影响分类，而 kNN 无此性质 [p.13]。
- Search engines [98]：作者报告被考察的 search engines（含 Google、Bing、Baidu）在大域搜索时出现 performance degradation [p.13]；开发者可复现部分 MR violations，并确认其由 software faults or design flaws 引起 [p.14]。
- Spreadsheets：一个非专业人员团队以 ad hoc 方式为五个含真实 faults 的 spreadsheets 识别 MRs，检出了全部 faults [73] [p.20]。
- 学习与教学：作者引 [55, 73] 称经验不多的 testers 在 a few hours 内即可学会 MT 并正确应用于多种系统 [p.5]；教学报告称学生接受并能较容易应用 MT，但在学习材料与活动的可得性上遇到问题 [p.18]。

**作者的解释与推论**

- Siemens 结果：作者写 This clearly demonstrates MT 与现有 test case selection strategies 互补，归因于 MT 从不同视角生成 test cases，并称其强调了 test case diversity [pp.10–11]。
- 编译器结果：作者称 Le 等与 Tao 等检出 faults 数量的 dramatic difference 强调了 MR 选择对 MT 检错效果的 significant impact；作者称不知道两个编译器的测试历史 [p.11]。
- MR 识别难度：作者称 [50] 用 a very simple MR 检出 hundreds of real-life bugs 是 strong evidence，表明识别 good MRs may not be difficult at all [pp.5–6]；另称 MR identification 无法完全自动化 [p.5]，多数以往识别以 ad hoc 方式进行 [p.9]。
- Metamorphic fault tolerance 的 Example 5：作者称该 naive 机制可能同时产生 false negatives 与 false positives [p.17]；MR violation 只能说明 MG 中至少一个 test case 与 fault 有关，作者称此 precision problem 是 MT 的 intrinsic characteristic 与 unavoidable cost [p.16]。
- MR 的来源：verification 来自 specifications，validation 来自 user expectations，quality assessment 可由 various stakeholders 定义 [p.13]。
- 7 项 Challenge：comprehensive empirical studies [p.9]；systematic MR identification and selection [p.9]；effective test case generation [p.11]；metamorphic proving [p.12]；unified and comprehensive framework [p.14]；new concepts [p.15]；new techniques [p.16]。
- 7 项 Opportunity：theory of MT，含基于 METRIC 的 MR diversity metric [pp.17–18]；teaching and training [p.18]；MR coverage criterion 与以 MR 作 open-source software 的质量度量 [pp.18–19]；end-user testing，作者称 MT may be the most appropriate testing technique for end-user programmers [p.20]；cloud and crowd [p.20]；big data [p.21]；agile development [p.21]。

## 5. 作者陈述的局限与前提

- MT 只能缓解 oracle problem：有用的性质数量巨大，几乎不可能得到完整的 MR 集；即使得到，因这些性质 necessary but not sufficient，也可能不等价于 test oracle [p.8]。
- MRs 被 tested 而非 proven：没有 MR violation，仍不能断定程序对全部输入满足该 MR [p.12]；现有基于 MT 的证明技术，其 applicability 与 scalability 依赖相应支持工具 [p.13]。
- 评估：对 MT 整体效果的 thorough evaluation 仍 lacking；多数实验限于一个领域或小、中型程序 [p.9]。
- MR identification 与 selection：多数以往研究 ad hoc、多数技术适用性有限；基于程序执行识别的 MRs 在实现有 fault 时可能 erroneous；METRIC 仍 relies somewhat on 测试者的专业经验；选择指南 qualitative 且较主观 [pp.9–10]。
- Source test cases 对 MT 效果的影响研究仍处初期，评估并保证所生成 test cases 的效果 quite challenging [p.11]。
- 集成：作者称 may not be universally possible 用 MT 增强每一种相关方法 [p.15]；MR violation 的定位存在 precision problem [p.16]。
- 范围：本文不是穷尽式综述 [p.3]；Section 7 的清单 not exhaustive，只含作者认为 most promising 的方向 [p.17]。

## 6. 关键术语

- oracle problem 与 test oracle：oracle problem 指 “extremely difficult, or impossible, to verify the test result of a given test case” [p.2] 的情形；test oracle 是检查执行结果的系统机制 [p.2]。
- Metamorphic Relation (MR)：f 在两个或更多输入及其输出上的 necessary property；necessary property 指可由算法逻辑推出的条件 [p.4]。
- source input / follow-up input / metamorphic group (MG)：已指定的输入为 source inputs，据其按 R 构造的为 follow-up inputs，二者构成的输入序列为 MG [pp.4–5]。
- semi-proving / proving MRs：proving MRs 指证明程序对整个输入域满足 MR；semi-proving 用 symbolic analysis 证明 MR，并可与 testing、debugging 结合 [p.12]。
- category 与 choice（METRIC）：categories 为影响被测软件执行的输入参数或环境条件，choices 为每个 category 的互不相交划分 [p.9]。
- metamorphic slicing：与 MR 相关的 slice，作者称其不仅 data oriented 也 property oriented；含 static、dynamic、execution、conditioned 四类 [pp.15–16]。
- metamorphic fault tolerance：按 equality MRs 构造多个输入并同时执行，据 MR 的满足情况判断原输入的输出是否 trustworthy，不可信时从 follow-up inputs 的输出中选最可信者 [p.16]。

## 7. 原文摘录

- "Metamorphic testing is an approach to both test case generation and test result verification. A central element is a set of metamorphic relations, which are necessary properties of the target function or algorithm in relation to multiple inputs and their expected outputs." [p.1]
- "Even if it were possible to obtain such a complete set of MRs, they might still not be equivalent to a test oracle due to the necessary (but not sufficient) nature of the properties." [p.8]
- "For each of the six subject programs in the study, MT only required an average of three to six diverse MRs to reveal at least 90% of the faults that could be detected by an oracle." [p.8]
- "Furthermore, some previous MT experiments have yielded contradictory results. As discussed in a previous survey [81], for instance, the effectiveness of MRs (such as those in [17, 62]) has not been conclusively determined." [p.9]
- "However, with an MR violation, it is only possible to say that at least one test case in the MR-violating MG is related to the fault, unless we do have a test oracle. It is not clear precisely which test case is related." [p.16]
- "It is advisable to consider MT in the development, which may alleviate the oracle requirement, extend the method’s scope and applicability, and even facilitate the development of a more comprehensive method." [p.22]
