# AI-Driven Statutory Reasoning via Software Engineering Methods

## 1. 研究问题与作者主张

- 目标：作者讨论如何用 generative AI（LLM）自动完成 statutes 与 contracts 中的规则式推理及其分析，并介绍若干自动化软件测试与程序分析概念；作者称这些概念应用于 AI 驱动的 statutes 和 contracts 分析时 could potentially be useful in computational law [p.2]。
- 两类任务：作者区分 statutory reasoning as Interpretation（把规则应用于已知事实，如 Example 1）[pp.2–3] 与 as Analysis（从起草者或其他利益相关者的角度分析 statutes 和/或 contracts 本身，用于识别有问题的 edge cases 或确保某些一致性性质成立）；作者称后者是 relatively less studied 的问题，并写道 GenAI 是处理它的 promising technology [p.3]。
- 核心主张：作者认为（Our main argument）规则式法律推理的自动分析现在可以从软件工程的视角来看；法律文本本身是一个 program，输入为关于某人或某情形的一组事实，输出为某个客观结果 [p.4]。作者说明把法律文件视为 programs 并不新（形式化定义 statutes [18]，computable contracts [12]），本文提出借助 LLM 直接把自然语言法律文件当作 programs 处理，以便应用软件工程技术 [p.4]。
- 结论：作者 argue 这一问题可受益于对 code coverage、function inlining、mutation testing、metamorphic property-based testing 等技术的 principled application，并希望本文成为研究者进一步探讨软件分析与 computational law 之间协同的基础 [p.11]。

## 2. 方法

- 总体做法：作者把法律文本视为 program（事实为输入，结果为输出）[p.4]；§3.1–3.3 的每项技术先以 Python 的 max(a, b) 函数说明软件中的做法，再把同一原则用于 statutes [pp.4–9]。作者向 LLM 提供 statutes 摘录，提出问题或要求生成例子，并展示输出、附上说明 [p.3][p.11]。
- Coverage 与示例生成 [pp.4–5]：软件测试以 code coverage 衡量测试套件 [p.4]；对 statutes，作者让 LLM 列出某个例子中条件被满足的规则（度量已有例子的 coverage），并合成使指定规则以指定方式适用的例子，如 §63(f)(1)(A) 适用而 §63(f)(1)(B) 不适用 [p.5]。
- Mutation testing [pp.5–6]：软件中对源代码作小改动（mutation，如把 return a 换成 return 2），再写能区分原程序与变体的新测试；作者称前两个测试在该变体下仍通过且显示 100% code coverage，需增加 max(3, 1) == 3 才能区分 [p.5]。对 statutes，作者让 LLM 假设 §63(f)(1)(B) 被修改为 remove the second clause（据 p.6 的 Claude 解释，指关于 §151(b) 下 additional exemption 的条件），再要求合成在修改后规则下适用而在原规则下不适用的例子 [pp.5–6]。
- Inlining [pp.6–8]：软件中编译器把对 max(x, x+1) 的调用替换为函数体，并化简为 w = x+1 [pp.6–7]。对 statutes，作者设计了一种 prompting strategy：LLM 不直接算最终答案，只执行一步替换并逐字输出修改后的法规文本，下一步在修改后的文本上继续 [pp.7–8]。任务为 Example 5（2025 年联合申报夫妇的 basic standard deduction），作者列出 8 步考虑 [p.7]。
- Property-based 与 metamorphic testing [pp.8–10]：软件中用自动生成的输入检查函数对任意输入应满足的性质（Python 库 Hypothesis [17]）；metamorphic testing 检查输入按指定方式变化时多次调用之间的性质，如 max 的单调性 [pp.8–9]。对 statutes，作者问 2018–2025 年间单身申报者的 basic standard deduction 能否逐年下降，并将其表述为性质：对满足 2018 ≤ X < Y ≤ 2025 的年份 X、Y，以及前一历年的 hypothetical C-CPI-U 值 Ix、Iy（取值范围 [100, 200]），令 D 为给定年份与给定前一历年 C-CPI-U 值下单身申报者 basic standard deduction 的计算，检验 D(X, Ix) ≤ D(Y, Iy)；对随机的 X、Y、Ix、Iy 循环，每次迭代用 LLM 以 inlining 技术计算通胀调整 [pp.9–10]。
- 其他技术 [p.10]：delta debugging [22]、change impact analysis [1]、automatic program repair (APR) [16] 各以一个问句提出，询问能否用于 AI 驱动的 statutory reasoning；文中未给出具体做法。

## 3. 数据与范围

- 法域与文本：美国联邦税法。Appendix A 摘录 26 U.S.C. §63（(b)、(c)(1)–(4)、(c)(7)、(f)(1)）、§1（(f)(1)、(f)(3)、(f)(4)、(f)(6)(B)）和 §151（(a)、(b)），as of April 2024，作为提示内容提供给 LLM；摘录中的省略处以 … 标示 [pp.11–14]。
- 数据：文中没有数据集评测，材料为 Example 1–5 与一个违反单调性的情形 [pp.2–10]。Appendix B 给出 hypothetical C-CPI-U（Chained Consumer Price Index for All Urban Consumers）值（2017–2024 年，按 §1(f)(6)(B) 的平均方法计算）：2017 年 138.2、2018 年 141.0、2019 年 143.2 [p.14]；2020 年 144.8、2021 年 149.1、2022 年 159.9、2023 年 168.3、2024 年 172.5 [p.15]。脚注称写作时（April 2024）2024 年的通胀数据及 2025 年的 standard deduction 尚未可知，作者据此写道 we are certain，LLM 无法用外部知识解决 Example 5 [p.16]。
- 模型：Claude 3 Opus（Example 2–5、coverage 列表、对单调性问题的直接提问 [pp.3–9]）；GPT-4 仅在 Example 5 的 baseline 中提到 [p.7]。模型版本日期、提示全文、采样设置、重复次数与性质检验的迭代次数，原文未说明。
- 范围限定：statutory reasoning 假定事实已清楚给定，不处理对可能含糊的术语的主观解释；合同法方面 can be expected 仅在 limited contexts 适用 [p.3]。

## 4. 结果

**实证结果（作者报告的演示与观察；除另行注明，重复次数与成功比例原文未说明）**

- Example 1 [p.2]：作者列出所需规则：§63(b)、§63(c)(1)、§63(c)(2)(A)(i)、§63(c)(2)(C)、§63(c)(7)(A)(ii) 适用；§63(c)(3)、§63(f)(1) 因 Alice 和 Bob 在 2018 年不是 65 岁而不适用；§63(c)(4)、§63(c)(7)(B) 的通胀调整不适用于 2018 年。最终答案为 $216,350-(2×$12,000)=$192,350。
- LLM 与 Example 1 类问题 [p.3]：作者称 Claude 3 Opus 在提示中给出相关 statutes 并要求解释 chain of thought 时 usually 能正确回答此类问题，比例原文未说明。作者引述既有研究：在含 IRC 子集 [13] 与 Japanese Civil Code [11] 的 statutory reasoning 数据集上，LLM 方法在不涉及数值计算的任务上达到 accuracy upwards of 75–80%；涉及数值计算的任务，文中未给出准确率。
- Example 2 [p.3]：作者描述的任务是让 LLM 判断 26 USC §63(b) 定义的 taxable income 能否为负并用例子演示；Claude 3 Opus 生成的例子为 Charlie 与 Diana（2018 年联合申报；Charlie 出生于 5/15/1952，Diana 出生于 8/22/1953；AGI $20,000；仅 standard deduction）。文中未印出该例的 taxable income 数值。
- Coverage 列表 [p.5]：作者称 Claude 3 Opus correctly 给出了 in this example 中条件被满足的规则：§63(b)、§63(c)(1)、§63(c)(2)、§63(c)(7)；原文未写明 this example 指哪一个编号例子。
- Example 3 [p.5]：作者描述的任务是要求 Claude 给出 §63(f)(1)(A) 适用而 §63(f)(1)(B) 不适用的例子，所得为 Charlie 与 Diane（2018 年联合申报；Charlie 出生于 3/15/1985，Diane 出生于 8/22/1953；AGI $185,000；仅 standard deduction）。所印 Claude 的解释写：Diane 在 2018 年度结束前已满 65 岁，故 §63(f)(1)(B) applies；Charlie 本人未满 65 岁，故 §63(f)(1)(A) does not apply。
- Example 4 [pp.5–6]：针对修改后的 §63(f)(1)(B)，Claude 3 Opus 给出 Ellie 与 Frank（2018 年分别申报；Ellie 出生于 5/10/1980，Frank 出生于 2/28/1952；Ellie 的 AGI $75,000，Frank 的 AGI $50,000；仅 standard deduction）。所印解释写：修改后的规则适用于 Frank；原规则不适用，因为 Frank 有 gross income，Ellie 不能依 §151(b) 为他主张 additional exemption。
- Example 5 的 baseline [p.7]：作者报告 in our experiments，Claude 3 Opus 与 GPT-4 即使使用 few-shot in-context learning 和 chain-of-thought reasoning，也 unable to solve this task correctly；作者称最终结果 almost always incorrect。
- Example 5 的 inlining [pp.7–8]：作者称按所设计的 prompting strategy，Claude 3 Opus is able to correctly solve Example 5 [p.8]。所印解答的数值路径为：$3,000 → $12,000 → 调整幅度 24.81% → $15,000 → 200% 即 $30,000 [p.7]。文中只展示第 3、5 步之后的修改文本；其余步骤的输出、运行次数、GPT-4 在 inlining 下的表现，原文未说明。
- 单调性的直接提问 [p.9]：作者写道，直接提问时 Claude 3 Opus 断定 basic standard deduction cannot decrease during the 2018-2025 period（理由是调整 can only increase 这些金额）；作者称 it turns out that this is not fully correct。
- 单调性的性质检验 [pp.9–10]：作者写道 it does not take many iterations 即可发现性质可被违反，迭代次数原文未说明。所印情形：D(2024, 168.1)=$14,600，D(2025, 167.0)=$14,500；即 hypothetical 0.65% deflation in 2024 时，2025 纳税年度单身申报者按 §63(c)(2)(C) 与 §1(f)(3) 算得的 basic standard deduction appears to be $100 lower than that computed for the previous year [p.10]。
- 三项其他技术 [p.10]：delta debugging、change impact analysis、automatic program repair 均以 Can we perhaps use ...? 的问句提出，文中没有对它们的实验或结果。
- 作者引述他人的结果 [pp.4–5]：researchers have found 以额外示例扩充训练数据可提高 COLIEE 数据集上某些任务的 accuracy [21] [p.4]；research has shown 按 mutation 方式产生的测试套件比只为 coverage 优化的测试套件更可靠地发现真实软件 bug [19] [p.5]。

**作者的解释或推论**

- 关于 Example 2 [p.3]：作者称 mechanical application of §63(b) 在 AGI 小于 standard deduction 时 appears 可得到负的 taxable income；作者（自述 not a lawyer）not aware of any specific law that prevents this interpretation，并指出 IRS Publication 525 (2023) [20] 在 recovering prior year adjustments to gross income 的语境中使用 negative taxable income 一词。作者的小结：LLMs 看来（appear to be）可用于合成例子，以推理假设情形。
- 关于 mutation testing [p.6]：作者认为它有助于生成这样的例子：不仅覆盖相关 statutes 的特定部分，还为理解某些规则为何如此书写提供推理依据；作者称该过程 can potentially 帮助起草者思考各种 edge cases。
- 关于 inlining [pp.7–8]：作者认为 baseline 出错是因为 subroutines 太多，LLM 的推理 inevitably falters，用错值或把值用错位置 [p.7]；作者称在每一步使用带 inlined substitutions 的修改后法规，使 LLM 能放慢（slow down）其 chain of thought [p.8]。
- 关于单调性 [p.10]：作者认为 §63(c)(7)(B) 与 §1(f)(3) 的调整确实只允许在 §63(c)(2)(C) 所列数值（2018–2025 年为 $12,000）上增加，但在后续年份出现 deflation 时，增加额 can seemingly 逐年下降。

## 5. 作者陈述的局限与前提

文中没有专门的局限小节；以下是正文中作者陈述的限定与前提。

- 作者写道基于 LLM 的解决方案 are far from perfect [4] [p.2]；直接让 LLM 分析 statutes 的一般性质 does not always produce accurate results [p.9]。
- 范围：statutory reasoning 假定相关事实已清楚给定，不处理对可能含糊的术语的主观解释 [10]；其在合同法中只被 expected 适用于 limited contexts [p.3]。
- 作者自述 not a lawyer，对 Example 2 的结论措辞为 appears [p.3]。
- 数据前提：Example 5 与 Appendix B 使用 hypothetical 通胀数据，原因是写作时 2024 年数据未知 [p.7][p.14][p.16]；statutes 摘录为 as of April 2024 [p.11]；性质检验中 Ix、Iy 取 [100, 200] 内的 hypothetical 值 [p.9]。
- 表述限定：作者以 could potentially be useful [p.2]、can potentially benefit drafters [p.6]、can potentially be automated [p.9] 描述这些技术的作用；§3.4 的三项技术以问句提出，文中未检验 [p.10]。
- 作者的前提：GenAI 使 many of these 自然语言法律文件可被 essentially 当作 programs [p.2]。

## 6. 关键术语

- statutory reasoning [p.2]：作者引用先前研究 [13, 15] 的用法，指把 statutes 的规则自动应用于特定情形（如某人在某年能否主张某项税收扣除），通常涉及识别相关规则并评估其组合。
- code coverage [p.4]：作者称其为衡量测试套件质量时最常用的准则，度量所有测试执行到的源代码比例（常按代码行计）。
- mutation testing 与 mutation [p.5]：以测试套件能否发现假设的程序员错误来衡量其质量；对源代码作小改动称为 mutation，再写能区分原程序与该 mutation 行为的新测试。
- inlining [p.6]：编译器的一种优化，把含函数调用的表达式替换为实现该函数的代码，并做必要的变量名替换；在 statutory reasoning 中指作者设计的 prompting strategy：LLM 只执行一步替换并逐字输出修改后的法规 [pp.7–8]。
- property-based testing [p.8]：编写泛型测试，表达函数对任意输入应满足的性质，并用自动生成的输入值检查这些性质。
- metamorphic testing [p.9]：property-based testing 的一个特殊类别，检查输入按指定方式变化时，多次调用之间应成立的性质。
- delta debugging、change impact analysis、automatic program repair (APR) [p.10]：作者的描述依次为：反复切分输入以得到仍能复现失败的最小片段；通过模块依赖有向图识别小补丁影响哪些模块；在小改动空间中机械搜索，使给定测试得到期望值。

## 7. 原文摘录

- "It appears that a mechanical application of §63(b) when adjusted gross income is less than the standard deduction can lead to a negative result for the computation of taxable income." [p.3]
- "The legal text itself is a program that computes, given an input —i.e., a set of facts about a person or circumstance—some objective result such as whether a tax deduction is available (and how much) or whether an insurance policy covers an incident (and to what extent)." [p.4]
- "In our experiments, modern LLMs like Claude 3 Opus or GPT-4 are unable to solve this task correctly even with few-shot in-context learning [5] and using chain-of-thought reasoning [14]. ... The end result is almost always incorrect." [p.7]
- "Using a modified version of the statute with inlined substitutions in each subsequent step allows the LLM to slow down its chain of thought. With this process, Claude 3 Opus is able to correctly solve Example 5." [p.8]
- "Unfortunately, asking an LLM to analyze general properties of legal statutes directly does not always produce accurate results." [p.9]
- "Property-based testing can reveal a situation where the monotonicity property is violated: D(2024, 168.1)=$14,600 and D(2025, 167.0)=$14,500; that is, if there was a hypothetical 0.65% deflation in 2024, then the basic standard deduction ... appears to be $100 lower than that computed for the previous year." [p.10]
- "Consequently, we argue that this prob- lem can benefit from the principled application of techniques well-studied in the field of software engineering such as code coverage, function inlining, mutation testing, metamorphic property-based testing, and more." [p.11]
