# A Survey on Metamorphic Testing

## 1. 研究问题与作者主张

- 研究问题：作者提出四个 research question：RQ1 技术有哪些改进，RQ2 已知应用领域，RQ3 实验评估如何进行，RQ4 未来研究挑战 [p.3]。
- 对象与动机：作者称这是对 metamorphic testing 的 exhaustive survey，覆盖 1998 至 2015 年发表的 119 篇论文 [p.1]；作者称 oracle problem 被公认为 software testing 的基本挑战之一，metamorphic testing 为缓解该问题而构想，写作时唯一已知的同类综述是 2009 年的中文文献 [p.1]。
- 总体主张：作者认为结果表明论文数量在增加、技术适用于远超数值程序的多个领域、报告在真实程序中检出故障的论文在增加，并把这些发现解读为（suggest）技术正在走向成熟，同时称仍有需要研究的方面 [p.15]。

## 2. 方法

### 2.1 作者对 metamorphic testing 的描述

- MR 由输入变换（用已有测试数据生成新测试用例）和比较一对测试用例输出的关系组成 [p.1]；形式上是 f 的 x1…xn（n > 1）与 f(x1)…f(xn) 之间的关系；与 program invariant 的区别是 invariant 须对每次执行成立，MR 是不同执行之间的关系 [p.2]。
- 三步：构造 MR；用任一传统测试技术生成 source test case；生成并执行 follow-up test case 并检查关系，关系不成立则该 metamorphic test case 失败，作者称这表明被测程序含 bug [p.2]。示例：sin(x) = sin(π − x) [p.1]；搜索引擎 Count(q) ≥ Count(q + k) [p.2]。

### 2.2 综述方法

- 依据 Kitchenham [21] 与 Webster 等 [22] 的指南 [p.3]；检索 ACM、Elsevier、IEEE、Springer、Wiley 的在线库（1998-01-01 至 2015-11-30，标题、摘要或关键词含 metamorphic test / testing / relation / relations），另加 Google Scholar 中来源之外被引 5 次或以上的论文，得 362 篇候选；两位作者按摘要筛选，意见一致，得 116 篇，联系其通讯作者后新增 3 篇，共 119 篇 primary studies [p.3]。
- 每篇填写 data extraction form（含贡献类型、应用领域、MR 数量、评估细节、经验教训等）[p.3]，至少由两位不同作者阅读两次，技术报告 [26] 发给各通讯作者核对，据反馈作了少量修改 [pp.3–4]；Section 4–7 对应 RQ1–RQ4 [p.5][p.9][p.12][p.15]。

## 3. 数据与范围

- 语料：119 篇 primary studies，发表于 1998 年 1 月 1 日至 2015 年 11 月 30 日 [p.3]，其中 86 篇在 2009 年或以后 [p.1]；Table 1 来源：ACM digital library 15，Elsevier ScienceDirect 6，IEEEXplore digital library 65，Springer online library 13，Wiley InterScience 4，Google Scholar (+5 citations) 16 [p.3]；脚注 2 写检索于 2015 年 12 月 30 日进行 [p.3]。
- 作者与地域：183 位合著者、74 个机构，T. Y. Chen 44 篇；按第一作者所属国家共 11 国，Australia 36、China 25、United States 17、Hong Kong 12 篇居前；按大洲 Asia 37 percent，Oceania 30 percent，Europe 19 percent，America 14 percent；72 个 venue，会议与研讨会 58 percent，期刊 23 percent，workshop 16 percent，技术报告 3 percent [p.4]。
- 贡献类型（Fig. 3a）：case study 50 percent，新技术与方法 31 percent，评估与实证研究 10 percent，杂项（相关综述、教程提要、指南）7 percent，以工具为主要贡献 2 篇（2 percent）[pp.4–5]；主题（Fig. 3b）：应用 49 percent，MR 构造 19 percent，与其他技术集成 10 percent，评估 6 percent，metamorphic test case 执行 5 percent，source test case 生成 4 percent，概述 7 percent [p.5]。
- 不含作者自行运行的实验，不涉及基准、评测的模型或法域；排除博士论文、非计算机领域、非英文及网上无法获取的论文 [p.3]。

## 4. 结果

以下关于单篇原始研究的内容均为作者（Segura 等）的转述；[27] 之类的方括号数字是原文参考文献编号。

### 4.1 实证结果

- 发表趋势：论文自 2001 年起持续出现，2010 年起尤多；累计数与二次函数拟合接近，R2 = 0.997 [p.4]。
- RQ1，MR 的性质：Chen 等 [27] 比较仅依据问题理论知识（black-box）与依据程序结构（white-box）得到的 MR，认为理论知识无法充分区分好的 MR；Mayer 与 Guderlei [38] 用六个带植入故障的矩阵行列式程序提出异议，称等式或线性方程形式的 MR 及贴近实现策略的 MR 效果有限 [p.5]。Chen 等 [27] 另报告好的 MR 使 follow-up 与 source test case 的执行尽可能不同；Asrafi 等 [46] 在两个被测程序中的一个上发现覆盖率与故障检测效果强相关（另一个原文未说明）；Cao 等 [47] 用 83 个有故障的程序和 7 种距离度量报告强且统计显著的相关；Just 与 Schweiggert [49][50]、Xie 等 [51] 报告由系统组件或程序特定部分导出的 MR 通常比由整个系统导出的更能检出故障 [p.5]。
- RQ1，MR 的描述与构造：Hui 与 Huang [53] 指出多数 MR 以自然语言非正式描述，提出用谓词逻辑的三元组形式化 [pp.5–6]。Liu 等 [54] 的 CMR 在一个 bioinformatics 程序上，组合后的 MR 通常故障检测效果高于（至少相近于）原 MR，条件是各组成 MR 的 tightness 相近；Kanewala 与 Bieman [56][57] 用机器学习预测 MR 类型，预测出的 MR 检出 988 个植入故障中的 655 个（66 percent）[p.6]；Zhang 等 [60] 在 4 个数学库的 189 个函数上推断 likely MR，报告其能有效检出 mutant [pp.6–7]。
- RQ1，source test case 与执行：Chen 等 [28] 报告 special values 的手工测试与 metamorphic testing 互补，Wu 等 [68] 与 Segura 等 [69] 报告 random source test case 比手工设计的更能检出故障，Segura 等另观察到二者组合检出故障更快；AMT [67] 支持的 MR 限于整数数值表达式 [p.7]。Murphy 等的经验研究 [75] 报告 metamorphic testing 优于 niche oracle 与 assertion checking [p.8]。
- RQ2，概况：以应用案例为主要贡献的论文为 58 out of 119；12 个以上应用领域，web services and applications 16 percent，computer graphics 12 percent，simulation and modeling 12 percent，embedded systems 10 percent，其他领域 21 percent，其余每个领域不超过四篇；数值程序 4 percent；首个应用于 2002 年（数值程序），其后几年多为理论探讨，2007 年起有多个领域的应用 [p.9]。
- RQ2，各领域所报告的结果：Google、Yahoo!、Live Search 检出内容与排序的不一致，Google、Bing、Chinese Bing、Baidu 的研究报告了若干 failure [pp.9–10]；real bug 或 defect：binary space partitioning tree 程序 1 个，无线计量系统 2 个，CPU 调度模拟器 2 个，machine learning 工具与 Weka 中若干 [p.10]；variability 工具（7 个工具中共 19 个 real bugs）、decision support 工具 Decider（1 个 bug）、两个 C 编译器（2 个 real bugs）、GCC 与 LLVM（另一方法得到 147 个 confirmed bugs）；偏微分方程程序中 special test cases 未检出植入故障而单条 MR 检出 [p.11]。casting simulation 一文未给出实证结果 [p.10]，两个 1918 年西班牙流感传播模型的 case study 未发现 bug [p.11]。
- RQ2，与其他测试技术结合：作者转述了 fault-based testing、semi-proving、SET、SBFL、MFT、Concolic Metamorphic Debugging 等结合 [p.12]；Rao 等 [141] 的结论是 SBFL 中未违反与违反的 MR 之比越高，技术越不有效；Comedy 在 21 个带植入故障的小程序上，88 percent 生成 debugging report，36 percent 精确定位故障；MFT 为理论描述 [p.12]。
- RQ3，被测程序、source test case 与故障：145 个 subject program，Java 46.2 percent，C/C++ 35.5 percent，报告规模 12 至 12,795 行 [p.12]；research program 自 2002 年、real world program 自 2006 年起使用，2015 年累计 research 83、real world 62；source test case：random testing 57 percent，现有 test suite 34 percent，基于工具的技术 6 percent；mutant 的结果始于 2002 年，真实 bug 的结果始于 2007 年，artificial faults 上升更陡；约 295 个 real faults、36 个工具（23 个为 real world 程序）[p.13]。
- RQ3，MR 数量、指标与含人的研究：5 至 9 条 MR 的研究占 39 percent，1 至 4 条占 24 percent，超过 25 条的 9 项研究（13 percent）均报告多个被测程序 [pp.13–14]。MS(t) = Mk / (Mt − Me)、FDR(t, f) = Tf / Tt 及按 MR 的变体被作者称为文献中的 de-facto standard；Hu 等 [29][36] 的受控实验（38 名 tester、3 个开源程序）报告 metamorphic testing 效率较低但检出故障更有效；Liu 等 [4] 报告 metamorphic testing 在多数程序上比有无 oracle 的 random testing 检出更多故障，3 至 6 条多样的 MR 与 test oracle 的故障检测能力相近 [p.14]。

### 4.2 作者的解释或推论

- 作者把拟合解读为 a sign of continued health and interest in the subject，称若趋势延续，2018 年前将超过 170 篇 [p.4]；作者称多数问题可识别出故障检测能力不同的多种 MR，建议使用多样的 MR [p.5]。
- 作者认为程序使用趋势表明 metamorphic testing 正在成熟（maturing），source test case 来源多样支持其适用性，295 个 real faults 的统计 suggest 其能有效检出 real bugs [p.13]；MR 数量的分布 suggest 少于 10 条 MR 通常足以取得 positive results [p.14]。
- 作者在 Section 7 列出六项挑战 [p.15]：(1) 已有的 MR 性质经验常互补甚至矛盾（如 [27] 与 [38]），缺少构造好 MR 的可靠 guidelines；(2) MR 的优先级与最小化，作者指出 test case minimisation 为 NP-hard，宜探索 heuristic 技术；(3) 生成 likely MR 被称为 probably the most challenging problem，已有结果主要限于数值程序；(4) IMT 与 CMR 的比较及组合条件；(5) 最佳 source test case 及其生成；(6) 119 篇中仅两篇以工具为主要贡献，作者称没有公开可用且持续维护的工具，并称这是 wide-spread use 的 significant obstacle。

## 5. 作者陈述的局限与前提

- 检索范围：作者承认检索可能没有找全论文，因为只检索了一部分有声誉的出版方，同时称仍有信心所报告的总体趋势准确 [p.3]。
- 纳入口径：排除博士论文、非计算机领域、非英文及网上无法获取的论文；内容很相似的同作者论文先分别分类评估，呈现时再合并 [p.3]。
- 作者设定的口径：地域按第一作者所属国家计 [p.4]；special values 测试归为手工测试 [p.7]；商业或开源程序算 real world program，设计为 benchmark 的开源项目（如 Siemens suite）算 research program [pp.12–13]；real bug 指被测程序中最初未知的潜在故障 [p.13]；mutation score 中等价 mutant 理论上应从总数中排除，实践中因程序等价性不可判定而不一定能做到 [p.14]。
- 作者对所综述方法的限制描述：AMT 支持的 MR 限于整数数值表达式 [p.7]；Kanewala 与 Bieman 的方法需要静态访问源代码 [p.6]；MR 生成的已有结果主要限于数值程序 [p.15]。除上列各点外，文中未另设局限讨论。

## 6. 关键术语

- test oracle 与 oracle problem：判断测试执行是否暴露故障的过程，常通过比较期望输出与观察到的输出；输出复杂时未必可行，该问题称为 oracle problem [p.1]。
- metamorphic relation（MR）与 source、follow-up、metamorphic test case：MR 是输入变换加输出关系，变换由已有测试数据生成新测试用例，输出关系比较一对测试用例的输出 [p.1]；follow-up 由 source 按 MR 的变换得到，二者构成的一对称 metamorphic test case，关系在这一对上不成立即检出故障 [p.2]。
- tightness：关系被随机输出偶然满足的难易程度，越 tight 越难被满足；作者的例子是 sin(x) = sin(π − x) 比 sin(x) ≠ sin(π − x/2) 更 tight [p.6]。
- CMR 与 IMT：CMR 把已有 MR 组合成新 MR，若一个 MR 的 follow-up 总可作为另一个的 source，则二者 compositable，组合对顺序敏感 [p.6]；IMT 链式应用 MR，把每个 MR 的 follow-up 复用为下一个 MR 的 source [p.8]。
- likely metamorphic relation：通过运行被测程序推断出、尚未经领域专家确认的关系 [pp.6–7]。
- Mutation Score 与 Fault Detection Ratio：MS 为 killed mutant 数与（mutant 总数减等价 mutant 数）之比；FDR 为检出故障 f 的测试数与测试总数之比；按 MR 的变体分别又称 mutation detection ratio 与 fault discovery rate [p.14]。

## 7. 原文摘录

- "Metamorphic testing provides an alternative, where correctness is not determined by checking an individual concrete output, but by applying a transformation to a test input and observing how the program output 'morphs' into a different one as a result." [p.1]
- "It is possible that our search has failed to find all papers since we focused on a subset of reputed publishers. However, we remain confident that the overall trends we report are accurate and provide a fair picture of the state of the art on metamorphic testing." [p.3]
- "They concluded that theoretical knowledge of the problem domain is not adequate for distinguishing good metamorphic relations. ... However, this was later disputed by Mayer and Guderlei [38], who studied six subject programs for matrix determinant computation with seeded faults." [p.5]
- "these are often complementary or even contradictory (e.g., [27], [38]). Therefore, there is a lack of reliable guidelines for the construction of effective metamorphic relations." [p.15]
- "All these findings suggest that metamorphic testing is gaining maturity as an effective testing technique, not only to alleviate the oracle problem, but also for the automated generation of test data." [p.15]
