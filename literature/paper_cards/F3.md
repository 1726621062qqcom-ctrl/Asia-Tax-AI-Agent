# An LLM Agentic Approach for Legal-Critical Software: A Case Study for Tax Prep Software

## 1. 研究问题与作者主张

- 问题：能否用 LLM agent 把自然语言写成的美国联邦税法翻译成可执行软件（作者以 U.S. federal tax software 作 legal-critical software 的案例）。作者指出，自然语言歧义、幻觉倾向和 oracle problem（确定某场景的正确输出常需解读法条）使一致性难以保证 [p.1]。
- 作者主张一：提出 metamorphic tests 的 higher-order 推广，即在相似个体间的结构化偏移上比较系统输出；作者称手工写出这类关系既繁琐又易出错，认为 agent 方式适合自动生成测试用例 [p.1]。
- 作者主张二：设计并实现 Synedrion，一组模拟真实软件团队角色的 LLM agent，其中的 metamorphic testing agent 在把税法译成代码时产生 counterexamples [p.1]。
- 作者报告：Synedrion 配合较小模型（如 GPT-4o-mini）时，复杂税法代码生成任务的 worst-case pass rate 为 45%，对照 GPT-4o 与 Claude-3.5 的 9%–15%；作者据此主张，LLM 驱动的 agentic 方法可作为由自然语言规格生成稳健、可信的 legal-critical software 的途径 [p.1]。
- 研究问题 RQ1–RQ4：基线 LLM 的表现；多 agent 设计与基线的比较；metamorphic testing agent 的贡献；各 agent 的贡献与成本–准确率权衡 [p.7]。

## 2. 方法

- 形式化：税务软件抽象为 (X, F)，X 是税表字段对应的变量（如 age、blind、sts），F 是软件计算的函数；任一输入的正确输出难以预知，故测试面临 oracle problem [p.3]。x ≡_L x′ 表示 x 与 x′ 在 L 之外的所有 label 上取值相同；盲人例：x ≡{blind} x′ 且 x.blind 蕴含 F(x) < F(x′) [p.3]。
- Higher-order metamorphic relations：作者在 pairwise（两输入两输出）关系之外采用 n-ary 关系 φ(x1,y1,…,xn,yn)，每对 (xi, yi) 满足 xi ≡_L yi [p.3]。示例（IRS Publication 17）：single 档 10% 税率至 $11,600，12% 覆盖 $11,601 至 $47,150，$20,000 收入应缴 $1,160 + $1,008，合计 $2,168；全部收入按 flat 12% 计（$2,400）的实现仍满足 4-ary 单调关系，作者的 8-ary 关系比较多个收入水平上的变化率，用以拒绝 flat-rate 实现 [p.3]。
- 五个 agent [pp.3–4]：TaxExpertAgent 把法律文本解析成 JSON 并生成各函数的 JSON 规格，须通过预定义 schema 校验，否则重新生成 [p.4]；两个 CoderAgent 与一个 SeniorCoderAgent 生成 Python 代码：一个 CoderAgent 先写，SeniorCoderAgent 对照规格评审并反馈，第二个 CoderAgent 修订；两个 CoderAgent 用同一基础 LLM、温度略有差异（如 0.1–0.2）[p.4]；代码经 JSON 键引用税则，不硬编码常量 [p.6]。
- MetamorphicAgent 接收 SeniorCoderAgent 的代码 [p.4]。作者先实现基本 metamorphic testing（扰动单个输入、核对输出方向），并称遇到两个问题：经 LLM 以一阶逻辑生成 metamorphic specification 困难（4-ary 也如此），以及 directional oracle 漏掉许多 bug [pp.4–5]。该 agent 考虑三类关系（proportional increase、threshold jump、saturation）[p.5]，依自然语言描述、税则、示例和输出格式让 LLM 生成输入元组 (xb, x1, x2)，比较变化率 R1 与 R2，违反关系时给出 counterexample [pp.5–6]。作者在开发期间人工抽查了部分生成的元组 [p.6]。
- 流程：MetamorphicAgent 报告触发输入、输出与涉及的函数，SeniorCoderAgent 据此修复；作者称这是由 counterexample 引导的迭代过程，结果反映框架的一次运行 [p.6]。

## 3. 数据与范围

- 六个 benchmark 由美国联邦所得税法与 IRS 文件派生，难度递增：(1) 税率档与标准扣除；(2) EITC；(3) CTC 与 ODC；(4) AOTC；(5) 分项扣除；(6) 1099-R 分配与罚则（含 IRS Simplified Method）[p.6]。
- 评测的模型：GPT-4o（文中称 200 billion 参数）[p.6]，GPT-4o-mini（8 billion）、Llama 3.1-70B、Llama 3.1-8B [p.7]，Claude 3.5-Sonnet（文中称 175B）[p.7]；基线提示为 zero-shot 与两阶段 step-wise CoT（先推理，后生成代码）[p.7]；框架的底层模型为 GPT-4o-mini、GPT-4o、Claude-3.5-Sonnet [p.8]。所有模型 temperature 设为 0.5 [p.7]。
- 评分：手写的 ground-truth 参考实现（Tax Year 2021，10 个函数），经边界压力测试，并与 OpenTaxSolver、Colorado Toolbox 做针对性边界抽查 [p.7]；对 ground-truth 软件做 symbolic execution（Z3）生成测试用例，比较生成代码与 ground-truth 的输出 [p.7]。每个场景的测试用例数，原文未说明。
- 指标：作者称 Pass@k 因多数 LLM 通不过全部测试而不适合作主要指标，主要指标为 Partial Pass@k（PP@1、PP@10、worst@10）[p.7]。
- 范围：仅美国联邦所得税；实验的基线提示只含 zero-shot 与 CoT，作者在讨论中说明选用通用 LLM 而非代码专用模型 [p.7][p.9]。

## 4. 结果

**实证结果**（Table 数值照录；三项指标依次为 PP@1/PP@10/worst@10；场景 Scen.1–6）

- 作者称其实验中，LLM 被提示按累进税率档计税时，可能对全部收入套用最高税率而非只对超出较低档阈值的部分；文中未给出该观察的数据 [p.2]。
- RQ1 zero-shot（Table 1）各模型 PP@1：llama 8b 53%/0%/0%/0%/15%/0%；llama70b 100%/71%/92%/42%/18%/0%；gpt-4o-mini 100%/83%/12%/23%/32%/4%；gpt-4o 100%/91%/94%/98%/98%/23%；claude 3.5 100%/100%/96%/97%/98%/39%。Scen.6 的 PP@10/worst@10：gpt-4o 18%/5%，claude 3.5 29%/14%，gpt-4o-mini 2%/0%，两个 llama 均 0%/0% [p.8]。
- RQ1 CoT（Table 2）各模型 PP@1：llama 8b 59%/0%/0%/0%/0%/0%；llama70b 100%/98%/98%/28%/32%/0%；gpt-4o-mini 100%/82%/10%/5%/2%/21%；gpt-4o 100%/98%/93%/68%/64%/28%；claude 3.5 100%/100%/98%/99%/98%/42%。Scen.6 的 PP@10/worst@10：claude 3.5 31%/15%，gpt-4o 14%/9%，gpt-4o-mini 9%/0%，两个 llama 均 0%/0% [p.8]。
- RQ2 框架（Table 3，Coder + S-Coder + T-Expert）PP@1：gpt-4o-mini 100%/100%/97%/94%/89%/78%；gpt-4o 100%/100%/100%/100%/95%/89%；claude-3.5 100%/100%/100%/100%/100%/93%。Scen.6 的 PP@10/worst@10：62%/45%，83%/72%，85%/78% [p.8]。与 Table 1 对照（卡片对照）：Scen.4、5 的 PP@1，框架 gpt-4o-mini 为 94%、89%，Table 1 的 gpt-4o 为 98%、98%，claude 3.5 为 97%、98% [p.8]。
- RQ3（Table 4，Scen.6；无 MT → +MT → +HMT）：gpt-4o-mini 78%/62%/45% → 80%/68%/55% → 81%/75%/69%；gpt-4o 89%/83%/72% → 91%/86%/83% → 100%/93%/88%；claude-3.5-sonnet 93%/85%/78% → 93%/90%/86% → 100%/95%/93% [p.10]。
- RQ4：gpt-4o-mini 由 Coder Only 加 S-Coder 与 T-Expert 后，Scen.3 的 PP@1 由 12% 变为 97% [p.9][p.11]；TaxExpertAgent 用 GPT-4o、其余 agent 用 GPT-4o-mini 时，Scen.6 的 PP@10 为 73%，全 GPT-4o-mini 为 62%，全 GPT-4o 为 83% [pp.9–10]。
- Token 用量：Scen.1 基础 agentic 代码生成共 18,457 tokens，加入 metamorphic testing 后 77,438 tokens；Scen.6 代码生成共 111,081 tokens，加入 HMT 后 450,134 tokens [p.9]。

**作者的解释或推论**

- 作者称 zero-shot 单独使用时，对涉及多步骤依赖与条件计算的税则 may be insufficient；CoT 对 Llama 8B 与 GPT-4o-mini 仅带来 marginal 改进，CoT 单独 does not significantly enhance 小模型处理复杂税务逻辑的能力 [p.8]。
- Answer RQ1：作者称 Claude 3.5 配合 CoT 的表现高于其他模型，在低至中等复杂度的 benchmark 上准确率最高达 98%，在最复杂的 benchmark 上 PP@1 与 PP@10 为 42% 与 31% [p.8]。
- Answer RQ2：作者称使用 GPT-4o-mini 等较小模型的多 agent 设计，表现 similar to or better than frontier baseline models [p.9]。
- Answer RQ3：作者称 MT 改进了功能正确性，HMT 的增益更大，尤其在复杂场景；例：Scen.6 中 GPT-4o-mini 的 worst@10 比 MT 高 14%（Table 4 为 69% 与 55%）[p.9][p.10]。作者称 HMT 使框架在最复杂场景也能生成 fully correct 的代码（Table 4 中 gpt-4o 与 claude-3.5-sonnet 的 Scen.6 PP@1 为 100%，PP@10 为 93% 与 95%）[p.9][p.10]。
- Answer RQ4：作者称 TaxExpertAgent 与 MetamorphicTestingAgents 是 critical components，metamorphic testing（尤其 HMT）提高了 worst-case 代码生成的 robustness；Tax Expert Agent 结构化税则并写出精确函数描述的能力，是准确生成代码所需要的，复杂度越高越是如此；用 GPT-4o 做 Tax Expert Agent、其余用 GPT-4o-mini 可提高 robustness（参见 worst@10）[p.9]。
- 作者称异构配置的表现可能介于较小与较大的同质配置之间 [p.10]。
- 作者称框架可用于其他 legal-critical software（如贫困救助资格筛查系统），能把政策自动译成可执行代码并用 metamorphic testing 验证；本文实验只涉及税务软件 [p.10]。

## 5. 作者陈述的局限与前提

- HMT 不保证找出并消除全部错误；它只覆盖三类 metamorphic relations，不保证覆盖所有税务计算行为或边界情形 [p.10]。
- 评测依赖 ground-truth 税务软件的正确性；作者以检查源码、边界压力测试和对照开源工具核对，但缺乏形式化保证，参考实现 may contain logical bugs [p.10]；参考实现固定为 Tax Year 2021，并严格对齐文中场景所述规则 [p.7]。
- 作者称穷举所有 LLM 组合不可行，只做了一组异构配置实验 [p.9]，进一步分析留待未来工作 [p.10]。
- 前提：作者假设（'We posit'）税法修订文本的结构化、形式化特点加上具体示例，使税务内容适合经 LLM 自动译成可执行软件 [p.2]。
- 结论中，作者称法律关键领域的 test case generation 仍受 oracle problem 影响；HMT 缓解了该问题，但带来 significant computational overhead（见 token 用量）；推广到其他法律领域需在准确性、效率与可解释性之间权衡 [p.11]。

## 6. 关键术语

- legal-critical software：作者用语，指金融、医疗、合规等领域中需把自然语言法规准确译成可执行代码的系统；案例为美国联邦税务软件 [p.1]。
- oracle problem：某输入的正确输出未知或不可得 [p.2][p.3]。
- metamorphic testing：不依赖绝对正确输出，而要求相关输入对的输出满足约定关系；作者的例子是，其他条件相同时，盲人纳税人的税负不高于非盲人 [p.2]。
- n-ary（higher-order）metamorphic relation：φ(x1,y1,…,xn,yn)，(x1,…,xn) 为 base test cases，(y1,…,yn) 为 follow-ups，每对满足 xi ≡_L yi [p.3]。
- HMT 的三类关系：proportional increase（输入增量对应税额的比例变化）、threshold jump（输入越过关键阈值时税率变化出现跃升）、saturation（输入落在 saturation 范围内时税额保持不变）[p.5]。
- Partial Pass@k：k 次生成中成功测试用例的平均百分比；PP@10 为 10 次生成的平均；PP@1 定义为单次生成中通过测试用例的最高百分比；worst@10 为 10 次生成中的最低百分比 [p.7]。

## 7. 原文摘录

- "A key innovation of our work is a higher-order generalization of metamorphic tests, motivated by our tax preparation case study, in which system outputs are compared across structured shifts among similar individuals." [p.1]
- "Our findings indicate that Synedrion, when employing smaller language models (e.g., GPT-4o-mini), can outperform frontier models (e.g., GPT-4o and Claude-3.5) in complex tax code generation tasks, achieving a worst-case pass rate of 45% compared with 9%–15%." [p.1]
- "Partial Pass@1: Highest percentage of test cases passed in a single generation, reflecting best-case performance. ... Worst@10: Lowest percentage of successful test cases across 10 generations, representing worst-case performance." [p.7]
- "Our multi-agent design with a smaller model like GPT-4o-mini shows performance similar to or better than frontier baseline models. With claude-3.5 agents, our framework achieved PP@1, PP@10, and worst@10 scores of 93%, 85%, and 78%, respectively, in the most complex scenario." [p.9]
- "Despite HMT’s improved bug detection capabilities over basic MT, our approach does not guarantee identifying and eliminating all potential errors. Furthermore, our HMT inherently focuses on three categories of metamorphic relations and does not guarantee that all possible tax calculation behaviors or edge cases will be covered." [p.10]
- "Our evaluation significantly depends on the correctness of ground-truth tax software. ... Due to the lack of formal guarantees, our reference implementations may contain logical bugs." [p.10]
