# Metamorphic Testing and Debugging of Tax Preparation Software

## 1. 研究问题与作者主张

- 问题：作者要为美国税务申报软件（tax preparation software）建立 data-driven debugging framework，发现并解释其中的 bug [p.2]。作者列出三个障碍：Absence of Oracle（正确申报因人而异，即 oracle problem）、Lack of trustworthy dataset（隐私与法律顾虑使 valid dataset 难以获得）、Computational infeasibility（在大数据集上按相似度比较个体决策不可行）[p.2]。作者援引 Langley v. Comm'r，称个人须对软件 bug 导致的错误负责 [pp.1–2]。
- 规约主张：作者假设（posit）美国税法遵循先例原则（stare decisis），故软件对某纳税人的输出所应满足的规约，要与被认为相似的个体比较；这类规约表现为相似输入应给出相似输出的性质，作者称之为 metamorphic relations，可表示相似纳税人之间（horizontal equity）和不同收入档之间（vertical equity）的关系 [pp.1–2]。
- 方法主张与研究问题：作者与法律和税务专家合作，把 IRS 文件（Form 1040、Publication 596、Schedule 8812、Form 8863）中的一组性质写成 metamorphic relations，提出随机测试用例生成策略，并用决策树解释可疑实例，工具为 TENFORTY [pp.1–2]。作者称就其所知，这是首次把 metamorphic relations 用于该领域 [p.3]。三个研究问题：RQ1 这些关系能否表达税务软件的法律要求；RQ2 带 Bayesian guarantees 的随机算法依规约测试时是否 effective；RQ3 fault localization 能否在 input space 与 internal space 中定位失败根源 [p.6]。
- 对发现与适用范围的主张：作者称 TENFORTY 在 OpenTaxSolver 中发现了不同 severity 的 accountability bugs，从税额接近零时的 non-robust behavior 到更新版本中缺失的资格条件 [p.1]；称框架可较容易地（readily）扩展到其他商业软件，本文 case study 聚焦一个开源软件 [p.1]；并称其技术可能（may）用于发现 forensic DNA 软件的类似 vulnerabilities [p.11]。

## 2. 方法

- 流程 [pp.3–4]：从法规与 IRS 文件提取场景（EITC 取自 Publication 596 的 Worksheet 1），写出 metamorphic properties；把每条性质编码为搜索问题，找一个个体及其 metamorphosed 个体，使二者偏离期望结果最大；用决策树解释失败条件。
- 形式化 [p.4][p.6]：软件为 (X, F)，X 是申报表中关于个人的字段（如 age、blind、sts），F 是软件算出的 federal tax return（p.4 写值域为 R≥0；Table I 题注称负值表示 the individual owns payment to the IRS）。x ≡L y 表示 y 在 L 之外的字段都与 x 相同。metamorphic relation 是含 ≡L、比较符、F、Boolean 连接词和量词的一阶逻辑公式，作者假设（w.l.o.g.）为 prenex normal form。例：∀x, y (x ≡age y) ∧ (x.age ≥ y.age) ⟹ F(x) ≥ F(y)。
- Falsification problem [p.4]：作者称其为 PSPACE-hard（可编码 TQBF），穷举搜索 intractable，故用随机的、基于搜索的测试；文中给出针对 ∀x.φ(x) 的采样策略，称可递归处理任意量词。
- Algorithm 1 [p.3][p.5]：输入软件 P、种子 I、性质 p、阈值 δ、Bayes factor B、置信下界 θ、超时 T。每轮从 promising input 扰动得 base test x1，再扰动得 follow-up x2，以 DISTANCE(P(x1), P(x2)) 计偏离 Δ；Δ > δ 标 failed，且 Δ 超过此前最大偏离时 x1 成为新的 promising input；否则标 passed。
- 统计检验 [p.5]：作者写明未观察到失败不等于正确，故对 x1 检验 H0: P(x1) ≥ θ 对 H1: P(x1) < θ（P(x1) 为从 x1 出发的 follow-up 通过的概率），采用 Jeffreys test（Bayes factor 的变体，uniform prior），要求连续通过数 K ≥ ⌈(−log2 B)/(log2 θ)⌉；B 可设为 100，θ = 0.95 时 K ≥ 90。
- 解释与实现 [p.5][p.9]：作者指出 follow-up 依赖 base、样本不独立，故用 feature engineering 为每个特征建两份（如 AGI_1、AGI_2），合并为一个实例后用 scikit-learn 的 CART 决策树。解释分 input space（税表字段）与 internal space（循环执行次数、if 分支、switch case 等执行 trace）；所有用例都失败时只报告性质的前提 [p.9]。实现用 Python，并用 llvm-cov 插桩收集每个输入 trace 的覆盖信息（如每行代码的执行次数）；B = 100、θ = 0.95、δ = 1.0、T = 900 [p.5]。
- 16 条关系（Table I，2020 税年）[pp.6–7]：不等号取自 Table I，pp.6–7 文字对 #5、#10、#11、#13 的边界写法（higher、over、below）与之不完全相同。#1–#2 Disability：senior 或 blind（含 MFJ 配偶）者的返还不低于其他方面相似的非 senior、非 blind 者；#3 MFS 无 EITC 资格；#4 MFJ 且 AGI > 56,844 无 EITC 资格；#5 符合 EITC 者的返还不低于相似的不符合者；#6 EITC 申报额较高者不低；#7 CTC 较高者不低（Table I 写 MFS 且 AGI ≤ 200k，p.7 文字写 MFJ）；#8 CTC 的 4-property；#9 MFS 无 ETC 资格；#10 MFJ 且 AGI ≥ 180k 无 ETC 资格；#11 AGI ≤ 160k 申报 ETC 者不低于相似的无资格或未申报者；#12 ETC 的 4-property（AGI ≤ 160k 与介于 160k 和 180k 之间）；#13 MDE ≤ AGI 的 7.5% 且 itemize 者与无 MDE 申报者返还相同；#14 选 standard deduction 时 Line 12 不影响返还（Table I 公式变动的是 MDE）；#15 MFJ 且 x.L12 ≤ 24.8k 时 itemize 者的返还不高于选 standard 者；#16 MFJ 且 x.L12 > 24.8k 时 itemize 者的返还不低于选 standard 者。
- 跨税年改写（Table II）[p.7]：#3 在 2021 年改为 F(x)≥F(y)（MFS 可领 EITC）；#4、#5、#6 的 AGI 门槛为 54,884（2018）、55,952（2019）、57,414（2021），2020 年为 56,844；#14 在 2018、2019 年 Not Possible（软件不允许勾选是否 itemize）；#15、#16 的条件改用 L8 24.0k（2018）、L9 24.4k（2019）、L12 25.1k（2021），2020 年为 L12 24.8k。

## 3. 数据与范围

- 数据：未使用真实纳税人数据集；作者称隐私与法律顾虑使 valid dataset 难以获得 [p.2]。测试输入由随机搜索在各字段的 domain 内生成，初始种子 I 的具体内容原文未说明 [p.3][p.5]。
- 被测软件：OpenTaxSolver 的 2018–2021 四个税年版本（含联邦个人所得税及若干州的计算）；2020 版联邦税计算所用功能为 6,017 行代码；输入字段数 2018、2019、2020、2021 版分别为 92、100、110、187，多为实数，少数为二值或分类变量 [pp.5–6]。
- 法域与领域：美国联邦个人所得税；senior/disabled 的 standard deduction、EITC、CTC、ETC、Itemized Deduction (ID) 五个领域 [p.6]；规约取自 IRS 文件，#9–#12 中作者假设 MAGI 等同于 AGI [p.1][p.6]。
- 规模：16 条关系 × 4 个版本；每个实验重复 10 次、每次 15 分钟，取平均 [p.7]。对比基准：原文未说明。

- input space 解释（Table IV）[p.9]：EITC (3) 仅在 AGI 低于 $16,720 且 FTR 低于 $79 时通过（p.4 写 FTR below $80 [p.4]）；ETC (9) 仅在税额为零时通过；ETC (11)、ID (16) 多数满足、少数 corner case 失败，失败含 FTR 为零的区间；ID (13) 在医疗费用超过 $13,487 且选择 itemize（A18 为 true）时失败，不 itemize 时正确。#4（2020 版）全部失败，作者称其前提本身即说明失败情形：软件未按 AGI 恰当检查 EITC 资格 [p.4]。
- internal space 解释（Table IV）[p.9]：EITC (3) 由第 93 行 while 循环的迭代次数与第 2156 行变量 L[34] 处是否退还税额区分；ETC (11) 指向第 423 行的 if 条件与第 340 行的 switch 语句。

### 作者的解释或推论

- #4 在 2020 版失败：作者称进一步检查后似乎（it seems）是软件未按新的 AGI 资格更新；#3 在未改动的 2021 版满足，作者称仅因政策已更新；作者称其经验表明软件可能（might）没有为税法变化做适当更新 [p.8]。
- EITC (3) 在低税额时通过：作者称这可能（might）在预期之内，因为税额很低时一些抵免具备资格 [p.4]。
- ETC (9)：作者推测（conjecture）通过的用例源于数值近似，软件仅因数值误差而对其正确 [p.9]。ETC (11)、ID (16)：作者称失败含 FTR 为零的区间，故软件因数值近似出错，其余情形正确 [p.9]。ID (13)：作者推测 2020 版新增 standard 与 itemized 的选项，更新可能未覆盖所有 corner case [p.9]。
- 作者对 RQ 的回答：RQ1 称 metamorphic relations 适合表达税务软件的正确性要求，可随政策变化以 minimal effort 更新（另称改编到其他税年只需 little effort [p.2]；工作量数据原文未说明）[p.7]；RQ2 称随机搜索算法 effective and efficient，更新后的软件在若干方面不再满足要求，弱点与 MFS 和 AGI 有关 [p.8]；RQ3 称决策树是可用于解释失败条件的 useful artifacts，并归纳为：软件可能缺失某资格条件、有限精度可能导致意外错误、允许用户选择选项的更新版本可能漏掉 corner case [p.2][p.9]。

## 5. 作者陈述的局限与前提

文中没有专门的局限一节，以下是散见于文中的说明：

- 作者写明未观察到失败并不意味着正确，称这是基于 metamorphic 的随机测试生成的一个 important shortcoming，并以统计假设检验给出无失败的统计置信度（B = 100、θ = 0.95）[p.5]。
- Falsification problem 为 PSPACE-hard，作者称穷举搜索 intractable；输入空间大或无限时，∃x.φ(x) 形式的子公式可能无法证伪 [p.4]。
- 前提：公式 w.l.o.g. 取 prenex normal form [p.4]；follow-up 依赖 base、样本不独立 [p.5]；#9–#12 中 MAGI 等同于 AGI [p.6]；规约须随税法逐年更新 [p.7]。
- #14 因 2018、2019 版软件不允许勾选是否 itemize 而无法写出，这两版跳过该性质 [p.7]。
- 作者把若干解释标为推测（conjecture）或 it seems [p.8][p.9]；case study 聚焦一个开源软件 [p.1]；税法在软件中体现的公平与伦理问题被列为 interesting future direction [p.10]。

## 6. 关键术语

- metamorphic relation / specification [p.1][p.4]：描述相似输入应给出相似输出的规约；形式上是含 ≡L 与 F 的一阶逻辑公式，x ≡L y 指 y 在 L 之外的字段都与 x 相同 [p.4]。
- oracle problem [p.2][p.3]：文中称 oracle 是 'black box module to decide whether the output of the system is correct for a given input' [p.3]。
- stare decisis [p.1][p.2]：文中释为 'to stand by things decided' [p.1]，即先例原则，'similar cases must follow similar rulings' [p.2]。
- horizontal / vertical equity [p.2]：作者分别指相似情形的纳税人之间、不同收入档的纳税人之间的关系。
- source (base) test / follow-up (metamorphosed) test [p.3]：source 是变换前的测试输入，follow-up 是按关系变换得到、用于核对输出关系的测试输入。
- falsification problem [p.4]：给定 (X, F) 与性质 φ，探索输入空间，找出使 φ 不成立的输入。
- FTR、TF [p.8]：FTR 指 federal tax return；TF 指 Table III 中首次观察到失败用例的时间，单位为秒。
- 缩写 [p.6]：MFJ = married filing jointly；MFS = married filing separately；AGI = adjusted gross income；EITC、CTC、ETC、ID 分别为 Earned Income Tax Credit、Child Tax Credit、Education Tax Credit、itemized deductions。

## 7. 原文摘录

- "We posit that, since the US tax law adheres to the legal doctrine of precedent, the speciﬁcations about the outcome of tax preparation software for an individual taxpayer must be viewed in comparison with individuals that are deemed similar." [p.1]
- "Metamorphic testing [8] is a software testing paradigm that tackles the oracle problem ... the correctness can be validated by comparing the output of software for that input with the output of a slightly metamorphosed one." [p.2]
- "While, the 2021 version of software fails for property #3, it passes all test cases for property #4." [p.4]
- "However, the absence of evidence for failures does not mean correctness. This is indeed an important shortcoming for metamorphic-based random test generations." [p.5]
- "In particular, we did not ﬁnd any evidence of failures for all 16 properties for 2018 and 2019 versions, whereas there is evidence of failures for 2020 and 2021 versions." [p.8]
- "While, the 2020 version failed to satisfy property #3, the 2021 version (without any updates) satisﬁes this property, solely due to the updated policy." [p.8]
- "We conjecture that the correct cases are due to numeric approximations as the computations are expected to use a small non-zero value, but are approximated due to the ﬁnite precision." [p.9]
