# CUTECat: Concolic Execution for Computational Law

## 1. 研究问题与作者主张

- 问题：作者指出，税额、社会福利资格、公务员工资等由 computational laws 规定的计算由专家程序执行，程序错误可造成重大社会影响，如向雇员支付错误的金额、未向有需要的家庭发放福利 [p.1]；正文举加拿大 Phoenix 与法国军队 Louvois 两个工资系统的故障为例 [p.2]。
- 目标：作者主张把 formal verification 用于 computational law 的实现 [p.3]，做法是在 Catala（面向 computational law 的 DSL）上实现 concolic unit testing，即具体执行与基于 SMT 的 symbolic execution 的结合 [p.1][p.3]。CUTECat 旨在检测所有 runtime errors（如除以零）以及由缺失或冲突的解释造成的法律不一致 [p.3]。作者列出三项挑战：工具须能高效处理 default logic；验证须尽量自动化、不要求 formal verification 专业知识；须给出律师可对照法律文本的具体样例 [p.3]。
- 主张：作者认为 computational law 常为「基础情形加分散于各条文的例外」的结构，可用 default logic 建模 [p.1][p.2]；作者给出 default terms 的 concolic semantics（结论中称其为 novel）并实现为 CUTECat [p.3][p.25]。
- 结果主张：作者报告 CUTECat 能生成 hundreds of thousands 个测试用例并覆盖这些法律文本的所有分支 [p.1]；在最大的现有 Catala 代码库（French housing benefits，19655 行 Catala，含规范）上，不到 7 小时 CPU 时间内生成 186390 个测试 [pp.3–4]。作者相信这为在立法过程中使用 formal methods 铺路 [p.1]。

## 2. 方法

- Default terms：形式为 ⟨e1,…,en | ejust :- econs⟩；∅ 为空值，⊛ 为两个 exceptions 同时出现时的 conflict 值 [p.4]。Fig. 2 的规则：所有 exceptions 为 ∅ 时，按 ejust 取 econs 或 ∅；恰有一个非空时取该值；多于一个非空时得 ⊛，即使结果相同也算冲突 [p.5]。示例税率项：⟨⟨income ≤ $10,000 :- 10%⟩, ⟨nb_children ≥ 3 :- 15%⟩ | true :- 20%⟩ [p.6]。
- Concolic 语义：concolic execution 以具体输入运行并收集符号约束，取反 path condition 的一部分，由 SMT solver 生成新输入，直到不再出现新路径 [pp.6–7]。作者在 Fig. 4 给出带 path condition χ 与 local constraint C 的 instrumented 规则，覆盖 exceptions 的各种组合及无异常时 ejust 的分支 [pp.7–9]；对 ⟨⟨b :- 1⟩, ⟨x = 0 :- 2⟩ | x > 0 :- 3⟩ 得到 5 个测试用例，两条路径分别得 ⊛ 与 ∅ [pp.8–10]。
- 实现：CUTECat 是 Catala 解释器（default calculus 阶段）的 fork，3,400 行 OCaml，经 OCaml bindings 调用 Z3；采用 DFS，取反最后新增的约束，内存中只保留最后探索的分支 [pp.11–12]。可用 assertions 限制输入空间，可给初始输入 hints [pp.12–13]。作者写道 concolic tools 把除法视为隐式分支并收集分母是否为零的约束；decimal 转 integer 的舍入用自定义 Z3 函数建模 [p.13]。
- 优化（Sec. 4）：lazy evaluation of exceptions，两个 exceptions 非空即停止求值 [pp.14–15]；依据 Th. 1（交换任意两个 exceptions 不改变归约结果）按自由变量重排 exceptions [p.16]；soft constraints，货币输入依次尝试 100 的倍数、10 的倍数、整数 [p.17]；pattern-matching case folding，取 arm 相同的分支的 patterns 之析取 [pp.17–18]；trivial constraints 简化与 Z3 incremental solving [p.18]。Table 4 中的 lazy-default 与 exception packing 对应 Sec. 4.1，Frontend opts. 指 Catala 编译器已有的优化（布尔部分求值、trivial defaults 简化）[p.21]。
- 评测设计：四个基准上的 ablation [pp.19–21]；对 housing benefits 做 mutation testing（随机选一个 default term，删除若干 exceptions、复制一个 exception 或取反 default condition）[p.23]；无限制 housing benefits 的 case study，及与参考解释器的开销比较 [pp.23–24]。

## 3. 数据与范围

- 基准：四个早于 CUTECat、由第三方有经验的 Catala 开发者编写的真实程序 [p.19]：US Tax Code Section 132 的一个片段（qualified employee discounts）；法国 SMIC（最低工资）；法国 Family Quotient（所得税计算中用到的 family quotient 的计算）；法国 rental housing benefits（限定为位于法国本土、少于 10 个孩子的家庭）[p.19]。
- Table 1（依次为 Section 132 / SMIC / Family Quotient / Housing Benefits）[p.20]：Catala LOC 133 / 368 / 776 / 19655；nb(default terms) 15 / 17 / 46 / 251；nb(if-then-else) 3 / 0 / 24 / 171；nb(match) 2 / 0 / 14 / 139；Python LOC 343 / 586 / 1413 / 31826。
- 其他评测对象：housing benefits 的 20 个变异程序；不加限制的 rental housing benefits [p.23]。
- 环境：Intel Core i7-12700，128GB DDR5 RAM（作者称从未见 CUTECat 使用超过 1GB），Ubuntu 24.04.1，OCaml 4.14.1，Z3 4.12.5 [p.19]。Table 4 为八次运行的平均值，± 后为标准差 [p.21]。
- 范围：输入均为 Catala 程序，求解器仅 Z3 [p.14]；所用法律文本的版本或年份原文未说明；作者称代码开源于 GitHub，实验结论记录在 artifact 中 [p.4]。

## 4. 结果

**实证结果**

- Table 2 [p.20]（无优化 → 全部优化）：solver calls，Section 132 为 41 → 24，SMIC 为 138 → 138，Family Quotient 为 13224 → 4142，Housing Benefits 为 355848 → 126147；Generated Tests 依次为 10 → 10、17 → 17、381 → 381、24995 → 17435。作者称 trivial constraints 的处理使调用数最多减少 3.2x（Family Quotient），pattern matching folding 只对 housing benefits 有帮助，SMIC 没有 matches 或 trivial constraints 因而不受影响。
- Table 3 [p.20]（Solve 时间，Standard → Incremental）：Section 132 为 0.23s → 0.01s，SMIC 为 0.85s → 0.01s，Family Quotient 为 69.46s → 0.23s，Housing Benefits 为 2262.38s → 69.88s；Total 时间与 Table 4 的 None、Incremental 两行数字相同。作者写道：housing benefits 上 CUTECat 的执行时间主要花在 concolic interpreter 上，solving 只占总时间的 35%；该例上 incremental solving 比 Z3 默认模式快 32x，总计节省超过 35 minutes。
- Table 4 [p.21]（ablation，八次运行的平均值 ± 标准差）：

| 优化 | Section 132 | SMIC | Family Quotient | Housing Benefits |
|---|---|---|---|---|
| None | 0.27s ± 0.00 | 1.01s ± 0.01 | 82.61s ± 0.55 | 6002.03s ± 19.46 |
| Lazy-default | 0.27s ± 0.00 | 1.02s ± 0.01 | 84.31s ± 1.15 | 5995.01s ± 15.21 |
| Exception packing | 0.27s ± 0.00 | 0.98s ± 0.01 | 83.41s ± 1.58 | 6013.71s ± 22.12 |
| Incremental | 0.02s ± 0.00 | 0.08s ± 0.00 | 5.21s ± 0.04 | 4306.72s ± 77.78 |
| Trivial | 0.09s ± 0.00 | 0.99s ± 0.01 | 12.62s ± 0.11 | 4258.93s ± 22.88 |
| Match folding | 0.21s ± 0.00 | 0.99s ± 0.01 | 46.89s ± 0.54 | 4045.87s ± 21.30 |
| Frontend opts. | 0.17s ± 0.00 | 0.99s ± 0.00 | 38.20s ± 0.42 | 3538.32s ± 22.37 |
| All | 0.02s ± 0.00 | 0.08s ± 0.00 | 4.34s ± 0.07 | 2843.01s ± 15.02 |
| Speedup | 1250.00% | 1162.50% | 1803.46% | 111.12% |

- 作者对 Table 4 的描述 [p.21]：几乎所有优化带来 noticeable 的性能提升，但各基准间有差异；小程序上改进最大的是 incremental solving；housing benefits 上其他优化再减少 25% 的总时间；lazy default 与 exception packing 不影响运行时间。
- Fig. 12 [pp.21–22]：作者称优化通过去除冗余情形缩小 exploration tree，incremental solving 明显缩短总时间，并观察到线性的测试生成速率。
- Table 5 [pp.21–22]（全部优化已启用；仅 Section 132 与 housing benefits 有货币输入）：Section 132 为 0.02s ± 0.00 → 0.03s ± 0.00（Slowdown 50.00%），10 个测试，100 的倍数的满足率 100%；Housing Benefits 为 2843.01s ± 15.02 → 2968.80s ± 16.90（Slowdown 4.42%），17435 个测试，满足率 87.04%（100 的倍数）、9.98%（10 的倍数）、2.80%（整数）；Section 132 的后两项为 N.A.。仅 30/17435（0.17%）个测试不满足任何 soft constraint。
- Mutation testing [p.23]：作者报告 20 个变异程序中 CUTECat 找出全部 20 个问题并给出具体输入，平均 0.55 seconds 到达被注入的 bug。
- 无限制 rental housing benefits [pp.23–24]：6h37m，186390 testcases，1338575 solver calls，总 solver 时间 366s。发现 1 个 conflict（与室友共用一间卧室的情形），该冲突此前已由 Merigoux [35] 手工发现；向相关公共行政部门询问后，该情形被认为不太可能发生，未给出法律解释；CUTECat 未在 rental housing benefits 上发现其他错误。人工检查发现输入空间 under-constrained，例如有测试对应位于海外且在 housing zone 3 的家庭，而据作者所知所有海外领地都在 housing zone 2。
- 开销 [p.24]：参考 Catala 解释器执行这 186390 个测试用 1h29，CUTECat 的开销为 4.5x；二者在所有生成的测试上结果一致。
- 舍入 [p.13]：对 rounding 的精确建模使作者发现 Python backend 的舍入与参考解释器有细微差异，已报告给 Catala 开发者并提交修复。
- 运行示例 [p.12]：生成 4 个情形，其中 income 为 $0 且有 3 个孩子的情形报告 conflict；作者称这不是实现错误，而是简化法律中的歧义。

**作者的解释或推论**

- 作者称结果 suggest incremental solving 是高效 concolic execution 的 cornerstone [p.20]；称线性生成速率 suggest concolic execution 不难到达某些路径，而这可能是 black-box fuzzing 等不够系统的方法的 shortcoming [p.21]；认为各基准上提升幅度不同 likely 与结构差异有关 [p.21]。
- lazy default 与 exception packing 无影响，作者认为在意料之中：基准只含成熟、对应已生效法律的程序，二者只在项可能返回冲突值时才有用，且据作者所知不存在含冲突的 Catala 示例语料；作者预期它们在开发过程与新立法准备中 shine [p.21]。
- 作者观察到 Table 1 中默认项多于其他分支结构，并称这 argues in favor of 其 importance [p.19]；相信 0.55 seconds 的平均时间表明 CUTECat 会尤其适合作为 continuous integration workflows 的一部分，也适合评估拟议的法律修订 [p.23]；相信其 scalability 与其他语言的 concolic 工具 comparable [p.24]；预期 soft constraints 的进一步扩展对性能影响很小 [p.22]。
- 作者称，与 Merigoux 等人 [38] 用 AFL 做 coverage-guided fuzzing（30,000 个初始用例得到 275 个最小化用例）相比，CUTECat 能生成探索不同路径、触及罕见歧义或未处理情形的用例 [p.25]；原文未给出同一基准上的对比实验。

## 5. 作者陈述的局限与前提

- 前提：作者称 computational law 及其 Catala 实现是确定性的、不含循环与递归，这缓解了 concolic testing 的一个已知难点 [p.3]；default condition 因类型保证不会归约为 ∅ 或 ⊛（原文省略细节）[p.4]；语义把 runtime errors 与 conflicts 都归为 ⊛ [p.13]。
- 支持范围：lists 与 dates 只部分支持；list 操作的符号编码需要 higher-order symbolic reasoning；月、年加法等 date 操作没有符号编码，完全依靠具体执行，作者写明代价是 completeness，符号模型留待未来 [pp.13–14]。作者称当前子集足以分析第 5 节中主要依赖 integer-rational reasoning 与 algebraic datatypes 的真实程序 [p.13]；仅支持 Z3，原型为单线程 [p.14]；探索策略目前固定为 DFS [p.18]。
- 未实现或替代：C-DefaultError-Early（Fig. 10）在 DFS 下难以实现，其他探索策略留待未来 [p.16]；Z3 原生 soft constraints 出现明显减速（作者认为可能源于非线性，已报告 Z3 开发者），改用多次查询自行实现，目前只针对货币输入 [p.17]；pattern matching 的折叠方案较简单，因 Catala 当前只支持对单个 sum type 的匹配 [p.24]。
- 评测前提：现有 Catala 代码库成熟、对应已生效的法律，作者称它们 highly unlikely 含此类问题，故用 mutation testing 注入错误 [p.23]；变异程序需手工检查，作者称变异方法在用户约束的情形下缺乏可靠所需的信息 [p.24]；ablation 使用的 housing benefits 限定为法国本土、少于 10 个孩子，作者称因评估不同设置需多次执行，每次已需 more than one hour [p.19][p.23]。
- 覆盖率未用作指标：Catala 解释器无覆盖率度量，编译后 Python 的结果不可靠——在可手工确定全部路径的小程序上，单次 Python 执行的行覆盖率为 65%，执行全部路径 barely 达到 80%，作者怀疑源于 default logic 到主流语言的 bloated translation [p.19]。
- 冲突与输入：消解歧义需要律师做法律解释 [p.12]；作者认为在律师指出哪些输入合法后，程序员可用 program assertions 限制搜索空间并加快分析 [p.24]；面向律师的流程与界面、跨学科实验列为未来工作 [p.25]。

## 6. 关键术语

- computational law：规定定义明确的计算（如家庭应缴税额、公务员工资、家庭是否有资格领取社会福利）的法律，通常由专家计算机系统实现 [p.2]。
- default term：形如 ⟨e1,…,en | ejust :- econs⟩，e1…en 称为 exceptions，ejust 称为 default condition；∅ 为空值，⊛ 为 conflict value [p.4]。作者称这种结构对应 default logic [p.2]。
- Catala：为实现 computational law 而设计的 DSL，default terms 是其核心语言中的 first-class citizens，并结合 literate programming [p.2]。
- concolic execution：具体执行与 symbolic execution 的结合；程序以具体输入运行并被 instrument 以收集符号约束，取反 path condition 中的部分约束后调用 SMT solver 生成新输入 [pp.6–7]。
- path condition χ 与 local constraint C：χ 为求值到当前 default term 之前收集的路径条件，C 为当前项求值期间收集的约束；作者称二者的区分在 Sec. 4.1 的优化中才起作用 [p.8]。
- soft constraints：求解器中的可选约束；CUTECat 通过多次查询自行实现，用于生成 human-friendlier 的测试输入 [p.17]。

## 7. 原文摘录

- "We show that CUTECat can successfully generate hundreds of thousands of testcases covering all branches of these bodies of law." [p.1]
- "Default terms take the form ⟨e1, . . . , en | ejust :- econs⟩, where e1, . . . , en are default expressions called ‘exceptions’, ejust is a boolean expression called ‘default condition’, and econs is a default expression." [p.4]
- "To handle these operations, we leverage the strengths of concolic execution over symbolic execution, and do not generate any symbolic encoding, relying instead entirely on concrete evaluation at the cost of completeness." [p.14]
- "Our evaluation therefore focuses on analysis times, and on the number of testcases generated. We defer a discussion of the completeness of CUTECat to Sec. 5.2." [p.19]
- "Notably, optimizations related to default terms, i.e., lazy default and exception packing do not impact the running times of CUTECat. This is however expected: these optimizations are only of interest when terms can return conflict values." [p.21]
- "CUTECat successfully identifies all 20 issues, providing concrete inputs to identify problematic cases. On average, CUTECat requires 0.55 seconds to reach the injected bug;" [p.23]
- "Despite querying relevant public administrations, this case was deemed unlikely to happen, and no legal interpretation was provided to resolve this ambiguity. No other errors have been found by CUTECat on the rental housing benefits." [p.23]
