# Logic-LM: Empowering Large Language Models with Symbolic Solvers for Faithful Logical Reasoning

## 1. 研究问题与作者主张

- 问题与目标：作者称 LLM 展现出类人的推理能力，但在复杂逻辑问题上仍有困难，并可能出现 unfaithful reasoning；目标是把 LLM 与 symbolic solver 结合，求解逻辑推理问题 [p.1]。
- 作者对原因的看法：LLM 本质上是 black-box probabilistic model，缺少保证推理 faithfulness 的机制；symbolic inference engine 基于符号化知识和明确的推理规则，因而 faithful 且 transparent；主要困难是把自然语言问题准确译成符号表示，作者认为这正是 LLM 擅长之处 [p.1]。
- 框架主张：LOGIC-LM 把问题分成 Problem Formulation、Symbolic Reasoning、Result Interpretation 三个阶段，并加入利用求解器报错信息修订符号形式的 self-refinement [pp.1–2]。作者认为，只要问题形式化正确，推理即 faithful，因为答案来自确定性算法的执行；与 CoT 相比，LLM 的任务从逐步求解问题转为用符号语言表示问题 [p.4]。
- 作者报告的总体结果：在 ProofWriter、PrOntoQA、FOLIO、LogicalDeduction、AR-LSAT 五个数据集上，平均比 standard prompting 提升 39.2%，比 CoT 提升 18.4% [p.1][p.7]；作者另报告所需推理深度增加时 LOGIC-LM 越来越有效 [p.2][p.8]，self-refinement 使 Exe_Rate 平均增加 5.01 [p.8]。
- 与既有工作的区别（作者表述）：既有 neuro-symbolic 方法依赖手工或专用模块而难以泛化，或因优化困难而 brittle，LOGIC-LM 无需训练或设计复杂的专用模块 [p.2]；以 Python 程序表示推理过程的做法尚未扩展到逻辑推理，作者认为原因是 hypothesizing、case-by-case analysis、process of elimination 这类 non-linear 推理难以用 functional programming 表示 [p.3]。

## 2. 方法

- 流程 [pp.3–4]：输入是自然语言描述的逻辑问题 P 与目标 G（选择题或自由问答）。Problem Formulator 用 LLM 经 in-context learning 把 P 与 G 译成任务专用的符号语言；Symbolic Reasoner 调用确定性求解器得到符号答案 A；Result Interpreter（rule-based 或 LLM-based）把 A 译回自然语言。
- 提示 [p.4][p.5][p.14]：提示含符号语言语法的说明和少量示范，示范用 SYMBOLIC_FORMULA ::: NL_STATEMENT 的格式对齐符号式与原句 [p.5]；作者称 InstructGPT 与 GPT-4 能据此识别 key entities、facts、rules 并按语法翻译 [p.4]。正文称每个数据集从训练集选 1-5 个示例 [p.6]；附录 C 称各方法的提示含 2 个示范，Standard 为 context、question、options 三部分，CoT 与 Logic-LM 为五部分（task description、context、question、options，外加 chain of reasoning 或 domain-specific symbolic program）[p.14]。
- 四种形式化与求解器 (Table 1) [p.5]：LP→Pyke（PrOntoQA、ProofWriter）；FOL→Prover9（FOLIO）；CSP→python-constraint（LogicalDeduction）；SAT→Z3（AR-LSAT）。Pyke 先建 knowledge base，再用 forward- 与 backward-chaining 推出新事实；Prover9 先把 FOL 转为 conjunctive normal form (CNF)，再用 resolution 判断结论为 true、false 或 unknown；python-constraint 提供有限值域上的 CSP 求解器；Z3 是 SMT solver。各形式化的定义见第 6 节。
- Self-Refiner [p.6]：求解器返回执行错误时，用含错的逻辑形式、求解器报错信息、以及展示常见错误（如 FOL 中的自由变量未被任何量词约束）与修正方式的示范来提示 LLM 修订；迭代到不再报错或达到允许的最大修订次数。§3.3 未给出最大次数；§4.4 比较 0、1、2、3 轮 [p.8]。
- Result Interpreter [p.6][p.18]：部分问题可用预设规则（如把 Entailment 映到 true）；CSP 的输出（如 {convertible: 1, tractor: 2, minivan: 3}）需译成 the convertible is the oldest [p.6]。附录 D：PrOntoQA、ProofWriter 比较 Pyke 返回值与目标语句；FOLIO 把 ENTAILMENT、CONTRADICTION、CONTINGENT 对应到 True、False、Unknown；LogicalDeduction 把每个选项解析成取值并检查是否在求解器返回的数组中；AR-LSAT 逐个选项尝试证明 [p.18]。LLM-based interpreter 用于哪些实验，原文未说明。
- 评测设定 [p.6][p.7]：基线为 Standard（in-context learning 直接作答）与 CoT；底座 LLM 为 ChatGPT (gpt-3.5-turbo)、GPT-3.5 (text-davinci-003)、GPT-4 (gpt-4)；各方法用相同的示例，temperature 为 0，取概率最高的回答；指标为选对答案的准确率 [p.6]。符号形式有语法错误、求解器不返回答案时，改用 CoT 预测 [p.7]；Table 2 的 LOGIC-LM 不含 self-refinement [p.7]。

## 3. 数据与范围

- 五个数据集均转成统一的多选格式（problem statement、question、options）；测试集规模与选项数见 Table 5 [p.6][p.14]。
- PrOntoQA（deductive reasoning，合成数据集）：hardest fictional characters version 中的 5-hop 子集；测试 500 例，2 个选项 [p.6][p.14]。
- ProofWriter（deductive reasoning）：open-world assumption (OWA) 子集，标签为 PROVED、DISPROVED、UNKNOWN；评测 depth-5 子集，为降低实验成本从测试集随机抽 600 例并保持标签均衡；3 个选项 [p.6][p.14]。
- FOLIO（FOL reasoning，专家撰写）：完整测试集 204 例；3 个选项 [p.6][p.14]。
- LogicalDeduction（CSP，来自 BigBench）：完整测试集 300 例；选项数 3、5、7 [p.6][p.14]。
- AR-LSAT（analytical reasoning，1991 至 2016 年 Law School Admission Test 的分析推理题）：正文称测试集 231 道选择题，Table 5 为 230；5 个选项 [p.6][p.14]。作者称 state-of-the-art 模型在该数据集上仅略好于随机猜测 [p.6]。
- 其他样本：§4.3 从 ProofWriter 的 0、<=1、<=2、<=3、<=5 hops 五个子集各随机抽 300 例并保持标签均衡；§4.4 的分轮 self-refinement 实验用 FOLIO [p.8]。
- 范围：不涉及法域或现实世界记录数据；作者在脚注称代码与数据公开 [p.1]。底座模型与基线见第 2 节。

## 4. 结果

### 实证结果

- Table 2 准确率（Standard / CoT / Logic-LM；Logic-LM 不含 self-refinement），ChatGPT (gpt-3.5-turbo)：PrOntoQA 47.40 / 67.80 / 61.00；ProofWriter 35.50 / 49.17 / 58.33；FOLIO 45.09 / 57.35 / 62.74；LogicalDeduction 40.00 / 42.33 / 65.67；AR-LSAT 20.34 / 17.31 / 26.41 [p.7]。
- Table 2，GPT-3.5 (text-davinci-003)：PrOntoQA 51.80 / 83.00 / 85.00；ProofWriter 36.16 / 48.33 / 71.45；FOLIO 54.60 / 57.84 / 61.27；LogicalDeduction 41.33 / 48.33 / 62.00；AR-LSAT 22.51 / 22.51 / 25.54 [p.7]。
- Table 2，GPT-4 (gpt-4)：PrOntoQA 77.40 / 98.79 / 83.20；ProofWriter 52.67 / 68.11 / 79.66；FOLIO 69.11 / 70.58 / 78.92；LogicalDeduction 71.33 / 75.25 / 87.63；AR-LSAT 33.33 / 35.06 / 43.04 [p.7]。
- 作者在 §4.1 的文字表述：Logic-LM 相对 standard 的平均提升为 39.2%（正文写作 With GPT-3.5），相对 CoT 的平均提升为 18.4%；GPT-4 相对 GPT-3.5 在 standard prompting 下平均高 48.46%；Logic-LM 使 GPT-4 相对 standard 与 CoT 分别平均提升 24.98% 与 10.44% [p.7]。
- 作者报告 CoT 的收益在 FOLIO、LogicalDeduction、AR-LSAT 上为 11.75%、9.41%、-3.2%（作者称相对较小甚至为负），在 PrOntoQA、ProofWriter 上为 51.59%、33.82%；作者另写到符号求解器在 FOLIO、LogicalDeduction、AR-LSAT 上带来 more marked improvement，分别为 +21.85%、+45.67%、+24.14%。这些百分比的基准，正文未写明 [p.7]。
- Table 3（Exe_Rate / Exe_Acc，self-refinement 前 → 后），GPT-3.5：PrOntoQA 99.4% / 84.9 → 100.0% / 85.0；ProofWriter 87.3% / 73.6 → 95.6% / 74.1；FOLIO 66.7% / 61.8 → 84.3% / 64.3；LogicalDeduction 100.0% / 62.0 → 100.0% / 62.0；AR-LSAT 11.3% / 57.7 → 21.8% / 60.3 [p.7]。
- Table 3，GPT-4：PrOntoQA 100.0% / 83.2 → 100.0% / 83.2；ProofWriter 99.0% / 79.6 → 99.0% / 79.6；FOLIO 79.9% / 80.4 → 85.8% / 79.9（表中 Exe_Acc 标 ↓0.5）；LogicalDeduction 100.0% / 87.6 → 100.0% / 87.6；AR-LSAT 32.6% / 60.0 → 39.8% / 58.8（表中 Exe_Acc 标 ↓1.2）[p.7]。表头写作 GPT-3.5 与 GPT-4，GPT-3.5 对应 Table 2 的哪一列，原文未说明。
- §4.2：作者称 LLM 在 PrOntoQA、ProofWriter、LogicalDeduction 上的 Exe_Rate 接近 100%，FOLIO 与 AR-LSAT 上 GPT-4 的 Exe_Rate 为 79.9% 与 32.6%，GPT-4 生成的逻辑形式总体有较高的 Exe_Acc，包括 AR-LSAT [p.8]；Table 3 中 ProofWriter 的 GPT-3.5 为 87.3%，GPT-4 为 99.0% [p.7]。
- Figure 3，ProofWriter 在推理深度 0、1、2、3、5 上的准确率：Standard 57.7、52.6、47.3、38.3、33.5；CoT 76.3、73.6、65.3、59.4、51；Logic-LM 81.7、77.3、73.6、71.3、71.1；图与图注未标明底座 LLM [p.8]。作者报告 Logic-LM 比 CoT 高 7.1%、5.0%、12.7%、20.0%、39.4%，正文把这五档写作 depth-0、depth-1、depth-2、depth-4、depth-5 [p.8]。
- Figure 4，FOLIO 上 0、1、2、3 轮 self-refinement 的准确率：Logic-LM (GPT-3.5) 为 61.27、62.25、64.56、63.84，对应 Exe_Rate 66.7%、79.4%、82.4%、84.3%；Logic-LM (GPT-4) 为 78.92、78.43、79.9、79.41，对应 Exe_Rate 79.9%、85.3%、85.3%、85.8%；图中 CoT (GPT-3.5) 为 57.87，CoT (GPT-4) 为 70.58 [p.8]。作者报告 Exe_Rate 随轮数增加、最终表现提高，但后续轮次准确率趋于停滞而 Exe_Rate 仍在增加；Table 3 的 self-refinement 使 Exe_Rate 平均增加 5.01 [p.8]。
- 案例分析 (Figure 6)：作者列出 GPT-4 的形式化错误，Example 1 把 Eastern wild turkey 生成为常量形式 WildTurkey(eastern)，而非谓词 EasternWildTurkey；Example 3 未区分 below 与 above，得到约束 Dan > Eve；Example 4 生成不合法的公式 Rating(subway, y) ∧ y > 9 [p.9][p.19]。作者称 Figure 5 的例子显示 LOGIC-LM 能把复杂问题译成符号形式，但在准确理解问题语义上仍有困难 [p.9]。

### 作者的解释或推论

- 关于 CoT 收益的差异 [p.7]：作者认为 a plausible explanation 是 CoT 模仿人类的 forward-chain 推理，与 PrOntoQA、ProofWriter 的问题相合；FOL 与 CSP 问题常需要 non-linear 的推理策略（hypothesizing、conditioning、recursive inference、process of elimination），作者认为符号求解器更适合这类推理。
- 关于 GPT-4 [p.7]：作者称 GPT-4 在 standard prompting 下的提升与 GPT-4 的主要增强在于复杂推理的说法相符；这可能表明扩大 LLM 规模可提高逻辑推理能力，但作者观察到 GPT-4 仍有大量 unfaithful reasoning errors（正文未给统计）。
- 关于形式化难度 [p.8]：作者称合成数据集上的高 Exe_Rate 在预期之中，因为这些数据集的问题多为合成、语言变化有限；真实且由专家编写的 FOLIO 与 AR-LSAT 上较低的 Exe_Rate 说明把真实问题译成逻辑形式有难度；作者认为较高的 Exe_Acc 体现符号求解器的潜力，前提是问题被精确译成符号形式。
- 关于推理深度 [p.8]：作者认为多步推理交给求解器后，LLM 面对的难点从 problem-solving 变为 problem representation；形式化的复杂度本应与所需推理的难易大体无关，作者称 Figure 3 的趋势验证了这一假设；Standard 与 CoT 的表现随复杂度上升而下降得很快，作者称这一趋势在 Logic-LM 中较不明显，并认为外部求解器提供的稳健推理能力大幅缓解了复杂问题上的性能下降。
- 关于准确率停滞 [pp.8–9]：作者归因于 self-refiner 只收到求解器的报错信息，只能把无效的符号表示变成有效的，而有效不等于对问题的正确形式化；作者提出可让 self-refiner 使用错误信息之外的反馈（如评估所生成符号形式准确性的附加模块给出的 reward signal），称其为有希望的方向，留待将来 [p.9]。
- 关于错误案例 [p.9]：作者认为把问题转成逻辑形式对现代 LLM 仍是难题，原因包括 FOL 形式化的复杂性、自然语言固有的灵活性、对问题整体理解的复杂性。

## 5. 作者陈述的局限与前提

- 适用范围受求解器限制 [p.10]：LOGIC-LM 依赖把推理问题译成求解器能处理的逻辑格式，因此适用范围受所用求解器表达能力的约束，例如并非所有问题都容易编码成 first-order logic；作者称可通过接入更多种类的求解器缓解，并称框架设计便于接入。
- 依赖 in-context learning 与 self-refinement 完成翻译 [p.10]：作者称遇到语法结构复杂的逻辑表示（如 probabilistic soft logic）时可能困难，因为难以在有限的示范与受限的上下文长度内把复杂语法规则传达给模型；作者提出的可能办法是开发专门的自然语言到符号语言的映射模块，如用求解器生成的合成数据微调 LLM。
- 前提：作者认为忠实性以问题形式化正确为条件 [p.4]；valid 的符号表示不一定是 correct 的问题形式化，self-refiner 只使用求解器报错信息作反馈 [pp.8–9]；不可执行的样本回退到 CoT [p.7]。
- 作者在 Ethics Statement 中称所用 LLM API，尤其 GPT-4，耗能较大 [p.10]。
- 作者提出的后续方向 [p.9]：接入 statistical relational learning 系统（Markov logic networks、probabilistic soft logic）以处理不确定性下的推理；扩展到需要常识的推理问题。

## 6. 关键术语

- unfaithful reasoning：作者引用既有研究，把它描述为 "the derived conclusion does not follow the previously generated reasoning chain" [p.1]，即得出的结论与先前生成的推理链不一致；作者称 symbolic inference engine 因基于符号知识和明确推理规则而 faithful 且 transparent [p.1]。
- Problem Formulator、Symbolic Reasoner、Result Interpreter：LOGIC-LM 的三个模块，分别负责把问题与目标译成符号语言、用确定性求解器推理、把符号答案译回自然语言 [pp.3–4]。
- Self-Refiner：利用求解器报错信息迭代修订不准确的逻辑形式的模块 [pp.5–6]。
- Exe_Rate 与 Exe_Acc：Exe_Rate 是可被相应求解器执行的符号形式所占百分比 [p.7]，作者称 "Exe_Rate only reflects the grammar correctness of the logical form" [p.8]；Exe_Acc 是可执行样本上的准确率，用于衡量 semantic correctness [p.8]。
- LP 与 FOL 形式化：LP 沿用 Prolog 语法，把问题表示为 facts P(a1, ..., an)（P 为谓词名，各参数可为变量、实体、数字或 bool）、rules（F1∧...∧Fm → Fm+1∧...∧Fn，意为 F1 至 Fm 为真则 Fm+1 至 Fn 也为真）与 queries（需由已知 facts 与 rules 证明的另一个 fact）；FOL 形式化把问题解析成 FOL 公式列表，分为 Premises（问题中的已知信息）与 Conclusion（待证明的未知公式）[p.4]。
- CSP 与 SAT 形式化：CSP 定义为三元组 (X, D, C)，X 为变量集，D 为各变量的值域集，C 为约束集 [p.4]；SAT 问题记为 (Φ, T, Q)，Φ 为理论 T 下的约束集，Q 为待查询的问题 [p.5]。
- Standard 与 CoT 基线：Standard 用 in-context learning 直接回答；CoT 采用逐步求解，在最终答案前生成解释 [p.6]。

## 7. 原文摘录

- "Our method first utilizes LLMs to translate a natural language problem into a symbolic formulation. Afterward, a deterministic symbolic solver performs inference on the formulated problem. We also introduce a self-refinement module, which utilizes the symbolic solver’s error messages to revise symbolic formalizations." [p.1]
- "Using this approach, the reasoning is guaranteed to be faithful as long as the problem formulation is correct since the answer A is the result of executing deterministic algorithms (e.g., forward/backward-chaining) embedded within the symbolic reasoner." [p.4]
- "Logic-LM significantly outperforms standard LLMs and CoT across all datasets. With GPT-3.5, our method outperforms standard LLM on all datasets, with an average improvement of 39.2%." [p.7]
- "A plausible explanation is ... that CoT emulates human forward-chain reasoning: beginning with known facts and sequentially deriving new conclusions until the goal is met." [p.7]
- "However, the accuracy tends to stagnate in subsequent rounds, even though the Exe_Rate continues to increase." [p.8]
- "However, a valid symbolic representation does not necessarily equate to a 'correct' problem formulation that accurately represents the problem." [p.9]
- "As a consequence, the model’s applicability is inherently bounded by the expressiveness of the symbolic solver, for example, not all problems can be easily encoded in first-order logic." [p.10]
