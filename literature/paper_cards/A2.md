# A modern compiler for the French tax code

## 1. 研究问题与作者主张

- 问题与目标：法国所得税（IR，impôt sur le revenu）依据纳税人的个人申报表计算，所用算法由 DGFiP 编写、设计并维护；作者称该算法依赖 1990 年设计的自定义语言和编译器，越来越难维护，也没有用上现代编译技术 [p.1]。作者的目标是：逆向工程 DGFiP 计算中未公开的部分；提供可解释（explainable）、开源、正确（correct）且可被独立审计的实现；现代化编译器基础设施，去掉因安全顾虑无法公开的手写 C [p.2]。
- 动机：作者称能独立复现并因而信任 DGFiP 的 IR 计算是 crucial，理由有三：纳税人需要理解结果（explainability）；公民可能想审计算法是否忠实实现法律（correctness）；独立、可复用的实现可对税改影响做完整而精确的模拟（forecasting）[p.1]。
- 核心做法：为 DGFiP 的语言 M 逆向出形式语义并在 Coq 中证明 type safety；设计新语言 M++（对 M 的扩展），用来编码 inter 驱动层的逻辑，以消除手写 C；实现开源工具链 Mlang（reference interpreter 加可生成 C 与 Python 的 optimizing compiler）；评估一致性、性能、数值表示、测试生成与覆盖度 [pp.1–2]。
- 作者在摘要中称：Mlang 基于逆向工程得到的形式化，已针对 DGFiP 的私有测试集验证（原文：thoroughly validated），有 formal semantics，消除了此前手写的 C workaround，可编译到 Python 等现代语言，并支持多种 instrumentation，这些 provide deep insights about the essence of French income tax computation；DGFiP 正式（officially）过渡到 Mlang 用于生产系统 [p.1]。正文称对遗留系统测试集达到 100% conformance，且作者已获正式批准开始替换遗留基础设施，数年内（within a few years' time）全部法国纳税申报将由该编译器处理 [p.2]。
- 作者对相关工作的陈述：对法律形式化的尝试早至 1914 年即有，这些工作都强调其复杂性，一个多世纪的研究后尚未出现能把法律文本系统地翻译成形式模型的 silver bullet；domain-specific 的尝试更成功（作者举例：smart contracts、商业合同、金融合同）[p.11]。作者称，就其所知（to the extent of our knowledge），被转成可复用、形式化软件产物的法律部分在规模与完整性上没有先例（unprecedented）[p.11]。

## 2. 方法

**M 与 µM 的形式化（第 2 节）**

- M：程序由声明（input、intermediary、output 变量与 exceptions；变量为 scalar 或定长数组，带描述和 kind 标注）与规则（变量赋值或 raise-if 语句）构成 [p.2]。M 没有无界循环和用户自定义递归函数，作者称其不是 Turing-complete [pp.2–3]；规则可按任意顺序给出，M 内置依赖解析并断言赋值无环 [p.3]。作者举例：M 没有数据类型或枚举概念，无法静态保证 V_0AC（单身）与 V_0AM（已婚）不同时为 1，于是声明 exception A031，并用一条规则在二者之和大于 1 时报错 [p.2]。
- µM 是作者的 M 核心演算：省略变量声明，去掉有界循环和类型别名（如 BOOLEAN）等语法糖，并假定计算已按合适顺序排列（Mlang 中用 topological sort）[p.3]。值为 undef 或 IEEE-754 双精度（64-bit）浮点数；M 假定默认取整模式（round to nearest, ties to even）[p.3]。类型为 scalar 或 array，无嵌套数组；变量可无赋值（税表条目留空）却被引用；M 不允许同一变量赋不同类型 [pp.3–4]。
- 操作语义（Figs. 4–6）：缺失变量求值为 undef；条件的 guard 为 undef 时整个条件为 undef；下标为 undef 时数组访问为 undef；负的越界下标得 0，正的越界下标得 undef，其余情形下标截断为整数 [p.4]。raise-if 的 guard 为非零 float 时报错，为 0 或 undef 时继续 [pp.4–5]。
- Fig. 6 对 undef 的规定 [p.6]：+、− 在两操作数都是 undef 时得 undef，仅一个是 undef 时该操作数按 0 计；×、÷ 任一操作数为 undef 时得 undef，第二操作数为 0 且第一操作数为 float 时得 0；比较与逻辑运算任一操作数为 undef 时得 undef；min、max 把 undef 按 0 计，两者都是 undef 时得 0；round(f) = floor_F(f + sign(f) * 0.50005)，truncate(f) = floor_F(f + 10^-6)，二者对 undef 得 undef；present(undef) = 0，present(f ∈ F) = 1。
- 证明：作者用 Coq 与 Flocq 库形式化 µM 语义 [p.3]，证明两条 type safety 定理——在 store 与 typing environment 一致的前提下，well-formed 的表达式总能求值出一个值，well-formed 的语句总能归约出新的 store 或错误；完整证明在补充材料 [21] 中 [p.5]。
- 逆向过程：先以 DGFiP 的简化在线税务模拟器为 oracle 做黑盒实验；M 规则开源后手工构造用例输入模拟器来调整语义；之后获准进入 DGFiP 办公室浏览其 M 编译器源码（条件是不带走任何信息），借此理解 inter 部分并确定自定义运算符（Fig. 15）[p.4]。

**M++（第 3 节）**

- 作者称，M 代码原本（insofar as we understand）表达整个所得税计算；DGFiP 为多年度计算在 C 的 inter 目录中写新逻辑，通过共享全局状态读写 M 变量 [p.5]。作者列出 C 带来的四个问题：不能公开（DGFiP 担心纳税人的恶意输入触发安全问题），纳税人缺少关键逻辑而无法复现计算；与 M 不可组合，影响可维护性、可读性、可审计性；限制现代化（在线模拟器完全用 C 经 Apache CGI 写成）；C 难以分析 [p.5]。
- M++ 是类似 Python 语法（缩进定义块作用域）的 DSL，作者写道 Python seems to be reasonably understood across various administrative services；程序为函数声明序列，用于重复调用 M 规则并每次给出不同的 M 变量赋值；局部变量仅存在于 M++（每个函数体一个作用域，禁止 shadowing，无 block scope 与 nonlocal），全大写变量属于与 M 共享的作用域 [p.5]。
- 与 M 交互的构造 [p.6]：`<-` 在内存副本中执行函数调用，只有左侧变量的值传回父环境；call_m 是执行 M 规则的特殊函数；partition with k 在块内把 kind 为 k 的变量暂设为 undef，块结束后恢复原值，其余变量的结果传回父作用域。cast 把 undef 转为 0，exists(k) 检查 kind 为 k 的变量中是否有非 undef 值，del v 归约为把 v 设为 undef [pp.6–7]。
- 作者称，这些语义受 DGFiP 需求影响，力求对法国行政部门的技术人员直观；形式化引入 call stack，把 M 计算视为返回多个值的函数调用，而原始 C 代码没有这一概念 [p.6]。
- 示例 compute_benefits（Fig. 8）：在 partition with taxbenefit 内调用 call_m，只保留 5 个 M 输出变量，用 cast 存入局部变量，再把部分值写回 M 变量供后续调用使用 [p.6]。

**Mlang（第 4 节）**

- 输入为 M 代码库、M++ 文件和一个 assumptions 文件；输出 Python 或 C，另有内置 interpreter；OCaml 实现，约 9,000 行 [p.7]。流程（Fig. 10）：parsing、desugaring、inlining 成单一的 BIR（由赋值与条件构成），再转为 OIR（BIR 的 control-flow-graph 等价形式）做优化，最后回到基于 AST 的 BIR 生成 C 文本 [pp.7–8]。
- Assumption files：作者称在 C 中声明原 M 规则里全部 27,113 个可能变量 would be quite unsavory，故用单独文件事先声明哪些变量作输入、哪些是关注的输出 [p.7]。作者手写了 5 个：All（空文件，对 2018 代码库留下 2459 input variables、10,411 output variables）；Selected outs（所有输入，只保留 11 个输出）；Tests（DGFiP 测试文件所用的输入与输出）；Simplified（DGFiP 每年在完整计算发布前几个月发布的简化模拟器，正文称 214 个输入，选 11 个输出）；Basic（输入仅为婚姻状况和夫妻各自的工资，输出为所得税）[p.7]。作者称这样做提高生成的 C 或 Python 的质量 [p.7]。
- 优化：在 OIR 上做 dead code elimination、inlining、partial evaluation 等 textbook optimizations [p.7]。因 undef，e * 0 不能改写为 0，e + 0 不能改写为 e，作者因此把 partial evaluation 与 definedness analysis 结合（格见 Fig. 12，转移函数 absorb# 与 cast# 见 Fig. 13，规则示例见 Fig. 14）[p.8]。+ 0 与 * 0 的优化在出现 IEEE-754 特殊值（NaN、minus zero、infinities）时无效；作者给 M 代码插桩确认其在所用值上有效，并只在设置 --fast_math 时启用这些 unsafe optimizations [p.8]。
- 后端：遗留后端生成 pre-ANSI (K&R) C，每条 M 规则生成两段计算，一段在 char 上判断结果是否已定义（0 未定义、1 已定义），另一段在 double 上做算术 [p.8]。Mlang 后端从 BIR 生成 C 与 Python，分别用了 500 行和 375 行；两个后端通过在整个测试集上运行并与 reference interpreter 比较结果来验证；生成代码只依赖一个小型 helper 库，经手工对照论文语义审计 [p.9]。

**评估设计（第 5 节）**

- 性能：比较遗留系统（DGFiP 编译器 + GCC -O0/-O1）与 Mlang 的 C 后端（Array 方案，Clang -O0/-O1）的耗时与二进制大小 [p.9]。
- 数值表示：后端改用 MPFR 多精度库（1024-bit float）；检测 IEEE-754 取整模式的影响；改用 big decimals（整数部分 bignum，小数部分定长位数）；改用有理数（分子分母均为 big integer）[pp.9–10]。
- 测试生成：随机变异遗留测试集（丢弃抛出异常的用例）；用 AFL 做 coverage-guided fuzzing，把合成用例不触发 M 错误（即有效用例）人为定义为 crash，并建立从 AFL 控制的不透明二进制输入到 DGFiP 输入变量的映射；尝试动态符号执行工具 KLEE [p.10]。
- 覆盖度：作者称传统 code coverage makes little sense，因为生成代码中条件很少；改用 value coverage，并称它是测试质量的 proxy [p.10]。

## 3. 数据与范围

- 法域与对象：法国所得税（IR）。作者称法国税法文本约 3,500 pages，计算含档次制（bracket system），以及随家庭构成（子女数、年龄、残疾等）参数化的税收抵免、扣除、可选规则和国家直接补助 [p.1]。被分析的是 DGFiP 的 IR 计算 2018 年版：48 个文件，共 92,000 行代码，用 M 写成 [p.2]。
- 遗留系统规模：90,000 行 M 规则经自定义编译器编译为 535,000 行 C（含空白与注释），规则已基本公开（mostly public）；inter 驱动层 35,000 行 C，未公开；两者每年随法律更新而修改，已有 30 年运行历史 [p.2]。架构（Fig. 1）：M 规则文件经 DGFiP 内部编译器生成 C 文件，与手写的 inter C 文件通过共享状态交互，由 GCC 编译为共享库（图中标为 calculette）[p.2]。
- 测试数据：DGFiP 私有测试集由律师逐年手工构建；作者从中提取 476 个不触发异常的可用用例；作者称该测试集中许多手写测试针对旧版税法 [p.10]。随机变异得到 1267 个测试；AFL 合成约 30,000 个用例，经 afl-cmin 缩减为 275 个 [p.10]。早期逆向阶段另用 DGFiP 的简化在线税务模拟器作 oracle [p.4]。
- 评测对象与环境：Mlang 的 C、Python 后端与 interpreter [p.7]，对比遗留系统（DGFiP 编译器 + GCC）；工具含 Clang、MPFR、AFL、KLEE [pp.9–10]；性能测量针对测试集中选出的一户（fiscal household）[p.9]。硬件与软件版本：原文未说明（fuzzing 一处称 high-end machine [p.10]）。
- 可得性：作者称代码开源并存档于 Zenodo（引用 [20]、[21]）[p.2]；所用 DGFiP 测试集为私有（private）[p.1]。

## 4. 结果

### 实证结果

- 一致性：作者报告在遗留系统测试集上达到 100% conformance [p.2]；对随机变异得到的 1267 个测试，也报告达到 100% conformance [p.10]。fuzzer 生成的用例指出了 Mlang 优化和后端中的少量 bug（a few bugs）[p.10]；原文未说明 fuzzer 生成的 275 个用例上 Mlang 与遗留系统输出的比较结果。
- 形式化：作者报告在 Coq 中完成 Expressions 与 Statements 两条 type safety 定理的证明 [p.5]；报告借助形式化及其实现确认，遗留系统目前不依赖 call_m 之间的 hidden state [p.6]。作者称弄清 M 的语义花了一年以上 [p.4]。
- 指令数：内联 M 与 M++ 后初始 BIR 指令数为 656,020，作者称其大致对应遗留编译器的输出，理由是遗留编译器不做优化 [p.7]。正文称不设任何假设（All）时优化把生成的 C 代码缩到未优化大小的 15%（a factor of 6.5），用最严格的假设文件（Simplified）时只剩原指令数的 0.47% [p.7]。Fig. 11 [p.8]：

| Spec. name | # inputs | # outputs | # instructions |
|---|---|---|---|
| All | 2,459 | 10,411 | 129,683 |
| Selected outs | 2,459 | 11 | 99,922 |
| Tests | 1,635 | 646 | 111,839 |
| Simplified | 228 | 11 | 4,172 |
| Basic | 3 | 1 | 553 |

- 运行性能：Fig. 16 [p.9]，Time 为主税务计算函数内耗时（测试集中选出的一户），Bin. size 为编译后二进制大小：

| Scheme | M compiler | C compiler | Bin. size | Time |
|---|---|---|---|---|
| Original | DGFiP | GCC -O0 | 7 Mo | ∼1.5 ms |
| Original | DGFiP | GCC -O1 | 7 Mo | ∼1.5 ms |
| Array | Mlang | Clang -O0 | 19 Mo | ∼4 ms |
| Array | Mlang | Clang -O1 | 10 Mo | ∼2 ms |

- 实现层面的报告 [p.9]：每个 M 变量生成一个 C 局部变量的最初方案，因有数以万计局部变量，运行需要 ulimit -s；作者称曾因过于直接（exceedingly naïve）的翻译而 breaking Clang 与 Python 的 parser；之后改用遗留系统同样的全局数组方案（Array）。Fig. 16 中 Array 方案的 Mlang 两行，Time 与 Bin. size 的数值均大于 Original 两行。
- 数值表示 [pp.9–10]：MPFR 的 1024-bit float 下所有测试仍通过；取整模式不是默认值时结果不正确，控制流大体不变，但一些与 0 的比较给出不同结果；big decimals 方案中，测试集里整数部分从未超过 9999999999（可用 37 bits 编码），小数部分 40 bits 即得到正确结果；有理数方案中分子分母均未超过 2^128，性能影响尚未研究。
- 测试生成 [p.10]：随机变异的 1267 个测试与遗留测试集很接近，没有覆盖很多新情形，但对逆向 M 语义有帮助；AFL 合成约 30,000 个用例，缩减为 275 个，全面 fuzzing 需几小时、定向 fuzzing 需数分钟；KLEE 对浮点计算的支持 extremely limited，作者计划在整数编译方案上再试。
- 覆盖度 Fig. 17 [p.10]，数值为各测试集中赋值所占百分比，列为每个赋值被赋予的不同值个数：

| 测试集 | 0 (uncovered) | 1 | 2 or more |
|---|---|---|---|
| DGFiP Private (476 tests) | 19% | 71% | 10% |
| Randomized (1267 tests) | 50% | 42% | 8% |
| Fuzzer-generated (275 tests) | 0% | 88% | 12% |

### 作者的解释或推论

- 作者把 -O1 下接近遗留代码的速度归因于该全局数组只有几十 kB、可放入多数现代处理器的 L2 cache，称这是 DGFiP 的 surprisingly fortuitous choice；称 Mlang 在 -O1 下 almost as fast as the legacy code，并认为相对于生成 PDF 摘要的 ∼200ms，500µs 的差异 insignificant [p.9]。
- 作者据 1024-bit float 下所有测试仍通过，认为 64-bit 双精度格式没有精度损失 [p.9]；据 big decimals 结果，认为 128-bit 整数可作为 double 的替代，且形式化分析工具更易处理 [p.9]；作者设想（wondered）能否完全不用浮点，并据有理数的分子分母均未超过 2^128，称可以设想（conceivably）用含两个 128-bit 整数与一个符号位的 struct 实现值 [pp.9–10]。
- 作者对覆盖度的解读：随机测试 did not result in meaningful tests（未覆盖赋值占比上升）；AFL 测试 significantly increase the quality of test coverage，合成了许多覆盖遗留测试集未访问语句的测试，且赋值更复杂（被赋予 2 个或更多不同值）[p.10]。
- 作者转述 Lawsky 对美国税法逻辑结构的研究，称她主张税法起草风格遵循 default logic（non-monotonic，难以用一阶逻辑 FOL 语言编码），并写道，因 M 也基于 FOL，这 could explain DGFiP 代码库的复杂性 [p.11]。
- 作者称，另一政府机构用 Python 重新实现了整个法国 socio-fiscal system [29]，该举措 was helpful，其结果用作多个在线模拟器的计算后端，但没有法律约束力（not legally binding），也未处理法律的所有 corner cases [p.11]。
- 作者称，把 M 语言带入 21 世纪，既 greatly enhance 生成代码的质量，也 unlock 一批 significantly increase 作者对法国税务计算信心（our confidence）的技术 [p.9]。
- 作者称，M++ 的形式化语义更 principled，相信这将降低未来出错风险 [p.6]；结论中称借助现代编译器构造技术，把遗留、保密的代码库变成了可复用的公开 artifact，可分发到几乎任何编程环境，并认为 DGFiP 的下一步是借鉴 programming languages 研究，设计 M/M++ 的后继者 [p.11]。

## 5. 作者陈述的局限与前提

文中未专门讨论局限；以下为散见于正文的相关说明。

- 测试数据：DGFiP 没有自动生成新情形的基础设施，遗留测试集覆盖的家庭类型 relatively limited，许多手写测试针对旧版税法，描述的情形按当前税法会被拒绝 [p.10]。作者对遗留测试集的了解不完整，只能访问部分测试；税额在审计后需调整时适用的一组特殊规则，其测试未提供给作者，作者希望将来能看到 [p.10]。
- 工具与实验：KLEE 的浮点支持 extremely limited，作者计划用整数编译方案再研究 [p.10]；有理数表示的性能影响尚未研究 [p.10]；检测取整相关错误的静态分析（恒为假的比较、可疑地接近零的数、denormals）仍是计划 [p.9]；作者还计划用 AFL 找满足税法原本没有的额外性质的用例，例如可能引发合法性疑问的过高边际税率 [p.10]。
- 前提与假设：M 假定默认的 IEEE-754 取整模式 [p.3]；作者在 µM 的形式化中假设计算已按合适顺序排列 [p.3]；+ 0 与 * 0 的优化在出现 IEEE-754 特殊值时无效，作者仅在所用值上做了插桩确认，并只在设置 --fast_math 时启用 [p.8]；assumptions 文件中的输入与输出随使用场景而异 [p.7]。
- 验证范围：作者写道，视 DGFiP 对形式验证的意愿，可能（may）验证整个编译器，因为语义相对较小 [p.9]。
- 限定语：对遗留系统的部分描述带有限定语，如 insofar as we understand [p.5]、we suspect [p.6]。

## 6. 关键术语

- M 与 inter：M 是 DGFiP 设计的自定义、non Turing-complete 语言，所得税的 rules 用它编写；inter 是 DGFiP 在 1995 年加入的高层 C glue code，调用图非递归，可用不同参数多次调用 rules 计算，用于涉及不同年度纳税申报的 liquidations multiples，35,000 行，未公开 [p.2]。
- undef：M 的特殊值，出现在引用未定义变量（税表条目留空）和数组越界访问两种情形；可用 + 0 显式转为 float；函数 present 区分 undef 与 float [p.3]。
- µM：作者给出的 M 核心演算（core calculus），省略变量声明与语法糖 [p.3]。
- M++：作者设计的伴随 DSL，作为 M 代码的 driver，重复调用 M 规则并每次给出不同的 M 变量赋值 [p.5]；call_m 是执行 M 规则的特殊函数，`<-` 在内存副本中执行它，partition with k 在块内把 kind 为 k 的变量暂设为 undef [p.6]；kind 是对税表同一部分变量的标注，如 triggers tax credit、is advance payment [p.2]。
- BIR 与 OIR：BIR（backend intermediate representation）是 M 与 M++ 内联后的单一中间表示，由赋值与条件构成；OIR（optimization intermediate representation）是 BIR 的 control-flow-graph 等价形式，优化在其上进行 [p.7]。
- Assumption files：Mlang 的输入之一，事先声明哪些变量可作输入、哪些是关注的输出；作者手写了 All、Selected outs、Tests、Simplified、Basic 五个 [p.7]。
- Definedness analysis：与 partial evaluation 配合的简单分析，格含 undef# 与 ⟨float⟩#，转移函数 absorb# 与 cast# 用来判断结果是否已定义 [p.8]。
- Value coverage：作者采用的覆盖度量，对代码中的每个赋值，统计一个完整测试用例执行期间被赋予的不同值的个数 [p.10]。
