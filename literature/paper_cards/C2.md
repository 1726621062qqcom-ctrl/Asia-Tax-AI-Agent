# Factoring Statutory Reasoning as Language Understanding Challenges

## 1. 研究问题与作者主张

- 问题：statutory reasoning 指判断以自然语言表述的法律条文（statute 的某个 subsection）是否适用于以文字描述的案件（case）[p.1]。作者写道，此前工作（Holzenberger et al., 2020）的 SARA 基准把该任务设为整体的 textual entailment 问题，神经网络基线 "performing nearly at-chance" [p.1]；该前作的 Prolog symbolic reasoner 被报告可完全解决任务，但需专家编写代码并把案件描述翻译成事实；统计模型表现差，原因被归为任务复杂度远超可用训练数据量 [p.1]。
- 做法：借用 Prolog 程序中的概念与结构，把 statutory reasoning 分解为四类 language-understanding challenge 任务，在已有基准上增补这四项任务的标注，并为其中三项提供基线；扩展后的数据集称 SARA v2 [p.1]。
- 核心主张：作者假设（posit）statutory reasoning 以 Recognizing Textual Entailment 与 linear regression 的形式呈现给统计模型时是 underspecified [p.1]，并据此把它重述为四个任务的序列 [p.1]。
- 作者声称的收益：模型 "shown to beneﬁt from the additional structure, improving on prior baselines" [p.1]；任务分解 "facilitates ﬁner-grained model diagnostics and clearer incremental progress" [p.1]；额外结构使模型更可解释，因而更适合实际应用 [p.1]；作者还希望四项任务为问题提供结构，并给机器学习算法提供 "a more efﬁcient inductive bias" [pp.1–2]。
- 基线的用途：作者称提供 Section 3 基线的目的，是找出所提任务序列中的 performance bottlenecks [p.8]。

## 2. 方法

**任务分解**（Figure 1 [p.3]）

- Argument identification：给定 token 序列，返回一组 span (s, e)，每个 span 是 subsection 中的一个 placeholder，作者称之为 argument；取值随案件而变的词（如 a taxpayer）算，指向固定对象的词（如 section 152）不算；标注为字符级 span，取最短的有意义短语 [p.2]。
- Argument coreference：给定 span 集合，返回矩阵 `C ∈ {0,1}^(S×S)`，两个 span 指同一变量时 C_ij = 1；只在单个 subsection 内解决，跨 subsection 的留给 structure extraction [p.2]。
- Structure extraction：解析 statutes 内显式与隐式的引用及其逻辑关系，并在 subsection 之间传递 argument（例如 §152(b)(1) 的 taxpayer 成为 §152(a) 的 dependent）；标注为 Horn clauses 风格，另给出各 subsection 起止的字符偏移；作者写道，标注一般需要专家知识，因为许多引用是隐式的，有些需借助 Treasury Regulations [p.2]。前三项任务只需 statutes 即可完成，对应抽取 Holzenberger et al. (2020) 的 symbolic solver 的浅层版本 [p.2]。
- Argument instantiation：输入为 subsection 字符串、前三项任务的标注，以及部分或全部 argument 的取值（key-value pairs）；输出为各 argument 的取值，其中 `@truth` 取 True 或 False，表示该 subsection 是否适用 [pp.2–3]。取值可以是案件中的 span，也可能需根据案件推算（常见于 dollar amount：把收入相加或计算 tax）；输入中未给出的 argument 的取值作为额外监督，不作输入 [p.3]。

**标注**

- 标注由作者全部手工完成，有一位 legal scholar 定期指导 [p.2]。SARA 的所有 (subsection, case) 对均有人工标注（gold）[p.3]；另运行 Holzenberger et al. (2020) 的 Prolog solver，为所有可能的 (subsection, case) 对生成标注（silver），case 属于测试集的对被排除，作者称这使可用训练数据量增加 by a factor of 210 [pp.3–4]。

**基线**（不为 structure extraction 提供基线：作者假设若人工只能标注四项任务之一，它的回报最高，并引用 Pertierra et al. (2017) 称相关的 semantic parsing 任务困难 [p.4]）

- Argument identification，parser-based：Stanford parser (Socher et al., 2013) 解析 statutes，把所有 NNP、NNPS、PRP$、NP、NML 成分抽为 span；作者报告去格式化（de-formatting）在其情形下差别很小 [p.4]。
- Argument identification，BERT-based CRF：9 个 sections 中把 §68、3301、7703 合为一个 split，得到 7 个等大 split，做 7-fold cross-validation（1 个作 dev，1 个作 test，其余训练）；BERT 编码每个段落，经线性层（3 维 logit）和 CRF 做 BIO tagging，以 gold tag 序列的 log-likelihood 训练；比较 Legal BERT 与 BERT-base-cased，冻结参数并可选解冻最后一层；batch size 32 个段落，learning rate 10^-3，Adam；按 dev F1，最佳模型为 Legal BERT 且解冻最后一层 [p.4]。
- Argument coreference：评测用 exact match coreference，只有返回的 mention 簇与某个 argument 完全一致才给分；作者说明它不同于强调 mention 间 link 预测的常规 coreference，对单 mention argument（无 link）与 5-mention argument（10 个 link）给同样的分 [p.4]。Single mention baseline 不预测任何 link；String matching baseline 在两个 argument 的 placeholder 字符串相同（忽略 such、a、an、the、any、his、every）时预测 link；另用 Pradhan et al. (2014) 的配套代码计算常规指标 [p.4]。Cascade：BERT-based argument identification 后接 string matching [p.5]。
- Argument instantiation，单个 subsection（Algorithm 1）：沿用 Chen et al. (2020) 的范式，迭代地把已知 argument 的取值插入 subsection 文本，再预测未取值的 argument；案件文本与改写后的 subsection 拼接，经 BERT 编码和 COMPUTEATTENTIVEREPS 得到该 argument 的 attentive 表示 [p.5]。取值为整数或案件中的 span：整数先对训练集整数值做 k-means，模型返回 centroid 的加权平均，权重由线性层加 softmax 预测；span 沿用 BERT 在 SQuAD 上的 fine-tuning 做法，从 token i 到 j 的未归一化概率为 `e^(l·x_i + r·x_j)`，l、r 为可学习参数 [p.5]。argument 按在 subsection 中出现的顺序处理，最后用 [CLS] 表示上的线性预测器预测 `@truth` [p.6]。
- Argument instantiation，带依赖关系（Algorithm 2）：按 structure 标注建成 dependency tree，节点是带 argument-value pairs 的 subsection 或逻辑运算；argument 值由根向下传给子节点；树可截断到预设深度；深度优先遍历：叶子 subsection 用单 subsection 函数求解；非叶子 subsection 先把子节点的 argument-value pairs（`@truth` 除外）并入自身再求解；NOT 取子节点 `@truth` 的反值；OR 取 `@truth` 值最高的子节点并赋其 argument 值；AND 汇集所有子节点的 argument-value pairs，值冲突时取 `@truth` 值较低者对应的取值 [p.6]。作者称该过程遵循 neural module networks (Andreas et al., 2016) 的形式；dependency tree 不允许 reentrancy，较早的决定不能在后续回溯 [p.6]。
- 评测指标：`@truth` 用 binary accuracy；dollar amount 用 numerical accuracy，当 `Δ(y, ŷ) = |y−ŷ| / max(0.1∗y, 5000) < 1` 时记 1，否则记 0（ŷ 为预测，y 为目标）；其他取值按字符串 exact match；三种 accuracy 按样本数加权平均，得到 unified accuracy [p.7]。
- 训练：`@truth` 用 binary cross-entropy，数值用 hinge loss `max(Δ(y, ŷ) − 1, 0)`，字符串用以案件中等于期望值的 span 集合 S 定义的 log 比值损失（Clark and Gardner, 2018），端到端梯度下降 [p.7]。先在 silver 数据上预训练：BERT-base-cased 与 Legal BERT（允许更新顶层）都试，留出 10% silver 作 dev，按 dev 的 unified accuracy 选模型；分三阶段：第一阶段无论预测值如何都插入 gold 值（teacher forcing），第二、三阶段插入模型预测值，前两阶段忽略 statutes 结构（等于 dependency tree 深度限为 1）[p.7]。再在 gold 数据上 fine-tune：SARA v2 训练集随机分成 10 个 split（测同一 subsection 的一对 case 放同一 split），按 10 个 split 上 dev 平均表现选超参数，最终模型取 dev 表现居中者，报告其 test 表现 [p.7]。
- Baseline 有三个参数：`@truth` 返回训练集中最常见的值；dollar amount 返回使训练集 hinge loss 最小的单一数值；其他 argument 返回训练集中最常见的字符串；这些参数随训练集是否并入 silver 数据而不同 [p.8]。表 5 中带 - 号的行是对 BERT 模型的 ablation [p.8]；'- pre-training'、'- structure' 的具体操作，原文未逐项说明。

## 3. 数据与范围

- 数据集：SARA v2，作者对 SARA（Holzenberger et al., 2020）的扩展 [p.1]；数据见 https://nlp.jhu.edu/law/ [p.2]，代码见 https://github.com/SgfdDttt/sara_v2 [p.4]。
- 法域与领域：美国，statutes 来自 US code [p.1]；SARA v2 statutes 含 9 个 sections [p.4]，原文未在一处列出，文中提到 §68、3301、7703 [p.4]，示例涉及 §1(d)(iv)、§2(a)(1)、§63(c)(5)、§151、§152、§3306(a)(1)(B) [p.3][p.14]。对照语料 Random 为从 Tax Code 随机抽取并标注的 9 个 sections [p.16]。时期：原文未说明。
- 样本量（附录 B；各表另有 stddev 与 median）：Table 6 的 subsection 数为 SARA 194、Random 146，每个 subsection 的 placeholder 数 average 为 3.0 与 4.0；Table 7 的 subsection 数为 SARA 161、Random 146，每个 subsection 的 argument 数 average 为 2.4 与 3.1 [p.16]。Table 8 的 argument 数为 SARA 473、Random 456，每个 argument 的 mention 数 average 为 1.2 与 1.3；Table 9 的 structure 标注覆盖 192 个 subsection，每个 subsection 的 arguments average 3.0、dependencies average 1.0；Tables 10、11（argument instantiation）的 total 行为 gold train 256、test 120、all 376，silver 75543 [p.17]。图 2 的直方图（SARA 与 Random）未在文中给出数值 [p.3]。
- 评测划分：argument identification 为 7-fold cross-validation，avg ± stddev 跨 test splits 计算；coreference baseline 无训练，avg ± stddev 跨 subsections 计算 [p.4]；argument instantiation 报告 test 集表现，超参数由 gold 训练集上的 10 个 split 选定 [p.7]。
- 评测的模型：Stanford parser、BERT-based CRF、single mention、string matching、cascade [pp.4–5]；argument instantiation 的 BERT 模型、ablation 与三参数 baseline [pp.7–8]；该模型最终用 Legal BERT 还是 BERT-base-cased，原文未说明。

## 4. 结果

### 实证结果

- Argument identification（Table 1；avg ± stddev 跨 test splits，括号内为 macro 列，文中未定义 macro）[p.4]：Parser-based 的 precision 17.6 ± 4.4（16.6），recall 77.9 ± 5.0（77.3），F1 28.6 ± 6.2（27.3）；BERT-based 的 precision 64.7 ± 15.0（65.1），recall 69.0 ± 24.2（59.8），F1 66.2 ± 20.5（62.4）。
- Argument coreference，exact match coreference（Table 2；avg ± stddev 跨 subsections，括号内为 macro）[p.4]：Single mention 的 precision 81.7 ± 28.9（68.2），recall 86.9 ± 21.8（82.7），F1 83.8 ± 26.0（74.8）；String matching 的 precision 91.2 ± 20.0（85.5），recall 92.8 ± 16.8（89.4），F1 91.8 ± 18.6（87.4）。String matching 完全正确解析 80.8% 的 subsection 的 coreference，single mention baseline 为 68.9% [p.4]。
- 常规 coreference 指标（Table 3，Precision / Recall / F1）[p.5]：Single mention 的 MUC 为 0 / 0 / 0，CEAFm 82.5 / 82.5 / 82.5，CEAFe 77.3 / 93.7 / 84.7，BLANC 50.0 / 50.0 / 50.0；String matching 的 MUC 为 82.1 / 64.0 / 71.9，CEAFm 92.1 / 92.1 / 92.1，CEAFe 90.9 / 95.2 / 93.0，BLANC 89.3 / 81.0 / 84.7。
- Cascade（BERT-based argument identification 后接 string matching；Table 4，exact match，avg ± stddev 跨 subsections，括号内为 macro）[p.5]：precision 54.5 ± 35.6（58.0），recall 53.5 ± 37.2（52.4），F1 54.7 ± 33.4（55.1）；作者报告 cascade 完全正确解析一个 subsection 的 arguments 的情形仅占 16.4% [p.5]。
- Argument instantiation（Table 5；单位 %，附 90% confidence interval；用 silver 一列依行标签底色，蓝色用、棕色不用；粗体为表中标出的最佳值；binary、numerical 为数据集初版随附的指标，定义见 Holzenberger et al. (2020)）[p.8]：

- 误差分析（作者对表 5 中 binary accuracy 最佳模型的检查；该列粗体最佳值在 '- structure' 行）[p.8]：39 对正、负 case 的回答相同，由此得到 39 个正确答案；其余 11 对中有 10 对两个 case 都答对。dollar amount 的最佳 BERT-based 模型对每个 case 预测同一个数，baseline 也如此。string 的最佳模型的预测通常与期望答案属同一类别（日期、人名等），但没有预测出正确字符串。

### 作者的解释或推论

- Argument identification：作者认为它是中等程度的挑战，基于语言模型的方法取得非平凡的 F1；parser-based 方法并非充分的解决方案，但其高 recall 可作为统计方法的骨干 [p.8]。
- Argument coreference：作者认为这是较简单的任务，string matching 完全正确解析近 80%（原文 nearly 80%）的 subsection，与法律语言在消歧 coreference 上很明确的直觉一致；Table 3 的常规指标看起来较低，但只反映任务的一个子集：这些指标只关注 link，只出现一次的 argument 除非被错误链接，否则不占权重 [p.8]。
- Cascade：作者称该设置 "offers a signiﬁcant challenge" [p.5]。
- Argument instantiation：作者称它是 by far the most challenging task，因为模型需要较强的自然语言理解能力；简单 baseline 在 `@truth` 上可达 50% 以上，因为所有 numerical case 的 `@truth` 都是 True [p.8]。作者称所提范式使 binary accuracy 有 slight boost，与此前在该基准上的结果不同；相比 baseline，模型在 dollar amount 与 numerical accuracy 上多数落后，作者认为可由缺少专用数值求解器和数据稀疏解释；作者提出若干简化假设可能妨碍模型利用 structure 信息，并写道这也可能解释为什么使用 dependencies 在某些情形下是 detrimental [p.8]。
- 误差分析：作者认为该结果提示模型可能在 39 对上是随机猜测、在 10 对上是理解了（原文 may be guessing randomly）[p.8]。
- silver 数据：作者称其带来的提升 noticeable and generally consistent（比较表 5 中蓝、棕单元格）；silver 来自人工编写的 Prolog 程序，成本高；作者提出的可能替代是在大型法律案例语料（Caselaw, 2019）中查找适用法条的提及，例如用 high-precision rules [pp.8–9]。
- 结论：作者认为每项任务的标注所需专业知识远少于把法律语言翻译成代码，且各有评测指标；该贡献使模型的打分与调试更细粒度，便于渐进改进和识别性能瓶颈；argument instantiation 与显式依赖解析带来更多可解释性；作者称该方法 could possibly inform 在法律 NLP 及其他领域中对以自然语言规定的规则进行推理的模型设计 [p.9]。

## 5. 作者陈述的局限与前提

文中没有单独的局限小节；以下来自 Discussion 等处作者自己写明的局限和前提。

- 简化假设（作者称其可能妨碍模型利用 structure 信息）：argument 按出现顺序实例化，不能联合预测；不允许回头修改既有预测，模型必须承受较早的错误决定；dependency tree 深度限为 3；信息以 argument 值而非稠密高维向量沿树传递，作者称后者同时限制了信息流与学习信号；未来工作涉及 joint prediction（Chan et al., 2019）与更谨慎地使用 structure 信息 [p.8]。
- 前提：作者假设人类通常能按文本顺序解决该任务，计算模型应当也可以；该方案意在计算高效，希望不损失过多表现；重新检验这一假设留待未来工作 [p.6]。
- 结果的限定：缺少专用数值求解器、数据稀疏（作者对 dollar amount 与 numerical accuracy 上落后的解释）[p.8]。每个任务目前都使用上游任务的 gold annotations，最终目标是把一个任务的模型输出传给下一个任务 [p.9]；文中只报告了前两项任务的 cascade [p.5]。
- 标注与数据：structure extraction 的标注一般需要专家知识 [p.2]；silver 数据来自人工编写的 Prolog 程序，作者称其成本高 [p.8]。

## 6. 关键术语

- statutory reasoning：判断给定 statute 的某个 subsection 是否适用于给定案件，二者都以自然语言表述；subsection 被隐式地视为对案件可真可假的 predicate [p.1]。
- SARA / SARA v2：Holzenberger et al. (2020) 提出的 statutory reasoning 基准；SARA v2 为本文增补四项任务标注后的扩展 [p.1]。
- argument（placeholder）：subsection 中取值随案件而变的词；argument identification 标出这些 span，argument coreference 判定哪些 span 指同一变量 [p.2]。
- structure extraction：解析 subsection 之间的引用与逻辑连接并传递 argument，标注为 Horn clauses 风格 [p.2]。
- argument instantiation：给定案件、subsection 和部分 argument 的取值，预测各 argument 的取值；`@truth` 为 True 或 False，表示该 subsection 是否适用 [pp.2–3]。
- gold / silver：gold 为人工标注；silver 由 Holzenberger et al. (2020) 的 Prolog solver 为所有可能的 (subsection, case) 对生成 [p.3]。
- exact match coreference：只有返回的 mention 簇与某个 argument 完全一致才给分的 coreference 指标 [p.4]。
- unified accuracy：`@truth` 的 binary accuracy、dollar amount 的 numerical accuracy 与其他取值的 exact match accuracy 按样本数加权的平均 [p.7]。

## 7. 原文摘录

- "Statutory reasoning is the task of determining whether a legal statute, stated in natural language, applies to the text description of a case." [p.1]
- "We posit that statutory reasoning as presented to statistical models is underspeciﬁed, in that it was cast as Recognizing Textual Entailment (Dagan et al., 2005) and linear regression." [p.1]
- "The cascade perfectly resolves a subsection’s arguments in only 16.4% of cases. This setting, which groups the ﬁrst two tasks together, offers a signiﬁcant challenge." [p.5]
- "Reentrancy into the dependency tree is not possible, so that a decision made earlier cannot be backtracked on at a later stage." [p.6]
- "We receive a slight boost in binary accuracy from using the proposed paradigm, departing from previous results on this benchmark." [p.8]
- "As compared to the baseline, the models mostly lag behind for the dollar amount and numerical accuracies, which can be explained by the lack of a dedicated numerical solver, and sparse data." [p.8]
- "In the remaining 11 pairs, there are 10 pairs where it gets both cases right. This suggests it may be guessing randomly on 39 pairs, and understanding 10." [p.8]
- "Further, we have made a number of simplifying assumptions, which may be keeping the model from taking advantage of the structure information ... This could also explain why the use of dependencies is detrimental in some cases." [p.8]
