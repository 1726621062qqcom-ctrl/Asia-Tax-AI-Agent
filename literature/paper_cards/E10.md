# Introducing L4-Docassemble

## 1. 研究问题与作者主张

- 背景与目标：这是作者在 Medium 上发表的介绍性博文（2021 年 5 月 5 日，标注 9 min read）[p.1]。SMU Centre for Computational Law 在开发开源的法律领域专用语言 L4，设想是用 L4 写法律规则（法律条文或合同），再由其他应用把编码翻译成其他形式去做有用的事；其中一项用途是构建 expert system [p.1]。作者写道，团队着手查看能否更容易地用声明式逻辑编码（declarative logic encoding）驱动 Docassemble 法律专家系统 [p.3]。
- 作者对现状的判断：作者称 Docassemble 是开源选项中的 best option available（原话见第 7 节），但没有 Oracle Intelligent Advisor（OIA）、Neota Logic、DataLex 等商业闭源工具具备的三项功能：法律与合同的逻辑表示、原型用户界面、答案的自然语言解释；作者说用开源工具做这几件事目前 「no easy way to do」 [p.2]。作者另列四项他称目前任何工具（含 OIA、Neota Logic、DataLex）都没有的能力：defeasibility、modular rules and data structures、multiple justifications、hypothetical reasoning [pp.3–4]。
- 对成果的主张：作者称 L4-Docassemble 是填补上述部分缺口的尝试 [p.5]。六项功能中，带 * 的三项（Logical Representation of Rules、Rapid Prototyping、Natural Language Explanations）在作者所知的其他开源工具中不存在；带 + 的三项（Defeasibility、Modular Data Structures and Rules、Multiple Justifications）对专家系统开发工具而言是 completely novel（原话见第 7 节）[pp.5–6]。Hypothetical reasoning 不在这六项之内，作者说仍在开发 [p.6]。
- 对用法的主张：作者称，已有某法的 s(CASP) 编码和 LExSIS 文件时，为同一套规则建一个回答不同问题的专家系统只需改一行代码；作者把这称作 rules as code 方法的 「huge promise」，并把规则编码的投入所得描述为一个 「app factory」 [p.12]。

## 2. 方法

本文是系统介绍，没有实验设计；以下转述系统构成、使用流程和演示所用的编码。

- 构成：L4-Docassemble 由团队在 GitHub 上提供的三个 package 和一个 docker container 组成 [p.5]。docassemble-scasp 使 Docassemble 能使用由 L4 翻译得到的 s(CASP) 编码；docassemble-datatypes（团队在 DocaCon 2020 介绍过）按数据结构自动生成原型界面；docassemble-l4 针对 s(CASP) 编码实现 LExSIS 格式，从而能依据 s(CASP) 编码与数据结构生成 interview；docker container 预装上述各包、s(CASP) 和 docassemble，即 L4-Docassemble，作者说它本身不含代码，只是一次装齐全部组件的便利方式 [p.5]。
- 使用流程：（1）安装；（2）把 s(CASP) 与 LExSIS 文件上传到 docassemble playground 的 static folder；（3）运行 interview generation tool，它创建 interview 并装到 docassemble server；（4）按需修改 interview [p.6]。生成的各部分只是默认值，开发者可用 plain old docassemble 替换 [pp.6–7]。
- 规则编码：演示对象是名为 Rule 34 的立法，第一步是把它编码为 s(CASP) [p.7]。节选的 Rule 34(5) 大意是：Second Schedule 所列条件全部满足时，locum solicitor 可在不提供任何 legal services 或 law-related services 的 business entity 接受 executive appointment；条文写明 despite paragraph (1)(b)，但 subject to paragraph (1)(a) 与 (c) 至 (f) [pp.7–8]。代码里它是 `according_to(r34_5,may(LP,accept,EA))` 规则，规则体含五个条件，其中一个是 `not provides_legal_or_law_related_services(BE)`；另有两条 `opposes`、两条 `overrides` 语句（涉及 r34_1、r34_5、r34_1_b），以及 `provides_legal_or_law_related_services(BE)` 的两条定义 [p.8]。
- LExSIS 文件：节选含 `rules`（r34.pl）、`query`（`legally_holds(Rule,must_not(Lawyer,accept,Position))`）和 `data` [p.8]。data 条目带 type、提问文本字段（any、another、ask、tell）、minimum、encodings（把答案对应到 s(CASP) 谓词）和嵌套的 attributes；节选中的 type 有 String、Boolean、Enum、Object，Object 条目带 `source: person` [pp.8–9]。文中未逐项解释各字段和占位符 {X}、{Y}；作者说以后另写博文介绍 LExSIS [p.13]。
- 运行与换问题：两个文件交给 interview generation tool 后，它创建并安装 interview、给出链接；用户点开后 interview 逐个提问，再按 LExSIS 文件的说明和用户已给的答案显示答案 [p.10]。要回答同一法律下的另一个问题，改 LExSIS 文件的 `query` 条目并重新运行 interview generator [p.12]。

## 3. 数据与范围

- 数据：全文不涉及数据集、样本、统计检验、基准或被评测的模型 [pp.1–14]。
- 比较范围：文中讨论的开源工具是 Docassemble，商业闭源工具是 OIA、Neota Logic、DataLex [p.2]。注释 1：开源推理工具 Blawx 与闭源工具 Regulation as a Platform 具备 logical representations 与 defeasibility，但没有开发用户界面的功能，被排除出分析 [p.13]。
- 演示对象：Rule 34；作者说它复杂，有 almost 100 个 input factors，演示用 LExSIS 文件因此相当长 [p.8]。原文没有明说 Rule 34 所属法域；LExSIS 节选里 jurisdiction 的 options 为 singapore 与 other [p.9]。原文说演示第一步是把 Rule 34 编码为 s(CASP) [p.7]，未说明是手写还是由 L4 翻译得到。
- 演示问题：`legally_holds(Rule,must_not(Lawyer,accept,Position))` [p.8]；换问题的例子是 `business_entity(Organization)` [p.12]。
- 发表信息：2021 年 5 月 5 日，Medium 上的 Rules as Code Diary [p.1][p.14]；作者说软件现已在 GitHub 上可得 [p.5]，原文未给版本号。

## 4. 结果

### 实证结果（作者报告的产出与演示；全文没有实验数据）

- 产出：作者报告上述各部分已合成 docker container，称为 L4-Docassemble，现已在 GitHub 上可得 [p.5]。
- 功能：作者列出六项，Logical Representation of Rules、Rapid Prototyping、Natural Language Explanations 带 *，Defeasibility、Modular Data Structures and Rules、Multiple Justifications 带 + [pp.5–6]。Hypothetical reasoning 不在其内，作者说仍在开发，预计 in a couple of months 能加入 [p.6]。
- 演示（Rule 34）：作者报告团队用 L4-Docassemble 做了一个能回答关于 Rule 34 的问题的专家系统 [p.7]。编码中，原法条的 despite 与 subject to 被写成 opposes 与 overrides 语句，作者称这样做无须在其他规则里添加任何内容 [p.8]。
- 界面行为：interview 逐个提问 [p.10]；终屏回答问题，用自然语言解释答案，并给出每个答案的所有可能 justifications [p.11]；作者称 LExSIS 的特性允许把被编码规则的原文和源材料链接作为 meta-data 提供，按用户要求显示 [pp.11–12]。
- 换问题：作者称改 `query` 一行并重新运行即得到回答另一个问题的系统，并建议读者把演示用 LExSIS 文件里的 query 改为 `business_entity(Organization)` 后重新运行 [p.12]；正文文字没有给出改动后系统的输出 [p.12]。
- 未报告：全文没有测试结果、用户研究、性能数据或失败案例 [pp.1–14]；功能对比以文字叙述给出 [pp.2–6]。

### 作者的解释或推论

- multiple justifications：作者称，它对希望让用户选择最有说服力的解释放进文档的专家系统有实际好处；让 legal knowledge engineer 以别处得不到的深度了解编码如何工作；在 Rules as Code 起草过程中，这种了解可能（may）让立法和合同起草者发现原本会漏掉的规则问题；还能看出编码（或法律、合同）中冗余的部分 [p.4]。
- defeasibility：作者称，若能按法律原样编码 defeating 关系，不必把压过的规则与被压过的规则合并，编码及规则变动时的维护会（would）简化 [p.3]。
- 模块化：作者称，收集信息的最好方式取决于要解决的问题而非法律，一部法律可解决多种问题；把收集信息的方式从规则编码中拿出，编码会更易复用，同一套规则可配多个界面而无须改写 [p.3]。
- hypothetical reasoning：作者称可用于给出附条件的回答、为用户目标生成计划，以及在不提供事实时分析规则和编码 [p.4]。
- 对改一行的解读：作者称规则编码所得是 app factory，可即时（instantaneously）生成回答你能提出的任何问题的应用，并称这是 rules as code 方法的 huge promise [p.12]。

## 5. 作者陈述的局限与前提

文中没有专门讨论局限的段落；以下是文中说到的限定、前提和未完成项。

- 未完成：hypothetical reasoning 尚未加入，作者说预计 in a couple of months 能加入 [p.6]。
- 在研性质：团队目前在试验（experimenting）把 s(CASP) 用作驱动专家系统的语言，L4 到 s(CASP) 的翻译由团队其他成员在进行 [p.5]。
- 输入前提：使用流程要求上传使用者自己的 s(CASP) 文件与 LExSIS 文件 [p.6]；一行代码的说法以他人已写好该法的 s(CASP) 编码和 LExSIS 文件为前提 [p.12]；作者说 Rule 34 的 LExSIS 文件因 almost 100 个 input factors 而相当长 [p.8]。
- 知识与比较范围：带 * 的功能不存在于作者所知的其他开源工具 [p.6]；开源缺口的措辞是 no easy way to do [p.2]；注释 1 把没有用户界面开发功能的工具（如 Blawx、Regulation as a Platform）排除出分析 [p.13]。
- 说明未尽：LExSIS 的详细介绍留待以后的博文 [p.13]。

## 6. 关键术语

- L4 与 L4-Docassemble：L4 是 SMU Centre for Computational Law 在开发的开源法律领域专用语言（open source domain specific language for law）[p.1]；L4-Docassemble 是预装 docassemble-scasp、docassemble-datatypes、docassemble-l4、s(CASP) 与 docassemble 的 docker container，本身不含代码 [p.5]。
- expert system：作者定义为一种应用，被给定一个要回答的问题，向用户收集相关信息，再给出专家会给出的答案 [p.1]。
- Docassemble：作者称为流行的开源 interview 工具，能决定问什么问题、按什么顺序问，并可方便地定制问题的显示；使用者熟练掌握 Python 时还可让它做其他事 [p.2]。
- s(CASP)：作者说团队在试验把它用作驱动专家系统的语言 [p.5]；致谢中称 Joaquín Arias Herrero 为其作者之一，并称之为 tool [p.13]；全称和语义原文未说明。
- LExSIS（Legal EXpert System Interface Schema）：团队创建的数据结构格式，用于依据 s(CASP) 编码和数据结构生成 interview，在 docassemble-l4 package 中针对 s(CASP) 编码实现 [p.5]；字段示例见 [pp.8–9]。
- Defeasibility：作者在这一标题下说明，法律与合同常含有压过其他规则的规则；若能按法律原样编码这种 defeating 关系，就不必把压过的规则与被压过的规则合并 [p.3]；演示编码用 opposes 与 overrides 语句表达，作者称这就是能写带 defeasibility 的规则的含义 [p.8]。
- Multiple Justifications：作者的描述是，现有工具给出的解释只说明工具如何推出答案，不能告诉用户在同样事实和规则下同一结论是否还能经别的途径得出；该功能给出一个结论的所有 justifications [pp.3–4]。
- Hypothetical Reasoning：作者说多数 sophisticated 的专家系统在必要事实未知时把结论报告为 unknown 而不是 false；作者设想工具能进一步说出哪些未知事实的组合须为真，结论才为真 [p.4]。作者说 L4-Docassemble 尚未包含它 [p.6]。

## 7. 原文摘录

- "An expert system is an application that is given a question to answer, collects relevant information from a user, and then provides the answer an expert would give." [p.1]
- "While it is the best open source option available, and has much to recommend it, Docassemble does not have some of the features of the best commercial and closed-source tools for legal expert system development, like Oracle Intelligent Advisor, Neota Logic, and DataLex." [p.2]
- "So we set about to see if it would be possible to make it easier to use a declarative logic encoding to power a Docassemble legal expert system." [p.3]
- "As mentioned, the features marked '*' do not exist in any other open source tool of which we are aware, and the features marked '+' are completely novel for expert system development tools." [p.6]
- "We are continuing to work on adding hypothetical reasoning, which we expect to be able to add in a couple of months." [p.6]
- "Note how the 'despite' and 'subject to' parts of the original law were translated into 'opposes' and 'overrides' statements in the code, without having to add anything to the other rules. That is what it means to be able to write rules with defeasibility." [p.8]
- "Using L4-Docassemble, building a new legal expert system to answer a different question about the same rules requires a single line of code." [p.12]
- "There are open source reasoning tools like Blawx and closed source tools like Regulation as a Platform that feature logical representations and defeasibility, but that do not have features for the development of user interfaces. Such tools are excluded from the analysis." [p.13]
