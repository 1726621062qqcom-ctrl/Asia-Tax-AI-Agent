# Constraint answer set programming as a tool to improve legislative drafting: a rules as code experiment

## 1. 研究问题与作者主张

- 目标：作者所在的跨学科团队（interdisciplinary team）要评估 s(CASP) 作为工具，在 Rules as Code 方法下改进立法起草（legislative drafting）时的 strengths and weaknesses [p.1]。作者写道，若发现此类起草问题，将展示（would demonstrate）用 s(CASP) 检测立法起草问题的可行性（feasibility）[p.1]。
- 方法背景：作者称，本文的 Rules as Code 指一种拟议的立法与法规起草方法。立法可表示为声明式代码（declarative code）以供自动化，这一点早已被认识（作者引用文献 6）；用形式化表示技术改进法律起草的机会同样如此（文献 1）[p.1]。Rules as Code 进一步提出：先以自然语言和计算机语言同时共同起草（co-drafting）法定法律文本，起草与自动化都会因此改进（文献 4）[p.1]。
- 作者对该方法的陈述：知识获取瓶颈（knowledge acquisition bottlenecks）与法定解释（statutory interpretation）相关的障碍在很大程度上（largely）得以避免；共同起草的编码只需反映法律文本说了什么，而不是立法者的本意；立法意图由掌握权威知识的起草者编码为测试，失败的测试可在起草过程中提示自然语言草案的问题；起草完成时已存在与立法意图一致的权威编码，可供监管者与被监管主体用于自动化服务和合规任务 [p.1]。
- 实验性主张：作者写道，其实验展示了（demonstrates）用 Rules as Code 方法在一份拟议法定文本中检测出一个起草问题，并验证了一项拟议修正的效果 [p.2]。
- 关于 s(CASP) 的陈述：作者对 s(CASP) 在此任务上的 strengths and weaknesses 作了说明，涉及 'why not' 查询与自然语言 justifications、abductive 与 deductive 推理的表现等，见第 4 节 [p.2]。

## 2. 方法

- 实验安排：作者把 Rule 34 的字面解释（literal interpretation）编码为 s(CASP) 程序，另行把作者对 Rule 34 行为的预期（expectations）编码为一组测试 [p.1]。那些被作者归因于仅为或主要为 Rule 34 自然语言起草问题的测试失败，由作者提交给有法律训练的团队成员（legally-trained team members），请其确认预期行为是否合理，以及失败原因是否为法律起草问题 [p.1]。
- 工具：s(CASP) 是 stable-model constraint answer set programming 语言，用 Ciao 编程语言实现（文献 3）[p.1]。作者给出的选用理由：能为 answer sets 生成自然语言解释（文献 2），并能用同一编码经少量调整进行 deductive 与 abductive reasoning（文献 3）[p.1]。作者另写道，自动化结论的 justifications 在法律应用中长期被认为有用，对终端用户和作为开发工具都是如此（文献 5）[p.1]。
- 失败调查：对未能由编码错误解释的失败，作者执行 'why not' 查询并审阅 s(CASP) 给出的 justifications [p.2]。该问题随后提交给研究团队其余成员；团队讨论后商定替换 Rule 34(1)(b) 的拟议条文 (1A)，作者将其编码并重跑测试 [p.2]。
- 拟议条文 (1A)：法律从业者不得接受会实质性妨碍（materially interferes with）下列事项的任何 executive appointment：(i) 其作为律师执业的 primary occupation；(ii) 其对可能寻求其律师服务者的 availability；(iii) 其对客户的 representation [p.2]。
- 编码方式：作者称 s(CASP) 便于使用一种 defeasibility 版本，使 'subject to' 与 'despite' 两类 defeating relations 能在文本出现处编码（文献 7）[p.2]。
- 代码：实验代码公开于 https://github.com/smucclaw/r34_scasp [p.1]。
- 原文未说明：25 个测试的具体内容与分组；s(CASP) 与 Ciao 的版本；团队确认所用的具体程序；修正案编码相对原编码的具体改动（原文只写 the proposed amendment was encoded）。

## 3. 数据与范围

- 法域与文本：新加坡。作者写道，Legal Profession Act (Cap. 161) 规范新加坡的法律职业；其第 VI 部分设立 Professional Conduct Council，该 Council 依第 71(2) 条被授予起草规范法律从业者执业、行为、礼仪（etiquette）与纪律的规则的广泛权限，并颁布了 Legal Profession (Professional Conduct) Rules (S 706/2015)；这些规则在 2015 年被大幅（significantly）修订，新增 Rule 34，规定对律师接受其法律执业之外的 executive appointments 的限制 [p.1]。
- 分析对象：Rule 34 [p.1]。文中涉及的具体款项为 Rule 34(1)(b)（失败测试所涉）与 Rule 34(9)（给出 business 的定义）[p.2]。原文未给出 Rule 34(1)(b) 的条文，只给出其拟议替换条文 [p.2]。
- 测试集：共 25 个测试；其中 4 个测试失败未能由规则或测试的编码错误解释 [p.2]。
- 性能数据：仅报告 25 个测试平均每个少于 1 second [p.2]；运行环境（硬件、软件版本）原文未说明。
- 无外部数据集；原文未报告与其他工具、其他编码方式或其他法规的比较。实验进行的时间原文未说明。
- 参与者与资助（据致谢）：作者感谢 SMU Centre for Computational Law 的同事，并点名四位对 legal analysis 有贡献的同事（Principal Investigator、Industry Director 与两位 Professor）；Gopal Gupta 与 Joaquín Arias 在 s(CASP) 的有效使用上提供协助；研究由 National Research Foundation (NRF), Singapore 支持 [p.2]。原文未说明确认测试预期的 legally-trained team members 具体是哪几位。

## 4. 结果

**实证结果**

- 作者报告共编码 25 个测试，其中 4 个测试失败未能由规则或测试的编码错误解释 [p.2]。原文未说明被归因于编码错误的失败有多少（如有）。
- 作者通过 'why not' 查询和审阅 s(CASP) 的 justifications 调查这 4 个失败，发现失败测试是基于这样的预期编写的：Rule 34(1)(b) 中的 business 指法律从业者的活动（a legal practitioner's activities）；而 Rule 34(9) 把 business 定义为一般性的一类 undertaking [p.2]。
- 作者报告：在 Rule 34(1)(b) 适用、同时采用 business 的定义含义的情形下设置测试，需要写出没有清晰现实对应物的陈述（statements that did not have clearly meaningful real world equivalents）[p.2]。
- 研究团队其余成员确认了三点：Rule 34(1)(b) 被忠实地编码（faithfully encoded）；失败测试的预期是合理的；为使该预期成立，或使其有任何清晰含义，Rule 34(1)(b) 需要采用与该词定义含义不一致的 business 解释 [p.2]。
- 作者报告，团队认真考虑过规则其他方面存在另一种解释、可使 Rule 34(1)(b) 更清晰的可能性，但没能找到既有此效果、又不使 Rule 34(1)(b) 与规则其他部分重复（redundant）的解释 [p.2]。
- 团队因此（therefore）得出结论：若 Rule 34(1)(b) 不指向 businesses 而指向 the holding of an executive appointment，会更为正确（more correct）[p.2]。
- 作者报告：将商定的替换条文 (1A)（内容见第 2 节）编码并重跑测试后，25 个测试全部通过 [p.2]。
- 作者称 s(CASP) 在 deductive reasoning 任务上的表现为 very efficient（原文措辞）：完成本实验的 25 个测试，平均每个少于 1 second [p.2]。
- 作者报告 s(CASP) 的 abductive 查询随代码复杂度增加而大幅变慢（slow down considerably）[p.2]；原文未给出 abductive 查询的具体耗时或复杂度指标。

**作者的解释或推论**

- 作者认为，失败测试的情形提示（suggested）Rule 34(1)(b) 可能（might）也以与定义含义不一致的方式使用 business，这将是一个起草问题 [p.2]。
- 作者认为，实验展示了用 Rules as Code 方法在拟议法定文本中检测起草问题并验证拟议修正案的效果；所发现的问题属于 Rules as Code 意在尽早处理的类型，即若不处理，会对法定文本的可自动化程度产生负面影响 [p.2]。
- 作者认为，s(CASP) 的 'why not' 查询和自然语言 justifications 在规则编码和测试失败分析两方面都 extremely valuable（原文措辞）[p.2]。
- 作者认为，s(CASP) 对约束（constraints）的 abductive reasoning，以及它返回 answer sets 而不是 bindings，使作者能同时用多种事实情景（a wide variety of fact scenarios）测试编码，并快速获得对编码行为的深层次了解 [p.2]。
- 作者认为，s(CASP) 便于使用的 defeasibility 版本使 'subject to' 与 'despite' 两类 defeating relations 能在文本出现处编码，这提升了代码的可维护性（maintainability）[p.2]。
- 作者认为，abductive 查询的变慢意味着该方法可能不适合 abductive reasoning 的实时应用（real-time applications）[p.2]。
- 作者认为，deductive 任务上的上述表现提示（suggests）s(CASP) 也可用于在面向用户的应用（user-facing application）中回答涉及复杂事实情景和复杂规则的法律问题 [p.2]。

## 5. 作者陈述的局限与前提

- 前提：作者描述的 Rules as Code 设想中，共同起草的编码只需反映法律文本说了什么，不反映立法者的本意；立法意图由掌握权威知识的起草者编码为测试 [p.1]。
- 实验范围：作者写道，实验中出现的任何问题，都处于对文本预期行为的非权威意见（non-authoritative opinions）之下；因此该实验不能用于诊断已颁布的 Rule 34 本身的问题（issues with the Rule as enacted）[p.1]。
- 性能：作者写道，abductive 查询随代码复杂度大幅变慢，因而 s(CASP) 可能（may）不适合 abductive reasoning 的实时应用 [p.2]。
- 推断的措辞：关于 deductive 推理可用于面向用户的应用，作者对该推断使用 suggests 一词 [p.2]。
- 除以上各点外，文中未专门讨论其他局限。

## 6. 关键术语

- Rules as Code [p.1]：作者写道，本文用它指 "a proposed methodology of legislative and regulatory drafting" [p.1]；脚注说明该短语也常被用来泛指 legal knowledge representation and reasoning [p.1]。
- co-drafting [p.1]：在起草阶段就以自然语言和计算机语言同时起草法定法律文本；作者称 Rules as Code 进一步提出这样做可改进起草与自动化 [p.1]。
- 测试 tests [p.1]：按作者对 Rules as Code 的描述，立法意图由掌握权威知识的起草者编码为测试，失败的测试用于提示自然语言草案的问题；本实验中的测试编码的是作者对 Rule 34 行为的预期 [p.1]。
- s(CASP) [p.1]：stable-model constraint answer set programming 语言，用 Ciao 编程语言实现；作者称它能为 answer sets 生成自然语言解释，并能用同一编码经少量调整进行 deductive 与 abductive reasoning；原文未定义这两种推理 [p.1]。
- 'why not' query 与 justification [p.2]：原文未给出定义；文中用法是作者执行 'why not' 查询并审阅 s(CASP) 提供的 justifications，以调查失败的测试 [p.2]。
- defeasibility 与 'subject to'、'despite' 两类 defeating relations [p.2]：原文未给出定义；作者称所用 defeasibility 版本允许在文本出现处编码这两类关系 [p.2]。
- business（Rule 34(9)）[p.2]：作者写道，Rule 34(9) 把它定义为 "a general category of undertaking" [p.2]；失败测试所依据的预期则是 Rule 34(1)(b) 中的 business 指法律从业者的活动 [p.2]。

## 7. 原文摘录

- "The author encoded a literal interpretation of Rule 34 in s(CASP), and separately encoded the author’s expectations of the behaviour of Rule 34 as a set of tests." [p.1]
- "Any issues arising would be in the context of non-authoritative opinions as to the expected behaviour of the text. The experiment cannot, therefore, be used to diagnose issues with the Rule as enacted." [p.1]
- "A set of 25 tests were encoded, and there were 4 test failures not explained by errors encoding the Rule or the tests. These four failures were investigated by the author by performing ’why not’ queries and reviewing the justifications provided by s(CASP)." [p.2]
- "This process revealed that the failing tests were encoded on the basis of an expectation that the word 'business' in Rule 34(1)(b) referred to a legal practitioner’s activities. But Rule 34(9) defines 'business' to refer to a general category of undertaking." [p.2]
- "The research team therefore concluded that it would be more correct if Rule 34(1)(b) referred not to businesses but to the holding of an executive appointment. ... The proposed amendment was encoded, and the tests re-run. All 25 tests passed." [p.2]
- "the access to 'why not' queries and natural language justifications was extremely valuable both in the encoding of the Rule, and in the analysis of test failures." [p.2]
- "s(CASP)’s abductive queries slow down considerably with the complexity of the code, and so it may not be an appropriate approach for real-time applications of abductive reasoning." [p.2]
- "its performance on deductive reasoning tasks was very efficient, completing the 25 tests in this experiment in an average of less than 1 second each, which suggests it can also be used to answer legal questions with complicated fact scenarios and complicated rules in a user-facing application." [p.2]
