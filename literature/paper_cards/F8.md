# The Oracle Problem in Software Testing: A Survey

## 1. 研究问题与作者主张

- 综述对象是 test oracle problem：作者称，给定系统的一个输入，把对应的期望（正确）行为与可能不正确的行为区分开来的挑战即为该问题；没有 test oracle 自动化，就须由人判断观察到的行为是否正确 [p.1]。
- 作者称，相对于测试自动化的其他许多方面，test oracle 的自动化获得的关注 'significantly less'，'remains comparatively less well-solved'，并称这一未解问题是阻碍更大范围测试自动化的 'significant bottleneck' [p.1]。
- 作者的目标是对 test oracle 问题的现有文献做 comprehensive review and analysis [p.1]。他们称此前有四项 partial surveys，均未提供对 trends and results 的 comprehensive survey [pp.1–2]；称该领域的研究由 fragmented 的社群承担，并称本文是对该问题的首个 comprehensive 分析与综述 [p.2]。
- 作者把解决途径分为四类：oracle 可被指定（specified）、可被推导（derived）、可由隐含信息构建（implicit），以及没有可自动化 oracle 但仍可减少人力（human oracle problem）[p.2]；并提出一套形式化定义，用于比较和对照文献中的技术 [p.2]。

## 2. 方法

**形式化（Section 2）**

- test activity 为 stimuli S（触发或约束 SUT 计算，含显式 test input 与环境因素）与 responses R（可观察响应，含输出与执行时间等非功能 profile）的不相交并 A = S ⊎ R，可展平为 L × C × V（标签、目标组件、值）（Def. 2.1，Fig. 1）[p.2]。test activity sequence 可用 x:[φ] 记法附带约束，如平方函数的 io:[o = i²]；作者称这些约束区分了所综述的各类 oracle 方法 [pp.2–3]。practical test sequence 要求至少一个 stimulus 后接至少一个 observation（Def. 2.3）[p.3]。
- test oracle D 是从 test activity sequence 到 true/false 的 partial function（Def. 2.4）；probabilistic oracle ~D 映射到 [0,1]（Def. 2.5）[p.3]。ground truth G 是总给出 'right answer' 的 total oracle；D sound 当且仅当 D(a) ⇒ G(a)，complete 当且仅当 G(a) ⇒ D(a)；probabilistic soundness 为 P(~D(w) = 1) > 1/2 + ε ⇒ G(w)，probabilistic completeness 为 G(w) ⇒ P(~D(w) = 1) > 1/2 + ε，ε non-negligible（Defs. 2.6–2.9）[p.4]。
- 作者用该形式化表述后文各类方法：pseudo-oracle 接受 f1(x) o1 f2(x) o2 : [f1 ≠ f2 ∧ o1 = o2] 形式的序列（Eq. 1）；N-version oracle 要求 k 个互不相同实现的输出中最大重数不小于阈值 t（Eq. 2）[p.9]；metamorphic relation 是对同一 f 至少两次 stimulus 的输出之间的约束 [p.9]；Daikon 式 invariant detection 是在序列前缀收集 likely invariants、在后缀强制执行的 unsound oracle [p.10]。

**文献库与趋势分析（Section 3）**

- 在 Google Scholar 与 Microsoft Academic Search 上，对 1978–2012 年的每一年用 'software + test + oracle' 与 'software + test oracle' 检索 [p.4]；再按四类各自的专门查询词补充（如 'algebraic specification'、'metamorphic testing'、'fuzzing + test oracle'、'test suite reduction'），所有查询加 'software testing'，并删去与软件测试和 test oracle 无关的文章 [pp.4–5]。
- 按论文所提技术或概念归类（如 Model Checking、Metamorphic Testing 归 derived，DAISTIS 归 specified）[p.5]；对每类的累计发表数用 power regression model 拟合（Fig. 2）[p.3] [p.5]；另按各技术或概念的最早已发表文献绘制时间线（Fig. 3）[p.5]。综述按 specified（Sec. 4）、derived（Sec. 5）、implicit（Sec. 6）、human oracle problem（Sec. 7）组织 [p.2]。

## 3. 数据与范围

- 文献库：694 篇关于 test oracle 及相关领域的 publications，1978–2012 [p.4]；分类计数 specified 317、derived 245、implicit 76、no test oracle 56（处理 test oracle 缺失的研究）[p.4]。
- 来源：Google Scholar、Microsoft Academic Search；作者说不同查询会得到不同结果，排名较低的结果差异尤其大 [p.4]。纳入期刊、会议与 workshop 论文集、杂志上的发表物，排除 technical reports 与 manuals [p.5]。作者称随文有一个论文库，附网址 [p.15]。
- 范围：作者称本文 'necessarily focused on the traditional approaches to the test oracle problem' [p.14]；对 specified oracle 只作 overview，称该主题 'could merit an entire survey on its own right' [p.6]。
- 被综述研究的数据集、被测系统与基准，文中只对少数研究有简述（Java 程序 [p.11]；web applications、随机生成的程序和小型 benchmarks [p.13]），其余原文未说明。除对文献库的统计与趋势拟合外，正文未见作者自行运行的实验。

## 4. 结果

### 4.1 作者对其文献库的统计与读图结论（实证结果）

- 文献库共 694 篇：specified 317、derived 245、implicit 76、no test oracle 56 [p.4]。
- 作者称 'test oracle' 一词最早见于 Howden 1978 年的工作 [p.4]；时间线上早于 1978 的条目有并发问题（deadlock、livelock、race）检测（可追溯到 1960 年代）和 regression testing（作者称其为 derived oracle 的前身）[p.5]；明确用 finite state machines 生成 oracle 的工作，作者追溯到 Jard and Bochmann 与 1986 年的 Howden [p.5]。
- 作者称四个 R² 值 'high'，'confirm that our models are good fits to the trend data'，趋势 'suggest a healthy growth in research volumes' [p.5]；图注称回归方程与 R² 指示 'upward future trend' [p.3]。回归方程与 R² 的具体数值不在提取文本中。
- specified 类：新技术和概念的提案在 1990 年代达到峰值、近十年逐渐减少，但每年发表数显示该领域仍有 'much research activity' [pp.5–6]。derived 类：整个时期都有方案提出，早期以理论为主，实证研究在 1990 年代后期随之出现 [p.6]。
- implicit 类：1978 年前已建立的方案的研究仍在继续，速度慢于其他类型 [p.6]。缺少自动化 oracle 的一类：直到近来才出现新技术与概念，并明确聚焦 human oracle cost [p.6]。

### 4.2 作者转述的被综述研究所报告的发现

- Staats et al.：Daikon 从一组 Java 程序推断出的 incorrect invariants 中有一半被 misclassified；该句前文讨论人工过滤 invariants，称其易出错、误分类常见 [p.11]。
- 作者称 inferred invariants 的准确性部分取决于 test cases 的质量与完备性；推断 'perfect' invariants 'almost impossible'，现有技术常推断出 incorrect or irrelevant invariants [p.11]。
- 作者称 Frouchni et al. 'successfully apply' semi-supervised machine learning 为 image segmentation 程序构建 test oracles；Zheng et al. 从 web 搜索查询及其结果中抽取 item sets，用 association rule mining 为 web search engines 构建 derived oracles，该类系统此前曾被认为不可测试 [p.11]。
- Prowell and Poore 的 sequential enumeration：作者称它倾向于发现许多不一致与缺失的 requirements，但可能遭遇输入/输出序列数量的指数爆炸，需用 abstraction 控制 [p.12]。
- Weyuker and Vokolos 的 case study：一个 CPU 使用过度的进程造成服务延迟与中断 [p.12]。Ricca and Tonella 的 empirical study：60 percent 的 web applications 表现出 anomalies 和 execution failures [p.13]。
- Ferrer et al.：在同时最大化 branch coverage 与最小化 test suite 规模的多目标问题上，用随机生成的程序和小型 benchmarks 比较 NSGA-II、SPEA2、MOCell 等算法，MOCell 表现最佳 [p.13]。Afshan et al.：在若干 case studies 中，人类 oracle 对其生成的字符串 test inputs 评估得更准确、更快 [p.14]。
- Pastore et al.：展示了 crowdsourcing test oracle 的可行性，同时指出向群体呈现测试问题使其易懂存在困难，且需提供足够的代码文档 [p.14]。
- specified 类：文中提到 Mouchawrab et al. 对 state transition systems 构建 oracle 技术的 empirical evaluation [p.6] 与 Araujo et al. 对 design by contract 的 systematic evaluation [p.7]，未转述其结果。

### 4.3 作者的解释、推论与结论性陈述（非实验结果）

- specified 类：作者称构建 specified oracle 须克服三个挑战——缺少 formal specification；模型因抽象而 imprecision；把模型输出对应到具体程序输出；并引 Gaudel：formal specification 的存在不保证存在成功的 test driver [p.8]。作者称 assertion 方法在实践中只能在程序某点检查有限的一组性质 [p.7]。
- derived 类：作者称，specified oracle 不可得时测试者转用 derived oracle，因为 specifications 'rapidly fall out of date when they exist at all' [p.8]。借助形式化，作者指出 algebraic specification 是一种 pseudo-oracle（对同一值激励两个不同实现并要求输出等价），metamorphic relation 则是对单个 SUT 至少两次激励后输出间关系的约束 [p.9]。
- 作者把 metamorphic relations 归入 derived 类，理由是实践中它们通常由对 SUT 的 white-box inspection 人工推断 [p.9]；称 metamorphic testing 的最大挑战是自动发现 relations，利用领域知识形成 relations 的工作 'still at an early stage and not yet automated' [p.10]。
- 作者称 regression testing 隐含假设前一版本可作为既有功能的 oracle；对 changed requirements（作者另立的一类 perfective maintenance），新 oracle 在 ΔD 的定义域内取 ΔD、其余取 D_i，不能与旧 oracle 简单求并 [p.10]；称 test suite augmentation 'more work is required' 才能同时扩充预期输出 [p.10]。
- 作者称等价性检查一般不可判定，inference 只对受限类程序（如可用 finite state machines 建模者）可行，且这类实验有 'serious practical limitations' [p.11]。
- implicit 类：作者称其不要求 domain knowledge 或 formal specification，几乎适用于所有程序，但 'not universal'：某系统在某情境下的异常行为，对另一系统或情境可能正常，崩溃在以发现崩溃为目的的系统中甚至可能是期望行为 [p.12]；称 fuzzing 'is an effective way' 发现 implicit anomalies [p.13]。
- human oracle：作者把降低成本的研究分为 quantitative（缩小 test suite 与 test case 规模）与 qualitative（提高 test case 可理解性）两方面 [p.13]；称 machine-generated test data 若未纳入领域知识，会取自不同于 SUT input profile 的分布，可能有利于捕获某类故障，但计入 oracle 成本后效用下降 [pp.13–14]。
- 未来方向：作者称 'Much work on test oracles remains to be done'，讨论 test oracle reuse（推广 reliable reset；在 software product lines 间共享 oracular data）与 test oracle metrics（oracle coverage、assertion 质量评估）两个方向，称后者 'More work is needed' [pp.14–15]。

## 5. 作者陈述的局限与前提

- 范围：本文 'necessarily focused on the traditional approaches to the test oracle problem' [p.14]；specified oracle 一节只作 overview [p.6]。
- 形式化：test oracle 是 partial function [p.3]；ground truth 'cannot be known in all but the most trivial cases'，但作者称其可界定 oracle 行为；test oracles 一般不能同时 sound 且 complete；作者称从纯哲学角度可论证 human oracle 能 sound 且 complete，此时正确性成为主观的人类评估，所给定义容许这种情形 [p.4]。
- 作者称 models 近似 SUT，二者行为差异不可避免，其中一些是 spurious 的，会错误报告测试失败 [p.7]。
- 检索与统计：不同查询返回不同结果 [p.4]；时间线只收录对 test oracle 问题明确表述的已发表工作 [p.5]；作者说尝试了 different regression models，图中趋势线用 power model，其他模型的结果原文未说明 [p.5]。文献分类的判定规则、是否多人独立分类，原文未说明；文中未专设 threats to validity 的讨论。

## 6. 关键术语

- test oracle problem：给定输入，区分期望的正确行为与可能不正确行为的挑战 [p.1]。test oracle：判定给定 test activity sequence 是否为 SUT 可接受行为的 predicate [p.3]。
- specified / derived / implicit test oracle：specified 依据给定的 formal specification 判断系统行为各方面 [p.4]；derived 依据可从中导出 oracle 的 artefacts（如先前版本）、文档、系统执行等 [p.4] [p.8]；implicit 依据一般性的隐含知识检测 'obvious' faults（如崩溃），不需领域知识或 formal specification [p.4] [p.12]。
- pseudo-oracle：独立产生的 SUT 替代版本（如不同团队或不同语言），不同版本对同一输入的输出应一致；N-version oracle 对 k 个实现的输出按阈值 t 判定，D_maj 取 t = ⌈k/2⌉，D_pso 取 t = k [p.9]。
- metamorphic relation：对 f 的实现 p 的多次执行，预期成立的、作用于 f 的应用结果之间的 relation；metamorphic testing 用它为后续测试用例生成 partial test oracles [p.9]。
- soundness / completeness：D sound 当且仅当 D(a) ⇒ G(a)，complete 当且仅当 G(a) ⇒ D(a)，G 为 ground truth oracle [p.4]。
- Human Oracle Cost：人类测试者的开销，分编写 test oracle 与评估测试结果两个维度 [p.13]。

## 7. 原文摘录

- "Given an input for a system, the challenge of distinguishing the corresponding desired, correct behaviour from potentially incorrect behavior is called the 'test oracle problem'." [p.1]
- "However, compared to many aspects of test automation, the problem of automating the test oracle has received significantly less attention, and remains comparatively less well-solved." [p.1]
- "A test oracle is a predicate that determines whether a given test activity sequence is an acceptable behaviour of the SUT or not." [p.3]
- "The trend analysis suggests that proposals for new techniques and concepts for the formal specification of test oracles peaked in 1990s, and has gradually diminished in the last decade. However, it remains an area of much research activity" [p.5]
- "Three challenges must be overcome to build specified test oracles. The first is the lack of a formal specification. ... Finally, one must contend with the problem of interpreting model output and equating it to concrete program output." [p.8]
- "Nevertheless, inferring 'perfect' invariants is almost impossible with the current state of the art, which tends to frequently infer incorrect or irrelevant invariants" [p.11]
- "In many cases, however, no such artefact exists so a human tester must verify whether software behaviour is correct given some stimuli." [p.13]
