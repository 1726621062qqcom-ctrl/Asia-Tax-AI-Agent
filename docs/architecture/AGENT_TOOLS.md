# Agent 工具与数据库契约

更新：2026-10-18。本文件描述已实现工具边界；早期流程设计文档和评估运行结果保留其历史含义。

## 数据来源

- 固定版本 `official.sqlite` 是只读官方资料发布包。`combined` 模式优先用它检索法条；知识服务按 `doc.type` 过滤请求类别，在截断前剔除不匹配来源。调用模式 `c` 也支持其已有指引，但不得以法条代替指引。
- PostgreSQL `sources` / `legal_units` 提供已登记、范围允许的 FSIE 指引、FAQ、示例和官方裁定。根据来源 `source_type` 分类，保留实际日期、哈希和漂移信息。很多 FAQ/示例单元使用通用 `guidance_block`，不能只看片段类型。
- 已授权的 `chat_cases.document` 是聊天案件事实源，读取使用现有 owner/revision 上下文。规范化 `cases/facts` 表不自动等同于网页事实。
- 规则使用现有 Git 版本包。云端有规则表结构不代表规则已经入库；工具不自动切换运行真源。

## 工具目录

| 名称 | 参数 | 返回/行为 |
| --- | --- | --- |
| read_case_facts | 无 | 按需整理当前用户陈述；预计算 case_state 已提供字段状态；不确认事实 |
| check_fact_gaps | 无 | 按本轮目标列相关缺口、冲突阻断与后续补充项；不授权部分分析 |
| search_law | query | 固定库法条证据、引用及覆盖观测；不推进访谈 |
| search_guidance | query | PostgreSQL 官方指引/FAQ/示例证据；实际路径和来源类型写入日志 |
| search_rulings | query | PostgreSQL 官方税务裁定，保留原案背景；不等于司法判例全集或相似性结论 |
| prepare_analysis | 无 | 仅在本轮明确请求且事实确认/范围等现有门槛满足时生成待复核内部稿 |
| calculate_tax | 无，服务端使用已校验的计算输入 | 仅计算子流程开放；现有 Python 引擎返回税额范围与待补问题 |
| finish | finish_reason | completed / evidence_gap / needs_user，及简短 reason；服务端检查明确要求的资料类型是否实际检索 |

所有决策可有一句 `reason`。`search_cases` 仅作历史调用别名，在验证时归一化为 `search_rulings`，不出现在新工具目录。身份、案件ID、日期范围与确认权限不能由模型改写。query 改写保留法域、年份和用户指定编号；每种工具最多一种额外改写，并有共享模型、时间、搜索和动作预算。

## 调度及输出

`research_context.py` 复用现有规则节点的 `NODE_LOCATORS` 作为版本化研究导航。预先计算事实状态、相关缺口及暂不相关字段；不传所有历史事实值给规划器。冲突阻断确定性个案结论；其他缺失信息不阻止解释一般规则，正式分析仍执行完整资格检查。

搜索只收集已授权证据。最终步骤合并来源、生成一次解释并执行语言/引用校验，必要时修复。固定快捷入口仍走其明确业务路径，普通输入使用动态工具循环。原文读取通过Provider完成，不新增任意SQL或任意代码执行工具。

工具观测包含唯一来源数、引用版本、来源类型、已定位/未定位问题及适用日期是否提供。`located_issues` 仅表示与已有条号导航相符，不证明某段解释已被法源完整支持，更不代表专业验证。技术失败、无匹配、入模受限和事实缺口分别记录。

末尾 finish 不能仅凭“读过事实”完成明确的资料查询；尚未查询用户要求的资料类型时，服务端在现有范围/预算内补充调用。有结果时预留最终生成与必要修复的模型额度；不为机械状态读取额外规划。

## 权限与版本

FSIE官方指引入模仅放行登记ID对应的精确HTTPS官方路径。没有扩大到任意IRD页面。原文展示、哈希核验、事实确认、部分分析授权和人工审核使用现有保护。未新增数据库迁移，也未修改固定SQLite发布包。

## 网页案例回归修复（2026-10-18）

- 描述事实并要求解释条件/证据/材料的混合输入进入 research；事实仍正常提取和审查，缺项限制个案结论，不中止一般规则研究。单纯事实访谈、冲突处理和正式分析门槛保留。
- 完整案例使用原始用户问题的版本化法条导航，模型短查询不能丢掉核心条款。规划观测同时包含当前搜索与累计定位结果；先完成明确要求的资料类别，再考虑是否结束。无额外裁定比较任务时不为凑来源增加裁定搜索。
- 中途读取达到预算上限时保留已核验原文，retrieval_stop 与工具循环、业务状态一致；最终回答提示尚未查完。部分结果不是完整通过。
- 每个有依据的论点后由服务端添加简短、可点击引用。只有来源身份本身已经定位到子条款时显示该子条号；父条原文显示已核验父条号。模型不能提供网址。最终原文面板继续可核对，正文不再重复整份引用列表。

PostgreSQL连接/SQL超时之外，Provider入口还按request.deadline_ms限制整个读取调用，包括连接池pre-ping。只读后台工作全局最多2个；超时返回TIMEOUT，迟到结果不加入本轮证据，不生成模型请求或写入案件。底层卡住时后台读取无法强制终止，但占用数量受限。总预算已耗尽时不再机械重试最终生成。

## 聊天税额试算（2026-10-21）

聊天增加 `calculation` 意图和 `calculate_tax` 工具。意图模型提取带本轮原文引用的结构化输入，Python 校验数值、日期、地区、币种和布尔值。资料齐全后，工具规划器选择 `calculate_tax`，由现有 `DomainCoordinator` 和固定版本 Python worker 执行。工具不接受模型提供的税率、公式、SQL、身份或审核权限。

- 新案情支持公司直接持股股息：付款/收款地区、收款主体、金额、币种、比例、完整取得/支付日期。缺项在聊天追问，不自动补日期或比例。固定股息路径不把投资资金来源误映射成利息，也不改变支付日期。
- 其他模板/复杂结构可以使用结构面板已保存的案情，在聊天明确请求计算；不会将不完整的聊天描述覆盖到已修改的结构。
- 引擎的条件税额区间和下一问题直接回到聊天。用户回答后使用同一问题校验逻辑重算；专业判断和资料维护问题仍受原有权限限制。
- 金额由引擎返回，服务端直接格式化，不交给语言模型重新计算或改写。仅支持引擎现有 CNY 范围；其他币种返回不支持，不自行折算。
- 计算在私有文档副本中准备。普通请求和 SSE 都由 `commit_prepared` 一次提交，保留 owner/revision/request_id、断线不提交和幂等重试。保留输入原文、候选事实、计算版本和运行记录，不自动确认事实或批准报告。
- 实现：`packages/domain_bridge/chat_calculation.py`。回归：`tests/integration/test_chat_calculation.py`。历史演示中“聊天尚不能调用计算”的描述在此变更后不再适用于上述范围。
