## Changes in this round

- Source inquiries retrieve official passages from the cloud before DeepSeek composes a direct answer. Each passage must include a retrieved passage ID and a verbatim quotation; source links are generated by the program. Missing matches or citation validation failures are reported explicitly, without filling the gap with unsupported answers.
- Queries support multiple statutory provisions, mixed case and statutory queries, Chinese parentheses, and deduplication. Results are selected in turn for each identifier so the first provision does not occupy all slots. Natural-language queries have limited topic matching, and short guidance passages are supplemented with adjacent original text from the same source and snapshot.
- The model cannot invent statutory identifiers to change the retrieval mode or add a Hong Kong connection to questions about other jurisdictions. Casual conversation, case summaries, and rule inquiries are handled separately.
- Structured output is attempted at most twice, and retries clear text left over from the previous attempt. Additional thinking is disabled for DeepSeek structured extraction and answer composition to preserve the output budget. Cancellation does not save partial messages or facts.
- Fixed errors caused by incorrectly classifying empty facts as an interview. Receipt dates cannot be automatically used as accrual dates. Corrected anti-hybrid provision navigation and prevented exemption thresholds from being treated as tax credit conditions during credit retrieval.

**Public source authorization**: on 2026-10-03, the user explicitly authorized sending public Hong Kong official statutory, guidance, and ruling passages from the source catalog to the configured DeepSeek service. Passages are selected only from registered official URLs. Real client data and keys are outside this authorization. Synthetic case testing rules remain unchanged. This authorization updates the corresponding earlier restriction on sending official original text to external models.

Conversations used the actual DeepSeek service and the configured cloud knowledge database, with synthetic facts and temporary isolated session storage. No data was written to users' personal chats. All 20 questions were run first, followed by targeted retests of T04, T11, and T12–T15. The final spreadsheet uses the latest actual result for each question. The complete case workflow uses the rerun of T12–T15; it does not constitute renewed acceptance of the HTTP workflow with real accounts or cloud session persistence.

The final 20 questions averaged 7.27 seconds, with a maximum of 18.90 seconds; the old baseline averaged 5.84 seconds. Answer composition after retrieval adds work, so overall speed improvements cannot be claimed. A retrieval round averaged approximately 0.87 seconds, with substantial network variation; this is not a stable performance metric. Concurrent load testing has not yet been performed.

## Product capabilities still outstanding

1. **Expert calibration**: check each explanation, whether citations actually support its conclusions, and the boundaries between exemptions and credits, and provide reference answers. The program currently checks only that source IDs and quotations exist, not whether the complete legal reasoning is valid.
2. **Independent recall evaluation**: the current 20 questions are a development regression set, including topics specifically repaired during development. New expert-annotated questions and relevant passages are needed to evaluate recall on questions not used for tuning.
3. **Answers and performance**: some answers remain too long, and questions about current applicability may include historical information. Continue reducing irrelevant paragraphs and measure time to first output, total duration, concurrency, and cache invalidation. Do not omit evidence checks merely to reduce latency.
4. **Complete rules and new sources**: financial entity exclusion, foreign taxation and switchover, anti-hybrid rules, main purpose, and filing/evidence retention remain five human review tasks. This round did not turn them into automated tax conclusions or add new jurisdictions, real-time regulatory updates, or new MCP capabilities.

The product remains a research assistant. These engineering results do not establish that Hong Kong FSIE is fully implemented, that tax expert acceptance has passed, or that outputs are tax reduction plans ready for execution.

## How teammates can retest

Install dependencies according to the root README, copy `.env.example` to `.env`, and configure the environment following the [authentication guide](../TAXORA_AUTH.md). Provide credentials privately; never commit the actual `.env` to Git.

```powershell
# Read-only cloud retrieval; does not call the model
.venv/Scripts/python.exe scripts/evaluate_retrieval.py --output reports/retrieval-check.json
# Live model calls consume API usage; fixed synthetic questions, isolated sessions, no cloud client records written
.venv/Scripts/python.exe scripts/evaluate_chat.py --output reports/chat-check.json
# Targeted retest: consecutive follow-ups must include preceding turns
.venv/Scripts/python.exe scripts/evaluate_chat.py --only T12,T13,T14,T15 --output reports/intake-check.json
.venv/Scripts/python.exe -m pytest -q -m "not integration"
```

Question sets are in `tests/chat/retrieval_cases.json` and `tests/chat/conversation_cases.json`. Raw local records are in the Git-ignored `reports/chat-final-2026-10-03.json` and `reports/retrieval-natural-*.json`; the Excel files let the team inspect actual answers. Identifier ranges and shorthand such as `15K至15M` (15K through 15M) and `15K(2)及(3)` (15K(2) and (3)) are not yet expanded; queries with many identifiers are still constrained by the result limit.

The implementation follows the bound-parameter query approach used by [SQLAlchemy](https://github.com/sqlalchemy/sqlalchemy) and draws on the context approach in [Haystack sentence window retrieval](https://github.com/deepset-ai/haystack/blob/main/haystack/components/retrievers/sentence_window_retriever.py). No code was copied and no retrieval framework dependency was added. DeepSeek request options follow the [official thinking mode documentation](https://api-docs.deepseek.com/guides/thinking_mode/).
