# 回答质量优化实施记录

2026-10-17。本轮修改保存在本地，未推送 GitHub。标准本地启动仍为 `./start-local.command`，使用真实配置模型、combined 知识服务及 hybrid 动态工具编排。

## 已落地的流程

1. 每轮由服务端确定 `reply_locale`。用户明确指定语言优先，其次依据本轮提问语言；数字、OK 等续答继承上轮语言，Why 等英文短问句使用英文。界面语言独立保存。路由、事实摘要、缺口、错误、生成正文和来源辅助说明使用本轮回答语言。
2. 工具负责读取事实、检查缺口和取得获准证据，最终阶段统一归并证据并生成答案。生产路径不再将各工具的完整答案拼在一起；重复法源和原文卡片归并展示。
3. 动态规划保留原有权限、范围和预算约束。为最终回答留出调用与时间；范围错误可退回原始受约束查询一次，拒绝的查询本身不执行。法规任务只读事实不能直接完成，必须实际执行检索。材料清单所需的条文导航从原始任务保留，避免规划器缩短查询时丢失目标。
4. 法源保留来源标题、定位和链接。模型选择服务端原文片段 ID；程序还原原文并逐项验证。末尾统一生成法规引用。支持旧式逐字引文的兼容校验，只有空白差异可以映射回原文，文字和数字变更仍拒绝。
5. 最终生成可在同轮预算内修复一次格式/引文问题；长业务问题及豁免与抵免关系可使用一次有界复核。复核失败时保留此前已通过引文校验的回答，并记录复核错误，不因此丢掉已取得的有效解释。这不等于税法专业审核通过。
6. 格式核验区分合法的多条件列表与损坏输出，避免有五项有效引文的清单被整体拒绝。生成器要求短标题、项目符号及直接答复；正文已有材料/下一步清单时，不再额外打印一份待确认清单或机械访谈问题。完整缺口仍保存在结构化数据中。

## 分场景呈现

| 场景 | 本轮回答结构 |
| --- | --- |
| 一般规定/概念 | 直接回答 → 相关条件或例外 → 末尾法源；简单问题不强制套完整案情模板 |
| 完整个案咨询 | 当前判断及未确认边界 → 分路径条件 → 优先材料/下一步 → 末尾法源 |
| 梳理事实 | 已记录的用户陈述 → 前五项优先缺口；其余随分析逐步核对，不展示字段迁移说明 |
| 查阅法条/案例 | 回答查询目标 → 必要原文或解释 → 来源标题、定位和链接；一般查询不启动全表访谈 |
| 计划或多笔交易 | 区分付款与主体、保留计划状态 → 可提前准备的资料 → 需事件发生后核实的事项 → 末尾法源 |

普通事实澄清、用户案情汇总不为凑格式编造法规引用。研究答案仍须从获准证据生成，未覆盖的部分应明确说明。

## 事实保护

- 月份或年份不足以形成日级日期。模型尝试补出 ISO 日期时，程序要求找到支持确切日的原文，否则移至带精度和出处的上下文记录，不传入日级规则字段。
- 已明确“收到股息”的陈述补足已发生状态，避免再机械追问是否发生；假设和计划不按实际收款处理。
- “刚才说错了，只持有3%，不是20%”可以更正该持股字段，其他字段不获得全局覆盖权限。历史及失效机制保留。
- 办公室、员工及投资控股业务描述不自动认定纯股权持有身份、税务居民或资源充分性。
- 多笔股息被识别后，清除单交易候选中的混合付款方、持股比例和日期，保留原始交易链描述。在交易仍未绑定时阻止正式规则分析。当前属于防污染保护，**尚不是完整的可切换多交易数据模型**。
- 中文自由文本事实在英文摘要中进行展示用途翻译；原始事实不被翻译结果覆盖。翻译数字须保持一致，不可用翻译补事实。

- Supabase认证偶发不可用仍可能导致请求失败，页面保留输入并支持重试；不能据此声称外部服务故障已经根治。
