# 数据库驱动的工具调整实施记录

日期：2026-10-18。承接工具设计审查与数据库实查方案，已修改本地业务代码、工具说明、相关注释及评估定义。本记录不表示已推送GitHub或完成新的真实模型网页案例评估。

## 已实施

1. `combined` 路由按真实资料分工：固定SQLite检索法条，PostgreSQL检索FSIE指引/FAQ/示例和裁定。Provider读取引用时保持资料所属路径，不因技术失败静默切换资料库。
2. PostgreSQL查询按登记来源类型分类，并把实际地区、生效日期等元数据传给证据契约。SQLite服务也在截断前按doc.type过滤，避免guidance请求返回law。已登记FSIE官方指引使用精确ID/HTTPS路径放行入模。
3. 工具搜索只收集资料，不在搜索内部推进访谈或生成回答。最终阶段统一合并、生成并校验；独立查询不会因普通事实缺失而提前结束。事实冲突、范围限制和正式分析确认门槛仍执行原有保护。
4. 增加版本化研究导航，复用既有规则节点条号；预先提供事实字段状态、本轮相关缺口及暂不相关项。观测含候选定位、未定位问题、唯一来源数、来源类型及日期状态。定位不等于命题支持或专业验证。
5. `search_rulings`作为明确的裁定工具名；`search_cases`为兼容输入别名。finish带结构化原因；服务端检查用户明确要求的资料类型是否实际查询，并识别显式排除的类型。query改写预算按工具分别计数，继续保留全局预算及范围约束。
6. 最终来源窗口交错纳入不同查询结果，防止第一批法条占满7个来源位置后排除指引/裁定。调用接近预算时优先为最终生成和必要修复留空间。
7. 英文回答后，“核对案例事实／开始分析”按钮跟随回答语言，中文界面可以保留。日志的详细覆盖观测只写独立日志，不新增聊天日志面板。
8. 更新`docs/architecture/AGENT_TOOLS.md`、`LOCAL_SETUP.md`、工具调度提示和数据库相关注释。规则仍从Git版本包加载，聊天事实仍取授权document；未改表、未修改固定SQLite发布包。
