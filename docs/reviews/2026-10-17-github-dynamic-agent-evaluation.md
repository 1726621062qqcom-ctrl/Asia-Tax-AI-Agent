- 已 fetch 并核对 GitHub `origin/main`，基线为 `ca422b8`；案例与远端一致。本地另有动态规划配置和启动日志变更。

- 全部从普通输入auto入口执行；这是对动态规划与上下文的评测，不是本次重新点击三个快捷按钮的浏览器测试。英文业务模板使用en界面语言。
- 每条运行一次，未与关闭动态规划的相同样本作对照。不能据此归因“动态规划改善/恶化”，也不能由引文逐字匹配推导法律推理正确。人工评价基于原用例主要预期和可观察的事实一致性；未进行税务专家认证。

## 优先修复项

1. **事实不能补猜（最高优先级）**：B01/B02把年月补成每月1号。B02还推断实体类别和持股关系。年月应保留精度，不能作为日级日期用于规则。B01的非纯股权持有身份也被直接断言，超出模板要求的待核对范围。
2. **交易与更正的上下文**：T14明确更正未落为3%；B03的直接派息主体、100%持股与indirect被混在一起。多笔拟议交易应先明确本次判断对象，不能跨主体拼事实。
3. **统一最终回答**：T11多个结果直接拼接，语义去重失效且条件关系不一致；T09同时显示回退摘录与成功解释。`join_answers`只去除完全相同段落，不能处理近义重复。应先汇总已校验的证据/任务结果，再形成一个最终回答并重新校验。
4. **用户可读字段与语言**：`summary_text`仍使用字段词典description_zh作为展示名，`human_value`未覆盖全部枚举；ToolHarness读事实未传locale，B01/B02/B03因此先中文摘要再英文缺口。
5. **范围拒绝与续答**：B02检索被tool_scope_rejected拦截，当前报告没有保存被拒绝query，具体触发条件仍需补充诊断；不能仅凭stop码判断是误拦还是模型越界。T04应先澄清主体与税务地区。
6. **引用与原文交付**：T20的pending_tasks提醒在引用之后追加，破坏“引用放最后”；T06回答日期但未直接展示日期原文。保留引文校验，优化失败后的可读提示及最终拼接顺序。
