## 案例1：工具有运行，但法条补查没有补准

Trace：`2cdb2510-4927-4fad-91e3-032889080f67`

Case：`6c6df530-5963-403c-9f22-025fdeaeda32`

- 实际进入tool_harness，未机械调用读取事实或检查缺口工具。
- 第一轮search_law取得s.15H/15I，两个父证据、三个展示片段，575.27ms。
- search_guidance取得七份可入模资料，覆盖四个官方来源，2982.29ms。调度器摘要明确识别经济实质、参与要求和外国税项缺口。
- 随后模型拟在query添加15H/15I，scope guard拒绝；服务端退回原范围query，实际再次执行law，40.28ms，仍得到相同法条。
- 工具日志的tool_count=4包括一条拒绝/修复记录，实际工具执行为3次，不能当成4次真实检索。
- 最终合并10个展示片段、5个唯一来源。生成1次，quality_review再1次，最后是grounded英语答复。
- 引用末尾包括法条和IRD资料，正文保留“同事说已处理税务不等于证明”以及日期未核实。
- 但日志仍记录economic_substance、participation_basic和foreign_tax_switchover未通过现有主法条导航定位；最终主要法条引用只有15H/15I，不能把evidence_available理解为问题全部覆盖。

## 案例3：回答有结构，但可选裁定查询耗尽预算

Trace：`aa2a2f3d-e521-40be-aa77-6f7923809b09`

Case：`2370c020-60f3-42e1-be6d-4cec1b149a6e`

- 工具顺序law→guidance→rulings。law取得15K/15M/15N三个父证据、十个展示片段；guidance取得七份证据。
- 调度器因为收款问题尚未定位，决定调用裁定补查。该选择未解决应优先检索收款法条的问题，并增加了原问题未明确要求的裁定检索成本。
- 证据预算14：law读取3，guidance读取7，rulings读取4后下一次触发BudgetExceeded。本轮裁定结果没有完整返回到最终研究结果。
- 最终仍使用此前法条和指引，合并17个展示片段、5个唯一来源；生成与quality_review各1次。
- 网页区分了日本→新加坡与新加坡→香港，保留计划状态，未捏造金额或2027具体日期；有文件清单及末尾引用。此处是产品行为检查，不是法律命题专业验证。
- 业务状态是paused_gap/budget_exhausted，但tool.finish又写completed，tool.loop_finished写finished。页面答复未清楚揭示可选裁定查询未完成，状态存在不一致。
- 最终导航已定位经济实质、参与要求和主要目的，receipt仍未定位；“有回答”不能代表该案例已经完整结束。

## 下一步优先项

1. 调整路由：用户明确要求解释、列清单、区分交易时，应先完成可独立进行的研究；缺事实约束结论，不让整段问题退化成一条访谈追问。
2. 将缺失issue映射成可信条号导航参数。补查现有规则映射中的已知条号，而不是依赖模型自己往query添加数字、被守卫拒绝后重复泛搜。
3. 用实际证据读取余量评估工具成本，先完成必要法条，裁定按需查；预算不足时保存可用部分并明确未完成项。
4. 统一业务状态、工具停止原因、最终提示与页面状态。技术或预算部分失败不能标记为全部完成。
5. 严格区分“检索有结果”“主法条已定位”“命题被来源支持”和“专业验证通过”。本轮日志verified_count均为0。
