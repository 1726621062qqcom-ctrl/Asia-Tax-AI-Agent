日期：2026-10-17。状态：本地已启用，尚未推送。

**已被后续实现替代：** 按用户要求，以下聊天面板及接口已删除，详细日志不再附在对话消息中。当前实现见 [Agent独立日志系统](2026-10-17-agent-logging-system.md)。本文保留为上一版埋点的历史观察，不作为当前操作说明。

## 查看方法

刷新本地网页后，**新产生的每条助手回复**下方都有“Agent 执行记录”。展开后可查看 Trace ID、调用数量、工具选择摘要和按时间排序的事件；每个事件可展开查看参数及结果摘要。“导出本轮 JSON”导出同一份记录。

对话底部的“查看最近执行记录（含失败）”读取当前案件最近5轮记录。对应接口为 `GET /api/cases/{case_id}/traces?limit=5`，最多20轮。接口先验证当前账号对案件的所有权，再读取记录；不能用其他案件ID查看其日志。

成功的图执行记录附在该轮助手消息的 `workflow.execution_trace` 中，刷新后仍能读取。标准本地启动器另写入 Git 忽略的 `data/local-setup/agent-traces.jsonl`，进入Agent执行后失败的轮次也会写入，因此无需为了保存日志而提交部分事实或半份回答。日志文件约5MB轮转一次，保留一个前卷；文件创建权限为0600。普通应用入口默认没有磁盘导出，只有本地启动器默认启用，也可通过 `FSIE_AGENT_TRACE_FILE` 指定项目 `data/local-setup/` 下的路径。

埋点不能补回启用前的历史记录，也不包含Agent开始前的认证、网络失败。当前日志覆盖聊天编排的服务端节点和可观测调用；独立结构分析界面所调用的外部税务引擎进程内部实现没有被修改，不能声称取得了那个进程每个内部步骤的实时遥测。

## 记录内容

| 层次 | 事件/内容 |
| --- | --- |
| 一轮请求 | trace_id、request_id、案件ID、开始与结束时间、状态、预算计数；不记录原始整段用户输入 |
| 图节点 | route、facts、consultation、fact_intake、reference_lookup、tool_harness、observe、validate；旧版retrieve、compose、validate也使用相同埋点 |
| 节点输入/结果 | 意图、动作、任务类别、查询、候选字段名、冲突字段名、状态和下一步；不复制事实字段值或完整提示词 |
| 路由 | 模型分类与简短决策摘要、格式/语言拒绝、重试、最终分支 |
| 工具规划 | 当时开放的工具、前序结果摘要、剩余预算、模型提议工具、查询参数、一句话选择理由 |
| 工具校验 | 接受、拒绝原因、安全修复、服务端覆盖；明确区分模型提议和实际执行 |
| 工具执行 | 工具名称、实际查询、耗时、结果状态、停止原因；失败只记录异常类型与安全错误码 |
| 证据 | 检索范围、资料数、原文读取与缓存、可入模/可展示数量、覆盖缺口数量、来源定位 |
| 模型调用 | 调用起止、调用计数；提供方上报时保存prompt/completion/total token数量，不上报时不估造 |
| 最终生成 | 初次生成、修复、复杂案例复核、校验拒绝、最终生成方式和段落数 |
| 其他已有分支 | 一般费用查询的prepare/search/answer；正式分析的前置校验和返回的规则节点结果 |

所有事件有序号、UTC时间、相对毫秒时间及父span关联；节点发生异常也有结束记录。每轮常规事件上限250条，超过后记录省略数量，保留错误事件。ContextVar隔离并发轮次，避免不同用户请求串日志。历史遥测不传回下一轮模型，也不反复复制进图的会话状态。

“决策摘要”是模型为调试返回的一句话说明，**不是模型内部逐字思维链，也不证明该选择或税法判断正确**。不请求、不记录私有推理内容。密钥、认证信息、完整提示词、模型原始回答和原文全文不进入遥测；查询及简短摘要做凭据、邮件和手机号脱敏。诊断数据仍按案件权限访问。

## 真实网页观察

会话：`ef467eb8-0f12-4b74-a654-aa374408e040`。

### 轮次一：参与豁免条件

输入：“香港境外股息的参与豁免需要满足哪些条件？请说明持股比例和持有期。”

Trace ID：`a90640a5-e84b-4bb6-84d4-e836705836ab`。78个事件，总图准备耗时约7.15秒，4次模型调用、1次工具执行/检索、2次证据读取。

实际路径：`route → facts → tool_harness → observe → validate`。

1. 路由模型选择research/reference_lookup，摘要为这是规则查询而非个案事实录入。
2. 工具规划器提议 `search_guidance`，查询保留香港、FSIE、境外股息、参与豁免、持股比例和持有期。服务端接受后执行。
3. 规划器看到7个相关展示片段后提议finish，给出的摘要是证据足够，无需其他工具。
4. 最终阶段生成一次获引文支持的正文。

这说明该轮实际只执行了一个检索工具，不应因系统有多工具能力就称其为“全部Agent依次执行”。工具名称、模型对资料的称呼和资料实际类型应分别核对；规划器“证据足够”的摘要也需要结合覆盖内容检查，不能仅用片段数量证明任务完成。

### 轮次二：普通续答

输入：“谢谢，先不用继续查询。”

Trace ID：`ab340c00-09f7-44a5-93ef-e4ccb306139d`。28个事件，约2.83秒，实际路径为 `route → facts → validate`，**没有工具调用**。

日志发现了一项可定位的额外开销：第一次路由返回`intent=chat`和`action=pause`，被现有动作与意图兼容性校验拒绝；第二次返回合法chat后完成，因此普通续答也消耗了2次模型调用。这里记录了实际提议、校验拒绝和重试，可作为后续优化路由协议的依据；本轮没有为掩盖现象而改写已有路由规则。

网页已实际展开节点列表和工具摘要，并验证最近执行记录接口返回成功。截图：Git忽略目录中的 `data/local-setup/agent-trace-panel-2026-10-17.jpg`。
