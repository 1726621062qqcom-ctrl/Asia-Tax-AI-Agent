# 网页回归问题：修改方案与实施记录

日期：2026-10-18。依据：三个 GitHub 案例的真实网页输出及361条埋点，详见同目录 github-web-test-telemetry 报告。

## 修改方案

1. 引用紧跟论点。模型仅选择已获准原文和支持段落，服务端生成短标签Markdown链接。来源身份已定位子条款时显示 s.15K(1) 等；父条原文保留父条号；不伪造子条款精度。正文不再重复整份引用列表，来源原文仍可展开。
2. 混合案情与研究请求进入研究路径。修正路由提示，并对明确要求解释条件、证据或材料的 intake 分类加服务端纠偏。保留事实提取、冲突处理、未知事项及正式分析确认门槛。单纯回答事实、暂停和正式研究稿请求不被强制转为查询。
3. 基于原问题导航法条。复用现有 NODE_LOCATORS，完整案例覆盖范围、收取、经济实质、参与及境外税问题；不依赖模型是否在短查询中复述关键词。明确要求的资料类型优先于重复法条和额外裁定。调度器取得累计覆盖情况，已完成导航与资料类型后结束收集，给生成及复核保留预算。
4. 部分检索仍保留结果。读取后续证据达到上限时保留之前逐条通过权限、哈希与版本检查的原文。工具结束、循环结束、业务状态统一记录 budget_exhausted；回答告知未完成部分。不能将中途失败标为完成。
5. 最终来源窗口优先保留主要法条，防止大量FAQ片段挤掉关键法条。

## 真实回归捕获的额外故障

最终复测中，案例二一次PostgreSQL指引读取耗时56.27秒，超过单次检索10秒和整轮45秒；最终返回可核对原文及未完成提示，业务状态正确标记partial_failure/budget_exhausted，不能计为正常回答通过。失败案例保留为`ebf01a8f-0ead-42c9-9502-da678fa42063`。

根因：已有connect_timeout和statement_timeout不能完整约束连接池pre-ping或失联TLS连接的客户端等待。增加Provider整体调用时限和全局最多2个只读后台任务；超时返回TIMEOUT并忽略迟到结果，给已取得法条的解释保留时间。受限线程不会写案件、调用模型或扩大数据库权限。极端网络卡死的后台读取不能强制终止，但数量受限，新的查询会按时返回超时。增加阻塞读取的离线回归，确认截止时间后不接纳迟到资料。同时修复最终生成无剩余额度时重复尝试的问题。


## 日期及陈述校验

真实输出发现年份被写为月份、用未通过决议推断未累算，以及在累算日期未确定时计算大概持有月数。新增可执行校验和定向修复反馈，未知累算日期仍然保留未知；三类情况有离线回归。最终网页案例三已不再出现“2027 payment month”或“nothing has accrued”。这不构成对税务准确性的完整自动验证。
